# 结果复盘表自动化系统 PRD

---

## 一、背景与目标

**当前问题：**
结果复盘表（225行）中，`索引修复状态` 右侧的所有字段（day14_impressions / day14_clicks / day30_进Top50词数 / 当前最高排名词（排名）/ day30_clicks / day60_pv / day60_目标国pv）全部为"待回填"，依赖人工逐一查询 GSC 和 GA4 后手动填入。225个页面人工维护成本极高，且滞后性大，错过优化窗口。

**目标：**
构建自动化系统，定时拉取 GSC 和 GA4 数据，自动填充复盘表字段，并基于字段数值自动生成针对性的 blog 优化任务清单——让每一个需要优化的页面在达到触发阈值时就能被发现，而不是等人工复盘时才看到。

---

## 二、系统流程

```
结果复盘表 CSV（页面列表 + URL）
        ↓
Module 1：数据拉取
  ├─ GSC API → impressions / clicks / top keyword / ranking
  └─ GA4 API → pv / 目标国 pv
        ↓
Module 2：字段自动填充
  （按申请时间计算 day14 / day30 / day60 节点，到期自动写入）
        ↓
Module 3：优化触发判断
  （逐行评估各字段数值，匹配优化规则，输出任务清单）
        ↓
输出：
  ├─ 更新后的 CSV（字段全部填充）+ 自动备份
  └─ 优化任务清单（Markdown，按优先级排列）
```

## 三、Module 1：数据拉取

### 1.1 GSC API（Google Search Console）

**拉取维度：** 按 URL 筛选，时间范围动态计算（见 Module 2）

**拉取字段：**

| 字段 | GSC 对应指标 | 说明 |
|---|---|---|
| day14_impressions | impressions | URL 上线后第 7–14 天的累计曝光数 |
| day14_clicks | clicks | URL 上线后第 7–14 天的累计点击数（与 day14_impressions 同窗口，用于计算 CTR）|
| day30_clicks | clicks | URL 上线后第 16–30 天的累计点击数 |
| day30_进Top50词数 | queries（position ≤ 50）| 第 16–30 天内，该 URL 排名 ≤ 50 的不重复关键词数量 |
| 当前最高排名词（排名）| queries（最低 position）| 当前排名最高的关键词及其位置，格式：`关键词（排名数字）` |

> `day14_clicks` 和 `day14_impressions` 必须来自同一时间窗口（第7–14天），CTR = `day14_clicks / day14_impressions`。不得跨窗口混用两个字段计算 CTR。

**时间窗口计算逻辑：**
- `day14`：`申请时间 + 7天` 到 `申请时间 + 14天`
- `day30`：`申请时间 + 16天` 到 `申请时间 + 30天`
- `day60`：`申请时间 + 31天` 到 `申请时间 + 60天`
- 未到时间节点的字段：保持"待回填"，不写入

> 注：GSC 数据有约 3 天延迟，时间窗口起点往后顺延 3 天补偿。

**API 配额说明：**
GSC Search Analytics API 免费配额为 **每日 2,000 次请求/项目**。225个 URL × 每次最多拉 3 个时间窗口 = 最多 675 次/天，在配额内。但每次请求需独立发起（不可批量合并 URL），建议在代码层加 `time.sleep(0.1)` 防止突发限速（429 错误）。

### 1.2 GA4 API（Google Analytics 4）

**拉取字段：**

| 字段 | GA4 对应指标 | 说明 |
|---|---|---|
| day60_pv | screenPageViews（按 pagePath 筛选）| 第 31–60 天内该页面总 PV |
| day60_目标国pv | screenPageViews（按 pagePath + country 筛选）| 第 31–60 天内目标国（美国/英语区）PV |

**目标国定义：** 默认为 United States，可在配置文件中调整。

## 四、Module 2：字段自动填充

**触发方式：** 每日定时运行一次（建议每天早上 8:00 UTC+8）

**`申请时间` 字段格式规范：** CSV 中该字段必须为 `YYYY-MM-DD` 格式（如 `2026-06-01`）。代码读取时使用 `pd.to_datetime(row['申请时间'], format='%Y-%m-%d')`，格式不符将抛出异常并跳过该行（记录到错误日志）。

**填充逻辑：**

1. 读取 CSV，逐行检查 `申请时间` 字段
2. 计算今天距离 `申请时间` 的天数
3. 对应到 day14 / day30 / day60 时间窗口
4. 若时间窗口已过且对应字段仍为"待回填"→ 拉取数据写入
5. 若时间窗口未到 → 跳过，保持"待回填"
6. 若字段已有数值（非"待回填"）→ 跳过，不覆盖历史数据

**当前最高排名词（排名）：** 每次运行时更新（实时性字段，不受时间窗口限制）。注意：该字段每次覆盖，不保留历史快照。如需追踪排名趋势，可在 CSV 中额外增加 `day30_最高排名词快照` 字段，在 day30 窗口到期时一次性写入并锁定，不再更新。

**`记录日期` 字段：** 每次成功写入任一字段时，同步更新为当天日期

**运行前备份：** 每次运行开始时，先将原 CSV 复制到 backup 目录（见§七配置），再执行写入。备份文件名格式：`结果复盘表-backup-{YYYY-MM-DD}.csv`，保留最近 7 份。

## 五、Module 3：优化触发判断

每次数据更新后，对全表逐行评估，输出优化任务清单。

### 5.1 优化触发规则

规则从上到下优先级依次降低，一个页面命中多条规则时，取最高优先级：

| 优先级 | 触发条件 | 优化动作 | 对应规范 |
|---|---|---|---|
| **收录异常** | day14_impressions = 0 且已收录（`索引修复状态` = 已收录）| 标记为"收录异常，检查URL是否正确/是否被noindex" | — |
| **P0** | day14_impressions ≥ 1000 且 day14_clicks / day14_impressions（CTR）≤ 1% | Title tag + Meta description + FAQ schema | 博客优化规范 §二、§三 |
| **P0** | 当前最高排名词排名 ≤ 10 且 day30_clicks 较低 | Title tag + Meta description（首页CTR优化）| 博客优化规范 §二 |
| **P1** | day14_impressions 500–999 且 day14_clicks / day14_impressions（CTR）≤ 2% | Title tag + Meta description | 博客优化规范 §二 |
| **P1** | 当前最高排名词排名 11–30 | 内链加强（争取进前10）+ 确认 FAQ schema 存在 | 博客优化规范 §三 |
| **P2** | day30_进Top50词数 = 0 且 day14_impressions ≥ 20 | 内容质量检查：主题覆盖是否完整，H2结构是否对齐搜索意图 | blog创作要求清单_v4.0 |
| **P2** | day14_impressions ≥ 100 且 无 FAQ schema | 补充 FAQ schema | 博客优化规范 §三 |
| **P3** | day14_impressions < 10 且 已收录 | 标记为"冷门观察"，暂不优化，day60 再评估 | — |
| **观察** | day60_目标国pv / day60_pv < 30% | 流量非目标国，检查关键词语言和地区设置 | — |

**FAQ schema 检测方式（P2规则）：**
```bash
curl -s {page_url} | grep -i '"@type":"FAQPage"'
```
返回空字符串 = 无 FAQ schema，触发 P2；返回非空 = 已有 schema，跳过。检测在 Module 3 运行时对命中 `day14_impressions ≥ 100` 条件的 URL 逐一执行。

### 5.2 趋势词 Blog 专项规则

趋势词 blog（URL 含世界杯/赛事/人名等时效性词）额外检测。

**`备注` 字段格式规范（代码可读）：** 趋势词行的备注字段必须包含结构化日期标记，格式：

```
event_end:YYYY-MM-DD
```

示例：`世界杯决赛前相关内容 event_end:2026-07-19`

代码通过正则 `re.search(r'event_end:(\d{4}-\d{2}-\d{2})', 备注)` 提取日期。无此标记的行跳过趋势词专项规则。

| 触发条件 | 优化动作 |
|---|---|
| `event_end` 日期未到（事件仍在窗口期）且 week-on-week 曝光下滑 ≥ 30% | 追加内容更新（参考博客优化规范 §四） |
| `event_end` 日期已过 7 天且曝光降至峰值 20% 以下 | 标记为"趋势衰减，不再优化" |

### 5.3 优化任务清单输出格式

```markdown
# AstrologyWiki 博客优化任务清单
生成时间：2026-07-05 08:00

## 收录异常（优先排查）

| 页面 | URL | 索引状态 | day14曝光 | 异常说明 |
|---|---|---|---|---|
| example-page | /en/wiki/... | 已收录 | 0 | 收录异常，检查URL/noindex |

## P0（立即处理）

| 页面 | URL | day14曝光 | day14_CTR | 最高排名词 | 优化动作 |
|---|---|---|---|---|---|
| bing-hastert-birth-chart | /en/wiki/... | 7,281 | 0.4% | bing hastert（4.1）| Title tag + Meta desc + FAQ schema |

## P1（本周处理）
...

## P2（下周处理）
...
```

## 六、技术栈

| 组件 | 方案 |
|---|---|
| 语言 | Python 3.10+ |

## 七、配置文件

```yaml
gsc:
  site_url: "https://www.astrologywiki.com/"
  credentials_path: ./credentials/gsc_service_account.json
  data_lag_days: 3          # GSC数据延迟补偿
  request_interval_ms: 100  # 每次API请求间隔（防429限速）

ga4:
  property_id: "YOUR_GA4_PROPERTY_ID"
  credentials_path: ./credentials/ga4_service_account.json
  target_country: "United States"

schedule:
  run_time: "08:00"         # 每日运行时间（UTC+8）

csv:
  input_path: "./astrologywiki.com - 结果复盘表.csv"
  output_path: "./astrologywiki.com - 结果复盘表.csv"   # 覆盖原文件（运行前自动备份）
  backup_path: "./backups/结果复盘表-backup-{date}.csv"  # 自动备份路径
  backup_retention_days: 7   # 保留最近7份备份
  task_output_path: "./优化任务清单-{date}.md"

thresholds:
  p0_impressions: 1000
  p0_ctr_max: 0.01
  p1_impressions_min: 500
  p1_ctr_max: 0.02
  trend_decline_pct: 0.30   # 周环比曝光下滑触发追更的阈值
```

## 八、开发优先级

| 优先级 | 模块 | 原因 |
|---|---|---|
| P0 | Module 1 GSC 数据拉取 + Module 2 字段填充 | 225个页面"待回填"是当前最大运营盲区 |
| P0 | 当前最高排名词（实时更新）| 直接指导内链和内容优化决策 |
| P1 | Module 3 优化触发判断 + 任务清单输出 | 将数据转化为可执行优化动作 |
| P2 | GA4 数据拉取（day60_pv）| day60 节点较晚，优先级低于 GSC |
| P2 | 趋势词专项规则 | 依赖 `备注` 字段补充 `event_end:YYYY-MM-DD` 标记后才能运行 |

## 九、与博客优化规范的对接

本系统的 Module 3 输出的优化任务清单，直接对应 `2026-07-05-blog优化更新规范-v1.0.md` 的执行动作：

| 系统输出的优化动作 | 规范对应章节 |
|---|---|
| Title tag + Meta description | §二 CTR 优化规范 |
| FAQ schema | §三 FAQ Schema 补充规范 |
| 追加内容更新 | §四 趋势词 Blog 内容更新规范 |
| 内容质量检查 | blog创作要求清单_v4.0.md |
