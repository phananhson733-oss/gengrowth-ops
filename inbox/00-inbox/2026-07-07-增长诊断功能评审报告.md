# GenGrowth 增长诊断 功能评审报告

> 评审方法：截图观察 + HTML 源码逆向提取（i18n 字符串、模块定义、评分公式），确保结论基于可核实数据，而非视觉猜测。

---

## 一、产品实际覆盖范围

### 评分体系

综合评分由 6 个维度加权构成（源码确认）：

| 维度 | 权重 |
|---|---|
| 技术健康 | 20% |
| 搜索可见性 | 20% |
| 内容质量 | 20% |
| 外链建设 | 15% |
| AI/GEO 可见性 | 10% |
| 合规性 | 15% |

缺失维度自动排除并重新归一化（例如合规模块当前重建中，不计入总分）。

### 技术健康模块（A1–A7，30+ 项检测）

| 子模块 | 覆盖检测项 |
|---|---|
| A1 可抓取性与索引 | JavaScript渲染（CSR/SSR判断）、Noindex、GSC验证、索引覆盖率、抓取错误、抓取预算、Sitemap、Robots.txt |
| A2 页面速度与核心指标 | LCP、INP、CLS、TTFB、页面总大小、渲染阻塞资源、第三方脚本、图片优化、多页面测试提示 |
| A3 移动端兼容性 | 移动端适配、响应式渲染分、触控目标、字体可读性、插页式广告 |
| A4 URL与站点架构 | 点击深度、重定向链、URL规范化、首页版本统一性 |
| A5 结构化数据 | Schema.org类型、Open Graph标签、Canonical URL |
| A6 安全与协议 | HTTPS、SSL证书、混合内容 |
| A7 页面SEO | Meta Title（30-60字符）、Meta Description（120-160字符）、H1标签、语言声明、内容新鲜度、Hreflang |

### 搜索可见性模块（B1–B4）

| 子模块 | 覆盖检测项 |
|---|---|
| B1 搜索表现基线 | 展示量趋势、点击量趋势、平均CTR、设备端表现差异、目标市场集中度、品牌词vs非品牌词比例 |
| B2 关键词资产 | 关键词覆盖（依赖Ahrefs/DataForSEO接入） |
| B3 SERP特征 | SERP特征占位分析 |
| B4 国际化SEO | Hreflang检测、多语言变体 |

### 外链模块

DR评级、引荐域名数量、链接增速、Follow/Nofollow比例、外链质量分层（DR>60 / DR 30-60 / DR<30）

### 合规模块（当前重建中，不计入总分）

Cookie横幅、GDPR、CCPA/CPRA、Cookie分类、数据最小化

### 内链分析（存在但依赖采样）

内链分布（每页平均内链数，建议≥3）、孤立页面检测（内链数=0的页面）——当前AstrologyWiki分析显示"未采样"，该检测未触发。

## 二、做得好的地方

### 1. CWV 阈值完全准确

LCP <2500ms、INP <200ms（已用INP替代旧指标FID）、CLS <0.1、TTFB <800ms，与 Google 当前标准完全一致。很多竞品工具仍在用已废弃的 FID 指标，这里没有。

### 2. JavaScript CSR 检测逻辑正确

三档判断——Pass（SSR检测到）/ Warn（可能CSR）/ Fail（CSR检测到）——对应的说明是"Google 可能无法索引内容"。这是真实且重要的 SEO 风险，检测结果准确。

### 3. 拒绝在数据缺失时编造指标

源码明确写明："缺失证据时会显示需补数据，而不是补造指标"。大部分 SEO 工具在数据不足时仍会输出估算值，这个设计取向是对的，对用户信任很重要。

### 4. 行动时间颗粒度设计合理

行动按执行时间分成三个桶："现在做（24-48小时）"、"本周做"、"需补数据"，并附有优先级排序规则："P0/P1 × 真实证据 × 时间敏感度 × 目标明确度 - 执行成本"。把 SEO 问题按时间紧迫性分层，比平铺所有问题实用很多。

### 5. 合规与 SEO 边界明确

GDPR/CCPA 放在独立合规模块，且源码明确标注"合规模块重建中，当前不计入综合评分"。产品团队清楚地知道合规和 SEO 增长是两件不同的事，这是边界意识清晰的体现。

### 6. Social-First 就绪度指标

"判断 SEO/GEO 主题是否适合先在 Reddit、X、LinkedIn 做探测，再扩大内容生产"——这把 SEO 和社媒验证连在一起，在内容分发策略上是一个有价值的判断节点，行业内基本没有工具覆盖这个维度。

### 7. 行业百分位设计

源码中存在 `percentileLabel`（行业百分位），说明产品计划提供评分基准对比。这对用户理解"26分意味着什么"非常重要。

## 三、功能层面的问题

### 🔴 严重问题

**问题1：搜索可见性评分为0，严重拉低总分，但原因未透明说明**

AstrologyWiki 截图显示搜索可见性=0，而这个维度占总评分20%。

源码显示 0 分的触发条件是：GSC 未连接，或"GSC 已连接但暂无可评分的搜索数据"。但 AstrologyWiki 有真实的 GSC 数据（W27 周期 195 次点击），说明 GSC 连接未打通或数据同步尚未完成。

问题在于：页面上没有清楚告诉用户"这个0是因为数据源未接入，而不是你的搜索表现真的是0"。一个有实际流量的网站看到搜索可见性=0，会对这个工具的准确性产生怀疑。

**建议**：搜索可见性为0时，明确显示原因（"GSC 未连接 / 连接中 / 数据不足"），并将其从总分计算中排除或标注为"待接入"，而非计入0分拉低总分。

---

**问题2：内容新鲜度检测依赖 sitemap lastmod，可靠性存疑**

源码确认：内容新鲜度的判断完全基于 sitemap 的 `lastmod` 字段。

这个信号有两个已知问题：
- 很多站点的 lastmod 不维护，或每次部署时自动刷新（与内容变化无关）
- 无法区分"实质性内容更新"和"样式/代码微调"

如果 AstrologyWiki 的 sitemap lastmod 不准确，内容新鲜度评分就失去意义，可能影响内容维度的评分（占总分20%）。

**建议**：补充 GSC 首次出现时间 + HTTP Last-Modified 作为交叉验证信号；或在说明中明确"此数据来自 sitemap lastmod，请确认你的 sitemap 已正确维护 lastmod 字段"。

---

### 🟡 功能性缺口

**问题3：内链分析存在但未触发（显示"未采样"）**

源码中确认存在"内链分布"和"孤立页面"两个检测项（分别检测每页平均内链数、内链为0的孤立页面），但在 AstrologyWiki 的这次分析中显示"未采样——本次分析未获取到页面采样数据"。

内链是对内容站影响最大的 SEO 杠杆之一，直接影响 PageRank 分布和 Google 对页面的发现效率。功能有但没跑起来，等于不存在。

**建议**：排查采样未触发的原因，确保内链分析能在标准分析流程中稳定运行。

---

**问题4：PageSpeed 仅测首页，对内容站意义有限**

源码中明确有提示："仅测试了首页——建议单独测试落地页、博客和产品页"，但这只是一条警告，没有提供解决方案。

对 AstrologyWiki 这样有 200+ 博客页面的站点，首页和博客页面的技术性能可以差异显著（不同的 JS bundle、不同的图片密度、不同的 Lazy Load 行为）。只测首页，遗漏了绝大多数实际用户访问的页面。

**建议**：增加对随机抽样内页（如10个）的 PageSpeed 检测，或至少增加"博客页面快速测试"入口。

---

**问题5：批量检测项只输出数量，不输出 URL 列表，结论无法执行**

以孤立页面为例：工具显示"存在大量孤立页面"，但不展示具体是哪些 URL。

孤立页面的严重程度完全取决于是哪类页面：blog 内容页和工具页是 P0，landing page 和 app 页（/dashboard、/onboarding）本来就不需要内链，无需处理。没有 URL 列表，用户无法做这个区分，唯一的选项是自己重新跑一遍爬虫——那这条诊断等于没有。

这是一个系统性问题，不只影响孤立页面，所有"影响 X 个页面"类型的检测项都有同样的缺口：用户拿到的是一个数字，而不是一张可以直接操作的清单。

**建议**：所有批量检测项的结果都应附带可筛选的 URL 列表，按页面类型或路径前缀分组（如 /en/wiki/\*、/en/tools/\*、/app/\*），让用户能区分"需要修复的"和"不需要管的"，诊断结论才能真正转化为执行动作。

---

**问题6：合规问题（CCPA/GDPR）出现在增长行动主列表，模块状态自相矛盾**

"G1 ccpa No US policy → pass"出现在增长行动 Top 5 中。

首先，CCPA 是法律合规要求，与搜索排名无关，本不应出现在 SEO 增长行动里。

更根本的矛盾在于：源码中合规模块明确标注"重建中，该维度暂不计入综合评分，也不展示任何分数"。但 CCPA 这条仍然出现在行动主列表——合规模块在评分层被暂停了，在行动层却没有暂停，两边状态不一致。用户会看到：合规模块没有分数，却在最重要的行动清单里看到合规问题排进了前5，无法理解这个矛盾。

另外，"影响所有页面"在这里是准确的——CCPA 是站级配置问题（需要添加隐私政策和 opt-out 机制），不是某几个页面的问题，所以此条不涉及"缺 URL 列表"的问题。

**建议**：合规模块重建期间，对应的行动项也应同步从增长行动主列表中移除；合规类行动在任何状态下都应放在独立的合规模块，不与 SEO 增长行动混排。

---

**问题7：CTA 覆盖率存在双重问题——放错模块位置 + 缺 URL 列表**

截图显示增长行动 Top 5 的第一条是"CTA 覆盖率 0→0.3，影响127个页面"。

**第一层：放错了位置。** CTA 覆盖率是转化率优化（CRO）指标，与搜索排名无关。将它排在增长行动第一位（优先于 JavaScript CSR 渲染问题），可能误导用户认为这是最重要的 SEO 问题，实际影响更大的技术问题反而靠后。

**第二层：同样缺 URL 列表。** "影响127个页面"没有展示具体是哪些页面，用户不知道从哪里开始优化。与孤立页面问题相同——有数量，没列表，结论无法直接执行。

两个问题叠在一起：执行层（没有 URL 列表）+ 优先级层（放错模块）。

**建议**：将 CRO 类行动归入独立的转化优化模块，不与 SEO 行动混排优先级；同时所有批量检测项补充可筛选的 URL 列表。

---

### 🔵 体验层面的改进建议

**问题8：多个维度评分为0，未说明是"无数据"还是"真的很差"**

截图中多个子维度显示0（搜索可见性、AI/GEO等）。对于用户来说，0可能代表：
- 数据源未接入（无法评分）
- 真实分析结果是0分（非常差）
- 模块未完成分析

这三种含义完全不同，但界面上的呈现方式一样。

**建议**：使用不同的视觉状态区分"未接入/灰色"、"分析中/黄色"、"分析完成=0/红色"，避免用户把数据缺失误读为评分极低。

---

**问题9：26分没有基准参照**

综合评分26分，用户无法判断这意味着什么——是同类内容站里的垫底，还是正常水平？源码中存在 `percentileLabel`（行业百分位）字段，说明这个功能已在规划中，但当前状态下没有显示。

**建议**：优先实装行业百分位显示，哪怕是粗略的分段（如"同类站中排名后20%"），都能极大提升评分的可读性和行动动力。

## 四、总结评分

| 评审维度 | 评分 | 说明 |
|---|---|---|
| 技术SEO检测覆盖 | ★★★★ | 30+ 检测项，CWV阈值准确，CSR检测逻辑正确 |
| 数据可信度原则 | ★★★★★ | 拒绝编造指标，行业罕见 |
| 搜索可见性评估 | ★★ | 强依赖GSC连通性，0分状态未向用户说明原因 |
| 内容质量评估 | ★★ | 新鲜度依赖lastmod，内链分析存在但未触发 |
| 行动优先级设计 | ★★★ | 时间颗粒度好，但CTA/CRO混入SEO行动干扰了判断 |
| 评分可读性 | ★★ | 多个0分状态歧义，缺乏基准参照 |

**最高优先级的两个改进**

1. **修复搜索可见性0分的说明**：这是当前用户首次使用体验中最大的信任破坏点——一个有真实流量的网站看到搜索可见性=0，会直接否定这个工具的准确性。
2. **确保内链采样稳定触发**：功能已写好但没跑起来，修复后能立即给用户提供对内容站最有价值的诊断维度之一。
