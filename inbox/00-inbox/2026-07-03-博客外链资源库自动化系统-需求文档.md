# 博客外链资源库自动化系统 · 需求文档

## 背景与目标

**背景：**
博客评论外链是一种低成本、可规模化的SEO外链获取方式。核心是找到"有评论区、允许填写网址、且链接为dofollow"的博客，在上面发布与内容相关的评论并附上自己的网站链接。

目前市面上存在人工整理的付费博客列表（约250条，¥19.9），但存在以下问题：
- 列表静态，不持续更新
- 无法按自己的产品方向筛选相关博客
- 对第三方产生依赖

**目标：**
构建一套自动化系统，能够持续发现、验证、管理可用于博客评论外链的目标站点，产出标准化的博客资源库，供后续评论工具（如 backlink-helper 插件）直接调用。

---

## 系统总览

```
关键词输入
    ↓
Module 1：SERP抓取（找候选博客URL）
    ↓
Module 2：页面验证（判断是否有效评论表单）
    ↓
Module 3：DR过滤（排除低权重域名）
    ↓
Module 4：测试提交（验证评论是否真实通过）
    ↓
Module 5：数据库管理（存储、更新、导出）
```

## Module 1：SERP抓取

### 功能说明
根据输入的关键词，自动构造Google搜索指令，批量抓取有评论区的博客页面URL。

### 输入
- 关键词列表（支持单个或批量）
- 语言/地区参数（如：英语/全球，日语/日本）
- 每个关键词的最大抓取结果数（默认100条）

### 搜索指令模板
系统自动将输入关键词拼入以下模板：

```
"leave a reply" "website" {keyword}
"leave a comment" "your website" {keyword}
"add a comment" "name" "email" "website" {keyword}
inurl:/blog/ "powered by wordpress" "leave a reply" {keyword}
"post a comment" "website url" {keyword}
```

每个关键词生成约5条搜索指令，每条指令抓取前20个结果，单关键词最多产出约100个候选URL。

### 抓取方式
- 调用 **SerpAPI**（推荐）或 **ScraperAPI** 获取Google搜索结果
- 不直接爬取Google页面（会触发封锁）
- 抓取字段：URL、页面标题、摘要文本

### 去重处理
- 同一域名下不同路径的URL：保留，均加入候选列表（同一博客可能有多篇文章可发评论）
- 完全相同的URL：去重，只保留一条

### 输出
候选URL列表，字段：
```
url | page_title | domain | keyword_source | crawl_time
```

## Module 2：页面验证

### 功能说明
对Module 1输出的候选URL逐一访问，判断该页面是否包含有效的博客评论表单。

### 判断条件（同时满足以下三点才算有效）

**条件A：存在评论表单**
页面HTML中存在 `<form>` 标签，且该表单含有以下字段（通过name/id/placeholder识别）：
- 姓名字段：`name`、`author`、`commentAuthor` 等
- 邮箱字段：`email`、`mail` 等
- 网址字段：`url`、`website`、`link`、`homepage` 等
- 评论内容字段：`comment`、`message`、`content` 等

**条件B：网址字段可填写**
网址字段不为 `readonly`、`disabled`、`hidden`，即用户可以实际输入URL。

**条件C：链接dofollow检测**
抓取该页面上已有的评论区链接，检测其 `rel` 属性：
- `rel` 属性含 `nofollow`、`ugc`、`sponsored` 中任意一个 → 标记为 **nofollow**（Google 2019年更新后，ugc/sponsored 与 nofollow 同等对待，WordPress 评论区默认输出 rel="ugc"，必须纳入检测）
- `rel` 属性不含上述三个值 → 标记为 **dofollow**
- 无 `rel` 属性 → 标记为 **dofollow**（默认）
- 评论区无已有链接 → 标记为 **unknown**（无法判断）

### 附加检测项（非必须但记录）

| 检测项 | 说明 |
|---|---|
| CMS类型 | 检测是否为WordPress（通过wp-content路径、generator meta tag识别） |
| 评论数量 | 页面上已有评论数量（数量多说明评论区活跃、审核宽松） |
| 页面语言 | 通过 `<html lang>` 或内容识别 |
| 是否需要登录才能评论 | 检测评论区是否有登录提示 |
| **外部链接数量** | **页面上全部外部链接总数（对应 cloudhu2000 插件的「外部链接数量」字段）。链接过多意味着单条链接权重被稀释，真实数据中出现过单页 31,841 条外部链接的极端情况。过滤规则：≤ 500 正常保留；501–2000 低优先级标记；> 2000 直接丢弃** |
| **页面AS** | **页面级 Authority Score（对应 cloudhu2000 插件的「页面AS」字段，来源为 SEMrush 或 DataForSEO）。与 Module 3 的域名 DR 是不同维度，均需记录** |

### 技术实现
- 使用 **requests + BeautifulSoup** 处理静态页面
- 如果页面检测到JavaScript渲染（评论区由JS加载），使用 **Playwright** 无头浏览器抓取
- 超时设置：10秒，超时则标记为 `timeout`，跳过
- 并发数：建议5-10个并发，避免触发目标站点反爬

### 输出
在候选URL列表基础上增加字段：
```
has_comment_form | has_website_field | dofollow_status | cms_type | comment_count | page_language | needs_login | external_link_count | page_as | page_content_snippet | validation_status
```

- `page_content_snippet`：页面正文摘要（约500字），**供 Module 4 AI生成评论时调用，避免 Module 4 重复抓取页面**
- `validation_status` 取值：`valid` / `no_form` / `no_website_field` / `login_required` / `too_many_links`（外链>2000）/ `timeout` / `error`
- `validation_status` 非 `valid` 的记录：保留在候选表中供审查，不进入后续模块

## Module 3：DR / AS 过滤

### 指标说明（重要）

本系统同时追踪两个权重指标，来源和用途不同：

| 指标 | 全称 | 维度 | 来源 | 对应插件字段 |
|---|---|---|---|---|
| **Domain DR** | Ahrefs Domain Rating | 域名级 | DataForSEO / Ahrefs | — |
| **页面 AS** | Authority Score | 页面级 | DataForSEO / SEMrush | cloudhu2000 插件「页面AS」 |

DR 反映域名整体权重；页面 AS 反映该具体页面的权威度，两者互补。cloudhu2000 插件导出的「页面AS」字段已在 Module 2 记录，本模块补充查询域名 DR。

### DR查询方式
- 优先使用 **DataForSEO API**（支持批量查询，成本低，可同时返回 DR 和 AS）
- 备选：**Ahrefs API**（成本较高，但数据权威）
- 每次查询以域名为单位（非页面URL），同一域名下多个URL只查一次

### 过滤规则

依据 cloudhu2000 真实运行数据（blog_run_stats_2026-06-22_to_2026-06-28.csv）校准阈值：插件实际使用的页面AS分布为 5–74，其中「高AS」专项名单下限为 51。

| DR范围 | 处理方式 | 说明 |
|---|---|---|
| DR ≥ 30 | 高优先级，进入验证队列 | 对应插件高AS名单质量区间 |
| DR 10–29 | 中优先级，进入验证队列 | 插件日常运行主体区间 |
| DR 1–9 | 低优先级，**保留入库，标记低优** | 插件中有AS 5–9的站点实际被使用 |
| DR = 0 或无数据 | 丢弃 | 无权重信号，无保留价值 |

DR阈值应可在配置文件中调整。

### 输出
在验证列表基础上增加字段：
```
domain_dr | dr_priority | dr_checked_at
```

## Module 4：测试提交验证

### 功能说明
对进入验证队列的博客URL，自动提交一条测试评论，等待一定时间后回访确认评论是否通过审核。这是判断该站点是否真实可用的最终关卡。

### 重要说明：不使用cloudhu2000插件

cloudhu2000的插件（backlink-helper / autoComment）是**人工操作工具**，依赖Chrome浏览器交互，无法被后端程序直接调用。Module 4是自动化流水线中的一个环节，需独立实现表单提交逻辑。

两者定位不同，互不依赖：
- **Module 4（本模块）**：后台自动运行，目的是验证博客是否真实可用，产出已验证列表
- **cloudhu2000插件**：日常运营时使用，读取已验证列表，人工确认后发布正式评论

### 提交实现方式

**方案A（优先）：HTTP POST直接提交**
- 复用Module 2中已检测到的表单结构（form action URL、字段name属性）
- 用 `requests` 库直接向表单 action URL 发送 POST 请求
- 携带字段：name / email / url / comment
- 优点：速度快、无需浏览器、可高并发
- 缺点：部分站点有CSRF token或验证码会失败

**方案B（降级）：Playwright模拟浏览器提交**
- 方案A失败时自动降级
- 用无头浏览器实际填写并点击提交按钮
- 优点：可处理CSRF token，成功率更高
- 缺点：速度慢、资源占用高

两种方案均需实现，执行时先尝试A，失败后自动切换B。

### 提交参数
测试评论使用固定的测试账号配置（在config.yaml中设置）：
- 姓名：可配置（建议用真实感强的英文名，如 "Sarah Mitchell"）
- 邮箱：专用测试邮箱（与正式推广邮箱区分，避免污染）
- 网址：测试站点URL（非正式推广站点）
- 评论内容：由AI根据 **Module 2 已存储的 `page_content_snippet`** 生成，不重新抓取页面；若 `page_content_snippet` 为空则用页面标题代替

### 已知局限：邮件验证场景
部分博客（尤其是 WordPress 默认配置）要求评论者点击邮件确认链接后评论才显示。该场景无法通过当前回访逻辑区分，表现为无限 `pending`。

处理方式：
1. 配置文件中填写 `test_email_inbox_api`（Mailgun/Mailbox.org API），系统在 48h 等待期内检查收件箱并自动点击确认链接（可选功能）
2. 若未配置收件箱接入，对 `pending` 超过 7 天的站点，在 `notes` 字段写入 `"可能需要邮件验证"` 并人工核查

### 回访检测
- 提交后等待 **48小时** 再回访
- 回访时检测页面是否存在该评论（通过提交的姓名或评论内容片段匹配）
- 结果标记：
  - `approved`：评论可见，该站点标记为"已验证可用"
  - `pending`：评论区显示"awaiting moderation"，72小时后再次回访（最多重试3次）
  - `rejected`：评论不可见，标记为"审核拒绝"
  - `disappeared`：仅在 Module 5 的30天重验证中检测（回访 `approved` 站点时搜索提交姓名是否仍在页面），不在本模块实时检测

### CSRF和验证码处理
- 方案A遇到 CSRF token：从页面HTML中提取 `<input name="nonce">` 等隐藏字段，随POST一同提交
- 遇到图片验证码（reCAPTCHA、hCaptcha）：直接标记 `captcha_blocked`，跳过该站点

### 输出
```
test_submit_time | test_comment_url | approval_status | approved_at | submit_method
```

`submit_method`：`http_post` / `playwright` / `captcha_blocked`

## Module 5：数据库管理

### 功能说明
统一存储和管理所有经过验证的博客资源，支持搜索、筛选、导出，并定期重新验证资源的有效性。

### 数据库字段（每条记录）

| 字段 | 说明 |
|---|---|
| id | 自增主键 |
| url | 博客页面完整URL |
| domain | 根域名 |
| page_title | 页面标题 |
| page_language | 页面语言（en/zh/ja/ar等） |
| cms_type | CMS类型（wordpress/blogger/other） |
| domain_dr | 域名DR值（来源：DataForSEO） |
| page_as | 页面 Authority Score（来源：DataForSEO，对应 cloudhu2000「页面AS」字段） |
| external_link_count | 页面外部链接总数（来源：Module 2 抓取，链接稀释信号） |
| dofollow_status | dofollow / nofollow / unknown |
| comment_count | 已有评论数量 |
| approval_status | approved / rejected / pending / captcha_blocked / disappeared |
| keyword_tags | 来源关键词标签（逗号分隔） |
| topic_category | 内容分类标签（见下方分类定义） |
| created_at | 首次入库时间 |
| last_verified_at | 最近一次验证时间 |
| is_active | 是否当前可用（布尔值） |
| notes | 备注 |

### topic_category 分类定义

初始分类列表（v0.1，后续可扩展）：

| 分类值 | 含义 |
|---|---|
| `seo_marketing` | SEO、数字营销、增长黑客 |
| `tech_tools` | 技术工具、在线工具、SaaS |
| `lifestyle` | 生活方式、旅游、美食、健康 |
| `business` | 商业、创业、电商 |
| `education` | 教育、学习、语言 |
| `entertainment` | 娱乐、游戏、文化 |
| `other` | 未分类或混合型博客 |

**标注方式**：v0.1 阶段使用 AI 自动标注——将页面标题 + `page_content_snippet` 传入 AI，按上表分类后写入字段；无法判断时写入 `other`。人工可随时覆盖。

### 搜索与筛选
支持按以下维度筛选：
- DR范围
- dofollow状态
- 页面语言
- topic_category
- approval_status
- is_active

### 导出格式
支持导出为 **CSV**，字段格式兼容 backlink-helper 插件的导入格式（至少包含：url、domain、dr、dofollow_status）。

### 定期重新验证
- 每30天对 `is_active = true` 的记录重新执行Module 2（页面验证）
- 如果页面评论表单消失或已转为nofollow，将 `is_active` 更新为 false
- **`disappeared` 状态检测**：对 `approval_status = approved` 的记录，在30天重验证时同时在页面上搜索之前提交的姓名（`test_name`），若已不存在则将 `approval_status` 更新为 `disappeared`、`is_active` 更新为 false
- DR/AS 数据（DataForSEO）每60天重新拉取一次

## 系统配置文件

系统应支持通过配置文件（YAML或JSON）调整以下参数，无需改代码：

```yaml
serp:
  api_provider: serpapi          # serpapi / scraperapi
  api_key: YOUR_KEY
  results_per_query: 20
  max_queries_per_keyword: 5

validation:
  timeout_seconds: 10
  concurrency: 8
  use_playwright: true           # 是否对JS渲染页面启用无头浏览器

dr_filter:
  api_provider: dataforseo       # 已确认使用 DataForSEO（同时返回 DR 和 AS）
  api_key: YOUR_KEY
  dr_high_threshold: 30          # DR≥30 高优先级
  dr_medium_threshold: 10        # DR 10-29 中优先级
  dr_low_min: 1                  # DR 1-9 低优先级（保留入库，不丢弃）
                                 # DR=0 或无数据 → 丢弃（无需单独配置）

test_submission:
  test_name: "Sarah Mitchell"
  test_email: "test@yourdomain.com"
  test_website: "https://your-test-site.com"
  recheck_hours: 48
  ai_api_key: YOUR_AI_KEY
  ai_model: "Qwen/Qwen2.5-72B-Instruct"

database:
  type: sqlite                   # sqlite / postgresql
  path: ./backlink_db.sqlite
  reverify_days: 30
  dr_refresh_days: 60
```

## 技术栈建议

| 组件 | 建议技术 |
|---|---|
| 语言 | Python 3.10+ |
| HTTP请求 | requests / httpx |
| 页面解析 | BeautifulSoup4 |
| JS渲染页面 | Playwright |
| 数据库 | SQLite（轻量）或 PostgreSQL（生产） |
| 任务调度 | APScheduler（定期重验证） |
| SERP接口 | SerpAPI |
| DR/AS 查询接口 | DataForSEO（批量查询 domain_dr + page_as，单次调用两个指标） |
