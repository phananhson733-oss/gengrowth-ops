# AstrologyWiki Blog 优化更新规范

---

## 一、核心原则：什么不能动

已上线页面的排名绑定在以下三个要素上，**任何情况下不得修改**：

| 禁止修改项 | 原因 |
|---|---|
| **URL / Slug** | 改 URL = 新页面，已有排名和外链全部失效 |
| **H1 标题** | 页面主题信号，改动可能导致排名词漂移 |
| **已有段落的核心内容** | 已被 Google 收录的文本结构，删除或大幅改写有排名风险 |

---

## 二、CTR 优化规范

> **触发条件**：GSC 28天数据中，某页面曝光 ≥ 500 且 CTR ≤ 2%，进入 CTR 优化流程。

### 2.1 Title Tag 优化

Title tag 是 SERP 里用户看到的标题，**与 H1 完全独立，可单独修改**。

**优化目标**：在不改变核心关键词的前提下，提升点击吸引力。

**四种有效公式：**

| 公式 | 示例 | 适用场景 |
|---|---|---|
| `关键词 + 具体承诺` | `Bing Hastert Birth Chart: Sun, Moon & Rising Explained` | 信息查询类（birth chart） |
| `关键词 + 年份` | `Lionel Messi Zodiac Sign (2026 World Cup Edition)` | 有时效性的趋势词 |
| `关键词 + 情绪钩子` | `What Harry Kane's Birth Chart Reveals About His Leadership` | 名人分析类 |
| `关键词 + 数字` | `England World Cup 2026: 5 Astrology Predictions` | 预测/列表类内容 |

**硬性规则：**
- Title tag 总长度 ≤ 60 字符（超出部分 Google 会截断显示）
- 核心关键词必须出现在前 30 字符内
- 禁止在 Title tag 中使用 `|` 以外的特殊符号
- 禁止堆砌关键词（同一词出现超过 2 次）

---

### 2.2 Meta Description 优化

Meta Description 不直接影响排名，但影响用户点击决策。

**字数**：120–155 字符（中文 60–80 字）

**写法公式**：`用户问题 + 页面能给出的答案 + 行动引导`

示例：
> "Curious about Bing Hastert's zodiac sign and birth chart? Discover her Sun, Moon, and Rising signs — and what they reveal about her personality and public image."

**禁止写法：**
- 纯罗列关键词（`Bing Hastert zodiac, birth chart, astrology, horoscope...`）
- 与 Title tag 完全重复
- 超过 160 字符（Google 会截断）

---

## 三、FAQ Schema 补充规范

FAQ Schema 让 SERP 展开显示问答内容，可增加页面视觉占位，**CTR 通常提升 20–30%**。

### 3.1 内容要求

- 每篇 blog 补充 **8–10 个 FAQ 条目**（已有 FAQ 直接复用，不足则补充至 8 条以上）
- FAQ 必须来自页面**可见正文中的实际问题和答案**，不能是独立编写的内容——Google 的 FAQ schema 要求 schema 内容与页面可见文字严格对应，不一致会触发 GSC 报错
- FAQ 问题必须使用**疑问句**（What / How / Why / Is / Can 开头）
- 每个答案 ≤ 300 字符（过长 Google 不展示）

**适合做 FAQ 的问题类型（参考 PAA 框架）：**
- "What is [人名]'s zodiac sign?"
- "What is [人名]'s rising sign?"
- "How does [人名]'s birth chart explain their [特质]?"
- "When was [人名] born and what does that mean astrologically?"

### 3.2 技术实现要求

AstrologyWiki 使用 React SSR，schema 必须在**服务端渲染阶段输出到 HTML**，不能只在客户端 JS 中注入（Google 首字节必须能读到）。

```json
{
  "@context": "https://schema.org",
  "@type": "FAQPage",
  "mainEntity": [
    {
      "@type": "Question",
      "name": "What is Bing Hastert's zodiac sign?",
      "acceptedAnswer": {
        "@type": "Answer",
        "text": "Bing Hastert is a [SIGN], born on [DATE]..."
      }
    }
  ]
}
```

**验收步骤：**
1. 上线后用 `curl -s [URL] | grep "FAQPage"` 确认 schema 在首字节 HTML 中存在
2. 用 Google Rich Results Test 验证无报错
3. schema 中的问答文字必须与页面可见 H3/段落文字逐字对应（参考 saturn-return-calculator 的 FAQ 标准）

## 四、趋势词 Blog 内容更新规范

### 4.1 触发条件

满足以下任一条件，触发内容更新：

| 触发条件 | 说明 |
|---|---|
| GSC 点击/曝光连续7天下滑 | 说明搜索热度变化，需追加新内容承接新需求 |
| 事件有新进展（赛事、新闻、新成就） | 趋势词生命周期未结束，应及时追加 |
| 事件结束前 3–5 天 | 最后一波搜索高峰前完成更新，吃尾部流量 |

### 4.2 更新规则

**只能做加法，不做减法：**
- ✅ 在文章末尾追加新段落（最新赛事进展、新的星盘分析）
- ✅ 更新页面顶部的"Last Updated"日期（触发 Google 新鲜度信号）
- ✅ 在已有 FAQ 末尾追加新问答条目
- ❌ 不删除已有段落
- ❌ 不修改已有段落的核心表述
- ❌ 不改写 H2 标题

### 4.3 追加内容的结构

```
## [事件节点] Update: [日期]

[2–3 段新内容，遵循 v4.0 原子化知识架构要求]

[如有新 FAQ，追加至页面 FAQ 区块末尾]
```

示例：
```
## World Cup 2026 Quarterfinals Update: July 2026

Argentina advanced to the quarterfinals on [日期], with Messi 
delivering [表现描述]...
```

## 五、工具页内链检查（新增，来源：unifab.ai 结构分析）

**每篇已上线 blog 在优化时，必须同步检查内链是否满足以下标准：**

| 检查项 | 标准 | 说明 |
|---|---|---|
| 工具页内链数量 | ≥ 2 条 | 每篇 blog 正文必须包含至少 2 条指向工具页的内链 |
| 锚文本类型 | 功能描述词 | 用"birth chart calculator"不用"AstrologyWiki" |
| 内链位置 | 正文中部和结尾 | 不要全堆在文章最末尾，中部植入一次效果更好 |

**适合作为内链目标的工具页示例（AstrologyWiki）：**
- Birth Chart Calculator
- Rising Sign Calculator
- Moon Sign Calculator
- Chinese Zodiac Calculator
- Saturn Return Calculator

若当前文章无内链或内链全部指向其他 blog 文章，在本次优化中补入 2 条工具页内链。这是趋势词流量转化为工具页权重的核心机制。
