# HashPower-BTC 产品调研与合作评估报告

> 调研日期：2026-07-15 | 产品类型：Consumer App × FinTech（加密货币云算力/云挖矿管理工具）| 主市场：美国（App Store 美区）| 调研机构：GenGrowth

> **调研对象**：HashPower-BTC（App Store id6764001819，官网 hashpower.cloud）
> **调研目的**：判断该产品是否适合 GenGrowth 开展社媒营销合作
> **结论前置（v2 修订）**：这是一个**风险偏好决策，不是框架硬否决**。若采用 **CPI/CPA 按交付计价**，则"获客形态 / 已验证产品 / 归因"三条都不构成障碍——那是"分成模型"下才成立的约束（详见 §5.5 更正）。真正剩下的唯一约束是**品类的声誉/伦理敞口**。**对本具体产品，建议不接**——理由不是框架，而是：①该产品诈骗先验极高且拿不出反证；②GenGrowth 现阶段厂牌太脆弱，承受不起"给疑似骗局导真实付费用户"的关联。品类本身非永久禁区（详见 §七）。

## 四、深度分析

### 4.1 变现与收入模式 [universal]

**变现结构**：纯 IAP 订阅制。四档覆盖「短周期试探（$7 7 天 / $9.99 周）→ 月费（$59.99）→ 年费锚点（$329）」。命名把「订阅时长」等同于「BTC 奖励天数」，即付费换取一个每日到账的收益承诺。

**ARPU 推算**：以 28 条评分粗略反推付费用户（评分/付费比按 1:5–1:20，约 140–560 人），叠加年费锚点 $329 与月费 $59.99，估算 ARPU 区间 **$60–$150/付费用户/年** [Low, 纯结构推断]。此 ARPU 对无算力成本的纯订阅 App 是高毛利，印证「收入 = 订阅现金流」而非「算力产出」。

**TAM / SAM / SOM 推导**（云算力服务市场）：

| 层级 | 口径 | 数值 | 置信度 |
|---|---|---|---|
| TAM | 全球云算力服务市场（2024） | **$1.25B**，2033 → $2.75B，CAGR 9.5% | [Medium] |
| SAM | 面向 C 端零售、移动端订阅型云算力 | 约 TAM 的 20–30% ≈ **$250–375M** | [Low] |
| SOM | 单个无品牌、无算力披露的新 App 现实可及 | 年化 **< $0.5–1M**（乐观） | [Low] |

> **核心洞察**：从变现看，它更像「订阅收割」而非「算力零售」。若无真实挖矿支撑，「每日 BTC 奖励」的资金来源只能是新订阅者的钱（庞氏）或纯数字幻象（不可提现）——两者都是诈骗定性。

### 4.2 用户增长与获客 [universal]

- **获客形态**：**B 类（web→app）**——有官网 hashpower.cloud，可做 web 落地/深链导 App。**（更正：v1 误判为 C 类"无 web 触点"，系检索失败，此处修正。）**
- **实际来源推断**：无官方数据。基于品类常识，典型来源为**加密原生广告网络**（Coinzilla/Bitmedia）、**推荐/联盟返佣**、**Telegram/加密社群**、**ASO**。28 条评分 + 官网零独立足迹 → 低自然流量、靠付费/返佣拉新或极早期 [Low]。
- **留存推断**：无 DAU/MAU。此类「收益承诺」App 典型曲线为「早期高 → 提现受阻后崩塌」[Low]。

> **核心洞察**：获客形态**不构成合作障碍**——它有 web 面（B 类），且若走 CPI 买量，导 App Store 本就是标准动作。§六.6.2「禁止裸导 App Store」那条是**分成要追收入**才需要走自有落地+深链；纯 CPI 按安装结算，平台/MMP 即可归因。

### 4.3 竞争定位 SWOT + Porter 五力分析 [universal]

#### 优势 (Strengths)
- 界面简洁、切中「云算力管理」细分；上架合规（Apple 3.1.5 允许链下云挖矿）；有官网可做 web→app 漏斗。

#### 劣势 (Weaknesses)
- 无算力/机房/公司/合规披露；仅 28 条评分；官网无独立足迹；品类信任赤字。

#### 机遇 (Opportunities)
- 云算力 TAM 9.5% CAGR 增长；C 端「被动收益」需求真实存在。

#### 威胁 (Threats)
- **监管高压（SEC/FTC 密集执法）+ 主流自助广告端限制 + 品类污名**。

#### 功能对比矩阵

|---|---|---|---|
| 链上可核验产出 | ❌ 无 | ✅ 有 | ✅ 有 |
| 真实算力/机房披露 | ❌ 无 | ✅ 有 | ✅ 有 |
| 公司资质/审计 | ❌ 无 | ✅ 上市审计 | ✅ 政府背书 |
| Web 获客面 | ⚠️ 有官网但足迹薄 | ✅ 有 | ✅ 有 |
| 订阅/收益承诺界面 | ✅ 有 | ⚠️ 合约制 | ⚠️ 合约制 |

#### Porter 五力分析

| 力 | 强度 | 说明 |
|---|---|---|
| 现有竞争 | 高 | 哑铃结构，合法端有上市巨头、灰色端海量小平台内卷 |
| 新进入者 | 极高 | 做一个「收益仪表盘 App」门槛极低，这正是诈骗泛滥的根因 |
| 替代品 | 高 | 直接买 BTC / 交易所理财 / 合法矿企股票（FUFU）都是替代 |
| 买方议价 | 中 | 用户可随时不续订，但收益幻象制造转移成本 |
| 供应商议价 | 未知 | 无真实算力供应链披露 |

> **核心洞察**：即使假设它合法，其竞争位置也极弱——无差异化、无护城河、无信任资产。但这关乎"作为投资标的强不强"，不直接决定"能不能作为 CPI 买量对象"（§七）。

### 4.4 产品类型专项分析（FinTech × 云挖矿）[type-specific]

**云挖矿诈骗标准模板对照表**（行业公认红旗 vs 本产品）：

| 诈骗红旗（Trend Micro / hashrateindex / 监管口径） | HashPower-BTC 是否命中 |
|---|---|
| 承诺「每日 BTC 收益」，收益随充值挡位上升 | ✅ 命中（`7-Daily`/`365-Daily BTC Rewards`、Hash Weekly/Month 挡位化） |
| 不披露真实算力 / 机房 / 矿池 | ✅ 命中（零披露） |
| 无可查公司实体 / 疑似壳名 | ✅ 命中（`United states happy Banana Inc`，语法怪异，无佐证） |
| 官网无独立足迹 / 无第三方评测 | ✅ 命中（全网零独立评测） |
| 小样本高分 / 疑似刷评 | ⚠️ 高度可疑（28 条评分、4.5 星） |
| 提现受阻 / 需再交「税费」解锁 | ❓ 未验证（需真实充值测试，见 §七尽调闸门） |

**命中 4 项确定性红旗 + 2 项高度可疑**。行业结论（hashrateindex）："云挖矿是比特币各细分里诈骗记录最差的一类"；已记录诈骗超 **$3.5B**（HashFlare $577M、BitClub $722M、GainBitcoin $2.1B、Mining Max $250M）[Medium]。

> **核心洞察**：在缺乏真实算力举证前提下，尽调默认立场应是「疑似诈骗，除非能自证」。**这是 §七"是否建议接"的决定性输入**——不是因为技术做不了，而是因为"给疑似骗局导真实付费用户"这件事本身。

### 4.5 产品架构与技术栈 [universal]

- 技术形态：iOS 前端 + 云端「仪表盘」后端。核心「技术」是账户/订单/收益展示，**不含可验证的挖矿计算**（自述明确不使用设备 CPU/GPU）。
- 技术护城河：**无**。收益数字由服务端下发，用户无法独立验证其对应任何链上真实产出。

> **核心洞察**：「云算力」在此更像营销词而非技术事实。没有链上可核验的产出证明，仪表盘数字与真实挖矿之间没有可证明的联系。

### 4.6 UX 与产品设计 [universal]

- 自述 UX：`"clean and easy-to-use dashboard"`、`"simple, transparent, and easy to manage"`。
- 解读：配合挡位化订阅，是**降低决策摩擦、加速付费**的转化型设计，而非帮助用户做真实算力尽调的工具型设计。
- 年龄分级 4+：涉及加密金融收益却标 4+，反映其规避金融类审查的分级策略。

> **核心洞察**：UX 服务于「快速转化订阅」，而非「帮助用户验证真实性」。

### 4.7 Go-to-Market 策略 [universal]

- 现状：App Store + 薄官网，无可见品牌营销。
- 对合作方（GenGrowth）的含义：若走 **CPI 买量**，我方可交付；主要交付物是**加密原生渠道买量 + web→app 落地/深链**，而非 SEO organic（SEO 在此品类因渠道政策受限）。

> **核心洞察**：GTM 与 GenGrowth 交付物之间**存在可用接口（CPI + B 类深链）**，不是"做不了"，是"要不要做"。

### 4.8 合规与监管 [universal]

**这是本报告权重最高的模块。**

**A. 平台广告政策（决定"社媒营销走哪些渠道"）** [Medium–High, 各平台官方政策]

| 平台 | 对加密挖矿促销的政策 | 对社媒营销的实际含义 |
|---|---|---|
| Meta（FB/IG） | 加密挖矿软硬件/变现服务广告**须事先书面授权** | 自助端**基本投不了**；无牌照难过审 |
| Google Ads | 仅**持牌/审核通过的交易所**可投 | 自助端**不可投** |
| TikTok | 加密受限，须有效牌照；「个人数字货币促销」禁止 | 自助端**不可投**（仅极窄持牌 beta） |
| **加密原生广告网络** | Coinzilla / Bitmedia / aad 等**不受上述限制** | **可投**——这是此品类买量的实际主渠道 |
| KOL / Telegram / YouTube crypto | 平台内容政策松于付费广告 | **可做**（有封号/合规风险，需素材审查） |
| Apple App Store 3.1.5 | 云挖矿（链下）**技术上允许上架**，不豁免金融诈骗风险 | 能上架 ≠ 合法/可推广 |

**B. 监管执法环境** [High, SEC/司法部]

- 2025-12：SEC 起诉 VBit Technologies，CEO 涉诈骗约 6,400 名投资者、挪用 $48.5M。
- 2025-08：SEC 对 Mining Capital Coin 获 $46M 缺席判决。
- 2025-02：HashFlare 联合创始人对 $577M 云挖矿诈骗**认罪**。
- 品类被 FTC/SEC/多国监管列为高风险「固定高回报计划」。

> **核心洞察（更正 v1 夸大）**：主流付费社媒（Meta/Google/TikTok 自助端）确实**基本投不了**加密挖矿——但**加密原生广告网络 + KOL/社群渠道能投**，这才是此品类买量的实际主渠道。所以准确说法是"**主流自助端受限、渠道池更窄、封号率更高**"，而非"完全投不出去"。真正的约束因此从"渠道"转移到**声誉/伦理**（§4.9、§七）。

### 4.9 重点市场专项——美国 [adaptive]

- 主市场：App Store 美区，面向英语 C 端。
- 美国是加密挖矿诈骗执法最密集的辖区（SEC + DOJ + FTC + 各州检察长）。为疑似诈骗产品在美导量，存在**协助推广的连带声誉与潜在法律风险**。
- 美国 C 端对「云挖矿」信任度已被历史大案透支，营销转化的信任成本极高。

**美国市场环境评估**

| 维度 | 评估 | 对营销的含义 |
|---|---|---|
| 监管强度 | SEC + DOJ + FTC + 各州检察长 [High] | 协助推广有连带风险 |
| 品类信任度 | 被 HashFlare 等大案严重透支 | 转化信任成本极高 |
| 主流付费社媒可及性 | Meta/Google/TikTok 自助端受限 | 需转向加密原生渠道 |

> **核心洞察**：美国市场对这一品类是「监管最严 + 信任最低」的环境。CPI 下我方财务可被隔离，但**声誉敞口无法被隔离**——这正是 §七的核心。

## 五、综合评估与建议

### 综合评分（五维星级）

> 注：本表评的是**"产品作为投资/信任标的"的强弱**（越弱代表产品越可疑），与"能否作为 CPI 买量对象"是两个问题，后者见 §七。

## 七、若合作：模式设计 · 风险规避 · 是否建议接

### 7.1 如果接，应该怎么做（CPI/CPA，绝不碰分成）

| 环节 | 做法 |
|---|---|
| **计价** | 按 install（CPI）或注册/首充（CPA）**固定单价结算**，**不做 rev-share**——把我方财务与产品真伪彻底解耦 |
| **渠道** | 加密原生广告网络（Coinzilla/Bitmedia/aad）+ crypto KOL / Telegram / YouTube + ASO；**不依赖** Meta/Google/TikTok 自助端 |
| **交付物** | web→app 落地层（利用其官网做深链落地）+ 买量执行 + 素材；**不做** SEO organic（品类受限、且养 DR 在对方域名不划算） |
| **归因** | MMP（Branch / AppsFlyer）或 Apple Search Ads，专属 campaign / 子渠道码，install 与事件**可数可对账** |
| **结算与防赖账** | **预付保证金 + 周结**；按 MMP 已验证 install 计数；不接受"月底一次性结算"（壳公司名，赖账风险高） |
| **主体隔离** | 用独立主体/白标执行，**GenGrowth 品牌不署名、不进 build-in-public 案例** |

### 7.2 必须先过的"尽调闸门"（接之前，一票否决）

要求对方在签约前出示，**任一项拿不出 → 默认它在诈骗侧 → 不接**：

1. 真实算力 / 机房 / 矿池凭证（可核验）；
2. 公司实体 + 银行主体（对应 `happy Banana Inc` 的真实工商）；
3. **小额真实提现测试**——自己充值 $7 挡，验证 BTC 奖励是否真实可提现；
4. ToS 是否藏「本 App 仅为游戏、无真实挖矿」免责条款（诈骗 App 常见）。

### 7.3 是否建议接

**不建议接这一个。** 决策逻辑：

- **可做性**：✅ 技术上完全可做，CPI 归因干净，财务可隔离——**这一层你判断对了**。
- **该不该做**：❌ 三点压过可做性——
  1. **产品诈骗先验极高且反证缺失**：命中 4 项确定红旗，官网都加载不出、开发方壳名、零算力披露；
  2. **厂牌承受力**：GenGrowth 现阶段靠"AI 增长发行厂牌 / build-in-public"叙事融资获客，一旦被关联"帮加密骗局导量"，损失 >> 两人团队从 CPI 抠出的边际利润；
  3. **机会成本**：同样的产能投在能进厂牌案例的合规标的上，复利价值高得多（§4 红线：纯 CPI 买量可复用性低，偏一次性外包）。

- **什么情况下会翻成"接"**：§7.2 尽调闸门**全过**（尤其提现测试通过 + 实体可核验），此时它已脱离"疑似骗局"档，变成"一个可信的加密 app + CPI gig"——那可作为一次性现金业务接，但仍建议匿名执行、不进厂牌叙事。

> **一句话**：**方法论你对，标的我否**。不是因为 crypto、不是因为获客形态、不是因为归因——是因为**这个具体产品大概率是骗局，而我们的厂牌现在还赔不起这个关联**。
