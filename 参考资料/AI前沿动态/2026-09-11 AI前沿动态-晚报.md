# 🧠 深度研究 ｜ 把 harness 变成水电：OpenAI Agents API 公测，agent 基建层的归属之争开打

> **一句话定性**：OpenAI 把自己跑 Codex 的那套 agent 执行引擎（harness）先在 8 月按 Apache-2.0 开源、再在 9 月 10 日做成**不额外收费的托管 API**——这不是又一个 SDK，而是一次教科书式的「commoditize your complement」：把每家 agent 公司正在卖的那一层变成免费水电，自己只收 token 和算力钱。对做多 agent 系统的团队来说，这同时是一份**现成的架构答案**和一张**锁定风险清单**。

**来源**：OpenAI 官方发布《Introducing the Agents API》，2026-09-10 公测上线（openai.com 对抓取返回 403，正文事实由 MarkTechPost 9/10 报道、AI/TLDR release notes、AnalyticsInsight、byteiota 四家交叉核实）。
🔗 原文：https://openai.com/index/introducing-the-agents-api/

## 一、为什么这一篇值得单独深读

过去一年"agent 框架"是个拥挤赛道：LangGraph、CrewAI、Claude Agent SDK、Google ADK、Semantic Kernel，各自卖的都是同一件东西——**harness**：那个负责理解任务、维护上下文、调工具、流式吐进度、崩了能恢复、必要时找人审批的执行循环。

OpenAI 这次做的是**连续三步**，而不是单点发布：

1. **2026-08-20**：把 Codex 的 harness 按 **Apache-2.0 开源**（`openai/codex`，Rust 实现，含 `codex exec` CLI、Codex SDK、app-server；截至 8/21 仓库 109,661 stars / 16,766 forks）。
2. **2026-06-03 起**：通知下线自家的 **Agent Builder 与 Evals**——Evals 10/31 转只读、11/30 彻底关停。AgentKit 里的 Agent Builder 从上线到判死刑约**八个月**。
3. **2026-09-10**：Agents API 公测，**把这套开源 harness 放到自己托管的基础设施上，一次 API 调用就能用**，且**不收 harness 费**。

把三步连起来读，信号很清楚：OpenAI 认定 harness 不该是一门生意，而应该是通往 token 消耗的**免费入口**。谁靠卖 harness 活着，谁的定价权在这一周被重置了。

## 二、核心事实（按确定性分层）

**A. 产品形态（官方口径，多源一致）**
- 上线日期 **2026-09-10**，**public beta**，面向全部开发者；请求需带 beta header `OpenAI-Beta: agents=v1`；官方示例用 **gpt-6-astra**。
- **四个对象**构成全部心智模型：
  - **Agent** —— 模型 + 指令 + 工具 + MCP servers 的打包定义；
  - **Environment** —— 可选沙箱，agent 在里面跑代码、改文件、读输出；
  - **Session** —— **可持续数小时到数天的 durable 实例**，可中途追加任务、可中途"掰方向"（steering）；
  - **Events / Items** —— 输入与输出的事件流，可 streaming 也可 webhook。
- **harness 替你做掉的四件事**：session 状态持久化、**上下文自动压缩**（"session 接近上限时自动压缩早期上下文"）、**崩溃恢复**、**子代理协调**（官方示例里最多 3 个并发 subagent，各自独立上下文）。
- 另有两个省 token 的内建能力：**tool search**（工具定义按需加载，而不是每轮把全量 schema 塞进上下文）与 **programmatic tool calling**（用代码编排并行/链式工具调用，而非一轮一次 round-trip）。

**B. 部署与计价（这是最硬的战略信息）**
- 沙箱三条路：**OpenAI 托管**（Codex/ChatGPT 同款基建，可配置文件、依赖包、skills）／**自托管**（自己跑 `codex exec-server`，用受限 key 经 WebSocket 接入）／**九家合作方**：Blaxel、Cloudflare、Daytona、DigitalOcean、E2B、Modal、Oracle、Runloop、Vercel。也可以完全不用沙箱。
- **不为 Agents API 本身收任何额外费用**：只按所选模型的正常 API 价计 token，加上 OpenAI 自带工具的标准费用，**加上 container 运行时长**。
- 对照组：Anthropic 的 **Claude Managed Agents（2026 年 4 月上线）**走的是**明码标价的托管 runtime**——第三方对比口径为 **token 标准价 + $0.08 / session-hour**，无月费。OpenAI 这次把同一层的 harness 费砍到 0，只留 container 时长。

**C. 客户侧数字（OpenAI 发布稿引用，属厂商口径，未经独立复现）**
- **Ciridae**：评测分 **0.71 → 0.85**，subagent 流程**延迟降到 1/4**。
- **SafetyKit**：迁移后**单 case 成本降 60%**。
- **Hypha**：**把 harness 与 sandbox 拆开之后，失败响应减少 86%**。

**D. 硬限制（官方自认，且是真门槛）**
- 公测期**仅美国数据驻留**。
- **不支持 ZDR（零数据留存）——即使你用自托管沙箱也不支持**。
- 直接后果：欧盟业务、医疗／金融／法律等受监管负载**现在不能迁**。第三方评测的原话是"这是硬阻断，不是小麻烦"。

## 三、机制拆解：为什么"harness 免费"是一步狠棋

**1）harness 是 agent 系统里唯一不可替换的位置。**
模型可换、工具可换、向量库可换，但 harness 握着**上下文与状态**：对话历史、工具输出、压缩摘要、跨 session 的偏好与习得行为——全都从它手里过。谁拥有 harness，谁就事实上拥有了 agent 的记忆。

**2）开源 + 托管的组合拳，堵死了两条反击路线。**
只托管不开源，客户会喊锁定；只开源不托管，客户嫌运维重。OpenAI 两个都做了：想跑自己的，仓库在那儿，Apache-2.0 随便改随便商用；嫌麻烦的，一次 API 调用就有人替你扛崩溃恢复和上下文压缩。框架厂商"我们比它开放"和"我们比它省事"这两句话同时失效。

**3）九家沙箱合作方是护城河而不是善意。**
把 Cloudflare、Vercel、Modal、E2B、Daytona 这些执行层供应商全拉进同一个 Environment 抽象里，等于让 OpenAI 的 **Agent 对象定义**成为这条链路的事实标准接口。合作方越多，这个接口越难绕开——被商品化的是沙箱供应商的差异化，不是 OpenAI 的。

**4）计价口径从"token"悄悄变成"token + container-hour"。**
一个跑几天的 durable session，大量时间在等工具、等审批、等外部系统——这些**空转时间过去不花钱，现在要花**。这是 agent 经济学的一次真实变化：单位成本得按 session-hour 重算，而不是按 token 数。

## 四、正反两面

**支持方（OpenAI 与早期客户）的主张**
- 你自己写的那套 session 管理、压缩、重试、子代理调度，是重复造轮子且大概率更差——Hypha 的 86% 失败率下降，指向的正是**自建 harness 与沙箱耦合**这个常见错误。
- harness 是 Apache-2.0 开源的，看得见核心逻辑，随时能自托管 `codex exec-server`——"开放"不是口号而是可执行路径。
- 定价上不额外抽 harness 税，比竞品按 session-hour 收钱更便宜。

**质疑方：LangChain 的 Harrison Chase（《Your harness, your memory》，2026-04-11）**
这篇比这次发布早五个月，但它预判的正是今天这个局面，点名的对象里就包括 OpenAI 与 Anthropic：
- **"If you use a closed harness, especially if its behind an API, you don't own your memory."**
- **"Memory will become locked into a single platform, a single model."**
- **"Without memory, your agents are easily replicable by anyone who has access to the same tools."**（引 Sarah Wooders："Managing context, and therefore memory, is a core capability and responsibility of the agent harness."）
- 点名清单：OpenAI Responses API、Anthropic 的服务端压缩、Claude Agent SDK、Claude Managed Agents，以及 **Codex 会生成加密的压缩摘要**——即压缩后的记忆你自己读不了。
- 他给的替代方案是 Deep Agents：开源、模型无关、走 agents.md / skills 开放标准、记忆用插件落到自己的 Mongo/Postgres/Redis、可自部署。

**三条不来自任何一方阵营的冷水**
1. **OpenAI 在这一层的产品寿命记录很难看**：Agent Builder 从发布到宣判约八个月，Evals 一起 11/30 关停，导出的工作流官方明说"不保证行为一致，上线前必须做 parity 测试"。你今天迁进 Agents API，就得给下一次迁移预留预算。
2. **合规是当下的硬墙**：无 ZDR + 仅美国驻留，意味着这套东西现在只适合内部工具和非敏感数据，不适合放客户数据。
3. **harness 本身已是攻击面**：同一窗口内 The Hacker News 报道 **DeepSeek Harness 的一个漏洞，让沙箱里的 agent 用一条命令就关掉了自己的沙箱**（9/9–9/10 在 HN 被广泛讨论）。harness 越"帮你做掉更多事"，它出问题时你越没有拦截点。

## 五、深度解读：对行业，以及对做多 agent 系统的我们

**对行业**
- **agent 框架这门生意的收费层被抬走了。** 今后卖 harness 收钱很难成立；活下来的差异化只可能在三处：**记忆归属**（数据落在客户自己的库里）、**模型无关**（跨 OpenAI / Anthropic / 开源权重）、**合规**（ZDR、EU 驻留、审计日志）。这三条恰好是 LangChain 早在 4 月就选定的阵地，也恰好是 Agents API 今天最弱的三处。
- **两大实验室的路线分叉正式成型。** OpenAI：harness 免费、开源、托管，赚 token 与算力。Anthropic：Claude Agent SDK 给更瘦的原语、让开发者自己掌握状态与评测，Managed Agents 按 session-hour 明码收钱。前者赌规模，后者赌可控性与可审计性。这个价差会被逼着回应。
- **执行沙箱层开始被标准化收编。** 九家合作方进入同一个 Environment 抽象，等于承认自己是可替换件。

**对我们（做多 agent 系统的团队）——七条可执行判断**

1. **把 harness 当可替换件来设计，而不是当地基。** 现在就定一条铁律：**session 事件流、工具调用记录、压缩摘要，必须在我们自己的存储里各留一份**。Codex 的压缩摘要是加密的——如果我们只依赖厂商侧的记忆，迁移那天等于从零开始。
2. **Hypha 的 86% 是本篇最可迁移的工程教训，且不依赖用不用 Agents API：把"决策循环"和"执行沙箱"拆成两个能独立崩溃、独立重启的进程。** 我们自己的 pipeline 如果还是一个进程里又想又执行，这就是现成的重构方向。
3. **tool search 与 programmatic tool calling 今天就能抄进自己的 harness。** 工具定义按需加载（不是每轮灌全量 schema）、工具编排用代码而非逐轮 round-trip——这两条是通用的 token 与延迟优化，跟供应商无关。
4. **成本模型改口径：从"每任务多少 token"改成"每 session-hour 多少钱"。** 长时 session 的等待时间现在计费。做选型对比时，OpenAI 的 container-hour 与 Anthropic 的 $0.08/session-hour 要放在同一张表里算，别只比 token 单价。
5. **合规先行筛选：任何触碰客户数据、欧盟数据或受监管数据的流程，这一轮不迁。** 无 ZDR 是硬阻断。可以先拿内部研究型、非敏感的 agent 流程试水。
6. **迁移成本要预先定价。** 参照 Agent Builder 八个月的寿命：只接受"能导出即能自己跑"的抽象层——Agent 定义、工具清单、session 事件必须能落成我们自己的格式。签之前先问 GA 时间与弃用政策。
7. **审批与权限边界必须在 harness 之外强制执行。** DeepSeek harness 那条"一条命令关掉自己沙箱"的漏洞说明：把 approval policy 交给同一个被 agent 操纵的执行循环，等于没有策略。权限检查要放在 agent 够不着的层。

**顺带一个免费的供应商短名单**：Blaxel / Cloudflare / Daytona / DigitalOcean / E2B / Modal / Oracle / Runloop / Vercel——这是 OpenAI 替我们做完的 agent 沙箱供应商尽调，选型可以直接从这九家里挑。

## 六、接下来盯什么（信号）

- **ZDR 与非美数据驻留何时开**；特别是**自托管沙箱是否率先解锁 ZDR**——那是它能否进企业的分水岭。
- **`openai/codex` 仓库是否同步开源 Agents API 的服务端逻辑**，还是托管版从此分叉。分叉了，"开源 harness"就只是营销词。
- **Anthropic 是否降 session-hour 价、或干脆把 Managed Agents 的 runtime 费砍到 0**；以及 Claude Agent SDK 会不会反向补托管。
- **九家沙箱合作方之间是否打起价格战**，以及有没有人被踢出名单。
- **Agents API 会不会重蹈 Agent Builder**：定期看 developers.openai.com 的 deprecations 页；关注 GA 时间表与 SLA。
- **subagent 并发上限**（官方示例目前 3 个）是否放开，以及 durable session 的时长上限。
- **LangChain / LlamaIndex / CrewAI 的应对**：会转向"记忆归属 + 模型无关 + 合规"三件套，还是硬碰 harness。
