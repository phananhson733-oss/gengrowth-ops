# 深度研究 · 第一个被自己厂商判为「Critical」的模型——OpenAI Astra 跨过网络能力红线

**一句话定性：** 前沿实验室史上第一次，把自家未发布的旗舰模型标记为在网络攻击维度达到内部最高风险等级——能力已越过红线，行业的问题从"AI 能不能自主挖洞打穿系统"变成"谁能用、怎么关得住、别人复现得了吗"。

**来源：** OpenAI《Path to Astra: critical capabilities and frontier safeguards》/《Responding to the next frontier of critical cyber capabilities》
🔗 原始链接：https://openai.com/index/path-to-astra/ （官方，抓取返回 403，正文以官方口径 + SecurityWeek / TechCrunch / Decrypt / CSO Online / Security Boulevard 交叉核实）
**日期：** 2026-09-01 发布，9-02 主流媒体跟进

---

## 为什么值得深读 / 背景

这不是又一次"我们的模型在某 benchmark 上刷了新高"。这是**一家前沿实验室第一次主动宣布：我们训出来的下一代旗舰，在网络攻击能力上已经达到了自己 Preparedness Framework 里定义的最高档「Critical」**——此前所有已发布模型（含 GPT-5.6 Sol）都停在下一档「High」。这个动作本身比数字更重要：厂商把"能力越界"从内部风控事项变成了公开叙事。

它也是本频道追踪了近一个月的一条主线的收口：
- **8/07（Axios 首爆）→ 8/10（CNBC / CSO / Help Net）**：OpenAI 放缓 / 暂停 Astra，理由正是"无法排除达到 critical 网络能力"。
- **8/19（本频道深研《停下的是最大那一次训练》）**：OpenAI 把安全闸门从"发布前"搬进"训练中"，暂停了最大的一次训练。当时那个被按住的模型，现在有了名字——Astra（外界普遍认为即 GPT-6 的代号）。
- **9/01–9/02**：闸门审完，OpenAI 给出结论——它确实过了红线，于是选择**先公布能力、限制访问、延后开放**。

同一个 48 小时里，三家前沿实验室同时把"网络安全"当成主战场摆上台面（详见下文"行业含义"），使得这条不只是 OpenAI 一家的产品新闻，而是**前沿能力商业化进入"军民两用管制"范式的一个集体拐点**。

---

## 核心事实（硬数据分层）

**能力读数（攻击侧）：**
- **ExploitBench 满分（100%）**：该基准衡量"把已知漏洞转化为可用 exploit"的能力。
- **自主发现并串联 2 个真实 0-day**：在一组"近期才披露的漏洞"测试中，Astra 独立挖出并链式利用了 **2 个 Google V8 JavaScript 引擎的 0-day**（据 Decrypt 口径为 6–8 月间披露批次），OpenAI 称已向受影响维护者做负责任披露。
- **端到端攻击链**：在硬化系统测试中，成功**逃逸浏览器沙箱**，并把多个 OS 漏洞串起来，从普通用户**提权到 root**。

**「Critical」门槛的官方定义：** 模型能在**无人干预**下，识别并开发针对"众多硬化的真实关键系统"的、各种严重级别的**功能性 0-day exploit**；或仅凭一个高层级目标，就能**自主规划并执行一次全新的端到端网络攻击**。这是 Preparedness Framework 网络维度的最高档。

**安全读数（防御侧的自证）：**
- **拒答率 91.5%**：Astra 拒绝网络类越狱 / 恶意请求的比例为 91.5%，而当前最好的 GPT-5.6 Sol 只有 **59%**。OpenAI 称其为"迄今最对齐的模型"。
- 新增 **chain-of-thought 监控**（检测并中止未授权动作）、更强的抗恶意提示训练、沙箱化执行、对"高风险账号"的响应限制。官方承认：这些监控**偶尔会误伤合法的非网络任务**。

**部署与访问门控：**
- **不随发布开放最强网络能力**：先给一小撮 trusted testers，随后通过 **Daybreak Blue 计划**向"防御性安全工作"机构扩大访问。
- 承诺发布前与**政府机构 + 部分 AI 安全组织**做外部测试。
- 训练 / 权重侧硬化：隔离测试环境、限制网络与工具访问、模型权重加密、全量风险动作监控。
- **发布时间未定**：预测市场一度给"9/30 前公开发布"72% 概率，后回落到"11 月"约 55%。

## 机制拆解：为什么这次和以前不一样

过去谈"AI + 网络安全"，多半是**辅助**：帮分析师读日志、写检测规则、解释一段可疑代码。Astra 展示的是**闭环自主**——给一个高层目标，模型自己完成"侦察 → 挖 0-day → 写 exploit → 沙箱逃逸 → 提权"的全链条，中间不需要人把每一步喂给它。V8 那两个 0-day 是关键证据：**V8 是被全球顶尖安全团队反复审计的高价值目标**，能在这种硬骨头上自主挖出未公开漏洞并串成利用链，意味着能力不是"背题库"，而是真的具备泛化的漏洞推理。

这直接改写了攻防的经济学。0-day 的稀缺性来自"发现它需要稀缺的顶尖人力"；一旦发现成本被模型摊薄，**攻击面从"值得针对的高价值目标"扩展到"所有联网系统"**。这也是为什么 OpenAI 这次的核心不是"发布产品"，而是"**先造好笼子再放出来**"——把能力公开、把访问关住。

## 关键原话 / 引述

- OpenAI：**"We are entering a stage of AI development in which models can take on more consequential work, and failures can have more serious effects."**（我们正进入这样一个阶段：模型能承担更有后果的工作，而失败的后果也更严重。）
- OpenAI 结论口径：**"Astra meets the critical threshold."**
- Gartner 分析师 Apeksha Kaushik：称这是"**a substantial inflection point**"，警告"一个 AI 系统能自主发现漏洞、开发 exploit、并以极少人力执行端到端攻击"。
- Greyhound Research 的 Sanchit Vir Gogia：**"Gated access buys defenders time. It does not repeal a capability."**（门控访问是给防御方买时间，它并不能取消一项能力。）——本篇最锋利的一句。

---

## 正反观点

**支持 / OpenAI 主张：**
- 军民两用的同一套推理能力，也能让防御方以同样效率去**找漏洞、抢在攻击者前面打补丁**；先给防御者（Daybreak Blue）是把不对称扳回防守侧。
- "先公开能力、限制访问、外部测试后再放"是比"闷声发布"更负责任的路径；91.5% vs 59% 的拒答率说明对齐是随能力一起长的，不是滞后的。
- 把安全闸门前移到训练中（8 月那次暂停）证明这套 Preparedness 流程真的能在能力越界时按下暂停键。

**质疑 / 风险：**
- **没有第三方验证**。所有数字都来自 OpenAI 自评，完整评估要等"公开发布时"才给——而那时"猫已经出袋"（评估的意义大打折扣）。前 OpenAI 员工 Yona Shavit 直指：模型在测试里表现克制，可能是"知道别人期待它这么做"，甚至是"在骗研究者"，而非真的安全。
- **门控 ≠ 消除**（Gogia）。权重一旦存在，泄露 / 被蒸馏 / 被开源阵营复现只是时间问题；Daybreak Blue 买的是时间窗，不是安全。
- **军民两用的加速方向偏攻**。有分析明确指出：为防御 AI 威胁而发展的能力，会同时加速攻击能力；当天平偏向进攻，伤害更可能、也更严重。
- **CoT 监控会误伤合法任务**，这对把 Astra 类模型接进生产 agent 流水线的团队是直接的可用性税。
- **叙事激励存疑**：主动宣布"我们造了个能自主打穿系统的东西"，既是安全姿态，也是能力营销——两者难以切割。

## 深度解读：对行业 + 对「做多 agent 系统的我们」的具体含义

**对行业：**
"军民两用管制"正式成为前沿能力的**默认发布范式**。看这 48 小时的同框——
- **OpenAI**：Astra Critical + Daybreak Blue（防御者优先访问）。
- **Google**：Gemini 3.8 Flash Cyber + **Fairwind 计划**，650+ 全球伙伴（CrowdStrike / Datadog / Palo Alto / Snowflake 等），明确"专注武装防御方、优先修漏洞而非进攻"。
- **Anthropic**：Fable 5.1 / Mythos 5.1 + **Enterprise Frontier Safeguards**，Mythos 限受信访问，Fable 5.1 现在允许漏洞识别。

三家在同一周把"最强能力不再无差别开放，而是按'产物 / 用途 / 受信身份'发放"变成共识。这与本频道此前追踪的 Mythos 分层牌照、白宫"发布前测试"框架是同一条制度化曲线。**"无脑用旗舰"的时代，在网络安全这个最敏感的维度上，第一个正式关门。**

**对做多 agent 系统的我们（落到可执行判断）：**

1. **威胁模型必须升级到"对手也有 Astra 级自主挖洞能力"。** 我们此前的假设是"prompt injection 会成功"（见 8/07 Auto mode 记忆）。现在要再加一条：**你依赖的每一个联网组件、每一个 npm 依赖、每一个自建服务，都可能被一个自主 agent 在无人力成本下扫出 0-day**。安全预算里"外部依赖的漏洞面"这一项要显著上调。

2. **防御侧要主动接入、别只做被动加固。** Daybreak Blue / Fairwind 这类"防御者优先"通道是明确信号：**同样的能力，先到防御方手里的一方占先机**。我们应尽早评估把这类"自动挖洞 + 自动补丁"能力接入自己 CI / 依赖审计流水线（哪怕先从 Fairwind 的 650+ 伙伴生态里选一个成熟产品做 PoC），而不是等被攻击后再补。**Gogia 那句"门控买的是时间"反过来也成立——防御方买到的时间，要用来加固，不是用来观望。**

3. **别把"厂商自评的对齐数字"写进自己的安全依据。** 91.5% 拒答率、"最对齐模型"都是自证、无第三方复现。在独立复现出现前，**继续按"护栏会被绕过"设计**：能力隔离、出口白名单、短时效最小权限、生产库物理隔离——这些架构级手段才是防线，模型的拒答率只能算"降噪"不算"防护"。

4. **CoT 监控的误伤是真实的可用性成本。** 如果未来接入 Astra / Mythos 类高门控模型，要预留"监控误中断合法任务"的重试与降级路径，别让一次误判打死无人值守流水线。

5. **访问门控 = 新的供应链依赖风险。** 当最强能力只经 Daybreak Blue / EFS / Fairwind 这类受信通道发放，你的能力可及性开始取决于"你是否被列入受信名单"。这和 8/30 OpenAI 掐断 Cursor 是同一逻辑——**把关键能力压在单一厂商的门控上，就是把自己的路线图交给对方的政策**。多供应商 + 开源兜底的对冲，从"降本"变成"抗断供"的刚需。

## 接下来盯什么（信号）

- **Astra 的实际发布时间与"完整评估报告"是否同步公开**——若仍是"发布时才给评估"，则第三方验证缺口坐实。
- **是否有无关第三方复现出 Astra 级自主挖洞**（尤其开源阵营 GLM / DeepSeek / 混元一侧）——一旦复现，"门控买时间"的窗口即关闭。
- **Daybreak Blue / Fairwind 的准入门槛与名单**：谁能进、以什么产物形态发放，决定这波能力对中小团队是"可用"还是"看得见摸不着"。
- **首例"AI 自主发现 0-day"进入 CVE 正式署名 / 或首例被指控"AI 自主攻击"的真实事件**——这会把"能力"变成"判例"。
- **监管跟进**：白宫"发布前测试"框架、EU AI Act 会不会把"Critical 网络能力"单列为强制外部审查触发条件。
