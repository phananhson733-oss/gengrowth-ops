# 深度研究 · 11 天，1300 万行 Lean——Claude 自主完成费马大定理的首个端到端机器验证证明

**一句话定性**：Anthropic 宣布 Claude 在 11 天内基本自主地写出了费马大定理（FLT）的首个端到端、机器可验证的 Lean 形式化证明——一个此前被数学界普遍认为需要人类社区干到 2029 年之后的宏大工程；这既是 AI-for-math 的历史性里程碑，更是「有完美验证器时长程多 agent 自治能跑多远」的第一份工业级实证。

- **来源**：Anthropic Research《Formalizing Fermat's Last Theorem》
- 🔗 **原始链接**：https://www.anthropic.com/research/formalizing-fermats-last-theorem
- **日期**：2026-09-04 发布（据 Claude 运行日志，证明实际在 2026-08-18 02:00 UTC 完成）
- **交叉信源**：Kevin Buzzard 本人博客《FLT: Anthropic has beaten me to it》（xenaproject.wordpress.com, 9/4）；HN 主帖 647 分 / 411 评论；GitHub 仓库 anthropics/fermats-last-theorem；Prove2Me 论文 arXiv:2608.28433

## 为什么值得深读 / 背景

费马大定理 1637 年提出，1995 年被 Andrew Wiles（与 Taylor）用 129 页现代数论证明攻克——但那是「人类审稿人相信的证明」。把它翻译成 Lean 这类证明助手可逐行机器检查的形式（形式化），是完全不同量级的工程：Kevin Buzzard 2024 年在帝国理工启动 EPSRC 资助的社区项目，写了 86 页蓝图，公开预期**至少干到 2029 年**。此前唯一的完整形式化成果只是 2025 年 Best 等人的正规素数特例。

现在 Anthropic 说：一个「大致相当于 Claude Fable 5.1」的内部研究模型，在多 agent 编排下 11 天端到端搞定了。被抢先的 Buzzard 本人第一时间编译了代码库、跑了比对器、还让 AI agent 扫了非数学代码段——结论是「it checks out」。这不是 benchmark 分数，是一个可下载、可复核、被最大利益受损方亲手验证过的 artifact。

对本频道读者，它还有第二层意义：过去两周我们连发三篇 agent 群失控深研（Hugging Face 事件、DSEWiki 劫持、AISI 越权测试）——同样是「几十个 agent + 天级自主运行」，这次跑在有完美验证器的封闭任务里，产出的不是串供留言板，而是数学史。**同一种能力，验证器决定成色。**

## 核心事实（硬数据）

**产出规模**
- 13,000,000+ 行 Lean 代码（Buzzard 口径 13.4M），约为 Mathlib（Lean 社区数学总库）的 **5 倍**
- 证明定理 **30,300 条**，其中 29,500 条用于最终证明链
- 消耗约 **60 亿 output tokens**（HN 社区按公开定价估算 token 成本约 $30 万量级，总算力开销未披露、大概率更高）
- 非样板行中约 **7%** 来自失败尝试后被弃置的努力

**时间与验证**
- 端到端 **11 天**（引入 Prove2Me 编排后）；运行日志显示根节点 2026-08-18 02:00:57 UTC 转为 PROVED
- 全部证明经 **Lean kernel 检查**，只依赖 Lean 三条标准公理，无任何额外假设（no sorry）
- comparator 工具确认定理陈述与 Mathlib 官方 FLT 陈述逐字一致（防「证了个假命题」）
- 覆盖指数 **n ≥ 17**（更小指数此前已被单独形式化，合并后即完整 FLT）

**方法与人力投入**
- 走的是 Darmon–Diamond–Taylor 对 Wiles 证明的简化阐释路线（非 Buzzard 在攻的「现代证明」路线）
- 复用并改编了 Buzzard FLT 项目与 flt-regular 项目的部分成果，构建在 Mathlib 之上
- 人类数学输入极少：仅 Tianyi Peng（Anthropic 研究员/哥大）偶尔给高层提示，如「Jacobian as a scheme 听起来是高优先级」
- 佐证可复现性：同套方法用 **3 个个人 Claude Max 订阅、3 天**形式化了 Vinogradov 三素数定理

**编排系统 Prove2Me（这是工程核心）**
1. 维护定理陈述的**有向无环图（DAG）**——几十个 Claude agent 按依赖关系并行认领节点，同时充当全局记忆，解决了早期纯自主尝试「跑丢项目状态」的失败模式
2. 把**定理陈述与证明拆到不同文件**——下游 agent 只依赖陈述即可开工，编译反馈回路大幅加速
3. 给每条定理配**自然语言描述做语义检索**——agent 能发现并复用彼此已证的结果

## 正反观点

**支持方主张**
- 被抢先者亲验背书：Buzzard 编译 + comparator + AI 审计非数学代码（约 100 行异常里只发现一个便利 tactic 定义），结论成立；这几乎是能得到的最强独立验证
- 5 年级社区工程 → 11 天：即使全部复用既有蓝图与 Mathlib，速度跃迁也是两个数量级
- 关键在通用性：模型「≈ Fable 5.1」而非特化数学模型，Vinogradov 定理用消费级订阅 3 天可复刻——护城河在 harness 与任务结构，不在秘密模型，意味着方法可被全社区复用
- Anthropic 配套动作：开源 repo + 给数学家免费/折扣订阅 + 形式化专项 grants，把单点成果推向生态

**质疑方 / 风险**
- **无新数学**：这是「翻译」不是「发现」——FLT 本来就被证明了，AI 没有解决任何开放问题；把它读成「AI 会做数学研究了」是过度外推
- **膨胀与不可维护**：13M 行 ≈ 5× Mathlib、编译时长 ≈ 20× Mathlib；HN 高票批评「AI is hopeless at using existing code, it likes to append only」——它更像倾倒出一座能通过检查的证明矿渣山，而非人类风格的精炼证明
- **成本黑箱**：只披露 6B output tokens；社区质疑总算力投入远超 token 口径，「无限资源堆出来的能力证明」对外推性存疑
- **「自主」的边界**：Prove2Me 平台是人设计的，路线（DDT 阐释）是人选的，还有人给高层提示；准确说法是「人定战略、AI 全权执行战术」——但须承认，战术层此前正是卡死人类社区 5 年+的部分
- **信任链**：13M 行 AI 生成代码的正确性全押在 Lean kernel 无 soundness bug 上；Buzzard 以「OpenAI 模型近期审计过该版本 Lean 未发现 soundness 问题」回应，但「AI 写、AI 审」的闭环仍让部分人不适

## 深度解读：对行业 + 对我们

**对行业**

1. **AI-for-science 叙事的最强单点证据落在 Anthropic 手里**。接 9/1 Fable 5.1 发布的科学产出线（Terminal-Bench-Science 翻倍、蛋白质结合物、金星高程图），如今补上一个大众能听懂的历史级标志物——且时点微妙：Reuters 9/4 报 Anthropic IPO 推迟至 10 月中、估值谈到 $2T。这是 IPO 路演级叙事资产，与 OpenAI 同周的「AGI era」宣言（GPT-6 Astra）正面对轰，路线差异清晰：OpenAI 秀通用智能分数，Anthropic 秀可验证的科学 artifact。
2. **数学的基础设施将被重写**。Buzzard 的判断值得全文抄送：文献级自动形式化若可行，审稿、纠错、知识库全变。Lean/Mathlib 从小众社区资产升格为 AI 时代基建——与同周 Nvidia $12.93B 买下 Hugging Face 同一逻辑：开放社区资产正在被重新定价。
3. **评测叙事转向 artifact**。benchmark 分数可以争 harness 归因（见 8/21 与 9/4 的 ARC 线），但一个 Lean kernel 通过、被对手方复核的证明没有可争的：**可验证 artifact 是比 benchmark 更硬的能力货币**，预计各家会跟进找各自领域的「FLT 时刻」。

**对做多 agent 系统的我们（可执行判断）**

1. **验证器决定自治预算**。11 天无人值守能成，唯一前提是 Lean kernel 这个零误报的 ground truth。落地规则：给任务配 verifier 强度分级——有硬校验（编译器/测试套/schema/对账）的任务才配天级自治；只有软评估（LLM judge、人审）的任务，自治窗口压到小时级并强制 checkpoint。我们最近三篇失控深研的共同点恰是 verifier 缺位。
2. **Prove2Me 三件套可直接抄进 orchestrator**：①用**依赖 DAG 而非线性队列**做任务分发，DAG 本身即共享记忆（解决 agent「跑丢状态」——我们 autopilot 的 claim ledger 是雏形，但没有依赖边）；②**接口与实现分离**——先让 agent 批量产出「陈述」（函数签名/API 契约/验收标准），下游只依赖陈述即可并行开工；③**给每个 artifact 配自然语言描述 + 语义检索**，让 agent 复用彼此产物而非重造（gbrain 就该当这个用）。
3. **给长程运行编列「膨胀税」**。7% 弃置率看似便宜，但 5× 库体积、20× 编译时长说明 append-only 膨胀才是主成本。判断：verifier 能过就先接受膨胀、单列压缩/重构 pass 在成功之后做——Anthropic 也是这么选的，顺序是对的。
4. **成本单位从「请求」变「campaign」**。6B output tokens 一役，对照 9/2 深研的缓存读降价 75%（agentic 负载省 ~45%）——Anthropic 显然在为 campaign 级工作负载铺价格结构。做预算时按「一次战役烧多少」评估 ROI，而非按次计价；Vinogradov 案例（3 订阅 × 3 天）说明小规模战役消费级就能打。
5. **别急着招「更强模型」，先补 harness**。官方明说模型≈公开可得的 Fable 5.1，早期裸奔尝试全失败、加了 Prove2Me 才通——能力差距的大头在任务结构化与编排，这正是我们自己可控的部分。
