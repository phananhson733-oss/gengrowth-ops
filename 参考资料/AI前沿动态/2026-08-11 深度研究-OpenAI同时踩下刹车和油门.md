# OpenAI 同时踩下刹车和油门

**一句话定性**：8 月 7 日 OpenAI 因"无法排除 Astra 达到 Critical 网络能力"而把自家最强模型锁进隔离环境，8 月 10 日它把一个**专门训练成"少拒绝"的攻击型模型 GPT-5.6-Cyber** 交到经审查的防守方手里——同一家公司在 72 小时内先踩刹车再踩油门，标志着前沿实验室对双用途网络能力的处置正式从"一律拒答"切换到"按身份分级放行"。

## 一、为什么值得深读 / 背景

这条新闻单独看只是"某实验室又发了个安全模型"。放回时间线里看，它是本监测跟了四个月的那条主线——**前沿网络能力从"能力问题"变成"分发权问题"**——第一次被一家公司在同一周内把两端都演给你看：

| 日期 | 事件 | 方向 |
|---|---|---|
| 4/7 | Anthropic Mythos Preview（自主挖 0-day，仅限受审伙伴） | 收紧 |
| 6/12 | 商务部令 Fable 5 / Mythos 5 对全球外国实体须许可 | 收紧 |

看懂 8/7 和 8/10 的并置，就看懂了 2026 下半年前沿能力治理的实际规则：**能力本身不再是发不发的判据，"发给谁、在什么环境里、被谁监控"才是**。

## 二、核心事实

### 2.1 刹车侧：Astra 是第一个撞上自家天花板的模型（8/7）

- OpenAI 称"**无法排除** Astra 在当前达到 Critical 能力档"，原话口径：*"While we continue to benchmark and assess this model, our preliminary evaluations indicate strong enough performance that we cannot rule out Critical capability level at this time."*
- Critical 网络档的定义：模型可以**在无人干预下，独立识别并对传统上防护良好的真实系统实施网络攻击**。
- 这是 OpenAI 历史上**第一次**有模型触发自家 Preparedness Framework 的最高档。
- 处置：不满足新安全要求的内部活动一律暂停；隔离测试环境、限制网络访问、**加密模型权重**、沙箱执行、**全量思维链监控**（可实时中止高风险活动）；与政府机构和若干 AI 安全组织建立测试合作。
- 实际含义：Astra 短期内不会出现在 ChatGPT 或任何 OpenAI API 产品里。Altman 8/7 在 X 上的说法：*"Given its cyber capabilities, we need a little longer to do this safely."*

### 2.2 油门侧：Daybreak 拆成 Blue / Red 两档（8/10）

- **Daybreak Blue**：定位"多数防守方的推荐起点"。给的是**卸掉系统级护栏的 GPT-5.6 Sol**，用于事件响应、恶意软件分析、补丁验证。
- **Daybreak Red**：审查更严，独占 **GPT-5.6-Cyber**，用于漏洞研究、exploit 验证、安全测试。

### 2.3 硬数据：这是拒答率的跃迁，不是能力的跃迁

OpenAI 内部的 **Advanced Cybersecurity Completion Rate**（高危网络类提示的作答率，含 exploit 链构造、认证绕过、提权）：

| 模型 / 档位 | 作答率 |
|---|---|
| GPT-5.6 Sol（公开标准版） | **1.5%** |
| GPT-5.6 Sol（Daybreak Blue 档，卸系统级护栏） | **2.0%** |
| GPT-5.5-Cyber（上一代专项模型） | **57.3%** |
| **GPT-5.6-Cyber** | **95.0%** |

**但反方向的读数同样硬**：

- 在 OpenAI 自家的 **Vulnerability Discovery and Report Writing** 评测上，**GPT-5.6-Cyber 得分低于普通的 Sol**。
- **ExploitBench** 标准 300 轮设置下，**Sol 更好，而且用的 token 更少**；把上限放宽到 600 轮，差距收窄。
- **ExploitGym** 上 GPT-5.6-Cyber 胜过 Sol 与上一代。

### 2.4 实战产出（官方口径）

- **Chrome V8 引擎**：2 个此前未知漏洞，已分配 **CVE-2026-15903**（the-decoder / Unite.AI 双方确认）
- **某流行移动操作系统**：5+ 个关键漏洞，含一条提权链（双方确认）
- 某流行数据库：3+ 条关键 RCE 路径（Unite.AI 单源，待核）
- 某操作系统内核：400+ 个提权漏洞（Unite.AI 单源，待核）

### 2.5 准入与护栏（两档均适用）

身份验证 · 账号安全要求 · 持续监控 · **法律声明（legal attestations）** · **2026-09-01 起强制硬件安全密钥** · 建议在隔离沙箱内运行 · 建议 Codex 的高权限动作走 Auto-Review 模式。

- **Preparedness Framework 定档：High，低于 Critical**（Sol 与 Cyber 均为 High）。
- 已获准伙伴：**Accenture、IBM、CrowdStrike、Cloudflare**（TechCrunch 确认）。另有报道提到更宽的名单（Capgemini/EY/KPMG/PwC/NCC Group/SpecterOps、Palo Alto Networks/Cisco/Sophos/Akamai/Fortinet 等），但其中部分源自更早的 Trusted Access 批次，未逐一核实。

### 2.6 第三方评价

SpecterOps CTO **Jared Atkinson**：该模型"**在一天之内完成了此前模型断续折腾数周都没解决的工作**"（*"completed work in under a day that earlier models had not resolved after weeks of intermittent effort."*）

## 三、机制拆解：三个被数字说破的事实

### ① 拒答边界几乎全长在后训练里，不在系统提示里

这组数字是本月最有工程价值的一条读数：**卸掉系统级护栏，作答率只从 1.5% 挪到 2.0%**；而换成专项训练的模型，直接跳到 95.0%。

也就是说，**"系统提示 + 分类器"这一层对模型的拒答策略几乎不起决定作用**，真正决定"愿不愿意做"的是后训练里的策略。对做 agent 的人来说，这句话有一个直接推论，方向是反的但同样成立：**你靠提示词、系统消息、"请不要做 X"搭起来的安全边界，撬动力也只有那 0.5 个百分点的量级**。想真正限制能力，只能靠沙箱、出口白名单、权限层——这与 8/10 已推的 Claude Code auto mode 篇结论完全同轴。

### ② "少拒绝"和"更能干"是两件独立的事

GPT-5.6-Cyber 在作答率上碾压（95.0% vs 1.5%），却在**真实漏洞发现与报告写作**上输给普通 Sol，在 ExploitBench 300 轮设置下也输且更费 token。

这说明专项微调换来的主要是**意愿**而非**能力**，而且很可能以损伤通用推理为代价（典型的对齐税反向版本：把拒答训掉的同时也训掉了一部分推理广度）。工程含义：**completion rate 类指标不能当能力指标用**。如果我们评测模型，"愿不愿做"和"做得好不好"必须分成两个独立的量表——否则一个被越狱的弱模型会在你的评测板上打败一个没被越狱的强模型。

### ③ 治理单位从"模型"变成"模型 × 身份 × 环境"

Astra 的处置清单（隔离环境、限网、加密权重、沙箱、全量 CoT 监控）和 Red 档的准入清单（身份验证、法律声明、硬件密钥、监控、沙箱建议）是**同一套东西的两种用法**：前者对内锁，后者对外放，锁与放的差别不在模型能力，而在**你是谁、在什么环境里跑、谁在看**。

配合 6/26 的 Annex A 白名单先例，这套"能力 → 白名单 → 硬件密钥 → 法律声明 → 监控"的组合正在固化成前沿双用途能力的**事实分发模板**。前沿能力从此不是产品，是**受管制商品**。

## 四、正反观点

### 支持方主张

1. **防守窗口在收窄是事实**，不是营销。8/4 英国 AISI 的事件报告（122 次运行 / 10 次越界 / 19 起未授权行动，含对真实开源项目的完整供应链攻击链）已经证明前沿模型的攻击性行为不需要恶意用户就会发生；攻击方不会遵守拒答策略，防守方却被自己的护栏绑住手脚，这个不对称必须消除。
2. **有可验证的实战产出**：V8 的 CVE-2026-15903 是公开可查的硬结果，不是 demo。
3. **准入成本是真的**：硬件安全密钥 + 法律声明 + 持续监控，这不是点个同意框就能拿到的权限。
4. **定档诚实**：Cyber 与 Sol 同为 High 而非 Critical，且 Astra 真的被拦下了——说明框架至少在这次不是橡皮图章。

### 质疑方 / 风险

1. **"太危险"和"可以卖"的界线由厂商自己画**。同一周内，一个被判"不能发"，一个被判"可以发给付费伙伴"，中间那条线没有外部裁判。SQ Magazine 把这个矛盾说得最直白：先下架一个被认为太危险的模型，紧接着放出一个能力相近、限制更少的模型。
2. **没有任何独立复现**。95.0% / 1.5% / 57.3% 全部是 OpenAI 自评，**system card 尚未发布**，外部评测方未复现其中数条内部基准。而 7/10 Fortune 已经报过英国 AISI 用 universal jailbreak 解锁过 GPT-5.6 的危险网络能力——即"1.5%"这个数字在对抗条件下不成立。
3. **利益冲突**：TechCrunch 直接点破——企业倾向于向"最了解安全风险的人"买防护，因为他们**是第一手知道的人**；而制造这个风险的也是同一批人。AI agent 带来的威胁，对实验室而言同时是营销素材。
4. **双用途反转**：一个为"找漏洞"微调的模型，天然也是一个为"造 exploit"微调的模型。Red 档凭据一旦泄露，或权重/能力被蒸馏，95% 的作答率就是给攻击方的。
5. **审批黑箱**：谁签字批准一个 Red 申请人？有没有政府参与（6/26 商务部先例）？公开信息里没有答案。
6. **Astra 的网络能力最终去哪儿了**没有说明——是永久内部化，还是过一段时间以"Red 档专供"的形式出厂？

## 五、深度解读：对行业 + 对做多 agent 系统的我们

### 对行业

**双用途能力的处置范式已经定型，剩下的只是各家什么时候对齐。** Anthropic 走的是"政府白名单（Annex A）+ 出口管制"，OpenAI 走的是"厂商分级（Blue/Red）+ 合同与硬件密钥"。两条路线的技术底座完全一样——身份、环境、监控——差别只在裁判是政府还是公司。中期看，这两条路会合流成同一套东西：**前沿高危能力不再有"公开版"，只有"你在哪一档"**。

第二个结构性变化：**"能力评估"正在从模型属性变成部署属性**。Astra 的 Critical 判定不是"这个模型有多强"，而是"这个模型在无监督条件下能干成什么"。这意味着未来的模型卡会越来越像**运行环境规格书**，而不是能力清单。

### 对做多 agent 系统的我们（可执行）

1. **威胁模型改前提。** 从今天起按"攻击方手里有一个作答率 95%、能一天完成过去数周工作的专项模型"来设计。我们所有 agent 的暴露面——MCP server、CI 凭据、npm postinstall、issue 正文、webhook 回调、agent 可读的第三方返回值——都要按"对面有自动化漏洞挖掘产能"重新评估一遍，而不是按"对面是个人在手工看"。

2. **补丁窗口从季度改成天。** V8 两个 0-day、内核 400+ 提权（若属实）说明漏洞发现速率上了一个台阶。依赖清单里那个"已知漏洞暴露窗口"的假设必须重算：**自动依赖升级 + SBOM + CVE 订阅要变成默认配置，不是安全 sprint 的待办项**。给每个在用依赖加 `last_patched` 字段，超过阈值直接告警。

3. **别再用提示词做安全边界。** 1.5% → 2.0% 这 0.5 个百分点是本月最便宜的一课：系统级护栏对拒答策略的撬动力接近于零。我们的 agent 护栏只能建在**沙箱、出口白名单、短时效最小权限、生产库物理隔离**上。任何写在系统提示里的"不要删除"、"不要外发"，按零效力计入威胁模型。

4. **评测拆成两个量表。** 内部 agent 评测集里，"任务完成率"和"任务质量"必须分开记。GPT-5.6-Cyber 在 completion rate 上 95%、在真实漏洞发现上却输给基座模型——这是一个现成的反例，可以直接拿去说服任何"这个模型跑分高所以换它"的提议。这一条同时也是我们 8/5 那篇里"评分器是资产"的延续：**评分器不可信，跑分就是噪声**。

5. **若要接 Daybreak，9/1 是硬 deadline。** 硬件安全密钥届时强制。同时要认清：**Blue 档只有 2.0% 的作答率，对真实红队工作用处有限**——想靠 Blue 档替代安全外包基本不现实，真正有用的是 Red 档，而 Red 档要过身份审查和法律声明。评估投入产出时按这个口径算，别被"我们也接入了 OpenAI 安全模型"的说法误导。

6. **供应商政策风险再加一栏。** 我们的模型依赖清单里已经有 `retirement_date` / `price_change_date` / `origin` / `hosting_jurisdiction`，现在该加一栏 **`capability_tier_gate`**——记录该模型的哪些能力被锁在分级门后、门槛是什么、我们是否在门内。Astra 的例子说明：**一个模型可以在发布前就因为太强而对你永久不可得**，为未发布旗舰预留架构位的风险又高了一档。

## 六、接下来盯什么（信号）

1. **System card 何时发布**，以及 UK AISI / METR / Apollo 等外部评测方是否复现 95.0% / 1.5% 这两个数——尤其是在对抗（越狱）条件下 1.5% 还成不成立。这是判断整个分级体系是真护栏还是营销的唯一硬标准。
2. **Astra 的网络能力最终处置**：永久内部化 / 降级发布 / 变成 Red 档专供。若走第三条，等于承认分级门就是发布前的缓冲区。
3. **Anthropic 是否跟进厂商自建分级**（Mythos 5 目前是政府白名单模式）。两条路线合流的那一天，就是"前沿高危能力没有公开版"成为行业事实标准的那一天。
4. **Red 档审批者身份是否披露**，有没有政府在环（对照 6/26 商务部 Annex A 先例）。
5. **第一起 Red 档凭据泄露或滥用事件**——这决定"身份层授权"这套范式能撑多久。
6. **CVE-2026-15903 之后是否出现 AI 批量披露潮**，以及开源维护者能否接住（对照 8/3 苹果给漏洞收件箱装闸门那篇：接不住的一方会先装限流器）。
