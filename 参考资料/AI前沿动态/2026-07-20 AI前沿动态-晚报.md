# GPT-5.6 花 $25 在 WordPress 核心挖出预认证 RCE：AI 攻防越过成本临界点

**一句话定性：** 一名安全研究员把 OpenAI「证明数学猜想」的那套多代理提示词改成漏洞挖掘指令，让 GPT-5.6 Sol Ultra 从第一性原理独立审计 WordPress 源码——约 10 小时、花约 **$25**，就在全网最受审计的核心软件里发现并跑通了一条**预认证 RCE**利用链（掮客开价 **$50 万**）。这是「发现关键漏洞」的边际成本第一次被压到近乎为零的标志性事件。

**来源：** Searchlight Cyber（Adam Kues 一手博客）· 🔗 原始链接：https://slcyber.io/research-center/exploit-brokers-pay-500000-for-a-wordpress-rce-i-found-one-with-gpt5-6/ · 日期：2026-07-20（漏洞本体 wp2shell 于 7/17–7/18 披露与修复；7/20 披露的是「怎么找到的」）

---

## 为什么值得深读 / 背景

过去一个月，「前沿模型能不能做真实世界安全研究」一直是本监测的一条暗线：Squidbleed（Claude 找出潜伏 29 年的 Squid 代理堆越读 CVE）、CISA 用 Anthropic Mythos 审政府代码、递归自我改进里 Mythos 一夜扫出上万漏洞——这些都还停在「AI 是很强的助手」层面。wp2shell 把这条线推过了一个**质变临界点**：

- 目标不是某个小众组件，而是 **WordPress 核心**——驱动全网 ~40%、超过 **5 亿**个站点、被人类审计了二十年的代码库，核心里出 SQL 注入本身就极罕见；
- 漏洞不是「读取信息」级别，而是**预认证（无需登录）→ 远程代码执行**，是攻击面金字塔的塔尖；
- 成本是 **$25**、约 10 小时，而同类 WordPress RCE 在漏洞掮客市场的挂牌价是 **$50 万**——约 2 万倍的成本坍塌；
- 找到它的不是定制安全工具，而是把 OpenAI 官方那条**用来「证明」Cycle Double Cover 数学猜想**的多代理提示词，几乎原样改写成安全研究指令。

换句话说：同一套「多代理 + 长时程 + 第一性原理 + 外部验证」的通用脚手架，从证数学题无缝迁移到挖 0day。对任何做 agent 系统的人，这既是能力上限的新参照，也是威胁模型的重写。

## 核心事实（硬数据）

**AI 是怎么被用的（一手细节）**
- 研究员 **Adam Kues**（Searchlight Cyber / Assetnote）把 OpenAI 的 Cycle Double Cover 提示词改造为漏洞发现指令，要求 Sol：**「任意时刻最多 4 个代理」**、**「放弃前至少投入 6 小时」**。
- 明确**禁止联网、不给 changelog、不给 git history**，逼模型从第一性原理读源码（避免它「抄近路」对着补丁反推）。
- 完整利用链耗时**「刚过 10 小时」**，总花费**约 $25**（Kues 形容为 $200 订阅「周用量的 50%」）。
- 其中把只读 SQLi 提权到 RCE 的那段，Sol **「只用了 4 小时写出来」**，但 Kues 自陈**「我花了远远更久才看懂它」**。

**漏洞本体（wp2shell，独立来源交叉核实）**
- **CVE-2026-60137**：WordPress 核心 `WP_Query` 的 `author__not_in` 参数存在 SQL 注入。
- **CVE-2026-63030**：REST API 批处理路由混淆（`/wp-json/batch/v1`），CVSS **7.5**；校验与执行的数组错位，导致「校验一个请求、实际执行另一个」，把未认证输入引到注入点。
- 单个 SQLi 与整条 RCE 链被评为 **Critical（>9.1）**。
- 受影响 / 已修复版本：
  - `6.8.0–6.8.5`：仅 SQLi（**6.8.6** 修复）
  - `6.9.0–6.9.4`：完整 RCE 链（**6.9.5** 修复）
  - `7.0.0–7.0.1`：完整 RCE 链（**7.0.2** 修复）
  - 完整 RCE 路径自 **6.9（2025-12-02 发布）**起存在。
- 影响面：**「超过 5 亿个 WordPress 站点」**（但只有 6.9+ 暴露完整 RCE 路径——这是一个诚实的收窄）。
- 处置：WordPress 于**周五（7/17）通过 auto-update 强制推送**修复；公开 PoC 于 **7/18** 出现在 GitHub（`Icex0/wp2shell-poc`）；截至发文**无野外利用确认**。

## 机制拆解：一条「荒谬到极致」的提权链

Sol 给出的不是单点漏洞，而是把一个**预认证只读 SQLi**一步步拼装成**新建管理员 → 上传后门插件 → RCE**，且全程不碰密码。关键跳板（按一手博客复述，压缩为可读版）：

1. 批处理端点的**校验/执行错位**——校验放行一个请求，实际执行另一个，绕过对匿名请求的限制；
2. **递归批调用**绕开「只允许 GET」的限制；
3. 经 `author__not_in` 完成 **UNION 型 SQLi**；
4. 用注入**投毒缓存**（塞入伪造 post）；
5. embed 处理强制数据库对账；
6. 利用**文章层级环检测**这个 gadget 触发 changeset 应用；
7. 一个**带未来日期的 changeset** 触发「按管理员身份处理」；
8. 在 `parse_request` 钩子重放中**保留管理员角色**；
9. 以提权后的权限**成功创建新管理员账号**；
10. 经后台上传后门插件 = **RCE**。

Kues 特别点名三处「过去以为只有人类才想得出」的手法：**用递归批调用规避 GET 限制**、**滥用缓存来应用 changeset 临时提权到管理员**、以及**专门挑一个最终会调用 `parse_request` 钩子的伪造 post**。这不是模式匹配已知漏洞，而是**新颖的漏洞链构造**。

## 正反观点

**支持方（能力已越界）：** 这是「AI 做真实安全研究」从辅助跨到**独立产出新颖利用链**的第一个高质量、可验证工件。目标是全网最硬的审计对象、结果是塔尖级的预认证 RCE、成本近乎为零、且用的是通用（非安全专用）脚手架——四个条件同时满足，此前从未有过。攻防的经济学被重写：找关键漏洞的边际成本从「$50 万 + 顶级人才数周」变成「$25 + 会写提示词的人一晚上」。

**质疑方 / 风险（别被叙事带偏）：**
- **「AI 找到的」是叙事简化。** 同一事件的技术复盘方（Strobes / Security Boulevard）**根本没归功于 AI**，只把它当作 Searchlight/Assetnote 团队的发现；提示词设计（禁网、去 git、限定 4 代理/6 小时）、独立验证、以及**看懂**那条链，全靠人。Kues 也承认元技能（选目标、定方向、验证）仍是人的活。真实图景是**人机分工**：AI 在被划定的目标里做超长时程深搜，人负责选题、把关、理解。
- **攻防是对称的。** 防御方（THN/Strobes 视角）强调这本质是**「曝露验证问题」**——「当匿名代码执行发生在跑着 5 亿站点的软件里，问题不是你有没有，而是**攻击者此刻能真正打到并执行的是哪些实例**」；「补丁堵住入口，但不会移除修复前已被植入的后门」；防御者的领先窗口**「以天计，不是以周计」**。同样的 $25 能力，攻击者也买得起。
- **可复现性存疑。** 单个案例、无失败率/误报披露；是否换个目标还能稳定复现，尚待更多独立实验。

## 深度解读：对行业 + 对「做多 agent 系统的我们」的具体含义

**对行业：**
- **出口管制/双用途争议再添最硬弹药。** 「读代码的前沿模型 = 潜在的漏洞发现者」不再是理论——OpenAI 自家那条数学证明提示词被改几行就成了 0day 工厂。这会直接喂给「前沿模型发布前测试/门控」的政策叙事，也会逼各家（尤其 Anthropic Mythos 网安线）重新表态。
- **漏洞经济学重定价。** $50 万掮客价 vs $25 边际成本，意味着**关键漏洞的供给将暴增**、掮客/赏金市场承压，防御侧被迫从「点时扫描」转向「持续曝露验证 + 强制自动更新」。WordPress 这次靠**强制 auto-update** 抢下几天领先窗口，本身就是范式信号。

**对做 agent 系统的我们（落到可执行判断）：**
1. **脚手架的通用性是真信号，不是噱头。** 有效配方被明确写出：**多代理并行（≤4）+ 足够长的时间预算（≥6h，不许早退）+ 第一性原理（禁网、去 changelog）+ 外部硬验证**。这套「广探索 + 长时程 + 对抗式自证 + 人来把关」正是我们该在自己 agent 里固化的模式——它刚在数学证明和 0day 两个完全不同的领域都兑现了。
2. **威胁模型必须重写：我们自己的 agent/工具面就是别人的甜点区。** 这条链的入口是**批处理/多路复用 API 的「校验与执行错位」**——这几乎是 MCP 工具批调用、tool-call 路由、REST 批接口的通病。立刻自查：预认证端点、批处理/multiplex 接口的「校验 = 执行」一致性、以及任何「query builder 拼 SQL」的路径。假设对手正用 $25 的 agent 逐个审你的依赖。
3. **人机分工模型是当下的操作现实。** AI = 在**划定目标**内做超人级深搜；人 = 选目标、验证、理解。别把 agent 当「全自动安全团队」，要把它当「一个便宜到可以并行几十个、但必须外部验证其每个结论」的深搜引擎。这也是我们评 agent 时该盯的口径：不是「能不能自己跑完」，而是「在给定目标 + 强验证下，产出/成本比」。
4. **成本结构变了。** $200 固定订阅让「顶级攻防能力」变成随取随用的商品。对我们意味着：安全审计、依赖体检这类「以前太贵不做」的事，现在可以常态化并入 CI——但每个 AI 结论都要配可执行的复现验证，否则就是在给自己制造幻觉级噪声。

## 接下来盯什么（信号）

- **wp2shell 首个野外利用**——防御窗口「以天计」，很可能几天内出现;关注 CISA KEV 收录。
- **可复现性**——是否有第三方把「前沿模型指向核心软件 → 挖出预认证 RCE」在别的普适目标上重演（nginx 7/19 也爆了 CVE-2026-42533 RCE、OpenSSL、Linux 内核、热门 npm/pip 包都是候选靶）。
- **各家反应**——OpenAI 是否对 Sol Ultra 这类用法加限制;Anthropic（Mythos）/Google 是否跟进「AI 挖真实漏洞」的公开工件;双用途/门控政策是否被本事件点燃。
- **赏金与掮客市场重定价**——供给暴增下，$50 万级挂牌价还撑不撑得住。
- **WordPress 生态硬化**——强制 auto-update 是否成为核心软件应对「AI 级漏洞挖掘」的默认姿态。
