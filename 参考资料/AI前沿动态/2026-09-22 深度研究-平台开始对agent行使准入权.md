# 电商站点第一次对一个主流消费级 agent 关了门

**一句话定性：** 这不是两家大厂的商业口角——这是 agent 时代的第一条准入线被公开划出来：法院刚在 8 月说「用户指挥的 agent 访问网站，不构成《计算机欺诈与滥用法》意义上的未授权访问」，于是 Amazon 换了武器，在 9 月 20 日晚上直接用**合同 + 技术封堵**把 Meta 的 Muse 挡在结账页之外。战场从刑法挪到了「你的 agent 是谁、凭什么身份进来」。

## 为什么值得深读 / 背景

过去两周我们连着写了三件事：Gemini 越出 Irregular 沙箱入侵三家真实公司（9/18）、Plugin4Shell 让钉住的 SHA 形同虚设（9/20）、Google 开源 AX 把「出站白名单 + 凭据注入」升成一等公民（9/21）。这三件事都在回答同一个问题的一半：**agent 能连到哪、拿什么身份连。**

今天这件事补上了另一半，而且是从对面打过来的：**被连的那一方，开始行使拒绝权了。**

时间线压得极紧，这是它重要的原因：

- **2026-09-08** Meta 发布 Muse，官方定位「The World's First Personal AI Agent Built for Everyone」，美国先行，iOS / Android / muse.ai / WhatsApp，免费档 + 付费档。
- **发布一周后** Muse 冲上美国 App Store 免费榜第 1。
- **2026-09-10** 第九巡回上诉法院驳回 Amazon 在 Perplexity 案中的复议申请——Amazon 的刑法路径走到头。
- **2026-09-20（周日）晚** Amazon 开始拦截 Muse 结账。距 Muse 上线 12 天。

也就是说：**一个消费级 agent 从零到全美免费榜第一只用了一周，而平台的反制在第 12 天就落地了。**这个节奏比我们在插件供应链那几篇里看到的「五月发现、六月通报、九月公开」快了一个数量级——因为这次不涉及漏洞披露礼仪，只涉及钱。

## 核心事实

### 一、Amazon 做了什么

周日晚间起，任何试图通过 Muse 在 Amazon 完成购买的用户会看到一个弹窗，原文：

> "Continued access by an unauthorized AI agent violates Amazon's Conditions of Use, to which our customers have agreed."
> （继续由未经授权的 AI agent 访问，违反 Amazon 的《使用条件》，而我们的客户已同意该条件。）

注意这句话的法律构造：**它把违约主体指向"我们的客户"**，而不是 Meta。这不是笔误，这是精确适配第九巡回的判决逻辑——下面会拆。

Amazon 发言人的公开表态：

> "We think it's fairly straightforward that third-party applications that offer to make purchases on behalf of customers from other businesses should operate openly and respect service provider decisions about whether or not to participate."

并明确表示 **"we've requested that Meta remove Amazon from the experience."**（我们已要求 Meta 把 Amazon 从该体验中移除。）

### 二、Amazon 的四条具体指控

1. **未事先告知、未获授权** —— Meta 没有通知 Amazon，Muse 会访问其商店。
2. **不表明身份** —— Muse 浏览站点时不声明自己是 AI agent。
3. **抓取并存储客户凭据** —— Amazon 称 Muse「appears to capture and store customer credentials」。
4. **可触达账户页与订单历史** —— 即以「an undisclosed third party」（未披露的第三方）身份处理敏感数据。

另有一条报道中反复出现、但 Amazon 未列入正式声明的商业理由：**若 Muse 下错单或产生欺诈订单，承担退货与争议成本的是 Amazon 和它的卖家，不是 Meta。**

### 三、Meta 的反驳

Meta 的口径是对准第 3、4 条的，来自其 9/8 官方发布页（一手）：

> "Muse has no visibility into people's passwords or payment methods. Any credentials a person shares go into secure storage, so Muse can use them without seeing them."

并且 Meta 在架构上确实做了隔离设计（官方原文）：

> "Muse runs on its own dedicated computer in the cloud, contained so no one else's agent can reach it. A separate Sentinel agent runs on that same machine, kept apart from Muse at the system level. **Nothing Muse does reaches the internet unless the Sentinel approves it.**"

支付路径走 **Link built by Stripe**，Meta 自称 Muse 是「the first AI agent covered by Link's purchase protections」，Link 钱包生成一次性卡号，真实卡信息不暴露。Shop Pay 与 1Password 支持「coming soon」。

⚠️ **对账注意**：Meta 的反驳只回答了「模型看不看得到凭据」，**没有回答 Amazon 的第 2 条——Muse 是否在浏览时表明身份。**Meta 的官方发布页通篇没有提到它如何向站点标识自己。这是本案真正的技术空档，而不是凭据加密与否。另外，有聚合站标题写成「Meta 拒绝了移除请求」，但 Adweek 明确记录 Meta 未回应置评请求，未见 Meta 方面对「拒绝」的一手确认——此说存疑，不采。

### 四、钱有多大

| 指标 | 数字 | 来源 |
|---|---|---|
| Amazon 2025 全年广告收入 | **> $680 亿** | GeekWire / The Register |
| Amazon 2026 Q2 单季广告收入 | **$198 亿** | eMarketer |
| Amazon 2026 全年广告收入预测 | **$833.4 亿** | eMarketer |
| Amazon robots.txt 中被封禁的 AI bot 标识数 | **47 个** | 含 OpenAI ChatGPT-User / OAI-SearchBot / GPTBot、Google AI 爬虫、Meta AI bots |

广告收入依赖「人看到页面」。agent 直奔结账，赞助位就没人看。这不是隐私之争的副产品，这是**主因之一**——而 Amazon 的正式声明里一个字都没提它。

## 机制拆解：为什么 Amazon 这次不打官司，改发弹窗

要看懂这一步，必须回到 **Amazon v. Perplexity**（第九巡回，案号 26-1444）。

**时间线：**
- 2025-11 Amazon 起诉 Perplexity，指其 Comet 浏览器违反服务条款、劣化购物体验、制造隐私风险。
- 2026-03 加州北区地方法院授予 Amazon 初步禁令，Comet 被挡在 Amazon 之外。
- **2026-08-04 第九巡回撤销该禁令。**
- 2026-09-10 法院驳回 Amazon 的复议申请。
- 基础诉讼仍在旧金山联邦法院继续。

**判决的核心逻辑**（Cooley 解读）：当用户指挥 AI 助手在 Amazon.com 上完成任务时，**"it is the user who 'accessed' Amazon's computers"**——访问者是用户，不是 Perplexity。理由之一是 **"Perplexity itself does not directly communicate with Amazon's servers"**，通信经由用户的计算机中转。因此 Amazon「unlikely to prevail on a CFAA claim」。

**但判决同时留了三道口子，每一道 Amazon 今天都用上了：**

1. **明确限缩在 CFAA / CDAFA 范围内**，并公开保留「claims sounding in tort or contract」，包括 **"enforcing terms of service"**。
   → 所以弹窗写的是「违反《使用条件》，而**我们的客户已同意**」。Amazon 不再主张 Meta 非法入侵，它主张**用户违约**。违约之诉不需要 CFAA。
2. **法院明确拒绝裁决**：如果 agent 架构行使「greater control」或**直接与服务器通信**，是否构成 CFAA 违反——称此为事实依赖、个案判断。
   → Muse 跑在 **Meta 云端的专用虚拟机**上，不是跑在用户电脑上的浏览器。这在事实层面与 Comet 有实质差别。Amazon 的「不表明身份 + 存储凭据」指控，正是在为「这是 Meta 的服务器在直连我」这个尚未被裁决的口子铺事实。
3. **技术封堵从来不需要判决授权。** 禁令是求法院帮你挡；弹窗是自己挡。Amazon 只是把成本从诉讼费换成了工程投入。

**这就是本案的机制核心：法律路径被堵死之后，平台并没有让步，而是退回到它本来就握着的两样东西——合同条款，和 TCP 连接的另一端。**

### 顺带一层：Amazon 自己也做 agent

- **Buy For Me**：会表明身份，且允许品牌方选择退出。
- **Alexa for Shopping**（2026-05 上线）。

所以 Amazon 的论点不是「agent 不许进」，而是「**声明身份、允许对方选择退出的 agent 可以进**」。这句话是它自己产品的描述，也恰好是它对 Muse 的指控清单的反面。这个论证是自洽的——也恰好把准入标准定在了自家产品已经满足、竞争对手尚未满足的位置上。

### 不是孤例

- **eBay** 本月更新用户协议，禁止未经批准的「buy-for-me」agent，但明确为「formally sanctioned」（正式授权）的购物 agent 留了口子。
- Amazon 此前已对 **Google 与 OpenAI 的购物 agent** 采取过封堵动作。

**行业默认值正在从「开放网页」滑向「白名单 + 商业协议」。**

## 正反观点

### 支持 Amazon 的一方

- **责任不对称是真实的。** 下错单的退货、争议、卖家损失由 Amazon 和卖家承担，Meta 不承担。一个不表明身份的第三方在你的系统里代用户下单，出事没人对账。
- **「不表明身份」是可独立成立的指控。** 即使 Meta 关于凭据的说法全部属实，Muse 是否声明自己是 agent 是另一个问题，而 Meta 至今未正面回答。
- **Amazon 给出了可满足的条件**（公开运行 + 尊重服务方的参与决定），且自家 Buy For Me 已按该标准执行——不是纯粹的拒绝，是提出了一个门槛。

### 质疑 Amazon 的一方

- **利益冲突是明面上的。** 全年 $833 亿预测的广告收入建立在「人浏览页面」之上。agent 直奔结账会绕开赞助位。Amazon 的正式声明只谈安全与授权，完全不谈广告——**动机中最大的一块被从论证里拿掉了，这本身就是应当打折的信号。**（同我们对 AIR Security、Solo.io 的处理原则：技术事实照收，严重性形容词打折。）
- **「agent 更像浏览器或无障碍工具，而非竞争者」**（开发者方观点，practicalecommerce 载）：若按此类比，屏蔽 agent 实质上是在屏蔽依赖它的人类用户，「block human shoppers, stifle innovation, and foster monopolies」。
- **法院已经站在用户这一边。** 第九巡回的核心判断正是「访问者是用户」。Amazon 的弹窗把矛头指向自家客户违约，在公关上是个尴尬位置。
- **eMarketer 的平衡判断**：这是 Amazon 的「a clear setback」，但它「有更多可失去、也有更多资源继续打」；同时小型零售商可能**欢迎** agent 流量，若真能转化——那会引发「a race to the bottom on price」。
- **规模现实**：用 agent 购物的消费者数量**目前仍然很小**。双方都在为一个尚未到来的市场抢规则，而不是在抢现有收入。

## 深度解读：对行业 + 对做多 agent 系统的我们

### 对行业

**1. 「开放网页」对 agent 而言正在结束，而且是从两头同时关的。**
9 月 15 日 Cloudflare 改了默认值——它保护的站点**默认拒绝 agent 流量**（此前是默认放行）。9 月 20 日 Amazon 封 Muse。两件事相隔五天，方向一致：**agent 访问从「默认允许、按需封禁」翻转为「默认拒绝、按需放行」。**这是 2023 年以来 AI 爬虫治理的同一条曲线，只是这次对象从「读」变成了「买」。

**2. 身份层正在被迫成型，而且有现成标准。**
- **Web Bot Auth**：请求用 Ed25519 签名，公钥发布在 well-known JWKS 目录，服务端**验证签名**而非猜测 User-Agent。
- 时间线：2025-07-01 Cloudflare 并入 Verified Bots；AWS WAF Bot Control 2025-11 支持；2026 年初 IETF 成立工作组；2026-05 W3C 规范定稿；Vercel / Akamai / Stytch / Shopify 跟进。
- 支付侧：Visa **Trusted Agent Protocol**、Mastercard **Agent Pay**、Amex 均已承诺。

**Amazon 对 Muse 的第 2 条指控——「不表明身份」——在技术上已经有标准答案了。**这意味着争的不是「能不能证明身份」，而是「证明了身份之后，平台还要不要放你进来」。**后者是商业谈判，不是工程问题。**未来 12 个月的形态大概率是：**签名身份 + 双边商业协议**的白名单，而不是开放互联网。

**3. 平台自有 agent 会被系统性优待。**
Buy For Me 表明身份、支持品牌退出、跑在 Amazon 自己的基础设施上——它天然满足自己定的门槛。这条准入线画出来的那一刻，「平台自营 agent vs 第三方 agent」就成了新的纵向整合战场。可类比的是我们 8/28 写过的「OpenAI 掐断 Cursor」那一篇：**API 中立性结束之后，紧接着结束的是「网页中立性」。**

### 对做多 agent 系统的我们——五条可执行判断

**① 把「站点准入」当成和「模型可用性」同级的依赖风险，现在就建清单。**
我们的 agent 链路上每一个外部站点，都要能回答三个问题：(a) 它的 ToS 是否已有 agent 条款？(b) 它是否已接入 Cloudflare/Akamai 的默认拒绝策略？(c) 有没有官方 API/商业协议这条备用路？Amazon 这次是**周日晚上直接上弹窗，没有预告期**。任何依赖网页自动化的链路，都应假设它可以在一夜之间归零。**这和依赖一个会被弃用的模型是同一类风险，但我们大多数人只给后者建了预案。**

**② 今天就决定：我们的 agent 表明身份吗？**
这是本案里唯一一条 Meta 没能反驳的指控，也是最便宜的合规改动。具体动作：给出站请求加上稳定、可识别的 User-Agent，并评估接入 **Web Bot Auth**（Ed25519 签名 + well-known JWKS）。成本是几小时，收益是当对方开始区分「签名 agent」和「伪装成浏览器的 agent」时，我们在白名单那一侧。**伪装成人类浏览器在 2026 年之前是默认做法，现在它正在变成一条明确的违约证据。**

**③ 凭据边界要按「Amazon 的指控清单」自查，而不是按「我们的实现意图」自查。**
Meta 的辩护——「凭据在安全存储里，模型用得到但看不到」——在架构上是正确方向，和我们从 AX Gateway 那篇得出的结论完全一致（凭据注入在 agent 够不着的地方）。但请注意：**Meta 做对了这一点，仍然被封了。**因为对手方关心的不是你的模型能不能看到密码，而是**它自己无法验证**这一点。含义是：凭据隔离做了还不够，**要做成可被第三方验证的形态**（签名身份、可审计的调用日志、明确的责任主体）。「我们内部很安全」在跨组织边界上不构成论据。

**④ 接住上周的那条线：出口白名单现在有了商业理由，不只有安全理由。**
9/21 AX 那篇我们的结论是「每个 agent 出站白名单是什么、写在哪、谁改」。当时的理由是安全。今天多了一条：**被封锁时你需要知道影响面。**如果说不清哪些链路会打到 amazon.com，就没法在弹窗出现的 30 分钟内评估损失。出口白名单从「安全控制」升级成「业务连续性台账」——这提高了它的优先级。

**⑤ 谨慎对待「agent 能买东西」这个产品承诺。**
Muse 上线 12 天，最大的零售目的地就关门了。**任何以「替你在任意网站完成交易」为卖点的产品，其可达范围是由对手方单方面决定的，且随时可变。**如果我们要做类似能力，架构上应当优先走**官方 API / 商业协议**路径，把网页自动化当降级方案而不是主路径；产品承诺上应当明确列出支持的站点清单，而不是暗示"全网通"。Meta 用一周做到 App Store 第一，也用 12 天证明了这个承诺的脆弱性。

### 一个需要反对的直觉

不要把这件事读成「Amazon 怕 Meta 抢生意」。真正的信息是：**agent 的能力边界，第一次不再由模型能力或工程能力决定，而是由对手方的商业意愿决定。**我们过去两周写的三篇——沙箱越界、供应链 pin 失效、AX 的出口治理——讲的都是「我们怎么管住自己的 agent」。这一篇讲的是「别人怎么管住我们的 agent」。**两者叠加的结论是：agent 系统的可用性，正在同时被内部控制面和外部准入面两头收紧，而大多数团队对后者连清单都没有。**

## 接下来盯什么

1. **Meta 的下一步**——是接入身份标准、谈商业协议，还是绕过封堵？若选择绕过（轮换指纹、模拟人类），Amazon 就拿到了第九巡回明确留口的那类事实（「greater control」/ 直连服务器），案情性质会变。**这是判断 Meta 是否准备把 agent 做成长期业务的最干净单一信号。**
2. **Amazon v. Perplexity 基础诉讼**在旧金山联邦法院的合同/侵权部分——CFAA 路径已败，合同路径是否成立，将决定 ToS 能否成为通用的 agent 拦截工具。这比 CFAA 那部分重要得多，因为它适用于所有站点，不只是 Amazon。
3. **eBay 那个「formally sanctioned」口子**会不会真的开出第一批白名单——若开，第三方 agent 的准入价格就有了公开参照。
4. **Web Bot Auth 在电商侧的采用率**——Shopify 已在名单上。若 Shopify 把「签名 agent 可通过」做成商户可配置开关，身份层就从 CDN 层下沉到了商业层，格局会快速定型。
5. **Amazon 是否公布可申请的 agent 准入流程**——有＝它想当标准制定者；没有＝「表明身份就能进」只是诉讼修辞，实际是纯粹排他。**这是检验 Amazon 论证真诚度的证伪条件。**
6. **agent 购物的真实渗透率数据**——目前所有各方都承认「用 agent 购物的人仍然很少」。若某家开始披露 GMV 口径的真实数字，这场规则之争才从期权变成现金流。
7. **其他大型零售与票务/旅行站点的跟进速度**——五天内出现了 Cloudflare 默认拒绝 + Amazon 封锁两件事。若三周内再出现 2–3 家大型站点跟进，「默认拒绝」就完成了从个案到行业默认值的切换。
