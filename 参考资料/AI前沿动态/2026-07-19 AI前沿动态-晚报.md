# GPT-5.6 关闭凸优化「30 年缺口」，并自带完整 Lean 机器验证

**一句话定性**：前沿模型第一次不只是"给出一个看起来对的新证明"，而是给出一个**由内核逐条校验、无人能赖账的新数学结果**——AI 做数学的争议从此不再是"信不信 AI"，而是"验证器认不认"。这把"AI 生成 + 机器验证"从口号变成了可复用的工程范式。

## 为什么值得深读 / 背景

"AI 做出新数学"这句话在过去一年已经喊过好几轮，且大多雷声大雨点小：

- **2025**：Sébastien Bubeck 用 GPT-5-Pro 在一个凸优化开放问题上把已知界从 1/L 改进到 1.5/L（人类后来推到 1.75/L）——真结果，但属"改进一个界"，且靠人工核对。
- **2026 年 7 月初**：OpenAI **自己**高调宣布 GPT-5.6 Sol Ultra 用 64 个子代理、不到 1 小时"证明"了 1979 年 Seymour 提出的**循环双重覆盖猜想**（Cycle Double Cover，50 年悬案）。数学家 Thomas Bloom 评价"很漂亮、很初等"，但**未经同行评审、未做任何形式化、还被指漏引 1983 年 Bermond–Jackson–Jaeger 等关键前作**。这类"猜想历史上尸横遍野的错误证明"，让整个数学界对 AI 自然语言证明保持高度警惕。

7/18 登上 HN 头版 #1 的这条不同——它恰好补上了前两轮最大的软肋：**这次的新结果附带一份完整、内核可校验的 Lean 4 形式化证明**。对做 agent / AI 产品的人来说，真正的信号不是"AI 又证了个定理"，而是"AI 生成的推理第一次被廉价、独立、可判定的验证器托底"。这是一个可以直接搬进我们工程实践的模式。

## 核心事实（硬数据）

**问题**：确定性、仅**零阶预言机**（derivative-free，只能查函数值、拿不到梯度）的凸优化——单位球上的凸 1-Lipschitz 函数，要问"到底需要多少次函数求值才能逼近最小值"。

**结果**（论文《Closing the Oracle-Complexity Gap in Derivative-Free Convex Optimization》）：

- **紧下界**：对维度 d = 2m，任何确定性精确值策略要达到优于 ε_m = 10⁻⁷/√(2m) 的精度，至少需要 **T ≥ m² / (100·log(em))** 次求值，即 **≈ Ω(d²/log d)**（HN 标题简化为 Ω(d²)）。证明手法是：针对**任意**策略，都能构造一个 max-affine（分段线性）凸 1-Lipschitz 目标，其最小值点落在单位球内，使该策略的误差必然超过阈值。
- 还有一个更早、更简单的 **d⁻³ 精度版本**：d = 2m ≥ 2000 且 1000T ≤ m² 时，误差 > 1/(25,000,000·d³)。
- 结论适用于**不限精度、不限内存、不限连续性**的一般"transcript-dependent"策略——即没有留任何取巧的口子。

**"30 年缺口"是什么**：这个问题类的**上界**（一个零阶算法用 ~O(d²) 次函数求值就能解）已知约三十年；但**匹配的下界**（证明"没有任何算法能更快"、即那个老算法本来就是最优的）一直没被证出来。这篇论文把上、下界对齐，**关闭了 oracle 复杂度缺口**——这正是标题所谓"close a 30-year gap"。

**关键差异化——机器验证**（作者 GitHub 仓库 `zero-order-bounds-lean-verification`）：

- 更强的 d⁻¹ᐟ² 下界及其吃重的几何机制（球面平均、Brunn–Minkowski、intrinsic Urysohn）**全部在 Lean 4 / mathlib 中形式化**。
- 仓库**内核逐条校验**（kernel-checked）、**无 `sorry` / `admit`**、仅依赖标准经典公理 `[propext, Classical.choice, Quot.sound]`，并提供 `lake env lean --trust=0` 的零信任校验命令。
- 也就是说：结论对不对，不取决于你信不信作者、更不取决于你信不信 GPT——你只需要信一个几十行、被无数人审过的 Lean 内核。

## 机制拆解：为什么"自带验证"是质变而非增量

AI 生成的推理天然是 **plausible-but-wrong**（看着对、其实可能错）：语言模型优化的是"读起来像证明"，不是"逻辑无漏洞"。数学界对 Cycle Double Cover 那份证明的警惕正源于此——50 年里它收过一堆貌似成立、细看崩盘的"证明"。

Lean 形式化把这个信任问题**外包给一个可判定的内核**：证明要么通过 kernel 校验，要么不通过，没有"看起来对"的中间态。于是这次事件的真正结构是：

> **生成（贵、易错、靠大模型） × 验证（便宜、可判定、独立于生成器） = 可信的产出**

模型负责"想出那个奇怪但正确的构造"，Lean 内核负责"担保它真的没漏洞"。二者解耦，是这件事能站得住脚的全部原因。

## 正反观点

**支持方（这是真进展）**：结果是一个货真价实、niche 但明确的复杂度下界猜想的关闭，且**带 kernel 级形式化**——这是所有"AI 数学"里证据等级最高的一次；模型给出的不仅是自然语言证明，还有连作者都写不出的 Lean 证明。HN 高票（500+）认可"这代表一次真实贡献"。

**质疑方（别过度解读）**：① 归因水分——人类做了一年铺垫、prompt 里含解题技术，"一个 prompt 搞定"是叙事包装；② 属"人给脚手架、模型补关键一跳"的人机协作，不是自主研究；③ 论文本身尚未走完 arXiv / 同行评审（形式化保证了"逻辑无误"，但不保证"结果重要/新颖/无重复前作"）；④ 与之并列的 Cycle Double Cover 证明恰恰**没**形式化、**没**同行评审、被指缺引用——提醒我们前沿实验室的 PR 口径与可验证事实之间有落差。

## 深度解读：对行业 + 对「做多 agent 系统的我们」的具体含义

**对行业**：AI 攻破知识工作的顺序，由"该领域有没有廉价的 ground-truth 验证器"决定。数学（Lean）、代码（编译器/测试/类型）、形式规约——这些**有可判定验证器**的领域会最先、最快被 AI 拿下，因为模型只要"生成得够多样"，验证器就能把错误挡在门外，进步是非线性的。反过来，战略、判断、品味这类**没有验证器**的软任务，进步会慢得多。这条线索直接决定哪些岗位/任务先被重构。

**对我们（做 agent 系统）——四条可执行判断**：

1. **验证层就是信任层，别让 agent 自证。** 这次事件的核心不是模型多强，而是"生成 × 独立验证"的架构。我们的 agent 输出（代码、SQL、迁移、配置、结论）默认都要当成 plausible-but-wrong，接一道**便宜、独立、可判定的 gate**：类型检查 / 测试 / 形式规约 / schema 校验 / 第二个 agent 对抗复核。把"相信一个大模型"降级成"相信一个几十行的校验器"——这正是我们 workflow 里"find → adversarially verify"该固化成默认的原因。

2. **"N 子代理 + 对抗验证"是已被前沿验证过的编排原语。** Cycle Double Cover 用 64 个子代理（多样化探索 + 专门的对抗代理找反例）。这与我们做复杂任务的模式同构：**fan-out 生成候选 → 独立 skeptic 代理逐条 refute → 只留活下来的**。生成便宜、验证便宜、且验证独立于生成，是 agent 质量的最大杠杆，值得做成基础设施而非一次性 prompt。

3. **人仍是"问题设定者 + 品味者"，把 agent 定位成放大器而非自治体。** 真实增益出现在"人给结构化问题与方向、模型补上关键构造与形式化"的闭环里，不是端到端自动化。产品含义：把预算投在**脚手架**（问题拆解、环境、验证器、可复核的中间产物）上，而不是幻想"丢个目标就自己跑完"。这也解释了为什么"给了正确脚手架就能突破"的 agent，比"更自主但没验证"的 agent 更有商业价值。

4. **优先做"可验证"的任务与产品面。** 选题、架构时向"能写下测试/规约/类型"的方向倾斜——那里 AI 有验证器托底、可靠性可控、可规模化交付；把无验证器的判断类环节留给人做 gate。这是把这波能力跃迁转成可交付质量的最直接方式。

## 接下来盯什么（信号）

- 这份 Lean 证明是否被 **mathlib / 第三方独立复核并合入**；论文是否上 arXiv、能否过同行评审（形式化保逻辑、但不保新颖性/无重复前作）。
- Cycle Double Cover 那份**未形式化**的证明能否扛住数学界审查——成立即里程碑，翻车即"AI 自然语言证明"的经典警示。
- OpenAI / Anthropic / Google 是否把"**生成即附形式验证**"产品化（Lean / 证明助手集成、带验证器的 coding agent、可核对的 reasoning 轨迹）。
- "**多子代理 + 对抗验证**"是否成为前沿推理的标准编排范式（直接呼应我们 workflow 的 fan-out + verify 模式）。
- 是否出现"AI 持续关闭已知开放问题"的稳定流水（Erdős 型问题、组合猜想、复杂度下界等），以及其中**带形式化**的占比——占比越高，越说明"AI + 验证器"进入工程化常态。
