# Grok 4.5 公开发布：agent-coding 第三极落地，「工具中立性会过期」开始兑现

**一句话定性**：马斯克把「模型（Grok）+ IDE（Cursor）+ 算力（Colossus）+ 分发（Grok Build / X）」四件套第一次凑齐并出货——Grok 4.5 不是又一个跑分模型，而是 6 月 SpaceX 600 亿美元收购 Cursor 那条「垂直整合闭环」论断的首个可验证兑现物；它用**别人（Cursor 用户）的开发数据**训练、以 Opus 级能力主张 + 远低于旗舰档的价格 + 4.2 倍的 token 效率切进 Anthropic/OpenAI 的腹地，也让我们两周来反复提示的「工具中立性是会过期的资产」从推演变成看得见的事实。

## 为什么值得深读 / 背景

这是本监测追踪了三周的一条明线的收口。时间线：

- **6/16**（seen 6/25am 深研）：SpaceX 以 600 亿美元全股票收购 Cursor/Anysphere，我们当时下的判断是——马斯克在搭「IPO→Cursor→Grok→Colossus」的垂直整合闭环，会「数据层→默认值层→定价层」温水煮青蛙地煮掉模型中立性；并预警 OpenAI 收 Windsurf 后 Anthropic 直接断 Claude API 的先例。
- **6/28**（backlog tracking 项）：Grok 4.5 进 SpaceX/Tesla 私有测试，1.5T V9 基础、整合 Cursor 会话数据训练，马斯克称「接近、或许超过 Opus」，但**无第三方独立基准**。我们当时明确写了「若 Grok 4.5/V9 公开发布并出可比基准（TerminalBench/SWE-bench）… 可深挖」。
- **今天（7/8-7/9）**：公开发布，附 xAI 自报基准。触发条件满足。

它够格做这次晚报的唯一一篇，理由是它同时命中选题的多个维度：**改变竞争格局**（agent-coding 从双寡头变三方，且是第一个「模型+IDE+算力」全栈玩家）+ **能力/效率信号**（token 效率 4.2 倍、价格 $2/$6）+ **直接冲击 agent 工程**（默认进 Cursor / Grok Build，涉及每个用 Cursor 的团队）。今早的晚报另一半（GPT-5.6 全球 GA）讲的是「门控范式的出口侧兑现」，这一篇讲的是「垂直整合与工具中立性的兑现」，两条线互补、不重叠。

## 核心事实（分层）

**发布与定位**
- SpaceXAI（xAI）于 **7/8** 面向开发者发布 Grok 4.5，**7/9** 面向大众（grok.com / X app，限 X Premium+ / SuperGrok）。
- 马斯克原话：「an **Opus-class model**, but faster, more token-efficient and lower cost」；内部更保守的说法是「roughly comparable to **Opus 4.7**, but much faster」。
- 架构：MoE，Musk 自报 **1.5T 参数 / V9 基础**（SpaceXAI 官方发布材料未确认参数量）。
- 与 Cursor **联合训练**：官方称用了「trillions of tokens of real developer-agent data」/「数十万个任务」，训练跑在 Colossus 的数万张 **NVIDIA GB300** 上（Cursor 4/21 宣布与 SpaceX 合作解算力瓶颈）。

**规格与价格**
- 上下文窗口 **500K**（注意：**比 Grok 4.3 的 1M 缩水一半**）。
- 速度约 **80 tok/s**（Artificial Analysis 实测 91.3）。
- 定价 **$2/M 输入、$6/M 输出、$0.50/M 缓存输入（75% 折）**；>200K 上下文加价。
- 文本+图像输入、文本输出；推理档 low/med/high（默认 high，不可关）。
- 分发：Grok Build（**默认模型**）、Cursor（**全部套餐**）、xAI API、grok.com/X、MS Office 插件、OpenRouter、Vercel、Cloudflare、Snowflake、Databricks Mosaic。**发布时不含 EU**（预计 7 月中）。

**基准（均为 xAI 自报；对照 Opus 4.8 / GPT-5.5 / Fable 5）**

| 基准 | Grok 4.5 | Opus 4.8 | GPT-5.5 | Fable 5 |
|---|---|---|---|---|
| DeepSWE 1.0 | 62.0 | 55.75 | 64.31 | 66.1 |
| DeepSWE 1.1 | 53 | 59 | 67 | 70 |
| Terminal-Bench 2.1 | 83.3 | 78.9 | 83.4 | 84.3 |
| SWE-Bench Pro | 64.7 | 69.2 | — | 80.4 |

- 对 Opus 4.8：**4 项胜 2（DeepSWE 1.0、Terminal-Bench 2.1）、负 2（DeepSWE 1.1 −6、SWE-Bench Pro −4.5）**。
- **Token 效率**：SWE-Bench Pro 上平均 **15,954 输出 token vs Opus 4.8 的 67,020 ≈ 4.2 倍差**。这是本次最硬、也最值钱的一个数。
- 另称 **#1 on Harvey's Legal Agent Benchmark**（供应商自报，无第三方核验）——一个主打编码的模型在法律 agent 榜登顶，说明训练配比不止工程。
- **第三方**：Artificial Analysis Intelligence Index 得 **54，综合排 #4**，落在 **Fable 5（60）、Opus 4.8（56）、GPT-5.5（55）之后**；并录得 **~54% 的高幻觉率**。

## 机制拆解：这次赢的不是「更聪明」，是「垂直整合 + token 经济学」

1. **数据护城河靠收购买来。** Grok 4.5 的卖点集中在 agentic coding，而它吃的是 Cursor 用户「真实的开发者-agent 交互轨迹」——调试痕迹、多文件 diff、用户纠偏。这类数据买不到、爬不到，只能拥有一个高活跃 IDE 才拿得到。SpaceX 花 600 亿买 Cursor，买的正是这条数据管线。佐证其威力也佐证其风险：Cursor 自己承认「早期一版 Cursor 代码库被误纳入训练，导致 Grok 4.5 在 CursorBench 上占便宜」——数据边界是糊的。

2. **token 效率 > 榜单名次。** Grok 4.5 在原始能力上并不领先（第三方 #4、xAI 自己的表里 Fable 5 三项、GPT-5.5 一项都压着它），但它在 SWE-Bench Pro 上用 1/4 的输出 token 达到接近的分数。对 agent 场景，**成本 ≈ 输出 token × 单价**，所以「$6/M 输出 × 4.2 倍效率」的有效每任务成本，可能显著低于名义更贵的旗舰。这是把「效率拐点/tokenmaxxing 退潮」（Lindy→DeepSeek 降 90%、自研硅 Jalapeño/三星 2nm）从需求侧和供给侧之外，补上「模型侧原生省 token」的第三条路径。

3. **全栈闭环第一次凑齐。** 此前 Anthropic/OpenAI 是「模型 + 少量自有 harness（Claude Code / Codex）」，Google 是「模型 + 云 + 少量工具」。xAI 现在是唯一「自有前沿模型（Grok）× 头部 IDE（Cursor）× 自有超算（Colossus）× 自有分发面（Grok Build / X）」齐备的一家，而且 Grok 4.5 已是 Grok Build 默认、Cursor 全套餐可选。默认值就是分发权。

- 马斯克：「an Opus-class model, but faster, more token-efficient and lower cost.」

## 正反观点

**支持方（看多）**
- 定价激进：$2/$6 落在 GPT-5.6 Luna（$1/$6）与 Terra（$2.5/$15）之间，却主张 Opus 级能力，叠加 4.2 倍 token 效率 → 有效每任务成本极具攻击性。
- Terminal-Bench 2.1（83.3）与 DeepSWE 1.0（62.0）确实压过 Opus 4.8；Harvey 法律 agent 榜自报 #1 说明泛化到工程之外。
- 全栈闭环 + Colossus 自有算力，供给端有别人没有的成本与迭代速度杠杆。

**质疑方（看空 / 风险）**
- **基准是自选的、且只赢一半。** 4 项里对 Opus 输 2；在 xAI 自己的表里，Fable 5 三项、GPT-5.5 一项都在它之上。无任何第三方核验。
- **第三方综合只排 #4**（Artificial Analysis 54，落后 Fable 5 / Opus 4.8 / GPT-5.5），**且幻觉率高达 ~54%**——高频代码场景的隐性成本。
- **上下文从 1M 缩到 500K**，长仓库/长会话场景反而退步。
- **CursorBench 训练污染**已被官方承认，说明「用自家 IDE 数据训练」既是护城河也是评测可信度的漏洞。
- **EU 缺席 + 政治缠绕**：马斯克的地缘/监管敞口，使「随时随地可用」这件事本身不可靠。
- **中立性冲突**：Cursor 长期以「模型无关」立身，如今却把用自家用户数据训的模型做成默认选项之一，对依赖 Cursor 中立性的团队是明确警讯。

## 深度解读：对行业 + 对「做多 agent 系统的我们」的具体含义

**对行业**：agent-coding 正式从「Anthropic vs OpenAI」双寡头，变成加入「xAI 全栈闭环」的三方（Gemini 3.5 Pro 7/17 GA 后或成四方）。真正的新变量不是 Grok 4.5 的分数，而是**第一次出现「模型厂同时拥有你天天在用的编码工具」**——数据、默认值、定价三个旋钮都握在同一只手里。这重演的正是 OpenAI 收 Windsurf 后 Anthropic 断供 Claude 的剧本，只是这次是马斯克，且垂直度更高。

**对我们（可执行判断，别套话）**：

1. **把 Grok 4.5 加进多模型热切换名册，但只当「成本/效率档候选」，不当默认。** 归档到「高频、低容错的编码/glue 任务」路由分支；**上生产的前置条件 = 独立第三方基准 + 我们自己的 $/task 实测（含把 4.2 倍 token 效率跑成真实账单）**。它第三方 #4、幻觉 ~54%——高价值/低容错动作仍留 Opus / GPT-5.6。这与 Sonnet 5「按步骤价值分档路由」是同一套打法。

2. **「工具中立性会过期」从推演变成现实，现在就对冲。** 若在用 Cursor：① 始终保留独立的 Claude / OpenAI API key 与 **Claude Code 备胎**，不把工作流绑死在单一 IDE 的默认模型上；② 假设「默认模型/定价将变」写进风险登记册（触发器：Cursor 内 Claude/GPT 访问或定价变更、Grok 4.5 被推成强制默认）；③ `.cursorrules` 等迁移成本提前摊销。

3. **「训练用了谁的数据」升级为供应链/治理一等条目。** Grok 4.5 = 「你的工具的遥测变成供应商模型的训练集」的活教材。**盘点你的 IDE/agent 工具向上游发送什么开发者会话数据、核对其 ToS 是否允许拿去训练**；能力/数据来源合规做成 to-B 信任资产。

4. **cost-per-task 要把「token 效率」做成与「单价」平级的维度。** Grok 用 1/4 输出 token 逼近旗舰，证明**名义 $/Mtok ≠ 每任务成本**。评测口径里加「平均输出 token/任务」，别只看 headline 价格；把 12-24 月成本模型的地板继续下移，别用今天的旗舰单价锁死定价。

5. **可用性/地缘风险 +1。** EU 发布时缺席 + 政治缠绕 → 多模型 × 多阵营 × 多地缘热切换继续是生存底线，别把任何单一 provider 当「随处可用」。

## 接下来盯什么（信号）

- **独立第三方基准**：Artificial Analysis 全套 agentic、SWE-Bench Pro 核验版、Terminal-Bench 2.1 榜、OSWorld——**4.2 倍 token 效率与 Terminal-Bench 83.3 能不能被复现**。
- **Cursor 的中立性走向**：Grok 4.5 会否被推成默认 / 拿到定价优势？Cursor 内 Claude / GPT 的访问或定价是否变化。
- **真实 $/task 报告**：有没有团队晒出「4.2 倍 token 效率 → 账单真降」的实测。
- **Anthropic / OpenAI 的回应**：是否对 Cursor 断供或降价/效率对标（Windsurf 先例）。
- **Gemini 3.5 Pro（7/17 GA）**：四方格局与真基准（SWE/Terminal-Bench/OSWorld）+ 定价。
- **EU 上线时间与监管摩擦**。
