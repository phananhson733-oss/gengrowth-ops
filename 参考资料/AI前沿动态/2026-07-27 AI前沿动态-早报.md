# Claude 分享链接又被 Google 索引：AI 会话/agent 产物的"分享即公开"正在成为系统性数据外泄面

**一句话定性：** 这不是一次高深的攻击，而是一个"低魅力、高杀伤"的产品默认——同一类事故（分享链接被搜索引擎索引）**在 14 个月里第三次**砸到头部实验室（ChatGPT 2025-07、Claude 2025-09、Claude 2026-07）。它本身规模有限、当事人可辩解为"用户自愿公开"，但对"做 agent 系统的我们"是一记正中靶心的提醒：**当你的 agent 开始批量生产可分享的产物（会话/报告/运行记录），"分享/导出/日志"这条最不起眼的输出链路，才是密钥与 PII 最容易溜出去的地方。**

## 为什么值得深读 / 背景

先说清楚为什么"今天推的是它"：过去一周本监测的深研高度集中在**格局/地缘轴**——Opus 5（每单位智能成本，7/25）、AgentForger（agent 供给时安全，7/25）、黄仁勋开源信（开放 vs 闭源站队，7/26）、Kimi K3 落地（开源推理经济学，7/26）。最近约 2 天里，这些大件要么已推、要么属旧事收尾（如 Kevin Weil 离职 / Prism 并入 Codex 实为 4 月旧闻的执行尾巴，非新事件；Codex 桌面 app / 多 agent V2 / Codex Micro 键盘均为 7/24 changelog 级）。**窗口内唯一"新且未覆盖"的独立事件，就是这次 Claude 分享链接泄密。**

它值得单独深读，不是因为规模大（并不大），而是因为它把一条**被反复忽视的输出侧攻击面**摆上台面，而这条面在 agent 化产品里只会越来越危险：

- 它与 7/25 已深研的 **AgentForger** 正好构成 agent 数据治理的一头一尾——AgentForger 讲的是"供给/接入侧"（连接器被 CSRF 劫持、致命三要素的**输入**端），这次讲的是"**输出/分享**侧"（同样一批数据经"分享"链路外泄）。中间的"处理侧"（prompt injection）本监测已多次覆盖。**这次把 agent 数据生命周期的最后一环补齐了。**
- 它是**同一坑第三次**，说明问题不在某家一次疏忽，而在"默认公开分享"这个 UX 原语本身与搜索引擎索引机制的结构性错配——**任何要给 agent 产物加"分享/导出"按钮的团队都会踩到。**

## 核心事实（分层）

**事件层：**
- **2026-07-26 周末**，一条 Reddit 帖（并有开发者在 X 跟进）曝光：用 `site:claude.ai/share` 这类搜索式，可在 Google 检索到**数百条** Claude 分享会话页（`claude.ai/share/…`），无需原始分享者给链接即可点开读全文。
- Google 对这些页的展示是 **"No information is available for this page"（本页无可用信息）**——这是"URL 被索引、但内容抓取被 robots.txt 挡住"的典型指纹。

**泄露内容层（多源交叉）：**
- **凭据类**：API key、登录凭据；
- **加密资产类**：加密钱包细节（含私钥/助记词的迹象；报道称截至发稿**无被实际盗用/无资金损失**）；
- **职业/商业类**：简历（CV）、公司内部文件、法律策略讨论、专有代码调试；
- 一名开发者在 X 上称"钱包细节和登录凭据就夹在搜索结果里"。

**分享机制层（Anthropic 文档口径）：**
- 会话**默认私有**，只有用户**主动点"分享"生成公开链接**才会外露；分享生成的是"到当前为止全部消息"的**公开网页快照**；
- **上传的文件、以及工具拉取的数据被排除**在分享页之外（这是本次比 2025 年"更有限"的关键原因之一）；
- **只有 Free/Pro/Max 可公开分享；Team/Enterprise 账户不能公开分享**（企业默认更安全——记住这条，后面要用）。

**处置层：**
- 到**周日**，Google 上受影响页面**已基本消失**（要么快速去索引、要么 Anthropic 后端修复）；但**此前已被他人保存的链接仍可访问，除非在服务端撤销分享**；部分内容仍能经其他搜索引擎找到。
- 截至报道时，**Anthropic 未就此公开表态**。

**历史层（这是第三次）：**
- **2025-07** ChatGPT："make discoverable"开关导致 **Fast Company 查到 4,500+ 条**被 Google 索引的分享会话，含姓名、简历、情感倾诉、机密工作内容；OpenAI（CISO Dane Stuckey）随即**关闭该开关**，称其为"引入了太多让人不小心分享出本不想公开内容的机会"的"短命实验"。
- **2025-09** Claude：约 **600 条** Claude 分享会话被 Google 索引（Forbes 报道）。
- **2026-07** Claude：本次；报道普遍认为**规模明显小于去年**。

## 机制 / 技术拆解：为什么 `robots.txt` 挡不住"被索引"

这是整件事最值得工程团队记住的一课，因为它是个**反直觉的经典陷阱**：

1. **`robots.txt` 管的是"抓取（crawl）"，不是"索引（index）"。** Anthropic 的 `robots.txt` 告诉搜索引擎"别抓 `/share` 下的页面"。但 Google 仍可以**通过外部入链发现这个 URL**，并把这个 URL **收进索引**——它只是读不到页面正文，于是在结果里显示"No information is available for this page"。**URL 本身进了索引；任何看到这条结果的人点进去，就能读到全部内容。**
2. **真正能阻止"被索引"的是 `noindex`**（`X-Robots-Tag: noindex` 响应头，或 `<meta name="robots" content="noindex">`）。**但这里有个致命悖论：要让 Google 看见 `noindex`，就必须先允许它抓取这个页面；而一旦你用 `robots.txt` 把抓取禁掉，Google 永远读不到那条 `noindex` 指令。** 于是"用 robots.txt 保护隐私页"这个做法，恰恰保证了 noindex 失效——只要 URL 一泄漏到论坛/社媒/误贴，它就会被索引。
3. 本次分享页缺乏正确的 `noindex` 处理，链接一经扩散即被收录。修复路径通常是：**允许抓取 + 返回 `X-Robots-Tag: noindex`**（让 Google 抓到并看见"别索引"），或走认证门 / 让 URL 不可枚举 + 可服务端撤销。

> 一句话记住：**`robots.txt` 是"请你别看"，`noindex` 是"看了也别收"。想让内容不进搜索结果，要的是后者——而且必须让爬虫能读到它。**

## 关键原话 / 引述

- Google 结果对受影响页的展示：**"No information is available for this page."**（被抓取拦截却仍被索引的指纹）
- 报道对根因的定性："Anthropic 的 robots.txt 挡住了搜索引擎访问分享页，但 Google 读不到被挡页面里的'隐藏'标签，于是照样索引了这些 URL。"
- 反方（开发者社区）对"隐私事故"定性的反驳：**"These are not private conversations. Users explicitly set them to public URLs."（这不是私密对话——是用户自己明确设成了公开 URL。）**
- 历史对照，OpenAI 2025 年关闭同类功能时的自评：该分享实验"introduced too many opportunities for folks to accidentally share things they didn't intend to."（"给了人们太多机会不小心分享出本不想公开的东西"。）

## 正反观点

**支持"这是真问题"（担忧方）：**
- 结果是实打实的敏感数据可被检索：API key、钱包细节、公司文件、法律策略——一旦落入公共索引，即使去索引，缓存/转存/他人保存仍可能长期存在。
- 根因是**结构性 UX 陷阱**（robots.txt≠noindex + "分享=生成可被索引的公开网页"），普通用户根本不理解"点了分享 = 可能进 Google"。
- **它是第三次**了。跨 OpenAI、Anthropic 反复复发，证明这不是偶发疏忽，而是"默认公开分享"这个原语的系统性风险。

**质疑"被夸大"（反方）：**
- 这些页面是**用户主动设为公开**的 URL，不是私密对话被攻破——严格说是"用户认知偏差 + 一个可修的索引 bug"，而非数据泄露/入侵。
- Anthropic 文档口径清楚（默认私有、需主动分享、**文件与工具数据被排除**），本次规模**明显小于 2025 年**（4,500+ vs 数百），且**数日内即去索引**。
- 没有出现资金被盗/被实际利用的证据。

**折中判断：** 两边都对，但对**产品与工程团队**而言结论是同一个——**"用户自愿公开"不能成为放任 UX 陷阱的借口。** 当"分享"这个动作的真实后果（可被搜索引擎永久收录、含用户没意识到自己粘进去的密钥）与用户心智模型严重不符时，这就是产品该承担的默认安全责任，而不是甩给用户。

## 深度解读：对行业 + 对"做多 agent 系统的我们"的具体含义

**对行业：** 前沿实验室正全力把产品 agent 化、拼命提速出货（OpenAI Presence 做企业 agent 部署、Anthropic 把 Opus 5 设成 Claude Code 新默认、Codex 要做"everything app"）。但**越是往 agent 冲，"输出/分享/导出/日志"这条低魅力链路的杀伤半径越大**——因为 agent 产物比人类聊天**密度更高地夹带机密**。这次事件是这条软肋的又一次暴露，且大概率不会是最后一次。企业采购方会越来越把"分享/导出是否认证门控、是否可服务端撤销、是否默认 noindex"写进尽调清单。

**对做 agent 系统的我们（落到可执行）：**

1. **把"分享/导出/日志"当成数据治理的第一类攻击面，与"连接器接入"（AgentForger）、"prompt injection"并列。** agent 数据生命周期是 **接入 → 处理 → 输出**，我们此前的防御重心压在前两段；这次事件说明**输出段同样能一键把整段上下文送上公共索引**，必须补齐。

2. **agent 会话/运行记录比人类聊天更"密钥密集"，要按"随时可能变公开"来对待。** agent 的 transcript 里塞满了工具调用参数、环境变量回显、粘贴的日志、API 返回体、它替你处理过的凭据。**一条被分享的 agent 运行页，可能比一段人类聊天泄露多得多。** 因此：**在任何数据可能进入 transcript / 可分享产物 / 日志之前，就对密钥、令牌、钱包助记词、PII 做脱敏/令牌化**——和"不要把 secret 打进日志"是同一条纪律。

3. **给"分享/导出"功能定一份硬清单（别再踩 robots.txt 的坑）：**
   - 不靠 `robots.txt` 防索引；对分享页**允许抓取 + 返回 `X-Robots-Tag: noindex`**，让爬虫能读到"别收录"；
   - URL 用**不可枚举的强随机 token**，别用可猜的自增 ID；
   - 分享链接**默认带过期时间 + 支持服务端一键撤销**（本次的教训正是"撤销前旧链接一直可读"）；
   - 高敏内容/企业场景**默认走认证门（只对指定人可见），而非公开 URL**——**Anthropic 对 Team/Enterprise 直接禁用公开分享，这就是正确默认**，值得照抄；
   - 分享页在服务端**渲染时再脱敏一遍**（把疑似密钥/助记词/邮箱等模式打码），做纵深防御。

4. **"可撤销"要做到端到端。** 生成分享物的同时登记一条可审计、可撤销的记录；撤销要真正让快照、缓存、CDN 副本一起失效，而不只是取消数据库里的一个 flag。

## 接下来盯什么（信号）

- **Anthropic 的正式回应与默认策略变更**：是否会像 OpenAI 2025 年那样**直接砍/收紧公开分享**，或把 `/share` 改成默认 `noindex` + 面向全部层级的认证门控。
- **是否升级为隐私/监管压力**：正值 OpenAI 因 ChatGPT 数据分享面临诉讼、Anthropic 刚了结 15 亿美元版权和解——"数据治理"已从脚注升为资产负债表项，任何一次分享泄密都可能被放大为合规事件。
- **"被分享的 agent 运行页"是否开始进索引**：目前曝光的还是聊天分享；一旦 agent 产物（运行记录/报告/dashboard）的分享物出现在公共索引里，杀伤面将显著扩大——这是我们要主动去 `site:` 自查的方向。
- **同类是否再次复发到第四家/第四次**：若 Gemini/Grok/Copilot 等也中招，则坐实"默认公开分享 + robots.txt 误用"是全行业通病，值得一篇横向复盘。
