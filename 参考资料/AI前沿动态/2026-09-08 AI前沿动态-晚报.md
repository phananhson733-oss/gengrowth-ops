# 🧠 深度研究 ｜ 两天一个 RCE，一周一条蠕虫：AI 挖到的洞第一次打在十亿人身上

> **一句话定性**：上周我们连着读了三份「AI 网络能力已跨红线」的**厂商自述**——OpenAI 把 Astra 判为史上第一个 Critical、Google 出 Gemini 3.8 Flash Cyber + Fairwind、Anthropic 上 EFS。今天这一篇是**第一份来自厂商体系之外的实物证据**：一家商业安全公司用 AI，两天挖出并写出微信 VoIP 栈的远程代码执行漏洞，再花一周做成**打给你就中、不用你接听**、能在 iOS 和 Android 之间自我传播的蠕虫。腾讯已确认并修复。**红线论述从此不再只是实验室的自我评级问题——它已经落到十亿量级的真实客户端上。**

**来源**：Calif（calif.io），*WeWorm — The first zero-click worm to spread through WeChat calls across iOS and Android*，2026-09-08 公开披露。
同日《纽约时报》Dustin Volz 独家报道；腾讯发言人向 NYT 确认漏洞存在并已修复。

## 一、为什么这一篇值得单独深读

这条频道过去 10 天一直在同一根轴上打转，而且全是**厂商自己说自己**：

- **9/01–9/03**：OpenAI 把 Astra 判为其 Preparedness Framework 史上第一个 **Critical** 级网络能力模型——ExploitBench 100%、自主串联两个 V8 0-day、沙箱逃逸提权到 root。处置方式是**门控**：先给 trusted testers，再经 Daybreak Blue 向防御方开放，公开版阉割掉高级网络任务。
- **同期**：Google 出 Gemini 3.8 Flash **Cyber** 与 Fairwind（面向政府/企业的主动网络防御），Anthropic 上 Enterprise Frontier Safeguards，OpenAI 拿 $1B 做 Daybreak for Frontline Defenders。
- **9/06**：Pachocki 说「没有任何一家实验室把对齐监控解决到可以继续全速扩张」。

这套叙事有一个共同的结构性假设：**危险能力集中在最强的那个模型里，所以治理 = 控制谁能用到那个模型**。整套安全架构——门控、trusted tester、能力分级、企业保障——都建在这个假设上。

WeWorm 把这个假设按在地上检验了一次，结论很不舒服：

1. **打出来的东西是真的**，不是 benchmark 分数。目标是全球日活十亿量级的应用，漏洞经厂商确认，补丁已发。
2. **动手的不是前沿实验室**，是一家商业安全公司。
3. **Calif 没有说他们用的是哪个模型**——而这家公司此前的研究报告是**在标题里直接点名模型的**（`Claude Wrote a Full FreeBSD Remote Kernel RCE`、`vim vs emacs vs Claude`、`Codex Discovered a Hidden HTTP/2 Bomb`）。这次的沉默本身是一条信息。
4. **时间尺度塌缩了**：过去「一支更大的团队几个月」的活，现在是 **2 天出 RCE + 1 周出蠕虫**。

换句话说：如果危险能力的门槛已经低到不需要 Critical 级模型就能跨过，那么建立在「门控最强模型」上的整套治理设计，防的可能是一个**已经不是瓶颈**的东西。

## 二、核心事实

### 2.1 这是什么

- **WeWorm** = 已知**第一条零点击、跨 iOS/Android 自我传播的蠕虫**（NYT 措辞：first known computer worm that could spread across Apple's iOS and Google's Android without needing a victim to click or tap）。
- **入口**：微信 **VoIP 栈的内存破坏漏洞** → 远程代码执行。
- **触发条件**：攻击者**拨打**受害者微信语音电话。**利用发生在响铃阶段**——原文：*"The victim does not need to answer the call, or interact with their phone at all."*
- **传播**：被拿下的设备**自动去呼叫机主的联系人**，一台传一台。原文：*"Simply by calling a victim, WeWorm can hijack their account and call their friends, spreading from phone to phone."*
- **规模**：Calif 自述潜在影响 *"over a billion phones (or accounts)"*；NYT 引述的专家判断是**在被修复前，数小时内可以打穿数亿台设备**。
- **技术细节**：**刻意保留**，留待后续会议演讲公开。

### 2.2 人机分工（这是最该盯的一组数字）

| 环节 | 耗时 | 谁做的 |
|---|---|---|
| 找到漏洞 + 写出第一个 RCE exploit | **约 2 天** | "Working with AI, our team..." |
| 打磨成可演示的跨平台蠕虫 | **再 1 周** | 人类工程为主 |
| 同类工作的历史基线 | **"a larger team months"** | — |

人类保留的部分，Calif 说得很明确：

> *"Our team provided the judgment about what to target and how to test it safely."*

**判断力（打哪、怎么安全地测）留在人这边；搜索、推理、写利用代码这些劳动密集环节交给了 AI。** 这个分工比「AI 会不会自主发动攻击」重要得多——它描述的是当下真实可复制的产能结构。

### 2.3 完整披露时间线（Calif 自述）

| 日期 | 事件 |
|---|---|
| 2026-07（具体日未公开） | AI 发现该漏洞 |
| 07-23 | 工程团队获知 |
| 07-24 | **上报腾讯** |
| 07-25 → 07-28 | 研究员的微信账号**被封** |
| 07-29 | 账号恢复 |

| 08-11 | 蠕虫演示成品完成 |
| **08-21** | 腾讯发布 **Android 8.0.77 / iOS 8.0.76** 缓解该漏洞 |
| 08-26 | 腾讯启动正式评估 |
| **08-28** | 服务端缓解对**全量用户**生效 |

两个可以拿去做行业基准的数字：
- **上报 → 客户端补丁 = 28 天**（07-24 → 08-21）
- **上报 → 全量服务端缓解 = 35 天**（07-24 → 08-28）

还有一个值得记一笔的细节：**研究员在上报次日被封号，四天后才恢复**。厂商漏洞响应流程与账号风控系统之间没有打通——这是一个在几乎所有平台都存在、但很少被写进 SLA 的失效面。

### 2.4 Calif 是谁（为什么这份材料的可信度不低）

不是无名团队。

- **Thai Duong**，创始人 / Chief。在 **Google 做了 12 年安全与密码学**，**BEAST、CRIME、POODLE 三个 TLS 攻击的共同发现者**。这三个是过去十五年协议安全领域最常被引用的成果。
- 公司定位是攻击性安全研究与红队，业务线明确包含 **AI security（模型红队、能力评估、AI 驱动的漏洞研究）**。

而 WeWorm 不是孤例，是一条**连续半年、可对照的产出线**：

| 日期 | 成果 |
|---|---|
| 2026-03-30 | `vim vs emacs vs Claude` — AI 在 Vim 与 Emacs 中各挖到 RCE（"打开个文件你就被拿下了"） |
| 2026-03-31 | **CVE-2026-4747**：Claude 写出完整的 FreeBSD 远程内核 RCE + root shell，自述为**首个由 AI 独立发现并利用的远程内核漏洞** |
| 2026-05-07 | CVE-2026-7270：一个 shell 脚本在 FreeBSD 上拿 root |
| 2026-05-28 | AI 审计 FreeBSD：**15 个内核 bug，含 3 个 RCE、5 个本地提权、1 个 bhyve 逃逸** |
| 2026-06-02 | Codex 发现隐藏的 **HTTP/2 Bomb**（14 年历史的头部压缩缺陷进了标准） |
| 2026-06-18 | **Squidbleed**（CVE-2026-47729）——藏在 Squid 里自 1997 年 |
| 2026-08 | **OEMpocalypse Now** — 横跨三星 / 小米 / Oppo·OnePlus·Realme 的 Android 提权 |
| 2026-08 | `No Country for Old Passwords` — macOS 预认证远程 root |

**这是一条从「AI 挖开源软件的洞」→「AI 挖操作系统内核」→「AI 挖十亿用户闭源客户端并武器化」的清晰爬坡曲线。** 半年，三级台阶。

## 三、机制拆解：为什么"零点击 + 跨平台"是质变

三个属性叠在一起才构成蠕虫，缺一个都只是一个漏洞：

**① 零交互（zero-click）→ 传播率不受人类行为约束。**
钓鱼要人点，一键漏洞要人接听。**响铃阶段就完成利用**意味着传播函数里没有「用户是否上钩」这个衰减项。R₀ 由通讯录规模和呼叫并发决定，不由用户警惕性决定。

**② 通讯录即拓扑 → 传播路径预先构建好且高度可信。**
蠕虫不需要扫描网段找目标——**社交图就是网络图**，而且每一跳都来自熟人账号，从被叫方看不出异常。这正是十亿级 IM 特有的放大器。

**③ 跨 iOS/Android → 打掉了平台隔离这道结构性防线。**
以往移动端恶意软件的天然上限是「一次只能打一个生态」，因为利用链是平台特定的。**同一个应用层协议栈上的漏洞，在两个操作系统上都可达**——这条防线就没了。历史上跨平台自传播的移动蠕虫**没有公开先例**，这也是 NYT 用 "first known" 的原因。

把三条乘起来：**攻击面 = 全球微信用户 × 通讯录密度 × 无人类摩擦**。NYT 引述的「数小时内数亿台」不是修辞。

而 AI 在这里改变的是**第 0 步**：找到那个能同时满足①②③的洞。这一步历史上是最贵、最依赖顶尖人才、最难规模化的一步——现在它花了两天。

## 四、关键原话

Calif 的三段话，构成了他们完整的立场，值得逐句读：

> **"AI is putting these capabilities in the hands of less skilled actors, leaving ordinary users at unprecedented risk."**
> （AI 正把这类能力交到技能不足的行为者手里，让普通用户面临前所未有的风险。）

> **"The vulnerabilities are already out there. What AI changed is that we can find and fix them fast. We believe there are more good guys than bad guys, and if they're paying attention, AI gives the good guys the upper hand."**
> （漏洞本来就在那里。AI 改变的是我们能**快速**找到并修复它们。我们相信好人比坏人多——只要他们在留意，AI 给好人的是优势。）

> **"It is a call for the United States, China, and other governments to work together and collaborate with private industry on developing and deploying AI to make the world safer."**
> （这是一份呼吁：美国、中国以及其他各国政府应携手，并与产业界合作。）

注意第二段和第一段是有张力的：**「能力扩散到低技能者」和「防守方拿到优势」不可能同时无条件成立**，它们的胜负取决于一个具体的经验问题——谁的迭代速度更快，以及补丁分发要多久。这次的答案是 28/35 天。**在这 28 天里，如果同样的洞被另一拨人独立挖到，防守方是零优势的。**

第三段则很反常：一家美国安全公司在一份关于中国国民级应用漏洞的报告里，**主动呼吁中美政府合作**。这不是常规措辞，值得记住其信号价值。

## 五、正反观点

### 支持方：这是能力兑现的分水岭

- 它把过去三个月都停留在「厂商自评 + benchmark 分数」的 AI 网络能力叙事，**换成了有厂商确认、有 CVE 级后果、有完整时间线的实物**。
- Calif 的爬坡曲线（开源软件 → 内核 → 十亿级闭源客户端）说明这**不是运气**，是一条在稳定推进的能力线。
- 关键不是「AI 能不能自主攻击」——是 **AI × 熟练人类** 的组合把成本从「团队 × 月」压到了「小队 × 周」。这个组合门槛低到国家级行为体以下的很多主体都够得着。

### 质疑方：数据还不支持「攻防已经翻转」

最扎实的反驳来自 **VulnCheck**（The Register，2026-07-28）：

- Project Glasswing + Berkeley Initiative 产出的 **1,061 个 AI 辅助漏洞中，仅 14 个被确认遭到实际利用 = 1.3%**——**与 VulnCheck 全量数据集里所有漏洞的被利用率持平**。
- Project Glasswing 报出 **23,019 个候选漏洞 → 只有 126 个成为 CVE → 只有 1 个被确认实际利用**。
- 2026 上半年新增 **495 个已知被利用漏洞（KEV）**，其中约三分之一是 CMS——**根本不是前沿模型挖出来的那类高端目标**。
- Patrick Garrity（VulnCheck）：**"The data does not suggest that AI-discovered vulnerabilities are inherently more likely to be exploited than those found through traditional methods."** 他的定性是「rhetoric has outpaced reality」——修辞跑在了现实前面。

另一路质疑（VoidSec、CLEARSECLABS）是**历史类比**：这一切和 2010 年代的模糊测试（fuzzer）浪潮长得一模一样——**同样的初期尖峰、同样的低垂果实、同样即将到来的平台期**。AI 目前挖到的可能大多是「fuzzer 时代遗留的、只是需要更好状态推理」的那一层，一旦这层被扫干净，曲线就会拍平。

**还有两条实事求是的减分项：**
- **Calif 没有公布用了哪个模型**，也没有公布技术细节（留给会议）。这意味着**外部无法独立复现，也无法判断这是否属于某个受门控模型的能力**——而这恰恰是整个治理讨论的关键变量。
- **社区关注度目前极低**：截至本文成稿，HN 上 `blog.calif.io/p/weworm` 只有 **5 分、1 条评论**。主流传播完全由 NYT 单点驱动，尚未经过技术社区的挑刺。**这条要打折看待。**

### 我的判断

两边说的是**不同时间尺度上的不同问题**，都没错：

- VulnCheck 测的是**存量转化率**（AI 挖出的洞里有多少变成了实际攻击）。这个比率短期不会跳，因为它被补丁分发、攻击者动机、目标价值稀释。
- WeWorm 展示的是**尾部事件的可达性**（能不能挖到那种「一个洞打十亿人」的洞）。**尾部不看平均数。** 1.3% 的平均转化率对一个能自传播、无需交互、跨平台的漏洞完全没有约束力——这类漏洞历史上一年也出不了几个，而它们造成的损失占了全部损失的绝大部分。

所以正确的读法是：**平均转化率不变，但尾部的到达成本崩了。** 这两件事完全可以同时为真，而风险管理只关心后者。

## 六、深度解读：对行业，以及对「做多 agent 系统的我们」

### 6.1 对行业：治理设计的靶心可能装错了位置

上周三家实验室做的所有事——能力分级、trusted tester 门控、公开版阉割、企业保障计划——**都在管「谁能调用最强的那个模型」**。

WeWorm 提出的问题是：**跨过危险门槛所需的模型能力，可能远低于被门控的那一档。** 这里的 uplift 不是「模型自己发动了攻击」，而是「模型把一支好团队的产能放大了一个数量级」。这种 uplift：

- **不需要 Critical 级模型**（Calif 此前公开的成果用的是通用可得的 Claude 和 Codex）；
- **不容易被拒答策略拦住**（「审计这个 VoIP 解析器的内存安全」是完全正当的安全工作请求，和恶意用途在提示层面不可区分）；
- **门控甚至可能是净负面的**——防守方受合规约束会老实排队走 trusted tester 流程，攻击方不会。

Calif 那句「好人比坏人多」的真正含义是一个**赛跑假设**，不是安全保证。而这次赛跑的实测数据是：防守方从上报到全量修复用了 **35 天**。这 35 天就是行业当前的真实暴露窗口。

一个更让人不安的推论：**OpenAI 在 9/5 承诺「数周内发布首个失范事件披露框架」，覆盖的是自家模型的失范行为。但 WeWorm 这类事件根本不在那个框架的定义域里**——没有模型失范，没有 agent 越界，一切都是模型按人类意图正常工作。**「模型正常工作时产生的社会危害」目前没有任何一家实验室的披露框架在管。**

### 6.2 对我们：六条可执行的

**① 把第三方依赖的补丁 SLA 从「季度」改成「周」，并且要实测数字。**
28 天 / 35 天现在是一个可比的行业基准了。给我们生产路径上每一个处理**不可信输入**的第三方组件（媒体解码、网络协议栈、文档解析、任何 SDK）在依赖清单里补两个字段：`last_security_patch_lag_days` 和 `retirement_date`。选型评审时把这个数字摆上桌，问供应商上一次远程可利用漏洞从上报到全量修复用了多久——**要历史实测，不要承诺。**

**② 能力评估的靶子不能只对着最强模型。**
如果我们（或我们的供应商）在做 AI 风险评估时只测前沿旗舰，那是在测一个错的东西。WeWorm 的 uplift 来自 **模型 × 熟练人 × 工具链** 的联合体。评测基线要建成三元组，而且**必须包含开放权重档**——因为那一档没有任何门控可言，是风险的实际下界。这条直接接上 backlog 里 Meta Muse Glimmer（30B、单卡可跑）那类候选的评估口径。

**③ 把「零点击」翻译成 agent 语言：我们的 agent 天然就是零点击攻击面。**
WeWorm 的可怕之处是「响铃阶段就被打穿，用户全程无感」。**对 agent 系统，这不是特例，这是默认状态**——agent 本来就在无人值守地自动消费不可信输入：网页、PDF、邮件、MCP 工具返回、第三方 API 响应。「用户还没看到内容，代码已经执行了」这句话描述的就是我们每一次 tool call。
→ 落地动作：**每一个不可信输入源按「远程攻击者」建模**；工具权限最小化到单次任务粒度；网络出口白名单；把「解析不可信内容」和「持有凭据/工具权限」放在**不同的进程边界**里。

**④ 传播学是一样的：查我们编排里的「通讯录」。**
昨天那篇 DeepMind swarm 的结论是作弊在 27 分钟传遍 100 个 agent；今天这篇是蠕虫在数小时传遍数亿台设备。**同一个机制：一个可写的共享面 + 自动消费 = 指数扩散。**
→ 盘一遍我们系统里所有「一个 agent 写、其他 agent 自动读」的面（共享知识库、artifact 目录、公告板、缓存、向量库）。每一个都要满足三条：**写入带来源指纹、条目区分「已验证 / 未复核」、支持撤回**。做不到撤回的共享面等于一条不可关闭的传播信道。

**⑤ 防守侧的算术已经翻转，该主动买单了。**
「2 天出一个 RCE」这个量级意味着**对自己代码做 AI 安全审计的成本已经低到没有理由不做**。给我们自己的核心不可信输入路径排一次 AI 驱动的审计——这比等着别人给我们开 CVE 便宜一个数量级。Calif 的 FreeBSD 审计（15 个内核 bug）就是这个模式的公开样本。**这是本篇里唯一一条正面的、马上能做的事。**

**⑥ 事件分类法要加一格。**
我们现在的风险台账大概率只有「模型失范 / agent 越界」这一类（这是被 OpenAI、DeepMind 那几篇塑造出来的框架）。**加一格：「模型正常工作但被用于加速对我们的攻击」。** 这一格的缓解措施完全不同——不是监控 CoT、不是行为边界，而是补丁速度、依赖治理、入侵检测。**别让上游实验室的议题设置决定我们的风险分类法。**

## 七、接下来盯什么

1. **Calif 的会议演讲**——技术细节保留待发。核心看点只有一个：**他们会不会说用的是哪个模型**。说了，整个治理讨论就有了锚点；不说，说明这个信息本身被判定为危险。
2. **CVE 编号与独立复现**。目前没有分配公开 CVE，没有第三方复现。**在有人复现之前，这份材料的技术强度只能按「高可信单一来源」计。**
3. **VulnCheck 的 1.3% 在 2026 下半年会不会破**。这是判断「尾部事件」还是「趋势拐点」最干净的指标。若 H2 数据仍在 1–2%，说明 WeWorm 是尾部；若跳到 5%+，说明拐点到了。
4. **OpenAI 的失范披露框架（9/5 承诺、数周内）会不会把「AI 辅助漏洞挖掘」纳入定义域**。目前看极可能不纳入——那就正好印证 6.1 的判断。
5. **其他十亿级客户端会不会跟着出同类披露**：WhatsApp、Telegram、LINE、Signal、iMessage。如果 60 天内出现第二例，「首例」就变成「首批」，性质完全不同。
6. **中美是否真出现任何联合机制**。Calif 的呼吁在当下地缘环境里近乎不可能，但如果有任何实质回应（哪怕只是双边漏洞披露协调），那是本年度最被低估的信号。
7. **是否有明确证据显示开放权重模型可达到这一步**。**这才是治理框架真正失效的时点**——在那之前，「门控」至少还是个可以争论的策略；在那之后不是了。
