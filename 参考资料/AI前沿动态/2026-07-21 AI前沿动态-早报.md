## 一、为什么这一篇值得单独深读

过去两周本栏目已密集覆盖「中国开源前沿」的**能力轴**：Kimi K3「首个前沿级开源大模型」（7/17）、「第二次 DeepSeek 冲击」的市场重估（7/18）、WAIC 上治理裂成两大阵营（7/17）、乃至北京酝酿给中国开源模型上**出口管制**（7/12）。这些都在讲「模型有多强、谁来发」。

7/19–7/20 这条不一样，它是那条能力曲线**第一次在美国这一侧结出的政策果实**，而且是一条**全新的轴**：

- 7/12 那条讲的是**北京**考虑管住中国开源模型的**出口**（发布前门控 / 出海限制）；
- 这条讲的是**华盛顿**考虑管住美国公司对中国开源模型的**进口与使用**——即一个**镜像出口管制的「域内使用禁令」**。

两个 AI 超级大国，在同一周、从**两端**同时对「开源权重」这件此前近乎无国界的公共品动手。这才是真正的格局信号：开源权重的「自由流通」假设正在被两边一起收紧。而它之所以值得深挖，是因为这次美国这边**撞上了三堵它自己也搬不动的墙**——宪法、物理（可执行性）、和政治（白宫内部分裂）——这决定了它最终会以什么形态落地，直接改变我们能建在什么模型上。

## 二、核心事实（分层）

### A. 触发的能力压力（为什么现在动手）

- **Kimi K3**（Moonshot，7/16）：2.8 万亿参数开源 MoE，1M 上下文，被本栏目 7/17 定性为「首个前沿级开源大模型」，完整权重放出排在 **7/27**。这是直接导火索。
- **Qwen 3.8 Max**（阿里，7/19 上海 WAIC 预览）：**2.4 万亿参数** 稀疏 MoE 多模态（文本 / 图像 / 视频 / 文档），1M 上下文，阿里内部评测自称**「仅次于 Fable 5」**；预览期以「标准价 10%」在 Token Plan / Qoder 上线。**关键保留**：无 benchmark 表、无 model card、无 license、未披露激活参数量，第三方（Artificial Analysis / LMArena）尚未评分；唯一独立盲测（Trilogy StackPerf）为 **80 分 vs Kimi K3 的 83 分**，且开源权重只是「soon」的口头承诺。→ 能力叙事很响，但**硬证据偏软**，本轮不以它单独立题，只作触发背景。
- **采用面已深**：a16z 研究称全球约 **80% 的开发者**在用中国开源模型；连 Airbnb CEO 都公开夸 Qwen「很好、又快又便宜」。这正是政策方紧张的根源——**不是怕它不好，是怕它太好、已经长进了美国的技术栈里**。

### B. 白宫正在权衡的「杠杆菜单」（据 Axios + 跟进报道）

从软到硬，据报道被摆上桌的至少有六种：

1. **威胁咨文（最软）**：NSA 与白宫国家网络总监办公室（ONCD）发布官方安全威胁通告，「劝退」美国机构使用中国 AI。
2. **联邦采购限制**：禁止/限制政府及承包商在采购中使用中国开源模型。
3. **公开施压 + 供应链草案**：商务部据报已在内部**流转草案**，援引**供应链安全权限**针对中国开源模型。
4. **行政令（EO）—— 担责版**：要求美国公司只有在能「担保安全并对数据泄露承担法律责任」的前提下才可使用中国模型。**这一版最阴**——它不需要「封」，只要把责任压到使用方头上，就能让中国权重对任何有合规部门的企业变成**法律毒药**（详见第三节）。
5. **实体清单（Entity List）**：商务部考虑把中国 AI 实验室加入出口管制实体清单，使美国公司「无许可证不得使用」其模型——最接近「硬禁」的一档。
6. **立法轨**：三部法案争取塞进参议院 NDAA——**AI Overwatch Act**、**MATCH Act**、**Chip Security Act**。

> 注意：这些是**同时在评估的备选**，不是已定方案；截至 7/20 **没有任何 EO 文本或最终规则公开**。这仍是「政策叙事 + 内部草案」阶段，硬工件尚未落地——这一点对下面的判断很重要。

## 三、机制拆解：三堵墙决定它最终长什么样

### 墙一 · 宪法：权重可能是「受保护的言论」

多篇报道点出同一个致命难题：**模型权重级的禁令「一头撞上第一修正案」**——在美国判例传统里，源代码长期被视为受保护的表达，模型权重（本质是一串数字/代码）大概率享有同等保护。这意味着「禁止发布/持有中国权重」这种最直接的做法在宪法上极其脆弱，很可能一诉即倒。**这正是白宫为什么绕开「直接禁」、转向「担责 / 采购 / 实体清单」等间接杠杆的根本原因**——它们管的是「商业行为/交易」，而非「表达」本身，宪法阻力小得多。

### 墙二 · 物理：开源权重不可召回

Tom's Hardware 的标题就是结论：**「可下载的开源权重让彻底封禁几乎无法执行」**。一句业内共识概括得更狠——**「模型一旦上了互联网，它就已经跑了」**。Kimi K3 的权重 7/27 全量放出后，任何禁令都无法把已经被全球下载、镜像、微调的权重收回。所以「域内禁令」现实里**只能在企业/采购/责任这一层生效**（谁敢在生产里用、谁来担责），而对个人开发者本地跑一份下载好的权重几乎无解。**换句话说：能被「封」的从来不是权重本身，而是「在美国合规地商用它」的资格。**

### 墙三 · 政治：白宫内部「开源派 vs 闭源派」已公开互撕

这不是行政部门对外的统一行动，而是一场**内战**。白宫 AI 与加密事务顾问 **David Sacks** 周日（7/19）在 X 上直接开火，反对派系正是与头部闭源实验室观点一致的一方（他点名回应了在 OpenAI 任职、对中国开源表达担忧的 **Dean Ball**）。Sacks 的核心指控是：**这场「安全」叙事，本质是闭源双寡头想借政府之手清掉开源竞争对手**。这把一条「国安 vs 中国」的对外故事，撕成了一条「开源 vs 闭源、竞争 vs 垄断」的对内路线斗争——而 Sacks 站在开源一侧，且他是**现任白宫顾问**，分量不轻。

## 五、正反观点

**支持限制（安全鹰派 / 与闭源实验室同调的一方）**
- 国安逻辑：中国以开源为「特洛伊木马」快速渗透美国技术栈，一旦 80% 开发者的底座依赖对手模型，形成**战略依赖**与供应链风险；权重可能藏**后门/漏洞**（讽刺的是，本栏目 7/11 刚覆盖过针对 *Claude Code* 的「中国检测」隐写指纹后门指控——后门恐惧其实是双向的）。
- 对等逻辑：既然美国用出口管制卡中国的芯片，也应有工具管住「反向」的模型进口，避免单边开放。

**质疑/反对（开源派 / Sacks / a16z 一侧）**
- **反垄断视角**：这是闭源双寡头的**监管俘获**——用「安全」话术把开源竞争者赶出市场，最终固化 OpenAI/Anthropic 的定价权与格局，伤的是创业者与开发者。
- **无效且有害**：权重不可召回，「禁」不掉，只会把美国开发者推向更隐蔽的使用方式，同时逼企业放弃「又快又便宜」的选项、削弱美国自身竞争力。
- **宪法脆弱**：权重级禁令大概率违宪，硬推只会招致诉讼、旷日持久、且很可能败诉。

## 六、深度解读：对行业 + 对「做多 agent 系统的我们」的具体含义

**对行业格局**
1. **「开源权重」正被两端同时收紧**：北京侧（7/12 出口管制之议）+ 华盛顿侧（本条进口/使用之议）。过去「谁都能下、谁都能用」的默认正在瓦解，**模型的「国籍」第一次开始决定它能不能进某个辖区的生产系统**。
2. **最可能落地的不是「硬禁」，而是「担责/采购」这类软刀子**——因为宪法与可执行性挡死了硬路。但软刀子对**企业级采用**的杀伤力可能比硬禁更大：不需要一纸禁令，只要「用中国权重＝自担数据泄露法律责任」写进 EO 或采购条款，任何有法务的公司都会自动远离。
3. **这是一场路线斗争的公开化**：Sacks vs 闭源派的互撕，意味着**最终形态高度不确定**——可能收窄成「仅联邦采购」（影响面小），也可能扩成「担责 EO」（影响面大）。押注任一端都危险，**要按区间做预案**。

**对做 agent 的我们（可执行判断）**
- **把模型层彻底抽象到路由后面**：Kimi K3 / Qwen / DeepSeek / GLM 与美系闭源模型之间，必须能按**辖区 / 客户类型**热切换。别让任何单一中国开源权重焊死在关键路径上——这不再是成本优化，而是**政策尾部风险的对冲**。
- **区分产品线的暴露度**：面向**美国企业 / 政府 / 受监管行业**的产品，现在起就不该把中国开源权重放进默认栈（担责/采购杠杆一旦落地，这类客户最先合规收紧）；面向**非美、非监管、成本敏感**的负载，中国开源权重的性价比（10% 定价、80% 开发者采用）仍极具吸引力，**套利真实存在，但从今天起带政策尾巴**。
- **风险点在「合规商用资格」，不在「能不能跑」**：你本地已下载的权重几乎不可能被追回；真正会被卡的是**企业采购、责任归属、来源证明（provenance attestation）**。提前给你的模型供应链留「可出具来源/可切换」的能力，比囤权重更重要。
- **盯准杠杆形态再动手**：在 EO 文本 / 实体清单 / NDAA 结果明朗前，不要为了「怕被禁」就仓促迁走已在中国权重上跑通的非美业务——过度反应本身有成本。建立「按信号触发」的迁移预案，而不是「一刀切」。
