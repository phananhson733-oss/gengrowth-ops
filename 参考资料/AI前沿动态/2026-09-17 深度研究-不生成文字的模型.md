# 🧠 深度研究 ｜ 不生成文字的模型：TypeSafe 用 Jev 把「agent 里 90% 的调用」重新定价

> **一句话定性**：一家 ChatGPT 共同发明人创办的公司说——你的 agent 里绝大多数模型调用根本不需要"会说话"，于是他们造了一个**只输出决策、不输出字符串**的模型，把这类调用的成本和延迟各砍两个数量级；HN 用 1831 分把它顶上全站第一，又用 482 条评论把它的"新模型类别"叙事拆了个七零八落。**结论不在"它是不是新东西"，而在它把一个我们一直含糊处理的架构问题摆到了台面上：agent 系统里的"判断"和"表达"，本来就不该由同一个模型、同一种解码方式承担。**

## 一、为什么这一篇值得单独深读

过去两年我们所有人都在做同一件事的变体：**拿一个为"取悦人类读者"而优化的模型，去做一件"程序要读"的事**。路由、分类、打分、工具选择、守卫判定、结果评审——这些调用的输出最终都会被一个 `if` 语句消费掉，可我们却让模型先写一段思维链、再吐一个 JSON、再由我们 parse、校验、失败重试。

TypeSafe 的论点很刺人：这不是优化问题，是**类别错配**。创始人 Diogo Almeida（前 OpenAI，参与 RLHF、InstructGPT、ChatGPT、GPT-4）的原话是：

> "We've been optimizing for humans, and we're superhuman at pleasing humans."
> （我们一直在为人类优化，而我们在讨好人类这件事上已经是超人了。）

值得读的不是产品，是它**顺手给出的一份 agent 成本结构体检报告**：如果你的工作流里 90% 的调用是 System One（快、直觉、可枚举）而只有 10% 是 System Two（慢、推理、开放生成），那你现在为前者支付的是后者的价格和延迟。这个判断即使 Jev 本身最后失败了，也依然成立。

## 二、核心事实（按可信度分层）

**A. 公司与融资（一手/多源确认）**
- 2026-09-15 出隐身，**$40M 种子轮**，**DCVC 领投**；Forbes 援引消息人士称估值约 **$2 亿**。
- 创始人：**Diogo Almeida**（CEO，前 OpenAI RLHF/InstructGPT/ChatGPT/GPT-4）、**Erik Gafni**、**Sasha Sheng**。公司成立于 2024 年。
- 模型名 **Jev** 取自 **Jevons 悖论**（效率提升反而抬高总消耗）——名字本身就是他们的商业假设：把单次决策做到近乎免费，决策总量会爆炸式增长。

**B. 机制（官方口径，架构细节未公开）**
- **不做自回归解码**。给定一个 schema，Jev 在**单次并行前向**里对 schema 内**每一个可能答案**打分，而不是逐 token 采样。
- 只有三种输出原语：**Choice**（从给定选项里选）、**Score**（按有序档位打分）、布尔判断。**没有自由文本生成能力**。
- 训练方法称为 **RLCD（Reinforcement Learning for Calibrated Decisions）**，官方说法是优化"认识论上诚实的概率"而非人类偏好——即每个答案都带**校准过的置信度**。
- CEO 在 HN 上对架构的回应：**"architecture is close to the chest for now, but we have talked about writing a paper"**（架构暂时保密，但我们讨论过写论文）。

**C. 性能数字（**全部为厂商自评**，无第三方复现）**
- 延迟：端到端 **70–500ms**；对比基线 LLM 的 **3–329 秒**。
- 定价：输入 **$0.042/MTok**，**输出 token 不计费**。
- 工作流级聚合：**快 193.6 倍 / 便宜 444.6 倍**（单次调用 **0.114s vs 8.566s**、**$0.000081 vs $0.013880**）。
- 千次工作流成本：Jev **$0.39** vs GPT-5.6 Luna **$3.31** vs Claude Haiku 4.5 **$19.49**。
- 并行度实证（Every 的独立测试）：**777 个判断在 <0.7 秒内完成**。

**D. 准确率——这才是真正的那一栏（厂商自评，且口径混乱）**
TypeSafe 自建 4 个工作流评测：安全事件响应、agent trace 可观测性、发票处理、客服。厂商 dashboard 聚合口径：

| 模型 | 聚合一致率 |
|---|---|
| **Jev** | **67.8%** |
| Claude Opus 5 | 73.1% |
| GPT-6 Sol | 74.1% |

分任务差距更刺眼：**发票处理 61.8% vs 79.1%**（差 17.3 个百分点）、安全事件 61.7% vs 66.2%、agent trace 71.6% vs 76.6%、客服 76.0% vs 78.3%。

⚠️ **两处必须标注的 caveat**：
1. **所谓"准确率"其实是"与参考答案的一致率"，而参考答案 = GPT-6 Astra 与 Fable 5.1 预测的平均值。**这不是独立验证的正确性，是"与 OpenAI/Anthropic 的模型有多像"。分母本身偏向对手。
2. 二手转述中流传着**另一套数字**（Jev 76.0% / Sol 79.1% / Opus 5 78.4% / Haiku 4.5 58.8%）。两套口径不一致，且都源自厂商。**在有第三方复现之前，任何一套都不该进你的技术选型文档。**

**E. 现实边界（官方承认）**
- 上下文 **32K**；**仅文本 + JSON**，无图像；**早期访问 waitlist 制**；**零具名客户、零营收披露**。
- 关于定价可持续性，TypeSafe 自己说：**"We can't prove it isn't subsidized; we'll need the long-term to prove sustainability."**（我们无法证明这个价格没有补贴，需要长期来证明可持续性。）

## 三、机制拆解：它到底绕开了什么

自回归 LLM 做一次分类，实际付出的代价是：

```
思维链 tokens（可能数百）→ 逐 token 串行解码 → JSON 格式化 tokens
→ 你的 parse → schema 校验 → 失败则重试（整条重来）
```

延迟 ∝ 输出长度 × 串行步数；成本 ∝ 输出 token 数（而输出 token 通常是输入价的 ~5 倍）；**而这一整条链路的产物，是一个枚举值**。

Jev 的做法是把"选哪个"从生成问题还原成**评分问题**：候选集在 schema 里已经是有限且已知的，那就在一次前向里给每个候选算一个分，取 argmax，附带概率。于是：
- 延迟与候选数量**解耦**（Wikiracing demo 里高达 255 个候选仍是单次调用）；
- 输出 token 数恒等于 0，所以"输出免费"不是促销，是**架构后果**；
- schema 合规性不是"校验通过"，而是**构造上不可能违反**——parse-validate-retry 这条税整条消失。

**但这也精确划定了它的天花板**：HN 用户 jacobgold 一针见血——"能输出图灵完备语言代码的生成式模型可以做计算机能做的任何事；Jev 只能生成结构化输出。" 速度对比的前提是**任务本身必须是可枚举的**。一旦决策空间需要被"构造"出来而非"选择"出来，Jev 连参赛资格都没有。

## 四、正反观点

### 支持方
- **HN 用户 lubujackson**：**"this is exactly how I am using LLMs in production, to narrowly make choices and return structured data."**（我在生产里就是这么用 LLM 的——窄窄地做选择、返回结构化数据。）这句话的分量在于：它承认了**大量生产流量本来就是 System One 形状**，只是一直在用错工具。
- **DCVC 的 Hardiman**：TypeSafe 解决的是"AI 最大的剩余挑战之一"——让模型能被**可靠地嵌入软件并规模化**。
- 独立测试有亮点：Near Here 的事件校验任务上 Jev **96%（48/50）**，高于两个竞品的 **84% / 86%**。说明在**决策空间干净**的窄任务上，它可能不只是便宜，还更准。

### 质疑方（更扎实，且部分来自创始人自己）
1. **"新模型类别"叙事被自己拆了**。当有评论者说"这基本上就是个 zero-shot classifier"时，Almeida 回复：**"exactly right!"** 对于一个以"全新模型类别"命名发布的产品，这是个相当致命的让步。
2. **先例一夜之间被列全**。工程师在几小时内把 Jev 映射到：encoder 分类器（BERT/DeBERTa）、GLiNER 类 span 模型、带 logit 置信度的 grammar/constrained decoding、text diffusion、conformal prediction、DSPy typed signatures。HN 用户 ramoz 直接点名 **GLiClass** 作为性能可比的开源零样本替代。当晚甚至出现一个 Hugging Face 复现，声称**根本不需要新训练**（该复现本身也无人验证）。
3. **"不会幻觉"是偷换概念**。HN 用户 8note：**"if it puts a high confidence value on a wrong answer, that's still hallucinating, no?"** 更关键的是厂商脚注自认 **0% 这个数字"不是实证得来的"**，Almeida 本人也承认 **"It's also possible to be confidently wrong."** 类型安全 ≠ 事实正确，这两件事被有意合并成了一个卖点。
4. **RLCD 没有任何可检验的证据**：无论文、无 reliability curve、无 ECE 数字、无消融实验；文档还承认校准是 **group-level 而非 per-answer** 的——也就是说，**你不能信任单次调用返回的那个置信度**，而单次置信度恰恰是你在 agent 里最想用来做 fallback 阈值的东西。
5. **Demo 被质疑放水**。HN 用户 bigglebear 指出 Doom demo 里"模型拿到的结构化状态并不受障碍物约束"，且**喂的是预处理状态而非原始像素**——把感知这个真正难的部分挪到了模型外面。
6. **"frontier model"的自我标榜**。WhitneyLand：**"It's nothing like a traditional LLM and so should not be compared to one."**

## 五、深度解读：对行业 + 对「做多 agent 系统的我们」

### 对行业
**推理市场正在沿着"调用形状"而非"模型大小"重新分层。**过去两年的分层逻辑是 Opus/Sonnet/Haiku 这种**同构缩放**——都是自回归 LLM，只是参数和价格不同。Jev 提出的是**异构分层**：把"判断"从"表达"里切出去，交给一个解码方式根本不同的模型。

这件事的真正含义不在 TypeSafe 能不能成（$2 亿估值、零客户、waitlist、32K 上下文，商业上极其早期），而在于：**如果这个切分是对的，那么大厂的 Haiku/Flash/Luna 这一档正在被从下方掏空。**注意那张表里最难看的一行是 Claude Haiku 4.5：**58.8% 准确率、$0.0047/call**——它在"便宜档"里既不够准也不够便宜。廉价档位的护城河从来不是模型能力，是**没人愿意为路由调用单独接一个供应商**。Jev 在赌这个惰性正在瓦解。

反过来看，**如果大厂响应，最省力的动作不是造新模型，而是给现有 API 加一个"decision-only 端点"**——输入 schema、只返回 argmax + logprob、输出不计费。这在技术上对他们几乎是免费的（constrained decoding 已经在跑），却能直接把 Jev 的定价优势削掉大半。**这是接下来 1–2 个季度最值得盯的一步棋。**

### 对我们（做多 agent 系统）
把它当**架构镜子**用，不是当供应商用。可执行的判断有四条：

**1. 先做一次「调用形状普查」，这件事今天就能做且不依赖 Jev。**
把过去 30 天的模型调用按输出被如何消费分桶：(a) 进 `if`/`switch` 的枚举值；(b) 进数值比较的分数；(c) 真正被人或下游模型阅读的文本。**如果 (a)+(b) 的调用数占比超过 60%，你的推理账单结构就是错的**——你在用 System Two 的单价买 System One 的东西。这个数字我们自己应该心里有数，目前没有。

**2. 这类调用的优化不必等 Jev。**
先例清单本身就是行动清单：对固定标签集的路由/分类，一个微调的 encoder（DeBERTa 级）在自有数据上往往比任何通用 LLM 又快又准又便宜，且**可以自己跑**；对需要零样本灵活性的，GLiClass 这类开源方案已经可用；对必须用 LLM 的，constrained decoding + logprob 已经能拿到"schema 保证 + 置信度"这两样东西的 80%。**Jev 的真正贡献是让我们意识到该做这件事，而不是它是唯一能做这件事的东西。**

**3. 但不要照抄它的置信度用法——这是最容易踩的坑。**
我们在 agent 里最想要的模式是：`if confidence < θ: 升级到大模型`。而 Jev 文档承认校准是 **group-level 而非 per-answer** 的。**group-level 校准意味着"这一批答案里约 70% 是对的"，不意味着"这一个标了 0.7 的答案有 70% 概率对"。**拿群体校准当个体阈值用，会系统性地在最需要升级的长尾上不升级。任何声称给置信度的模型（包括我们自己从 logprob 里算的），上线前都必须在**自有数据**上画一条 reliability curve、算一个 ECE，没有这条曲线就不要接阈值逻辑。

**4. 分层要按"决策空间是否可枚举"切，不要按"任务难不难"切。**
这是 Jev 给出的最有价值的切分准则。我们过去用"简单任务给小模型、复杂任务给大模型"，这个准则是错的——它导致我们在"简单但开放"的任务上用小模型翻车，在"难但可枚举"的任务上用大模型烧钱。正确的第一道分叉是：**候选集是不是有限且已知的？** 是 → 评分问题，用分类器/约束解码，延迟与候选数解耦；否 → 生成问题，只能用 LLM。**我们的 router 目前是按前一种准则写的，这是一个明确的重构点。**

**一条反向警告**：Jevons 悖论是他们自己的品牌隐喻，也该是我们的风险提示。**当单次判断降到近乎免费时，真正的成本会从推理费转移到"判断太多、没人审计"。**一个每秒发出 10 次结构化判断的 agent（Doom demo 的 ~$7/小时），产生的是每小时 3.6 万条无人阅读的决策日志。**便宜的判断必须配更贵的可观测性**，否则省下的钱会以"不知道系统为什么这么做"的形式加倍还回来。

## 六、接下来盯什么（信号）

1. **第三方复现**：有没有独立团队在**非 TypeSafe 自建**的公开基准上跑出这组数字。在此之前 67.8% 和 76.0% 这两套数字都只是市场材料。
2. **那篇论文**：Almeida 说"讨论过写"。RLCD 有没有 reliability curve 和 ECE，是判断这家公司是研究型还是叙事型的分水岭。
3. **大厂的 decision-only 端点**：OpenAI/Anthropic/Google 任何一家推出"只返回结构化决策、输出不计费"的 API 档位 —— 这会同时验证切分正确、并宣告独立供应商的窗口关闭。
4. **首批具名客户与留存**：waitlist 转化成有名有姓的生产案例需要多久；以及第一个公开的"我们迁回去了"的复盘。
5. **定价可持续性**：$0.042/MTok 加输出免费，撑过第一个真实负载高峰不涨价，才算数。
6. **能力边界扩张**：32K 上下文 + 无图像是硬约束。若加入视觉，Doom demo 的"喂预处理状态"这个批评才算被回应。
