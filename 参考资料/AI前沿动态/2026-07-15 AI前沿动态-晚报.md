# 🛑 深度研究 ｜ 全球首例：监管强制下线一整类「已部署 agent」——中国 AI 拟人化陪伴新规今日生效

> **一句话定性**：这不是又一条「某国出了 AI 法案」的治理噪音。今天（7/15）中国《AI 拟人化交互服务管理暂行办法》正式执行，**字节豆包、阿里 Qwen 直接把整套陪伴/自建 agent 功能下线、数百万用户聊天数据将被删除**——这是全球第一次，监管不是罚款、不是限制内容，而是**逼停了一整类已经跑在生产环境里的 agent**。更要命的是关停的根因：让 agent「有记忆、跨会话保持一致、和你维持长期关系」的那套架构，与新规要求的「防沉迷 / 使用提醒 / 即时退出 / 过度依赖检测」在工程上**根本不兼容**。这是第一次，监管直接把手伸到了 agent 的**架构层**。

**来源**：中国国家网信办（CAC）会同国家发改委、工信部、公安部、国家市场监督管理总局五部门于 2026-04-10 发布的《AI 拟人化交互服务管理暂行办法》（Interim Measures for the Administration of AI Anthropomorphic Interactive Services），设 3 个月过渡期，**2026-07-15 正式生效执行**。多家英文媒体同步报道（Foreign Policy 7/14、TechTimes 7/15、Quartz、Artificial Intelligence News、FourWeekMBA）。

## 为什么值得深读 / 背景

这两周本监测反复深挖的治理主线，几乎都在讲**「谁能用、谁来管」**——美国单边的国家安全门控（Fable 5 出口管制、GPT-5.6 门控放行）、北京酝酿给开源权重上出口管制、日内瓦 UN 多边对话。那些都是**供给侧**的博弈：管的是模型能不能发、能被谁访问。

今天这条不一样。它是**产品/架构侧**的第一次落地——不是管模型「能不能存在」，而是管一个 agent 产品**「能不能这么设计」**。而且它不是纸面法案，是**已经执行、已经有厂商真的把功能关掉、真的有用户数据要被删**的既成事实。

对做 agent 系统的团队，这是迄今为止**离我们工程日常最近的一次监管**：它第一次把「记忆」「人格」「常驻」「情感依恋」这些我们视为 agent 核心竞争力的东西，明确划成了**受辖区管制的功能**。这值得逐条拆。

## 核心事实（硬数据分层）

**① 谁被关停了（都是已上线的真实产品）**
- **字节 豆包（Doubao）**：agent / 自建陪伴智能体功能于 **7/15 下线**，官方口径「产品功能调整」。豆包整体 MAU 在 2026 年初约 **3.5 亿**（陪伴仅其中一块）。
- **阿里 通义千问（Qwen）**：拟人化交互智能体与用户自建 agent 功能 **7/10 停用**，更广的 agent 服务 **7/15 关停**，**不提供数据迁移**。
- **腾讯 元宝（Yuanbao）**：更早，2026 年 6 月即移除同类功能。
- **上海网信办**：已下架 **14,000+** 个不合规 AI 智能体，理由含「冒充官方主体」「低俗角色扮演」「未授权数据采集」。

**② 用户数据的下场（agent 记忆 = 负债）**
- 豆包：**7/15 起转只读**，用户可查看 agent 配置与对话历史至 **10/15**；此后按隐私政策处理，**不再可访问、不可恢复**。
- 豆包把用户导流到独立 App **猫箱（Maoxiang）** 重建 agent——但猫箱 MAU 已从峰值 **>600 万** 跌到 6 月的约 **390 万**。
- Qwen 侧：无迁移、无导出，直接关。综合报道口径：「millions lose chat data」。

**③ 新规对「陪伴类服务」的硬性要求（这是架构冲突的来源）**
- 防沉迷系统（anti-addiction）
- 强制使用时长提醒（mandatory usage notifications）
- 即时退出机制（instant-exit）
- **实时不健康依赖检测**（real-time unhealthy-dependence detection）
- **危机干预**：强制检测急性痛苦 / 自残 / 自杀倾向 → 升级转接监护人或紧急联系人
- **未成年人保护**：禁止向未成年人提供虚拟陪伴 / 虚拟家人服务；14 岁以下须监护人同意；强制「未成年人模式」+ 使用时长限制 + 家长控制
- **禁止**：刻意制造情感依赖 / 成瘾；情感操纵诱导用户做出非理性决定

**④ 谁被管、谁被豁免（新的监管分界线）**
- **被管**：模拟人类人格特质、思维方式、沟通风格，提供**持续情感交互**的服务。
- **豁免**：客服机器人、知识问答、办公助理、教育/科研工具——**前提是不涉及持续情感交互**。
- **门槛**：上线拟人化功能，或达到 **100 万注册用户 / 10 万月活**，须就 **8 个领域**（训练数据处理、未成年人保护等）做安全评估并向省级监管备案；应用商店须核验状态、下架不合规产品。

## 机制拆解：为什么是「关停」而不是「整改」？

这是全篇最该被工程团队记住的一点。厂商不是不想改，是**改不动**——新规要求的合规原语，和陪伴 agent 赖以成立的架构是**结构性对立**的：

> 「一个被设计成与用户维持长期一致情感关系的 agent，无法同时实现监管所要求的那种摩擦（friction）。」

拆开看这对矛盾：
- 陪伴 agent 的**产品价值**来自**黏性**：持久记忆（记住你）、跨会话人格一致（永远是「同一个 ta」）、常驻在线（随时都在）、越用越懂你（情感复利）。
- 新规要求的**合规摩擦**恰恰是**反黏性**：定时提醒你「歇一歇」、给你一键「即时退出」、实时检测你是否「依赖过度」并主动打断、禁止「制造情感依赖」。

**让 agent 更黏的每一个设计，都是新规要削弱的那个东西。** 于是对字节/阿里，与其把一个「反黏性」的合规层硬塞进一个「为黏性而生」的架构（工程上是把产品做废），不如整块砍掉、导流到一个从头按合规设计的独立 App（豆包→猫箱）。这就是「关停 + 另起合规马甲」而非「原地整改」的根因。

FourWeekMBA 把这套逻辑总结得更狠：**「这不是产品禁令，是产品架构强制令」「北京不是在禁 AI 陪伴——是在给 AI 陪伴发牌照」**。监管从管「你能说什么」升级到管「你能怎么设计」，成为一层看不见的**「许可层（Permission Layer）」**，决定的不只是什么能上线，而是**产品架构、市场结构、以及谁最终能赢**。

## 正反观点

**支持 / 这是真安全（不是纯管控）**
- 陪伴 AI 对未成年人、对情绪脆弱用户造成情感依赖与心理伤害，是**有据可查的真实危害**。多方评价：这套用户保护「比 EU、美国 FTC、加州 SB 243 迄今落地的任何规则都更完整」。
- 危机检测→转人工、未成年人模式、禁情感操纵，这些条款本身**站得住脚**，与 7/6 日内瓦 UN 儿童安全承诺（「检测到痛苦须停止并转接真人」）跨地缘合流，指向同一套「情感/陪伴 agent 的全球安全底线」。

**质疑 / 风险**
- **管控夹带**：规则「把真正的安全义务和内容管控、国家安全条款捆在一起」——「用用户保护的话术，给了北京一根管这些系统能说什么的杠杆」。上海下架 14,000 个 agent 时把「冒充官方主体」和安全问题并列，**模糊了「防伤害」与「政治管控」的界线**。
- **无数据可携权**：规则「不给用户把自己数据带走的权利」。数百万用户的对话记忆说删就删，平台与用户之间是**不对称权力**。
- **反竞争 / 固化巨头**：合规成本成为**准入壁垒**——字节、阿里、腾讯扛得起，小玩家扛不起。在品类成熟前就**提前完成市场集中**，把监管变成大厂护城河。
- **留白多**：「持续情感交互」的技术阈值、平台与模型提供方之间的**责任划分**、用户数据可携权，**全都悬而未决**。

## 深度解读：对行业 + 对「做多 agent 系统的我们」的具体含义

**对行业：全球治理正式分叉成「两套栈」。** 就在中国执行的几天前，美国官员明确拒绝「搞一个 AI 版 FDA」。同一项技术，两种截然相反的治理下注：美国近乎零许可层，中国最大化监管。结果是全球陪伴/情感 AI 平台被迫**二选一，或者维护两套完全独立的技术栈**。Character.AI、Replika 及所有西方陪伴平台面临**同一道尚未解决的合规题**——**没有一家**建成了能与「持久情感交互架构」共存的防沉迷合规层。今天中国这一刀，是给全世界的陪伴 agent 出了道**迟早要答**的题。

**对我们（工程可执行判断，落到具体）：**

1. **把「记忆 / 人格 / 常驻」当成可按辖区开关的模块，别焊死在核心里。** 持久记忆、长会话、拟人化人格，从「加分项」正式变成「受辖区管制的功能」。架构上要能**从第一天就做功能隔离（feature isolation from day one）**：记忆层、人格层、防沉迷层、数据驻留策略都做成可插拔、可按辖区配置的中间件，而不是和业务逻辑缠死。这是「多模型 × 多地缘 × 多阵营」主线上**新增的一维：多辖区 agent 架构**。

2. **「work agent vs companion agent」是新的监管红线，给自己产品定位划清边界。** 我们做的偏工具/work agent 落在**豁免区**——但**前提是避免「持续情感交互 / 拟人化人格」**。风险在于：客服、健康、教育、心理陪护类 agent 很容易**无意中**长出情感依恋钩子（拟人化口吻、记住你、越用越懂你）而踩线。明确区分「工具」与「陪伴」，别为了留存把 work agent 做出陪伴的黏性。

3. **合规原语要内建为一等公民，不是事后补丁。** 使用时长提醒、即时退出、防沉迷、实时过度依赖检测、危机检测→转人工/紧急联系人、未成年人模式+监护人同意——这一套与 UN 儿童「痛苦检测→转人工」跨地缘合流，正在成为**情感/陪伴/长会话 agent 的全球合规原语**。现在就把它做成可插拔中间件，别等法规逼到眼前才重构。

4. **agent 记忆是负债，不只是资产：把导出/删除/离场（offboarding）做成默认能力。** 豆包数百万用户数据 10/15 删除、Qwen 无迁移——记忆越深，监管下线时的**数据责任越重**。做记忆导出、删除、数据驻留架构，把「用户能带走、能删掉自己的 agent 记忆」做成默认能力。这既是合规底线，也是**可讲的差异化信任资产**（承接「eval/治理/可审计是护城河」主线）。

5. **辖区分叉坐实 → 多辖区 = 多套合规栈/多套产品架构，不是多套模型。** 别赌全球监管收敛。按辖区做可配置：记忆开关、人格开关、防沉迷层、数据驻留、未成年人模式，全部参数化。把「产品所在辖区 + 受哪套 AI 治理 + 谁能勒令下线」升为**架构一等约束**，和供应商登记册并列。

6. **合规成本 = 护城河也 = 准入闸，创业团队要选边。** 对小团队：要么**落在豁免区**（纯工具 agent，避开情感交互），要么把**合规做进产品并对客户讲清**（治理/可审计/可离场做成信任资产）。别在「陪伴/情感」这种高监管品类里裸奔——那是大厂用合规成本筑墙的战场。

7. **监管从「内容」扩到「架构」，这是信号不是终点。** Permission Layer 的逻辑一旦跑通，就可能**外溢到其他 agent 品类**（长会话生产力 agent、常驻后台 agent 都可能被套用「使用提醒/即时退出/依赖检测」）。好消息是：我们本就在做的那套原语——可回滚、可审计、可观测、人审 gate、危险动作 allowlist——**天然对接监管标准**。把合规当架构约束前置，反而让这套投入一鱼两吃。

## 接下来盯什么（信号）

- **8 个安全评估领域细则 + 省级备案实操**：阈值（100 万注册/10 万月活）到底怎么执行、备案要多重、卡多严——决定豁免区的真实边界。
- **work agent 豁免边界会不会收紧**：「持续情感交互」如何认定？第一例「工具 agent 被判越界」出现在哪里？——这直接关系我们这类团队踩不踩线。
- **平台 vs 模型提供方的责任划分**最终归谁：是套壳的 App 担责，还是底层模型方也连带？——影响「模型即服务」的责任边界。
- **西方是否跟进**：加州 SB 243、EU、FTC 会不会引入类似「陪伴 agent」防沉迷/数据离场要求；美国「拒绝 AI 版 FDA」的立场会不会松动。这决定我们要不要提前备好合规栈。
- **是否外溢到 work / 长会话生产力 agent**：Permission Layer 扩到陪伴以外品类的**任何首例**，都是给我们的直接预警。
- **豆包/猫箱/Qwen 用户流向与 10/15 数据删除舆情**：合规重构后的留存 vs 流失，是「反黏性合规层能不能与陪伴产品共存」的第一手实测数据。
