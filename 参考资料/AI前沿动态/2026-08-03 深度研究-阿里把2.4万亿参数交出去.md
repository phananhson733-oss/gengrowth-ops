# 🧠 深度研究 ｜ 阿里把 2.4 万亿参数交出去：Qwen3.8-Max 转正，下周放开源权重

> **一句话定性**：这不是又一次"中国模型发布"。这是**史上最大规模的开源权重承诺**——一个自称仅次于 Claude Fable 5 的 2.4 万亿参数旗舰，输出价只要 Opus 5 的 24%，并且下周要把权重扔到 Hugging Face 上。它同时踩中三条线：模型能力、推理经济学、以及华盛顿正在辩论的"要不要禁中国开源权重"。

**来源**：Alibaba Qwen 官方发布（2026-08-03）；Bloomberg / SCMP / InfoWorld / The Decoder / MarkTechPost 同日交叉报道。

## 一、为什么这一篇值得单独深读

7 月 19 日 WAIC 上，阿里预览了 Qwen3.8-Max，当时的公开信息只有三句话：2.4 万亿参数、多模态、"仅次于 Fable 5"。**没有基准表、没有 model card、没有 license、没有激活参数数、开源权重只承诺 "soon" 且无日期**。独立评测圈当时的评价相当刻薄——一个收费的旗舰发布却不给任何可复现的度量，本身就是一个信号。

8 月 3 日这一天，缺的东西补上了大半：转为全球普遍可用、给出定价、给出基准表、给出激活参数、并且**把"soon"换成了"下周"**，还额外承诺同步开源一个 Qwen3.8-27B。港股当日涨 7% 收于 HK$125.20。

这就是它值得单独拆的原因：**"中国实验室发个接近前沿的模型"已经不新鲜了（Kimi K3、DeepSeek V4、openPangu 2.0 都在过去两周内）。新的是"把最大的那个也开出来"**——阿里今年上半年一度把旗舰转为闭源，这次是掉头回来。而这个动作直接落在我们 7/20 那篇《华盛顿要不要"封"中国开源权重》所追踪的政策命题上：当时那场辩论的两个触发物，一个是 Kimi K3，另一个就是 Qwen 3.8。现在触发物要真的落地了。

## 二、核心事实（分层）

**A. 规格（厂商口径，8/3 公布）**
- 架构：稀疏 MoE，**2.4 万亿总参数**，每次推理约激活 **950 亿**（预览期未披露，本次给出）
- 上下文：**100 万 token**；最大输入 991K（开思考时 983K），最大输出 131K，思考预算上限 262K
- 模态：文本 / 图像 / 视频 输入，文本输出
- 旋钮：`reasoning_effort` 三档，速度与深度可调
- 接口：同时兼容 **OpenAI Chat Completions 协议**与 **Anthropic API 协议**，外加 DashScope
- 分发：Alibaba Cloud API、Qwen Cloud、Qwen Studio、QwenWork（办公 AI 平台）

**B. 定价（每百万 token）**
| 项 | 价格 |
|---|---|
| 输入 | **$2.00** |
| 输出 | **$6.00** |
| 隐式缓存输入 | $0.25 |
| 显式缓存写 / 读 | $2.50 / $0.17 |
| 限速 | 2M tok/min，15K req/min |

预览期通过 Token Plan 给到标价的 10%。

**横向比价（输出价，每 Mtok）**：Qwen3.8-Max **$6** ｜ Claude Sonnet 5 促销价 $10（9/1 起 $15）｜ GPT-5.6 Terra $12 ｜ Claude Opus 5 $25 ｜ GPT-5.6 Sol $30 ｜ Claude Fable 5 $50。
→ 它自称对标 Fable 5，输出价是 Fable 5 的 **12%**、Opus 5 的 **24%**。

**C. 基准（全部为阿里自报，独立验证未完成）**
| 基准 | Qwen3.8-Max | 报道给出的对照 |
|---|---|---|
| Terminal-Bench 2.1 | **86.6** | Claude Opus 4.8 84.6 |
| GPQA Diamond | **92.6** | — |
| PaperBench | **93.0** | — |
| FrontierSWE | **73.5** | Claude Fable 5 88.8 |
| OSWorld-Verified | **86.1** | — |
| 内部 10+ 基准综合分 | 0.474 → **0.725** | （自身迭代对比） |

⚠️ **一处需要存疑的口径冲突**：MarkTechPost 把 88.8 记为 Fable 5 在 FrontierSWE 上的分，The Decoder 则把 88.8 记为 GPT-5.6 Sol 在 TerminalBench 上的分。我们此前记录的口径是 Terminal-Bench 2.1 上 GPT-5.6 Sol 89.5 / Opus 5 89.1。**取交集能确定的只有一件事：Qwen3.8-Max 的 86.6 落后当前双前沿约 3 分，而在 FrontierSWE 这类最难的软件工程任务上仍有明显代差。**

**D. 长时程案例（阿里自报，无第三方复核）**
- `oh-my-cli` 开发：**16 天，265 次提交，127 个 PR，151 个 issue**
- 复现一篇研究论文：约 5 天，7,600 行代码，把 AIME24 提升 2.7 分
- 对话竞赛：排在 526 名人类选手中的第 458 名之前；准确率 0.60 → 0.853
- 芯片设计：逻辑门数 8,298 → **678**，物理面积降 **81%**
- 电商模拟经营：起始 10 万元 → **416,252 元**，比亚军好 38%

阿里把能力跃迁归因于**"强化学习阶段大幅扩展训练环境"**：从单任务训练环境，扩到多天工作流与嵌套目录结构。

## 三、机制拆解：开权重 ≠ 你跑得起

这是整件事里最容易被口号盖掉的部分。**2.4 万亿参数的权重，放出来之后谁能真的加载？**

Wafer 在 7 月 31 日对 Moonshot Kimi K3（2.8T）做的实测给了一个精确读数：

- K3 **光权重就需要超过 1.5TB 显存**——还没开始给 100 万 token 的 KV cache 分配空间
- 能单节点装下的只有 **288GB/GPU 的 B300 和 MI355X**；192GB/GPU 的 B200 装不下，必须双节点 TP16

| 配置 | 单流解码 | 峰值聚合/节点 | GPU 时价 | 每美元 tok/s |
|---|---|---|---|---|
| MI355X (TP8) | 118 tok/s | 952 | $2.50 | **48** |
| B300 (TP8+DCP8) | **172 tok/s** | **1,568** | $6.00 | 33 |
| B200 (TP16, 双节点) | 90 tok/s | 498 | $4.25 | 7 |

B300 在绝对吞吐上赢 MI355X 约 1.65 倍，但价格是 2.4 倍——**perf/$ 上 MI355X 反超**（48 vs 33）。这是 AMD 第一次在一个真实的前沿规模负载上，靠 HBM 容量拿到可测量的结构性优势。

按同样的算术给 Qwen3.8-Max 估个量级：**2.4T 参数在 4-bit 下粗算约 1.2TB 权重**（这是我们的换算，不是厂商口径），比 K3 略松，但结论不变——**你需要一台 8×288GB 的节点才谈得上自建**。

所以"开源 2.4T"的真实含义是：

1. 对绝大多数团队，**能用的其实是同时开源的 27B**，不是那个 2.4T 的旗舰；
2. 对旗舰而言，开权重带来的**不是"人人自建"，而是"可审计、可迁移、可当谈判筹码"**——$2/$6 的托管价比自建划算得多，除非你有极大的稳定推理量或硬性的数据驻留要求；
3. 硬件侧的连带效应是真的：**2T+ 级模型正在把"单节点显存容量"变成一条硬准入线**，而这条线上 AMD 和 NVIDIA 是平的，价格却不平。

## 四、关键引述

> "Alibaba is narrowing the gap, but the larger story is the rapid maturation of open-weight models."
> —— Charlie Dai，Forrester 副总裁兼首席分析师

> "Sixteen days of what? How many times did a human step in? Did the output survive code review?"
> —— Amit Jena，Kanerika AI 开发经理，质疑那个 16 天自主编码案例

> "publishing weights is a separate act from opening an API endpoint."
> —— 同上，提醒"承诺开权重"与"真的放出可用权重和 license"是两件事

## 五、正反观点

**支持方**
- **Forrester（Dai）**：真正的故事不是阿里追近了多少，而是**开源权重模型整体成熟得非常快**——企业在软件工程和成本敏感场景上，第一次有了对闭源模型的可用替代。
- **Gartner（Nitish Tyagi）**：MoE 架构 + 100 万上下文，让 AI 辅助开发**"在经济上更可行"**，直接回应了"AI 编码成本可能超过开发者平均工资"这个 2026 年的现实担忧。2.4T 参数只激活 950 亿，正是这个经济性的来源。
- 结构性论点：接口层同时兼容 OpenAI 与 Anthropic 两套协议，**把切换供应商的工程成本压到接近零**——这是厂商自己交出来的议价权。

**质疑方 / 风险**
- **数据全是自报**。The Decoder 明说独立验证仍未完成；Artificial Analysis、LMArena、HuggingFace Open LLM Leaderboard 至今**没有 Qwen3.8-Max 的条目**。7 月预览期"零基准发布"的前科加重了这个折扣。
- **长时程案例的口径不透明**（Jena）：16 天里人介入了几次？产出过了 code review 吗？这类"自主经营/自主开发"叙事在过去两周已经被打过脸——Bottleneck Labs 让 GPT-5.6 Sol 真实经营一门生意，结果是净亏 $447、最后 12 小时慌乱改价 6 次。
- **license 与 model card 仍未公布**。"下周开权重"是承诺不是交付；开的是 Apache 2.0 还是带使用限制的自有协议，决定了这件事的全部成色。
- **辖区与法务风险**（Tyagi）：中国境外的组织会犹豫使用中国托管的模型；转经 hyperscaler 部署要加成本；而开源权重**不带商业厂商提供的侵权赔偿担保（indemnification）**。
- **真正的瓶颈可能不在推理效率而在评测吞吐**（Jena）：企业没有能力对每两周冒出来的新旗舰做严肃评估。
- **能力来源的悬案**：Anthropic 6 月 24 日曾指控阿里/Qwen 实验室发动"史上最大蒸馏战"（约 25,000 个欺诈账户、2,880 万次交互，专挑软件工程与 agentic reasoning 两项能力）。这次跃迁与那件事的关系，双方都没有给出新证据。

## 六、深度解读

**对行业格局。** 三件事在这一天同时成立：

1. **"开源权重的天花板"被抬到 2.4T。** 此前最大的开源权重旗舰级模型是 Kimi K3（2.8T，但那是 Moonshot 的选择）和 Thinking Machines 的 Inkling（9750 亿）。阿里作为一家上市大厂、在上半年闭源之后回头开源最大的那个，是一次明确的战略站位：**用开源换生态占位与地缘话语权**，而不是用闭源换毛利。
2. **价格战的形态变了。** 上周 OpenAI 靠"模型自己优化推理栈"把 Luna 降价 80%，那是**在自己的价目表内部**降。这次是**从外部把价目表的地板抽掉**——一个自称对标 Fable 5 的模型，输出价只要 Fable 5 的 12%。哪怕自报数打对折，这个价位也会重定价整个"中高端 agent 推理"档。
3. **美国的政策命题从假设变成现实。** 7/20 我们推过那篇"域内开源权重进口禁令"的辩论，当时是纸上推演。下周权重一旦落地在 Hugging Face 上，**"禁"这个动作的技术可执行性会被立刻检验**——权重一旦公开分发，任何进口禁令都只能约束商业主体，约束不了 git clone。

**对做多 agent 系统的我们——七条可执行判断：**

1. **进候选池，但不进核心闸门。** 把 Qwen3.8-Max 加入多模型路由的"长上下文 + 长时程 + 成本敏感"档做压测。但 FrontierSWE 73.5 那一栏说明最难的软件工程任务上仍有代差——**不要把它放在需要正确性保证的编码闸门上**（代码审查、发布前检查、迁移改写）。
2. **先跑我们自己的评测集，再谈迁移。** 所有数字都是自报且独立榜单无条目。判定标准只有一个：在我们自己的真实任务上跑出的分。这也直接呼应 Jena 那句"评测吞吐才是瓶颈"——
3. **把"新模型接入 → 私有评测集跑完 → 出结论"做成流水线。** 过去 30 天里出现了 GPT-5.6 全系、Opus 5、Fable 5、Kimi K3、DeepSeek V4-Flash、openPangu 2.0、Qwen3.8-Max。**手工评估已经跟不上发布频率了**，这条流水线的优先级应当高于任何单个模型的接入。
4. **模型适配层现在该收敛。** 它同时兼容 OpenAI 与 Anthropic 两套协议——如果我们还在为每家写独立 SDK 适配，现在应该收敛成"一套 OpenAI/Anthropic 兼容 client + 一张路由表"。厂商已经把切换成本给我们降到零了，不用是浪费。
5. **`reasoning_effort` 三档 + 262K 思考预算是现成的成本旋钮。** 在 agent 编排里显式分档：规划/反思步开高档，执行/格式化步开低档。这是比"换更便宜的模型"更精细的成本手段。
6. **辖区字段要落到依赖清单里。** 按 7/27 那篇的做法给每个在用模型打上 `origin` / `hosting_jurisdiction`。开源权重给了跨辖区冗余的**真实**选项（自托管 27B），但 Tyagi 的 indemnification 提醒必须写进合同评估——**开源权重出事没人赔**。
7. **别把"16 天自主编码"当排期依据。** 对照 7/28 SlopCodeBench 的实测（Opus 5 严格通过率 24%、长时程结构侵蚀）与《2x, not 10x》。对外口径按 2 倍量级说，内部排期按 2 倍量级排。

## 七、接下来盯什么（信号）

1. **下周（8/10 前后）权重是否真的落地，以及 license 是什么。** Apache 2.0 / 类 Llama 的限制性协议 / 还是延期——这是判断"开源"成色的唯一硬指标。同步看 model card 是否给出训练数据说明与完整激活参数。
2. **Artificial Analysis / LMArena / Terminal-Bench 官方榜何时出现独立分数**，与自报的 86.6 差多少。差 3 分以内说明自报可信，差 8 分以上说明整张表都要打折。
3. **华盛顿的反应。** 7/20 那场"域内开源权重进口禁令"的辩论会不会因为权重真的落地而转成具体立法动作。
4. **Qwen3.8-27B 的独立评测**——对大多数团队，那才是真正能用的东西。
5. **$2/$6 是否维持。** 预览期给的是标价 10%，正式价与实际结算价的关系需要观察一个计费周期。
6. **AMD 侧的连带效应。** 2T+ 级开源权重变多，会不会把 MI355X 的 perf/$ 优势（48 vs B300 的 33）转成真实的部署份额迁移。
