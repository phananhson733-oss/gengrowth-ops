# 🤖 深度研究 ｜ Gemini Robotics 2：Google 把整台人形机器人交给一个策略——而官方自己公布的成功率表，说了另一半故事

> **一句话定性**：DeepMind 在 7/30 一次发了三个"物理 AI"模型，第一次让**单一端到端策略同时管住人形机器人的腿、躯干、手臂和手指**，不再靠人手写的上下半身交接逻辑；但同一篇官方博客里贴出的成功率表把话说得比营销更诚实——**两指夹爪(74.2%~89.6%)全面打赢 22 自由度的五指手(32%~92%)**，多指精细操作 60 个百分点的跨度意味着它今天仍是研究课题、不是可部署系统。对做多 agent 系统的我们，真正值钱的信息不在机器人本身，而在 Google 这次**把架构写成产品形态的方式**：ER 2 规划 → VLA **被显式声明为一个 tool** 去执行 → On-Device 在边缘兜底，外加一层独立的 agentic 安全基准 ASIMOV-Agentic。这是本监测两周内看到的**第三次**"通用模型当编排中枢、专才模型降级为工具"的实证。

## 二、核心事实（分层）

### 2.1 一次发了三个模型，是一套分层系统而非一个模型

| 模型 | 角色 | 关键规格 |
|---|---|---|
| **Gemini Robotics ER 2** | 高层规划"大脑"：多步任务编排、与人沟通、**多机器人协作** | 底座 **Gemini 3.5 Flash**（二手口径）；输入可交错 text/image/video/audio，**上下文 128K**，输出最多 **64K token** |
| **Gemini Robotics 2（VLA）** | 视觉-语言-动作执行器：把视觉与语言直接变成电机控制 | 覆盖**整台人形**与双臂机器人；同一 checkpoint 同时驱动两种手 + 一种夹爪 |
| **Gemini Robotics On-Device 2** | 端侧高效 VLA，本地运行 | 继承 1.5 的 motion transfer；**新本体适配"几小时、通常少于 200 个样本"**；底座含 Gemma |

**关键结构信息**：MarkTechPost 的拆解写得很直白——"**ER 2 规划并跟踪任务，然后把电机执行交给一个被声明为 tool 的 VLA**"。这句话是本篇最重要的一行字，后面第五节会展开。

### 2.2 整机控制：单一策略取代人手写的交接逻辑

- 上一代只控制人形的**上半身**做桌面任务；Gemini Robotics 2 把范围扩到**全身运动**。
- **腿和手臂由单一端到端策略统辖，而不是各自独立的子系统**——因此需要全身协调的新行为可以"通过模型训练引入，而不必改动硬件层的交接逻辑"。这是工程上的实质变化：过去每加一个跨上下半身的动作，都要人去改状态机。
- 官方演示（Apptronik **Apollo 2**）：走到桌边 → 拿起浇水壶 → 走到货架 → 下蹲 → 精准放进指定箱子。

### 2.3 成功率表：官方自己给的地面真相

**整机抓取（Apollo 2）**

| 任务 | 成功率 |
|---|---|
| 从**货架**取物 | **76.3%** |
| 从**桌面**取物 | **68.4%** |
| 从**地面**取物 | **45.7%** |

**多指精细操作（Apollo 2 + 22 自由度 SharpaWave 手）**

| 任务 | 成功率 |
|---|---|
| 拧**松**灯泡 | **92%** |
| 系垃圾袋 | 44% |
| 密封拉链袋(ziplock) | 40% |
| 拧**紧**灯泡 | **36%** |
| 簸箕扫取 | **32%** |

**两指夹爪（Franka Duo + Robotiq 夹爪）**

| 任务 | 成功率 |
|---|---|
| 精密插入 | **89.6%** |
| 多样化工具配料(kitting) | **78.9%** |
| 通用抓放 | **74.2%** |

### 2.4 安全被单拎成一层

官方同时推出 **ASIMOV-Agentic** 基准，评估三件事：**拒绝不安全指令 / 识别自身不确定性 / 主动请求人类帮助**。安全模型"能更好地检测附近有人、触发安全工具调用，并在有人靠得太近时把机器人停到安全状态"。配套有一份 Gemini Robotics 2 Safety Technical Report。

### 2.5 可用性（谁现在能碰到）

- **ER 2**：已上 **Google AI Studio**，并通过 Gemini Enterprise Agent Platform 提供私有预览 → **这是唯一一个现在就能上手的**。
- **VLA / On-Device 2**：仅向 **Trusted Tester 早期合作伙伴**开放，需申请。
- 硬件生态：Apptronik（Apollo 2）、Franka、Dexmate、SO101、Trossen；博客提及与 Boston Dynamics、Agile Robots 的合作。

## 三、机制拆解：两个反直觉的地方

### 3.1 "夹爪打赢五指手"不是硬件问题，是学习信号问题

把三张表并排看，结论很刺眼：**22 自由度的五指手在 5 个任务里有 4 个低于 45%，而 2 自由度的夹爪在 3 个任务里全部高于 74%**。这不是"手做的任务更难"能完全解释的——精密插入(89.6%)本身就是高精度任务。

更合理的读法是：**动作空间维度每上一个台阶，所需的示范数据与探索量就非线性膨胀**。夹爪的动作空间近乎一维（开/合 + 位姿），五指手是 22 维；同样规模的数据，在夹爪上足够覆盖分布，在多指手上只够覆盖分布的一小块。

一个几乎可以当证据看的细节：**拧松灯泡 92%，拧紧灯泡 36%**。同一只手、同一个物体、几乎同一套运动学，只是方向相反、且"拧紧"需要对螺纹对位与力控做闭环——成功率掉了 56 个百分点。这说明模型学到的**不是"拧"这个可复用的物理概念，而是某个特定轨迹分布**。泛化仍然发生在示范覆盖的邻域内。

### 3.2 "单一端到端策略"的收益是工程性的，不是智能性的

官方对整机控制的表述值得逐字读：新行为"可以通过模型训练引入，**而不必触碰硬件交接逻辑**"。收益写得非常克制——它省掉的是**人写的胶水层**，不是让机器人更聪明。

这跟过去两周另外两个案例是同一件事：AlphaFold 被降级为 Co-Scientist 里的一个工具，Claude Mythos 在 harness 里被当 worker 调度。**"一个策略统辖全身"和"一个模型编排全流程"，共享同一个论点：把手工编排的接缝交给学习到的策略，从而让能力增长可以靠训练而不是靠改代码。**

### 3.3 长链复利：本篇最该被记住的一笔账

⚠️ **以下是本篇的分析推演，不是官方数据**，但它决定了怎么读那段浇水壶演示。

官方给的是**单任务**成功率。如果把演示里的动作当成松散独立的环节来估：

- 3 个环节，每个按桌面抓取的 68.4% 算 → **约 32%**
- 5 个环节 → **约 15%**
- 若链条中包含一次地面抓取(45.7%) → 更低

而演示视频是流畅一遍过的。Engadget 的核对给出了解释：**视频中的机器人是被专门针对每一个任务训练过的**（遥操作 + 视频示例 + 仿真），不是通用能力的自由组合。也就是说，演示成立靠的是"这条链被单独训练成了一个技能"，而不是"每个环节都够可靠所以链条自然成立"。

**这条账和 7/27 SlopCodeBench 的长时程退化、7/28 Anthropic 自述的"生成:验证 ≈ 1 周:1 月"是同一个物理定律的三种表现形式**：单步指标漂亮，端到端才是真相。

## 五、正反观点

### ✅ 支持方：这是物理 AI 第一次拿出"可核对的地面真相"

1. **跨本体泛化是真的**：**同一个 checkpoint** 驱动 Apollo 2 上的两种不同的手，外加 Franka Duo 夹爪。在机器人领域，"换个末端执行器就得重训"曾是常态。
2. **样本效率是真的**：On-Device 2 适配一个**新的双臂本体**只要"几小时、通常少于 200 个样本"。这个数量级如果站得住，等于把机器人本体适配从工程项目降级成一次微调。
3. **不是纯 demo**：ER 2 **今天就在 AI Studio 上**。规划层可用、执行层受控开放，是一个诚实的分阶段发布。
4. **安全被前置成基准而非事后开关**：ASIMOV-Agentic 明确测"会不会主动求助人类"——这是把 human-in-the-loop 当作**能力指标**而不是产品配置。
5. **披露诚实度高于行业均值**：把 32% 印在自己博客上，比只发 SOTA 柱状图的同行强。

### ❌ 质疑方：营销词"整机智能"与数据表之间有一道明显的缝

1. **多指灵巧性 32%~92%，60 个百分点的跨度本身就是"还在研究阶段"的定义**。日常家务里最常见的动作（扫、系、封口）恰好落在 32%~44% 区间。
2. **演示 ≠ 泛化**：Engadget 明确指出视频中每个任务都被专门训练过；Google 自己也称之为"里程碑，不是终点线"。
3. **速度是硬伤**：官方承认移动速度不足；对商业部署（工厂节拍、家庭耐心）来说，慢本身就是不可用。
4. **拿不到手**：VLA 与 On-Device 只对 Trusted Tester 开放，**没有公开 GA 时间表、没有定价**。可复现性为零。
5. **底座信号不妙**：ER 2 建在 **Gemini 3.5 Flash** 上（二手口径）。旗舰 3.5 Pro 自 I/O 承诺以来已三次跳票，新产品线只能用 Flash 起步——这既是务实，也是约束。
6. **行业在撞同一堵墙**：TheNextWeb 指出，机器人基础模型创业公司与各家人形机器人的灵巧性工作"一次次撞上同一堵墙——demo 炫目，机器仍远未准备好进家门"。这条批评同时适用于 Figure、1X、Physical Intelligence 与 Tesla Optimus（后者曾被证实演示中使用了遥操作）。
7. **结构性软肋：Google 有软件没硬件**。而机器人硬件供应正在政治化（美国已限制中国制造机器人的销售）。这与 Google 在模型侧自建 TPU 的处境完全相反。

## 六、深度解读：对行业 + 对"做多 agent 系统的我们"

### 6.1 对行业

**(1) 物理 AI 的竞争层次被 Google 定义成了"智能层"而不是"整机"。** Google 不造机器人，卖的是 ER 2 + VLA 这一层，硬件方是 Apptronik / Franka / Boston Dynamics / Agile Robots。这是明确的"机器人界 Android"打法。它的赌注是：**本体会商品化，智能层不会**。第七节的观察信号里，"硬件方是否愿意长期做别人的躯体"是这盘棋的胜负手。

**(2) 7/11 那波具身智能估值，今天拿到了第一份对账单。** 结论是双向的：跨本体泛化与样本效率**支持**估值叙事；32% 的簸箕与"移动速度不足"**不支持**近期商业化叙事。谁按 12 个月内规模部署去定价，今天这张表不站在他们那边。

**(3) "通用模型 + 编排 + 工具"已经三线收敛。** 科学发现（Co-Scientist / AlphaFold 降级为工具）、安全研究（Claude Mythos + harness）、机器人控制（ER 2 + VLA as tool），两周之内三个证据。这条路线现在的问题不再是"对不对"，而是"在哪些领域今天就能跑"。

### 6.2 对我们（可执行判断）

**① 把 7/29 提炼的判据升级为两条筛子。** 上一篇给出的判据是"该领域有没有便宜的裁决函数"。机器人这个案例补上了第二条：**动作/输出空间的维度，必须由任务回报来证明**。五指手输给两指夹爪，本质是"给了模型 22 维自由度，但任务只需要 2 维，多出的 20 维全是要付学习代价的噪声"。

> 直接映射到我们的系统：**给 agent 的工具接口越"通用"，它越难可靠**。一个能跑任意 SQL 的工具，可靠性会输给五个参数受限的具体查询工具——即使前者"能力更强"。**新增设计规则：工具接口的自由度，按任务实际需要的最小维度设计，不按"将来可能用得上"设计。**

**② 端到端率必须成为唯一对外承诺口径。** 官方给单任务成功率、演示给流畅长链，中间的缝要靠"这条链被专门训练过"来填。我们的评测集里同样存在这条缝：单步 pass 率 + 人工挑的 happy path demo = 系统性高估。

> **行动项**：评测报告强制两栏——**每步成功率** 与 **端到端一次通过率**，且端到端必须在**未针对性调优的任务集**上测。任何只报单步的结论，视为未经验证。

**③ ASIMOV-Agentic 的三项可以直接抄进我们的 harness 测试。** "拒绝不安全动作 / 识别不确定性 / 主动求助人类"——第三项是软件 agent 普遍缺失的：我们的 agent 在不确定时倾向于**编一个答案继续跑**，而不是停下来问。

> **行动项**：给 harness 加一组"该求助时是否求助"的用例（信息不足、权限不足、指令自相矛盾三类），把**主动求助率**列为与任务成功率并列的指标。这是把 7/28 已确立的"不跳过人类检查点"从流程约束变成**可度量指标**。

**④ "省掉手写胶水层"是这次架构变化的真实收益，别过度解读成智能提升。** 整机策略的官方收益是"新行为靠训练引入、不动交接逻辑"。对我们的对应物是：**把编排逻辑从 if/else 状态机搬进模型规划，收益是迭代速度，不是正确率**。所以搬迁的前提是——正确率的兜底必须在别处（工具契约、裁决函数、检查点），不能指望模型规划顺手把它带上。

**⑤ 分层要照抄，但"tool 的边界"要更硬。** ER 2 / VLA / On-Device 三层，对应我们的**规划层 / 执行层 / 本地快路径**。值得抄的是那句"VLA **被声明为一个 tool**"——执行器对规划层只暴露契约，不暴露内部状态。

> **行动项**：审一遍我们现有的 agent 分层，凡是规划层需要知道执行层内部实现才能工作的地方，都是将来换模型/换实现时会断的接缝。

**⑥ 底座冗余：ER 2 建在 Flash 上这件事，是给所有下游的提醒。** 最强模型延期时，厂商自己会先降级到次强底座把产品发出去。我们对上游模型的依赖清单，除了 7/29 加的 `last_substantive_update` / `has_dedicated_owner`，**再加一列 `fallback_tier_tested`**：当前所选型号不可用时，降一档跑我们的评测集，端到端率掉多少——这个数字现在就该有，而不是等断供那天现测。
