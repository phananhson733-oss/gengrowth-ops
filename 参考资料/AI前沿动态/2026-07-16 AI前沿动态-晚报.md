# 深度研究：Mira Murati 交出「Inkling」——美国迄今最大的开源权重前沿模型

**一句话定性**：前 OpenAI CTO 用一个 9750 亿参数、Apache 2.0 的多模态模型，把「美国也能做真·开源前沿」这件事从口号变成了权重文件——它不是当今最强，却可能是美国开源阵营在 Meta 转向闭源后最重要的一次补位。

- **来源**：Thinking Machines Lab 官方公告 + The Register / BenchLM / TechCrunch 交叉核实
- 🔗 **原始链接**：https://thinkingmachines.ai/news/introducing-inkling/
- **日期**：2026-07-16（今日发布）

---

## 为什么值得深读 / 背景

过去两个月，本监测反复记录一条主线：**开源近前沿正在成为对抗「单边下线 / 断供 / 监管下线」的保险**——从中国的 DeepSeek、GLM、Kimi、Qwen、LongCat、腾讯 Hy3，到欧洲的 Mistral。但美国这一侧却在往反方向走：

- **Meta 刚刚变节**：7 月 Muse Spark 1.1 附带 Meta 史上首个「闭源托管、按 token 付费」API，标志着 Llama 时代那个「美国开源担当」正式转身去做 OpenAI/Anthropic 式的付费 API。美国开源前沿由此出现真空。
- **OpenAI 依旧闭源**，Anthropic 从来闭源，Google 旗舰（明天预期 GA 的 Gemini 3.5 Pro）也是闭源。

正是在这个真空里，**Mira Murati——OpenAI 前 CTO、GPT-4/4o 与 ChatGPT 时代的核心技术负责人**——带着她 2025 年创立、拿下 AI 史上最大种子轮（20 亿美元 / 120 亿估值）的 Thinking Machines Lab，交出了成立以来**第一个从零训练的自研前沿规模模型**，并且直接选了 **Apache 2.0 完全开源权重**。The Register 的标题一针见血：「前 OpenAI CTO 做了 Altman 不肯做的事：发布一个真正开放的前沿模型。」

这既是一次技术发布，也是一次**路线宣言**——它把「开源 vs 闭源」之争重新摆回美国前沿实验室的牌桌，且发布方的身份（Altman 的前二号人物）让象征意义拉满。

---

## 核心事实（硬数据分层）

**模型规格**
- 名称 **Inkling**；架构 **MoE（专家混合）**：**9750 亿总参 / 410 亿激活参数**（256 个路由专家 + 2 个共享专家，每 token 激活 6 个专家）
- 伴随小模型 **Inkling-Small**：2760 亿总参 / 120 亿激活
- **上下文窗口：100 万 token**；**多模态**（文本 / 图像 / 音频 / 视频）
- **预训练 45 万亿 token**，用 Nvidia GB300 NVL72 系统训练
- **许可：Apache 2.0，完全开源权重**（企业友好、可商用）

**分发与工程**
- 首发 Hugging Face + 自家 Tinker 平台，即将上 TogetherAI / Fireworks / Modal / Databricks / Baseten
- 支持推理引擎：vLLM / SGLang / Miles / TokenSpeed / Llama.cpp
- 部署门槛硬：**原生 16-bit 需 >2TB GPU 内存（8×Nvidia B300 或 16×H200）**；NVFP4 量化可减半

**官方基准（effort=0.99）**
- AIME 2026：**97.1%**
- GPQA Diamond：**87.2%**
- SWE-Bench Verified：**77.6%**
- Terminal-Bench 2.1：**63.8%**（匹配 Nvidia Nemotron 3 Ultra，但**只用约 1/3 的 token**）
- HLE（Humanity's Last Exam）纯文本 29.7%、带工具 46.0%
- 独立聚合 BenchLM：78 个合格模型中排**第 30**，综合分 69；Design Arena 网页开发 Elo 1258，与 Claude Opus 4.6 打平（单一窄基准）

**定位坦白**
- 官方原话：**「Inkling is not the strongest overall model available today, open or closed.」**（明确承认不是当今最强，无论开闭源）
- 相对位置：**胜过** Nvidia Nemotron 3 Ultra，落在 **Kimi 2.5 与 Kimi 2.6 之间**，**落后**闭源前沿 Claude / GPT

## 机制 / 技术拆解：三个真正的看点

1. **可控思考努力（controllable thinking effort）**：开放一个 **effort 参数（0.2–0.99）**，让开发者按任务难度调节推理 token 的花费。官方用它在 Terminal-Bench 2.1 上「用约 1/3 的 token 匹配对手」。这本质上是把 **per-task 的 token 预算旋钮**直接交给使用方——对长跑 agent 的成本控制是实打实的工程杠杆，而非营销话术。

2. **MoE 的「大而稀疏」**：9750 亿总参但每 token 只激活 410 亿（约 4.2%），走的是与 DeepSeek/Kimi 同样的「fat but sparse」路线——用巨大的知识容量 + 低激活换取推理成本可控。

3. **开源权重 + 定制平台的商业闭环**：Inkling 不是孤立发布。BenchLM 的分析点破了它的商业逻辑——**「开源权重不是附带的副项目，它们补全了产品闭环」**：免费放出基座模型做分发，真正收费的是「可靠的后训练 / 定制」这个更难的问题，即 Tinker 微调平台（launch 期 $1.87/百万 token，5 折）。**基座免费、定制收费**，是对「纯 API 订阅」范式的一次正面另辟。

## 正反观点

**支持方（为什么这是大事）**
- **真·开源**：Apache 2.0 完全权重，可自托管、可商用、可微调——与 OpenAI 闭源、Meta 刚转闭源形成鲜明对照。美国前沿开源阵营终于有了一个重量级、且带旗帜性人物背书的玩家。
- **能力够用**：SWE-Bench Verified 77.6 / Terminal-Bench 63.8 / AIME 97.1，对绝大多数 agentic 与推理场景是「可用的近前沿」，且多模态 + 100 万 ctx。
- **效率是真优势**：1/3 token 匹配 Nemotron，可控 effort 参数直击 agent 运行时的 token 经济学。

**质疑方（冷静的一面）**
- **不是最强，官方自认**：落后 Claude/GPT，BenchLM 78 中第 30，纯文本推理偏弱（HLE 30%），缺多语言覆盖。「近前沿」不等于前沿。
- **「开源」有水分**：这是 **open-weight（开放权重）而非 open-source**——训练数据、训练决策、生产系统均不公开，下游无法复现或改进完整训练管线。
- **2TB 硬件门槛=天然市场分层**：8×B300 或 16×H200 才能原生跑起来，绝大多数团队根本无法真正「自托管」。BenchLM 直言这个门槛**「是特性，不是 bug」**——它把用户挤向 TML 自家的托管 Tinker（以及 Together/Fireworks 等伙伴），所谓「开源自主」在经济上仍然 vendor-dependent，只是把依赖延后到部署规模变大时才显现。
- **基准可刷**：The Register 提醒「刷 AI 基准并不难」，官方数字有待独立复现。
- **商业模式仍是问号**：TML 烧了 20 亿美元、2025 年底冲刺 500–600 亿估值被投资人**否掉**（当时只有 Tinker 一个产品），至今仍停在 120 亿估值、约 140–169 人。Inkling 是补齐「产品记录」的关键一步，但「基座免费 + 定制收费」能否撑起这个体量，尚未被市场验证。

## 深度解读：对行业 + 对「做多 agent 系统的我们」的具体含义

**对行业格局**：这是**开源 vs 闭源路线之争在美国本土的重新点火**。此前的叙事是「中国 + 欧洲做开源近前沿，美国做闭源最强前沿」；Meta 转闭源后，这条分界一度要变成「美国 = 纯闭源」。Inkling 把一个反例摆上桌，而且发布者是 Altman 的前二把手——它未必改变能力天花板（天花板仍是 Claude/GPT/Gemini），但它**改变了「美国能不能有真·开源前沿」这个预期**，并给「基座免费、定制变现」这一商业范式提供了一个高调样本。对 Murati 个人，这也是重启那轮流产的 500 亿融资的筹码。

**对做 agent 系统的我们，落到可执行判断**：
1. **加进「可切换供应商矩阵」，但别急着自托管**。Inkling（Apache 2.0、SWE 77.6 / Terminal 63.8）值得纳入我们的模型冗余清单，作为**抗单边下线 / 断供 / 监管下线**的一层保险（还记得 6 月 Fable 5 被出口管制强制全球下线吗？多阵营冗余不是理论风险）。但 **2TB 门槛意味着「自托管开源」对多数团队是伪命题**——真要用，先算清 Together/Fireworks/Baseten 托管的实际单价 vs 闭源 API 的 TCO，别把「开源」等同于「免费/自主」。
2. **effort 参数是可以马上抄的思路**。哪怕不用 Inkling，「按任务难度动态调推理预算」这一旋钮值得在我们自己的 agent 编排里对齐——它直接对应我们关心的长跑 agent 单位成本 / token 熔断。
3. **垂直定制场景，开源权重 + Tinker 微调可能优于闭源 API 提示工程**。如果 agent 任务领域窄、需要稳定的领域后训练，可自控权重的价值会超过闭源模型的能力小幅领先。
4. **一句话结论**：把 Inkling 当**成本对标锚和冗余选项**去评估，而不是当「新王」——盯它在**非官方**真实 agentic 评测里的复现，以及托管伙伴的实际定价，再决定投入多少。

## 接下来盯什么（信号）

- **独立复现**：第三方在 SWE-Bench Verified / Terminal-Bench 2.1 / OSWorld 上的实测 vs 官方 97.1/77.6/63.8——差多少决定它是「可用近前沿」还是「基准漂亮」。
- **托管定价落地**：Together / Fireworks / Baseten 上线后的每百万 token 报价 → 这才是真实的推理成本地板，也检验「2TB 门槛把人推向托管」的判断。
- **Tinker 采用**：企业微调客户与案例增速——「基座免费、定制收费」能否成立看这里。
- **融资动作**：Murati 是否借 Inkling 重启 500 亿估值那一轮（产品记录已补）。
- **对手回应**：中国开源阵营（Kimi K3 / DeepSeek 下一版 / GLM 6）与 Meta（会不会被激回开源）的动作；以及明天（7/17）预期 GA 的 **Gemini 3.5 Pro**——闭源前沿旗舰，正好与 Inkling 构成「闭源最强 vs 开源可用」的即时对照。
