# Claude Code 被曝植入「中国检测」隐写指纹、潜伏 3 个月——阿里 7/10 全面封禁 Anthropic AI

**一句话定性**：一个你天天在本机运行的编码 agent，被查出会静默探测你的时区与代理地址、再把地缘标记用「肉眼看不见的 Unicode」隐写进每次请求的 system prompt 回传厂商——"负责任 AI"头牌撞上供应链信任的硬墙，也让 6/24 的「蒸馏战」第一次双向开火。

**来源**：CNBC（阿里禁用+Anthropic 回应）＋安全研究者 GitHub 验证报告（LegitMichel777）＋Anthropic 工程师 Thariq Shihipar 的 X 说明＋Malwarebytes / International Cyber Digest 技术复盘
🔗 原始链接：https://www.cnbc.com/2026/07/06/alibaba-anthropic-ai-ban-claude-china.html
**时间线**：植入 ~v2.1.91（4/2）→ 研究者 6/30 发现 → ~v2.1.197-198（7/1）回滚 → 阿里 7/10 全面禁用

---

## 为什么值得深读

过去两周我们反复深挖「前沿能力边境武装化」（出口管制下线 Fable 5、Daybreak Trusted Access、6/24 Anthropic 指控阿里「史上最大蒸馏战」、7/3 封堵中国访问）。这条是同一主线的**质变节点**：矛头第一次**反向**指向 Anthropic 自己，而且不是政策口水，是**代码级实锤**——在数百万开发者装机的 Claude Code 二进制里,藏着一段**隐写（steganography）指纹逻辑**。

对做 agent 系统的团队，这远不止一条地缘新闻。它把一个平时没人较真的问题摆到台面上：**你本机跑的 agent 工具，到底在读你什么、回传什么、你能不能审计到？** 当"负责任 AI"品牌的头牌工具都能静默植入隐蔽信道 3 个月无人察觉，"厂商声誉=安全保证"这个默认假设就正式失效了。

## 核心事实（分层）

**① 触发条件——它在找谁**
- 监控环境变量 `ANTHROPIC_BASE_URL`：一旦 API 路由**偏离** `api.anthropic.com`（即走了代理/中转），就提取代理主机名。
- 检查系统**时区**是否为 `Asia/Shanghai` 或 `Asia/Urumqi`。
- 把代理主机名与一份**解码后的 147 条域名列表**比对，含中国科技公司（百度、阿里、蚂蚁、字节）与 AI 实验室（DeepSeek、Zhipu、Moonshot、MiniMax、Stepfun），外加已知 API 转售/镜像域名；另有约 11 个 AI 实验室关键词。命中即打标。

**② 编码手法——标记怎么藏**
把每次会话 system prompt 里那句人畜无害的 `Today's date is 2026-06-30.` 改写成暗号：
- **分隔符替换**：`2026-06-30` → `2026/06/30`，标记"中国时区"。
- **Unicode 撇号替换**：在四个**视觉上完全相同**的字符（`'` `'` `ʼ` `ʹ`）间切换，标记"代理是否命中域名/关键词列表"。研究者原话——多数用户**永远不会注意到差异**。
- 关键定性（byteiota）：它**没有单发遥测包（"did not send a telemetry packet"）**，标记是搭正常请求的便车回传。所以它**不是外泄你的代码/文件**，而是给你的会话**打一个厂商可读、你不可读的地缘指纹**。

**③ 版本与发现**
- 至少从 **v2.1.91（2026-04-02 发布）** 就已静默存在，**release notes 只字未提**。
- **6/30** 由研究者 **LegitMichel777** 发现（Reddit 起爆 → GitHub 验证报告核对 v2.1.193/195/196，确认为 system prompt 内的隐蔽信道）。
- Anthropic 约 **7/1** 在 v2.1.197-198 悄悄回滚，至今**未发布详细公开 postmortem**。

**④ 后果**
- 阿里 **7/10** 把封禁从 Claude Code **扩大到全部 Anthropic AI 工具**，员工被要求改用自研 **Qoder**。这是 6/24 蒸馏战 → 7/3 Anthropic 封堵中国访问 → 7/4 阿里禁 Claude Code 的**报复性升级**。

## 关键原话

> "an experiment we launched in March that was meant to prevent account abuse from unauthorized resellers and protect against distillation."
> —— Anthropic 工程师 **Thariq Shihipar**（X），把这段代码定性为"3 月上线的实验"，用于防未授权转售商滥用账户＋防蒸馏。

时间点值得玩味：实验"3 月启动"，而 Anthropic 指控阿里的蒸馏攻击是 **4/22–6/5**、约 25,000 个欺诈账户、**28.8M** 次交互——**防蒸馏动机在事实层面成立**，但手法引爆了另一场信任危机。

## 正反观点

**辩护方（Anthropic / byteiota「The Backdoor That Wasn't」）**
- 它只**打标记不偷数据**，没有独立遥测通道，够不上"后门"的严格定义。
- 蒸馏/转售滥用是**真实且昂贵**的威胁（28.8M 次交互实锤），账户完整性与供应链完整性需要**识别谁在借代理绕过地理封锁**。在出口管制/国家安全语境下，厂商有动机做来源甄别。

**质疑方（Medium/Rahul Wale、原报道作者、安全研究者）**
- **对高级攻击者无效、却静默抓住了其他所有人**：真蒸馏方随手改时区/换代理即可绕过，反而是用 VPN/研究网关的**正常开发者**被无差别打标。
- **教科书级供应链风险**四件套：隐藏行为（hidden behavior）＋地理定向（geographic targeting）＋混淆代码（obfuscated code）＋零披露（zero disclosure）。
- **对审查日志的开发者不可见**——隐写进 Unicode 撇号，正常日志审计根本看不出来。
- **双标反噬**：一边以"史上最大蒸馏战"占据道德高地指控阿里，一边自己在工具里埋 3 个月隐蔽信道，正好击中 Anthropic 一贯的"透明/负责任"人设。

## 深度解读：对行业 + 对「做多 agent 系统的我们」

**对行业**：这是「工具中立性会过期」从推演变成**带血的实证**。AI 编码工具正沿地缘断层**信任分裂**——阿里切 Qoder、议员盯着企业用中国模型、Anthropic 反过来给中国来源打指纹。同一件事在两个方向上都在发生：**你用的工具在防着某些用户，某些用户也在防着你的工具**。头部厂商的"负责任"品牌，不能再直接换算成"可安全托管你代码库的信任"。

**对我们（可落地判断，别套话）**：
1. **把"agent 工具在本机采集什么、回传什么"升为供应商登记册一等条目**。Claude Code 读了时区、`ANTHROPIC_BASE_URL`、代理主机名——任何本机跑的 agent CLI/IDE 都是遥测面。**对出站流量做基线抓包审计**，把"不可审计的静默遥测"直接列为淘汰理由（安全敏感场景尤甚）。
2. **system prompt 与出站 payload 做规范化校验**。厂商能把标记塞进 date line 的 Unicode 撇号，攻击者/prompt injection 同样能用这条隐蔽信道。**把 system prompt 做 Unicode 归一化（NFC）＋跨版本 diff**，把"看不见的字符差异"当一等异常告警——这正是我们「MCP/工具返回默认不可信」原则该延伸到的地方。
3. **多工具冗余从加分项变生存底线**。阿里的应对就是热切换到 Qoder。我们照做：保留 Codex / Cursor / 开源 CLI 备胎＋独立 API key，**把 Claude Code 迁移演练真跑一遍**（别等被断供或不信任那天才发现迁不动）。
4. **供应链信任是会过期的资产，别拿声誉当兜底**。危险原语 allowlist、可回滚、独立验证器、出站审计——这些**自扛的控制项一个都不能省**，无论 vendor 招牌多亮。
5. **跨地缘团队把"地理/时区差别对待"写进风险登记册**。若团队含中国境内成员或走代理，vendor 的地缘指纹会实际影响你的**可用性与合规**；提前盘清敞口。
6. **反过来自查**：我们自己的 agent 产品有没有类似"为反滥用而做的静默标记"？**要做就明写进文档/release notes**——这次事件证明，隐蔽=一旦被扒就是信任核弹，透明反而是最便宜的护城河。

## 接下来盯什么（信号）
- Anthropic 是否补发**正式 postmortem**、把反滥用甄别改成**可披露/可审计**机制（决定信任能否修复）。
- 阿里禁令是否**扩散到其他中国大厂**（腾讯/字节/华为内部），或引发对等的"中国工具在美被查"。
- 是否出现**独立复现/CVE 化**，把"agent 工具隐蔽信道"做成一个安全检测品类。
- 议员/监管是否借此推**agent 工具遥测透明度**要求（呼应两周来的门控范式与州级立法碎裂）。
- 是否有厂商顺势打**"零隐蔽遥测/可审计"**差异化牌——这会成下一个供应商甄别维度。
