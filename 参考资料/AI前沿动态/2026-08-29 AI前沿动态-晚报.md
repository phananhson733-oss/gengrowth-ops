# 深度研究 · 给物理世界装上 USB 口——Anthropic 用 MHS 把 agent 的手伸进实验室和工厂

**一句话定性**：继 MCP 统一「agent↔软件」之后，Anthropic 8/27 发布 Model Hardware Standard（MHS），用同一套打法去统一「agent↔物理设备」——AI agent 第一次拿到操作显微镜、移液器、机械臂的标准接口，这是 Anthropic 首次正式进军 physical AI。

**来源**：Anthropic 官方《Previewing the Model Hardware Standard》
🔗 https://www.anthropic.com/news/model-hardware-standard-research-preview
**日期**：2026-08-27（研究预览第一阶段开启；Fortune/CNBC/Bloomberg 同日报道，HN 同期上榜）

## 为什么值得深读 / 背景

2024 年 11 月 Anthropic 发布 MCP，一年内成为整个行业「agent 连软件」的事实标准（8/24 早报刚拆过 MCP 新路线图：整个协议正在重造给无人值守的 agent）。现在同一家公司、同一套剧本——先研究预览、再和伙伴共建安全评估、最后开源——对准了下一层：**物理硬件**。

这不是凭空跳跃。8/18 Anthropic 刚发布蛋白质设计成果（Claude 自主设计 de novo 结合剂，14/15 靶点成功），当时的瓶颈就摆在那里：模型能设计，但「动手做实验」还要靠人和湿实验外包。MHS 起源正是 Anthropic 与 HHMI Janelia 研究园区的合作（源于 Arco Bast 的复杂脑成像实验自动化），本质是把「AI 做科学」链条里最后一段人肉环节——操作仪器——接口化。而外围环境同样在共振：同日 a16z 设立 $11 亿「Machine Age」硬件基金，Nvidia 正洽购 Hugging Face（$130 亿报价传闻，而 HF 的 LeRobot 恰是 MHS 首批伙伴）。物理 AI 的圈地已经开始，Anthropic 选择的武器是「开放标准」。

## 核心事实

**MHS 是什么**：一份共享规范，让 AI agent 能**发现、监控、操作**可编程物理设备（显微镜、液体处理器、机械臂、相机、传感器），把硬件集成时间从「数周到数月」压到「数小时到数分钟」。

**首批实测数据（一手公告披露）**：
- **QuEra Computing（量子计算机激光锁）**：人工脚本恢复一次激光锁需 150 秒、成功率 58%；agent 优化后 6 秒、96%；最终 700 次试验验证成功率 **99.3%**。agent 还调了 12 个相互依赖的 PID 参数，残余噪声从 15.7 mV 降到 1.55 mV（约 10 倍改善）。
- **Carnegie Mellon**：串行稀释剂量反应实验提速 **3 倍**；跨三套互不兼容接口的设备编排，集成用时 **8 小时**（厂商方案通常需数周）；自主错误恢复 + 曲线判读（R²>0.98）。
- **HHMI Janelia**：把 **7 个没有共享接口的厂商程序**统一进单一编排系统，新硬件接入从「数天的工程项目」降到「几分钟」，实现闭环双光子显微成像（斑马鱼）。
- **Genentech**：BCA 蛋白检测自动化，Claude 自主优化不同液体的流速（水 140 µL/s，粘稠 BSA 10 µL/s）——但遇到气泡类物理故障时把它当软件 bug 处理，需人类指导。
- **Tetsuwan Scientific**：9,143 次移液、300 种转移类型实测，精度预测比厂商标称改善 12-17%。

**生态阵容**：AWS（Strands Robots 库）、Danaher、Doosan Robotics、Tecan、QIAGEN、Universal Robots、Automata、MBF Bioscience、Hugging Face（LeRobot）、Raspberry Pi 均在建设或测试 MHS 集成。申请入口 modelhardwarestandard.com。

## 机制拆解：三层设计，安全压在模型之下

1. **标准化驱动层**：任何设备用「read/write」原语暴露能力（读温度/设温度），设备以标准格式可被发现，不再需要逐台写翻译程序。
2. **自然语言元数据层**：驱动带标签，允许用自然语言记录设备物理特性——重量、可调参数、**安全上限**（如激光功率封顶、机械臂速度和角度限制）。可以人写，也可以让 agent「采访」你的设备后自动生成参考文件。
3. **编排层**：MCP、命令行、代码文件（API）三种通道并行。关键模式：对长时任务，agent 把驱动命令**编译成代码文件自主执行**，而不是每步都过一遍推理——QuEra 的 6 秒恢复正是这么来的。

安全设计的核心判断是：**限制放在接口层强制执行，而不是写在 prompt 里**。设备级安全限制自动生效，官方还做了六种诱导故障（缺板、板旋转、读板机占用、相机断连、设备不可达、急停）的安全验证。这与 8/19 OpenAI pacing、8/22 SB 53 修法呼吁是同一条收敛线：**拒答不是边界，环境才是**。

## 关键原话

- Anthropic 官方：「After giving Claude the prompt, we left the model to execute autonomously.」（承接蛋白质设计的自主执行口径）；「Claude interacts with experiments and hardware in an exploratory manner, much as a scientist would.」
- Jonah Cool（Anthropic 生命科学合作负责人）：「In many cases, the science doesn't happen because you can't use the equipment.」——反 vendor lock-in 是明确卖点，对标「非常脆的专有方案」。
- Alek Kemeny（Anthropic）把 MCP 比作「AI 连软件的 USB 口」——MHS 就是 AI 连硬件的那个口。

## 正反观点

**支持方**：① 数据是硬的——QuEra 99.3%、CMU 8 小时集成、Janelia 7 系统统一，都是第三方机构实名背书的实测；② 模型无关 + 承诺开源 + 任何 harness 可经 MCP 接入，复制的是 MCP 被全行业采纳的成功路径而非封闭护城河；③ 「能力文件 + 接口层强制安全限制」是当前 agent 安全最务实的工程化方案。

**质疑方/风险**：① **监管暗礁**（TheNextWeb 点破）：欧盟机械条例 2023/1230 于 **2027-01-20** 生效，首次覆盖「AI 安全功能与自演化行为的机械」——MHS 里那份限制机械臂速度角度的能力文件，本质上**在执行安全功能**，高风险类别下自我符合性声明将不再够用，可能需要第三方认证。「写这份文件的人，可能写下的是一个受监管的安全部件」。② **物理直觉缺口是真实的**：Genentech 的气泡、QuEra 承认 Claude 无法排查需要物理理解的意外硬件故障——官方自陈「spatial and physical reasoning have limitations that still require expert oversight」。③ 没有编程接口的存量设备接不进来，adoption 依赖厂商配合；④ HN 质疑：软件 agent 出事可以回滚，物理世界的失误不可逆，后果量级完全不同（对照 FelonyBench 那条线——agent 越界已在进入执法视野）；⑤ 实验室自动化已有 SiLA 2、OPC-UA 等标准，MHS 与它们是吞并、桥接还是叠床架屋，官方只字未提（首批伙伴 Tecan、QIAGEN 恰是 SiLA 阵营核心）。

## 深度解读：对行业 + 对我们

**对行业**：① Anthropic 的「协议打法」已经成型且在复利——MCP 拿下软件层后，任何新层级（硬件、支付、身份）它都有先手优势，因为生态默认它的标准「会赢」，厂商提前站队（这次首批就有 AWS 和四家硬件大厂）。② 物理 AI 的竞争格局出现**路线分叉**：Nvidia 路线是买资产（洽购 HF、投 Perplexity）+ 芯片绑定，Google 路线是垂直行业控制平面（8/25 Gemini Enterprise Legal），Anthropic 路线是开放标准 + 科学场景切入。标准一旦开源成功，护城河不在协议本身而在「谁的模型最会用这套协议」——这和 MCP 的逻辑一模一样。③ 「AI 做科学」的闭环补上了最后一块：设计（蛋白质篇）→ 操作仪器（MHS）→ 验证，瓶颈从「能不能动手」转移到「谁来为动手的后果负责」。

**对我们（做多 agent 系统的团队），四条可执行判断**：
1. **能力文件（capability file）模式值得立刻抄**：给每个工具/设备/外部依赖写一份声明式描述——能力、可调参数、硬性安全上限——并在 harness 接口层强制执行，而不是塞进 system prompt。MHS 把这套模式做成了行业级范本，我们的软件工具层同样适用（与 8/24 MCP 路线图的 server-side enforcement 是同一方向）。
2. **「推理编排 → 编译成代码工件」是成本与可靠性的双重杠杆**：QuEra 从 150s/58% 到 6s/96% 的跃迁，来自 agent 写出确定性控制脚本、而非每步在线推理。我们的长程 agent 任务里，凡是重复执行的子流程都应该走「agent 生成 + 人/测试验证 + 固化为脚本」路径，把推理留给探索。
3. **元数据/描述文件正在变成责任载体**：欧盟机械条例的信号是——agent 读的那份「设备说明」可能成为受监管的安全部件。引申到软件侧：我们写给 agent 的工具描述、权限声明，未来在审计与追责时会被当作「设计意图证据」。从现在起把它们当正式工程工件管理（版本化、评审、测试），不是注释。
4. **物理直觉缺口 = 验证仍是限流阀**：气泡案例再次印证 8/2 苹果篇的判断——生成/操作成本趋零，验证成本没降。接物理或高后果系统的 agent 链路，人类审批点应设在「不可逆动作」前，且要给 agent 明确的「哪些异常属于物理世界」的先验，否则它会把一切故障当软件 bug 重试。

## 接下来盯什么

- **MHS 开源的时间点与治理模式**：像 MCP 一样走开放治理，还是 Anthropic 单方控制 spec——决定它是行业标准还是产品附件。
- **OpenAI / Google 是否跟进**：兼容 MHS（=标准确立）还是推竞品标准（=硬件层协议战）。一家是实验，三家是新层级。
- **与 SiLA 2 / OPC-UA / ROS 2 的关系表态**：Tecan、QIAGEN 两头下注，桥接方案出现与否决定存量实验室的迁移速度。
- **2027-01-20 欧盟机械条例生效前**，MHS 能力文件是否被正式认定为安全部件、由谁认证。
- **第一起 MHS 相关物理事故/越界事件**：对照 FelonyBench 与阿拉巴马州 AG 调查线，物理世界的 agent 事故将直接进入执法与立法视野。
- **Nvidia 洽购 Hugging Face 是否落地**：LeRobot 是 MHS 首批伙伴，若归 Nvidia，开放标准阵营第一块多米诺。
