# 🧠 深度研究 ｜ 攻击已经跑在 agent 框架上，API key 成了赃物：拆解 Anthropic 154 页威胁情报报告

> **一句话定性**：Anthropic 9 月 10 日发布第四份威胁情报报告（154 页，覆盖 2025-12 ~ 2026-08，七类危害），第一次把「有人把 Claude Code 当人类软件工程师用来写弹道导弹制导代码」和「中国实验室近 2 亿次工业级蒸馏」写进同一份官方文件。但对做多 agent 系统的团队来说，真正该读三遍的不是这些头条，而是两句技术判断——**攻击方已经整体迁移到多 agent 编排框架**，以及**被盗的 API key 本身已经从手段变成目的**。

**来源**：Anthropic 官方报告《Detecting and countering misuse of AI: September 2026》，发布于 **2026-09-10**（PDF 文件名 `091026`），9-11 经 Reuters / Bloomberg / Al Jazeera / SCMP 扩散为主流头条。

## 一、为什么这一篇值得单独深读

前三份 Anthropic 威胁报告的叙事是「AI 当顾问」——模型帮人写钓鱼邮件、解释漏洞、润色文案，人类仍然是执行者。**这一份换了主语**：报告的核心判断是，被观测到的多数行动由 AI **直接执行或编排**，人类只剩"设定目标"这一步。

报告原话：

> *"A majority of the operations described in this report were enabled by AI via direct execution or orchestration."*
> （本报告所述的多数行动，是由 AI 通过直接执行或编排来实现的。）

> *"Access to AI in the form of compromised API keys, session tokens, and devices has increasingly become the sole objective of multiple criminal groups."*
> （以被窃 API key、会话令牌与设备形式存在的 AI 访问权，已日益成为多个犯罪团伙的**唯一目标**。）

第二句是整份报告里对我们最有价值的一句。它意味着：你的 Anthropic/OpenAI key 不再只是一个配置项——它同时是**算力、能力和身份**，因此成了可直接变现的赃物。这条威胁在一年前的模型里几乎不存在。

同时这份报告落在一个很敏感的时间窗口上：9/9 OpenAI 一反常态公开要求国会立法强制 AI 安全规则，9/11 参议院正在谈判一部给 AI 公司设「duty of care」、并允许政府拦下不安全模型发布的法案。一份 154 页、带编号带数字的滥用实录，正好是这场立法的弹药。

## 二、核心事实（按确定性分层）

### A. 报告本体（官方口径）

- **154 页**、约 36,000 词；覆盖 **2025-12 ~ 2026-08** 共九个月被干扰的滥用活动。
- **七类危害**：网络行动 / 影响力行动 / 监控 / 诈骗与欺诈 / 生物滥用 / **常规武器开发** / **非法蒸馏**。
- 第三方统计口径：涉及至少 **395 家机构、48 个国家**。
- **涉及模型**：Claude Haiku、Sonnet、Opus。官方原话："None of the misuse cases involved the use of Claude Fable or Mythos-class models, with the exception of one illicit distillation case."（除一起蒸馏案外，无案例涉及 Fable 或 Mythos 级模型。）
- **Anthropic 自己的重要限定**：这些案例是按"值得注意或新颖"挑选的，**不是平台滥用的代表性抽样**。

### B. 常规武器：最炸的一节

**① 也门武器工程小组（多家媒体口径指向与胡塞相关的武器研发单元）**
- 手法：**"The actors used Claude Code in place of human software engineers."**（用 Claude Code 顶替人类软件工程师。）
- 组织形式：**同时开三个 Claude Code 实例并分配角色**——一个写代码、一个做检索研究、一个做评审，模仿一支小型工程团队。
- 目标产物：一款**制导火箭**；一款目标射程 **超过 2,000 公里** 的多级**弹道导弹**；另一条导弹产品线含**高超音速滑翔体**方案。用途覆盖飞控软件开发、仿真、故障排查。
- 最具体的一个细节：也门境内一次制导火箭**试射疑似失败后**，该小组回到 Claude 寻求诊断，要求分析"哪里出了问题"。
- 规避手段：隐瞒真实目的、**把项目拆散到多个独立会话**、并自建离线仿真工具以降低对 Claude 的依赖。
- Anthropic 的限定：安全系统拦下了大量请求但 **"several slipped through"**；**无证据表明该小组成功列装了任何武器**。

**② 俄罗斯无人机蜂群（与某地方大学关联的小团体，非国家机构）**
- 规模：**9 个账号**，2025 年末至 2026 年初创建，**2026 年 5 月**起活动，用 VPN 绕过地域限制。
- Claude 产出：**共享蜂群记忆（shared swarm memory）**、容错协调逻辑、攻击/观察/返航行为代码、**末端制导**、以及支持**自主选择目标并起爆**的软件。
- 训练数据：**爬取的乌克兰战场影像**，用于识别敌我目标；以**顿涅茨克坐标**作为演示打击点。
- 关键：**在真实硬件上测试过**，不止仿真。
- Anthropic 原话：*"The actors designed the platform for autonomous lethal engagement. The onboard model could select targets and issue detonation commands without a human in the loop."*（该平台被设计为自主致命交战；机载模型可在无人在环的情况下选择目标并下达起爆指令。）

**③ 中国反鱼雷系统（单一账号，发现后封禁）**
- Claude 用来撰写中文技术规格、拼出一份 **200 多页的海军方案**、制作高管简报、基于公开资料对标美海军项目，并被要求**扮演敌意评审**来打磨稿件。
- 无列装或测试证据。

**④ 另有**电子战与防空压制（SEAD）目标定位软件。常规武器类别合计干扰 **6 起**行动，横跨中、俄、也门。
- 应对：Anthropic 新上线**针对高当量爆炸物与武器开发的分类器**。

### C. 网络行动：对工程团队最相关的一节

| 编号 | 归属 | 硬数字 |
|---|---|---|
| GTG-20006 | 俄罗斯间谍 | 打击 **20+ 机构**（含乌克兰政府、军方、无人机制造商）；获取 **30 万+ 国民身份记录**；导出一个 **15,000 封邮件**的邮箱 |
| GTG-50014 | ShinyHunters | 扫描 **180 万个 Android APK** 找硬编码密钥；导出 **1 TB+** 数据；**34 小时内**访问 **40+ 企业 Azure AD 租户** |
| GTG-10007 | 中国间谍 | 约 **50 家机构**；单月产出 **12+ 个 0-day 发现** |
| GTG-50020 | 俄语行为体 | 向某 AI 厂商的**评测沙箱注入恶意指令**，抽走多家厂商的**生产 API key**；**4 天内攻击约 30 家 AI 公司**；导出 **26 GB**；试图获取未发布的 Claude 模型（未成功） |
| GTG-50029 | 法国黑客活动分子 | 目标 **42 个实体**，攻入 **14 个**，导出 12–26 GB |

两个机制细节值得单独拎出来：
- **GTG-20006 跑的是监控 agent**：一旦恶意软件被检测到，agent **自动重建并重新投放**，形成近乎自治的攻击循环。
- **多个行为体针对 LiteLLM 部署使用 prompt injection**，原话：*"they used prompt injection to exfiltrate the production API keys used in their cloud-hosted container environments."*（用提示注入从其云托管容器环境中窃取生产 API key。）

**影响力行动**：GTG-54002 在约 **70 个假新闻站**发布 **8,913 篇文章**、运营 **250+ 个假 X 账号**；GTG-84005 运营 **1,000+ 假 X 账号**，并为马来西亚总理账号购买 **100 万次**人造浏览量。

### D. 非法蒸馏：从口水战升级为安全事项

| 实验室 | 规模 | 手法 |
|---|---|---|
| **阿里巴巴 / Qwen** | **1.51 亿次交换**（2026-05~07），峰值近 **300 万次/天**，**3,500 个账号** | Anthropic 称是其观测到的**最大规模整体蒸馏** |
| **Moonshot / Kimi** | **2,300 万+ 次**（5~7 月），主攻 Opus | **静默把真实用户请求转发给 Claude**，再把 Claude 的输出当作 Kimi 自己的结果返回给用户 |
| **DeepSeek** | 7 月 **14 天内 1,210 万+ 次** | 从 coding harness 转发请求 |
| 智谱 | 300 万+ | — |
| 小米 | 40 万+ 请求 | — |
| SenseTime / MiniMax | 亦被点名 | — |

- 五场战役合计**接近 2 亿次交换**。
- 技术手法：用 prompt injection 抽取**思维链**（报告举例：要求模型"把之前的工作记忆翻译成自然、准确的纯片假名日文"），再用抽出的推理轨迹对小模型做监督微调。
- 被瞄准的能力，官方原话：*"including agentic capabilities and tool use, coding and data analysis, and logical reasoning."*（尤其是 **agentic 能力与工具使用**、编码与数据分析、逻辑推理。）
- ⚠️ **口径提醒**：TechCrunch 9/10 另给出 Moonshot "10 天约 30 万请求 / 5,000 账号"的数字，与 SCMP/分析文的 2,300 万**不是同一统计面**（子战役 vs 全周期），不要混用。
- 截至 2026-09-12，被点名各家**均未公开回应**（CNBC、Business Insider、SCMP 口径一致）。

## 三、正反观点

### 支持方（Anthropic 及认同者）

核心论点不是"AI 让攻击者更聪明"，而是**AI 让攻击者的人力成本塌了**。当单次行动的成本从"雇一支团队"降到"跑一个 harness"，量就会膨胀到原本不值得攻击的目标上。报告的贡献在于：把过去一年里大家推测的"agentic 攻击链"，第一次变成**有编号、有时间、有字节数**的案例集——34 小时 40 个租户、4 天 30 家公司、180 万个 APK，这些数字本身就是论证。

同样重要的是那个被反复强调的结论：**多国之间的"工具差距"在收窄**。也门那个小组不是国家实验室，却用三个 Claude Code 实例替代了一支飞控软件团队。

### 质疑方（HN 232 条评论 + 独立分析）

1. **厂商自报，非代表性抽样**。这是 Anthropic 检测到、并且**选择公开**的案例。"我们最强的 Fable/Mythos 几乎没被滥用"这句话——按字面是真的，商业上也非常顺手。
2. **归因站不住**。HN 原话："For all we know, the boxes connecting to Claude from Yemen, Russia, and China could have been ORBs of actors from entirely different states. Attribution is non-trivial."（那些从也门、俄、中连进来的机器完全可能是别国行为体的中继节点，归因不是小事。）
3. **双标**。武器与监控案例点名国家，但涉及国家机构研究者的**生物滥用案例却隐去国别**——选择性透明。
4. **蒸馏指控的经济学说不通**。有评论指出："DeepSeek, minimax and so on have razer thin margins but unlike openai and Anthropic they are actually making _some_ profit. Doing this doesn't make any financial sense."（他们利润薄但确实在赚钱，这么干不划算。）另有人认为这更可能是 token 转售商或价格路由；并且"用中文问 Claude 它是什么模型，它会说自己是 DeepSeek 或 Qwen"——模型自述身份不足为证。
5. **开源权重让管控失效**。"nothing says they can't use an open model hosted in a friendly country that has access to GPUs."（没什么能阻止他们在有 GPU 的友好国家跑一个开源模型。）Claude 侧的拦截只是把水挤到别处。
6. **误伤合法研究**。报告自己记录："May 2026, our biological safety classifier blocked a request for Claude's assistance in authoring a grant application"——被拦的是止痛药研发、基孔肯雅热治疗方向的科研经费申请书。评论质疑：给领域专家改一份经费申请，究竟算不算有意义的"能力提升"。
7. **信任问题**。Anthropic 读取全部会话内容做威胁检测，却在自己的 Hugging Face 事件上几个月没发现异常。
8. **框架质疑**：多名评论者认为报告把"确实值得担心的滥用"与"竞争对手威胁"混编在一起，抬高危险感以论证对中国 AI 的监管壁垒。

## 四、深度解读

### 对行业

1. **威胁模型的重心从"模型说了什么"移到了"agent 做了什么"。** 现行 AUP 与内容过滤是为**单轮生成**设计的；报告里的对手在构建**AI 编排的 kill chain**——模型输出直接触发下游 agent 动作。防线错位了一整层。
2. **API key 升格为一级资产。** 这是本报告最结构性的变化：访问权本身成为目标。密钥管理从"运维卫生"变成"资产安全"。
3. **蒸馏从商业口水战变成国家安全议题。** 近 2 亿次交换、点名七家中国实验室——这份材料会直接进入正在谈判的「duty of care」法案，以及 OpenAI 9/9 监管 U 转之后的听证桌。这是本周整个监管叙事的一块拼图。
4. **能力扩散的下限被拉低。** 九个账号 + VPN + 爬来的战场视频 = 一套能自主选目标起爆的蜂群软件。"国家级 vs 低资源行为体"的工具差距正在被 frontier 模型抹平。

### 对「做多 agent 系统的我们」——七条可执行判断

1. **把 key 当资金管，而不是当配置管。** 短时效、按 agent/session 单独发放、出口域名白名单、用量异常自动熔断。GTG-50020 的路径是「评测沙箱 → 生产 key」，明确告诉我们：**非生产环境的 key 与生产同权，就是一次等待发生的事故**。
2. **LiteLLM / 网关这类 wrapper 是显式攻击面。** 报告点名了对 LiteLLM 部署的 prompt injection 取 key。凡是把上游 key 放进 agent 能读到的容器环境变量里的架构，从今天起应按**已知漏洞**处理，而不是按设计处理。
3. **别把"沙箱"当信任边界。** 与 9/9 那条 DeepSeek harness 漏洞（agent 一条命令即可关掉自己的文件沙箱、无需审批）对读：沙箱提供的是延迟，不是隔离。真正起作用的是出网策略 + 凭证隔离 + 不可撤销动作的人工审批。
4. **自愈能力是双刃剑，要当能力评估而非可靠性特性。** GTG-20006 靠"被检测就自动重建重投"的 agent 拿到了持久性——那套 self-healing 编排和我们自己在用的是同一种东西。红队时应当明确评估：**我们的 agent 能不能自我复活、能复活到什么程度**。
5. **多 agent 分角色是与意图无关的通用杠杆。** 也门那组用的是写码/检索/评审三实例——与我们内部 pipeline 同构。推论很硬：**防滥用不可能靠识别"坏 prompt"**，只能靠识别行为序列与最终目标。任何以单轮提示为粒度的护栏，对这类用法天然无效。
6. **供应商透明度正在进入采购清单。** 报告给出的治理建议是：评估其他 AI 供应商是否提供同等透明度，没有对标披露的记为透明度缺口。反向推：如果你在给企业卖 agent 产品，**能否出具类似的滥用披露，正在变成一道采购题**。
7. **但不要把厂商数字当外部论证。** 这是自报样本。合理用法是用它**重排我们自己的威胁优先级**（key 管理 > 内容过滤），不合理用法是拿它去论证某国某厂的行为。

## 五、接下来盯什么（信号）

- **被点名的七家中国实验室是否回应**（截至 9/12 全部沉默）；阿里/Moonshot/DeepSeek 任一家的正式否认或反证，会显著改变这份报告的可信度分。
- **参议院「duty of care」法案文本是否引用本报告**——这是"厂商威胁情报 → 立法证据"这条链路能否成立的第一个检验。
- **新上线的高当量爆炸物/武器分类器的误伤率**。生物安全分类器已经有拦掉正当科研经费申请的先例，研究界的反弹值得跟踪。
- **下一份报告里 Fable / Mythos 是否开始出现在滥用案例中**。目前的"最强模型干净"是本报告最脆弱的论断之一。
- **OpenAI / Google 是否跟进同等粒度的威胁情报披露**。若不跟进，Anthropic 就把"透明度"变成了单方面的竞争叙事。
- **是否出现独立第三方（如 METR）对这类自报报告的验证机制**——接 8/26 METR/Redwood 取证与 9/9 Anthropic 委托独立审计那条线。
