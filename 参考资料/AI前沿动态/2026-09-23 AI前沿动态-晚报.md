# 深度研究 · 「以为 AI 会替我们查过」——五角大楼 Minab 学校误炸调查，第一次把「过度依赖 AI」写进致命事故的正式归因

**一句话定性**：这不是「AI 失控」，而是一条被 AI 压缩了几个小时的决策链，拆掉了原本兜底的人、却没人给 AI 交代「兜底」这件事——这是 agent 时代「责任真空」的第一个有尸体的案例。

**来源**：Bloomberg 调查报道《Inside US Military 'Kill Chain' That Destroyed an Iranian School》（2026-09-18 周五）；后续报道《US Military Modifies AI, Combat Targeting After Iran Minab School Strike》（2026-09-22）
🔗 原始链接：https://www.bloomberg.com/graphics/2026-iran-school-attack/
🔗 后续：https://www.bloomberg.com/news/articles/2026-09-22/us-military-modifies-ai-combat-targeting-after-iran-minab-school-strike

## 一、为什么值得深读

- **第一次有官方调查把「overreliance on AI」列为致死事故成因之一**。此前所有 AI 事故（沙箱越界、agent 删库、幻觉引用）都是财产/声誉损失；这次是 2026-02-28 两枚战斧导弹、150+ 人死亡、其中至少 123 名儿童。
- **链条上有前沿模型**：Maven Smart System 是 Palantir 承建、合同上限 13 亿美元的目标生成/战场管理平台；据 Military Times 3 月报道，其中嵌入了 Anthropic 的 Claude 用于目标排序与自动生成法律依据。Amodei 6 月曾公开说「不知道 Claude 在这次打击中扮演了什么角色」——本轮调查仍未单独点名 Claude 的具体作用。
- **失败模式与我们做的多 agent 系统同构**：数据源陈旧 + 系统之间没打通 + 人工审核环节被裁 + 使用者对系统能力的错误预期 + 吞吐量压垮验证。把「目标」换成「工单/合同/代码变更」，这就是任何 agent 流水线的事故剧本。
- **后续动作已经发生（9/22）**：CENTCOM 不是减少 AI，而是**给 Maven 加了几十项升级**、加更多 AI 做核查。这决定了「AI 出事 → 用更多 AI 修」将成为行业默认反应。

## 二、核心事实（分层）

**事件本身**
- 时间：2026-02-28 伊朗战争首日；目标：米纳布（Minab）Shajarah Tayyebeh 小学；学校距一处 IRGC 海军设施不足 100 码（约 90 米），中间有围墙隔开。
- 伤亡：Bloomberg/五角大楼口径「150 余人死亡，至少 123 名儿童」（Wikipedia 统计 156 人；部分评论文章引 168/170，口径不一，本文以官方调查口径为准）。
- 节奏：战争首 24 小时打击超过 1,000 个目标；学校是 90 秒内 9 次初始打击中的第 4 个建筑。

**调查指认的「级联式可预防失败」（cascade of preventable failures）**
1. **陈旧数据**：军方数据库多年把该院落标为军事设施。商业卫星图像显示学校 2017 年已完工、有独立入口与围墙，2018 年已能看到操场、足球场标线；NYT 称用于打击的卫星图像「七年未更新」。学校甚至有活跃的网站和社交媒体。
2. **信息孤岛**：一名分析员**早在 2019 年就注意到变化并录入了电子备注**——但那个系统**没有接入**支撑目标选择的主情报数据库。
3. **对 AI 的错误预期**：部分 CENTCOM 人员「expected Maven to flag stale records or contradictions」（期待 Maven 标出过期记录或矛盾），但 Maven 并非为此设计；调查也没搞清楚他们为何有此预期。
4. **人工兜底被拆**：在国防部长 Hegseth 指令下，平民伤害缓解（CHM）团队全军裁减约 90%，降到不足 20 人；**CENTCOM 的 CHM 团队从 10 人减到 1 人**；打击前**没有任何 CHM 官员审查过 Minab 这个点位**。
5. **速度压缩验证**：传统流程要经过情报分析员、图像专家、targeteer、律师、指挥官、发射单位；Maven 把「数小时的工作压缩到几分钟」。

**各方回应**
- Palantir：公司「is not responsible for the underlying data nor identifying intelligence deficiencies」（不对底层数据负责，也不负责识别情报缺陷）；「AI 能快速处理情报，但无法纠正输入的错误信息」。但同时承认事后新增功能，用于「re-review underlying intelligence to identify factors that would disqualify a target and flag inconsistencies and inaccuracies that human review may have missed」，据称「已经抓到一些异常」。
- 五角大楼：事件「仍在调查中」。白宫官员：「The United States does not target civilians.」特朗普 3 月曾称「在我看来……是伊朗干的」。
- 联合国独立国际事实调查团（9/18）：有「合理理由」认定美方实施了不分皂白的攻击、构成战争罪，美方「未履行核实学校地位的义务」。
- 国会：3/11 共 46 名参议员、另有 120 余名众议员致函追问 Maven 在目标识别中的作用，五角大楼未公开答复。

**9/22 后续：CENTCOM 的整改**（据 Bloomberg 9/22 报道摘要）
- 重做「刷新与复核计划目标」的流程与工作流；
- 新增开源数据流，用于追踪平民活动；
- 对 Maven 做**数十项升级**，包括新的情报梳理方式，帮助**区分建筑的实际功能**。

## 三、机制拆解：这不是模型错了，是「系统边界」错了

把这条杀伤链抽象成一个多 agent 流水线：

```
[军方主情报库] ──(陈旧标签: 军事设施)──▶ [Maven: 融合/排序/生成目标包]
[分析员备注系统]  ──(2019 已有更正, 未连接)──╳
                                              ▼
                              [人工复核: CHM 10→1, 未审此点位]
                                              ▼
                                  [指挥决策 + 发射]  (24h 内 1000+ 目标)
```

四个结构性缺陷，每一个我们在 agent 系统里都见过：

1. **Garbage in, authoritative out**。Maven 输出的是结构化、带置信感的「目标包」，把一条 7 年未更新的标签包装成了「今天刚算出来的推荐」。**格式的权威感掩盖了数据的年龄**。
2. **负样本通道断了**。唯一能纠错的信息（2019 年分析员备注）存在于一个没接入的系统。系统越自动化，**没被接进来的数据就越等于不存在**。
3. **能力边界没有被写成契约**。使用者以为 Maven「会查冲突」，设计者从没承诺过。没有任何地方把「本系统不做数据新鲜度校验」显式地告诉下游——这是典型的**隐式职责假设**。
4. **吞吐量 × 固定错误率 = 更多绝对伤害**。Quincy Institute 的 Feldstein 原话：「even if there is more accuracy, because the number of targets is so much vaster, the ultimate number of civilians harmed is likely far higher.」AI 让目标数从每天几十变成每小时上千，而人工复核能力同时被砍掉 90%——**验证带宽和生成带宽的剪刀差**才是真正的致命参数。

关于准确率的一个参考数字（Military Times 3 月报道，非本次调查结论）：Maven 整体准确率约 60%，人类分析员约 84%，恶劣条件下低于 30%；空军 ISR 官员 Simpson 评价一套早期实验性目标 AI：「It was confidently wrong」。

## 四、关键原话

- 调查定性：「a cascade of preventable failures」「an array of missed opportunities」。
- Palantir：「is not responsible for the underlying data nor identifying intelligence deficiencies.」
- 前 CENTCOM 情报主任 Karen Gibson 中将：「A commander somewhere will ultimately be held responsible — not a machine or a software engineer.」
- Joseph Busby（《The Banality of AI Targeting》）：「The decision to kill had been diluted to the point at which no one could be held directly accountable.」
- HRW 的 Deborah Brown：「evidence doesn't suggest that this is limiting the harm.」

## 五、正反观点

**「不是 AI 的错」一方**
- 数据是人维护的、CHM 是人裁的、打击是人批准的；Maven 按设计工作。Aero Center 的 Ihor Matviyuk：「The main problem was not the AI — it was how close the military object was to the school.」前军方官员（Semafor）：「Humans — not AI — are to blame.」
- Palantir 与军方主张：AI 只是加速器，正确做法是**加更多 AI 核查层**（9/22 整改正是这个方向），而且整改后「已经抓到一些异常」。
- 把事故归咎于「AI」反而会让真正的决策者（裁撤 CHM 的人、批准速度优先的人）脱责。

**「AI 就是问题的一部分」一方**
- Busby / Quincy Institute：「系统恰恰按设计运行」这句话本身就是控诉——设计目标就是速度，而速度正是用来绕开人的。AI 目标平台的真正功能是**稀释责任**，让每个人都能说「是系统推荐的」。
- 「更多 AI 修 AI」没有实证：五角大楼从未公开证明 AI 降低了平民伤亡；Feldstein 的规模论证说明，即便精度提升，总伤害仍可能上升。
- 调查 7 个月才出、依赖媒体披露，联合国已给出战争罪认定——问责机制本身在失灵。

**我们的判断**：两边都对一半。AI 不是事故的「原因」，而是事故的**放大器与遮蔽器**：它放大了吞吐量、遮蔽了数据年龄和责任归属。真正可操作的教训不在「AI 该不该用」，而在「用 AI 时谁对哪一段负责，以及这件事有没有被写下来」。

## 六、深度解读

**对行业**
1. **「人在环路中（human-in-the-loop）」正在变成摆设式合规**。这次有人在环路里——但环路里的人从 10 个变成 1 个，面对的是每小时上千个候选。HITL 的有效性必须用「复核带宽 / 生成速率」来衡量，而不是用「流程里有没有一个人签字」。预计欧盟 AI Act 高风险条款、各国军用 AI 规范会开始讨论**量化的复核比例**。
2. **前沿实验室的「可接受使用」边界将被重新审视**。Claude 被报道嵌在 Maven 里，Anthropic 与五角大楼此前就「自主武器」与「6 个月撤出」有过公开拉锯。今晚（9/23 纽约时间）联合国安理会首次请 OpenAI、Anthropic、DeepSeek、Moonshot 就 AI 风险作简报——Minab 几乎必然被提及。**模型供应商对下游集成的责任边界**，会从伦理话题变成合同和监管话题。
3. **「用更多 AI 修 AI」成为默认路径**。CENTCOM 的整改和 Palantir 的新功能都是加核查模型，而不是恢复人手。这对卖 eval / 监控 / 数据治理的公司是利好，也意味着「验证层」会成为 agent 基础设施的新标配品类。

**对「做多 agent 系统的我们」——可以直接落地的 6 条**
1. **每条事实都带「数据年龄」**。任何从知识库、缓存、向量库检索出的事实，在 agent 间传递时必须带 `as_of` 时间戳；超过阈值的，下游 agent 必须降级为「待核实」而不是直接采用。我们自己的 research-monitor 就踩过「聚合站把两周旧闻当今日」的坑——同一类 bug。
2. **把「本 agent 不负责什么」写进契约**。每个 agent/工具的描述里，除了能力还要写**非职责**（例如「不校验数据新鲜度」「不做冲突检测」）。下游 agent 和人类操作员最危险的，就是 Minab 式的「我以为它会查」。
3. **负样本通道必须接入主链路**。人工更正、用户纠错、历史事故标注，不能停留在旁路系统（日志、备注、另一个表）。检查：我们的「纠错」有没有真正回流到 agent 下一次决策读取的那个源？
4. **监控「生成速率 / 复核容量」比值**。给每条流水线设一个硬上限：当候选产出速度超过人工或验证 agent 的处理能力时，**自动降速或排队，而不是让复核抽样率悄悄下降**。
5. **不可逆动作前做「反证检索」**。对删除、发送、付款、发布等不可逆动作，强制一个独立 agent 专门去找「这个动作不该做的证据」（类似 Palantir 事后加的「disqualifying factors」复查）。关键是这个 agent 要**读不同的数据源**，否则只是同一份陈旧数据复读两遍。
6. **责任归属可审计**。每个最终动作都应能回溯到：哪个 agent 推荐、依据哪些数据（及其年龄）、哪个人/哪条规则批准。出了事能说清楚「谁对哪一段负责」，这是 Minab 调查花 7 个月都没做到的。

## 七、接下来盯什么

- **9/23 联合国安理会 AI 会议**：Altman 现场、Amodei 远程、DeepSeek/Moonshot 发言；看是否有人点名 Minab / Maven，以及 Anthropic 对 Claude 在军用集成中角色的表态。
- **五角大楼正式调查报告是否公开**、是否有具体个人被问责（Gibson 中将说的「commander somewhere」）。
- **Anthropic / OpenAI 使用政策修订**：是否对「目标选择 / 杀伤链」集成增加明确限制或审计要求。
- **国会动作**：46 名参议员与 120+ 名众议员的追问是否升级为听证或 NDAA 修正案（如强制 CHM 最低编制、AI 目标系统的复核比例）。
- **Maven「数十项升级」的细节**：是否包括数据新鲜度校验、跨库冲突检测——这些设计会成为民用 agent 验证层的参考。
