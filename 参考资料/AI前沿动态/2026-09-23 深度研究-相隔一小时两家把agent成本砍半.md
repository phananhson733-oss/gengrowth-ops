# 🧠 深度研究 ｜ 相隔一小时，两家把 agent 的单位成本砍掉一半——而智商几乎没动

> **一句话定性**：2026-09-22 是前沿实验室第一次在**同一天、同一个方向**正面对撞——对撞的方向不是能力，是**成本**。真正的信号不是「降价了」，而是这一代的进步条被整体从「更聪明」挪到了「更便宜、更省 token」；而且独立评测显示，降价带来的收益会被模型自己变大的 token 胃口吃掉一大半——**每 token 便宜 ≠ 每任务便宜**。

**来源**：Anthropic《Introducing Claude Opus 5.5》（2026-09-22 官方）＋ OpenAI 同日发布 GPT-6 Sol / GPT-6 Luna。按 Simon Willison 的记录，两次发布**相隔约一小时**（另有口径称约 90 分钟）。

## 一、为什么这一条值得单独深读

过去两年的发布节奏是「你发一个更强的，我发一个更强的」。9/22 反过来了：Anthropic 把 Opus 从 $5/$25 降到 $4/$20，**刚好贴上 OpenAI 当时 GPT-5.6 Sol 的价位**；约一小时后，OpenAI 直接把 GPT-6 Sol 定在 $2/$10——把自己上一代同名产品**砍半**，并反手压到 Opus 5.5 之下。

这不是巧合式撞车，是**贴身还击**。它意味着两件事同时成立：

1. 前沿厂商已经认定，当前这一代的**主战场是 agent 的长时运行经济性**，不是排行榜分数；
2. 两家都有足够的推理成本冗余，能在一小时内完成一次对价格的战术响应——说明**毛利空间比外界想象得厚**。

对做多 agent 系统的团队，这是近几个月最直接影响预算表的一天。

## 二、核心事实（分层）

### A. Claude Opus 5.5（Anthropic 官方口径）

**价格**
- 输入 **$4** / 输出 **$20** per MTok（Opus 5 为 $5/$25，**−20%**）
- **缓存读 $0.50 → $0.20，−60%**。这是结构性调整：从 input 价的 10% 降到 **5%**
- 缓存写 $6.25 → $5；Batch $2/$10；Fast 档 $8/$40
- 官方称典型工作负载**总成本低约 40%**——因为除了单价，它还**少用 token**

**规格**：1M 上下文；同步输出上限 128K；Batch 输出可到 300K（需 beta header）；知识截止 2026-06；effort 分 low/medium(默认)/high/xhigh/max。

**官方基准**（对比 Fable 5.1 / Opus 5）
| 基准 | Opus 5.5 | Fable 5.1 | Opus 5 |
|---|---|---|---|
| Terminal-Bench 4.0 | **66.4%** | 55.8% | 52.3% |
| FrontierCode v1.1 | **54.4%** | 50.3% | 48.0% |
| CursorBench 4.0 | **57.8%** | 51.8% | 46.6% |
| AutomationBench | **40.0%** | 31.4% | 26.9% |
| GDPval-AA v2.1 | **1846 Elo** | 1735 | 1708 |
| OSWorld 2.0（partial） | **81.8%** | — | 74.0% |
| HLE（带工具） | **67.7%** | — | 63.6% |

FrontierCode 上 54.4% 对 GPT-6 Astra 的 53.3%——而 Astra 是 $10/$50。官方称默认档即可胜过 Opus 5 的 max 档，**成本约为其五分之一**。

**Token 效率（这才是 40% 的来源）**
- BigFinance Bench：输出 token **−50%**
- 命令行任务：调用次数 **−40%**，token 用量约**减半**
- Rogo 评测：输出 token **−60%**；Factory 评测：**−20~25%**

**厂商展示的真实案例**（注意：均为 vendor-selected）
- 一位测试方在**不到一天**内完成 **68 万行**代码迁移
- 另一方**不到 3 小时**审计并修复 **20 万行**代码库（Opus 5 需 20+ 小时）
- HAProxy C→Rust 翻译：**9.5 小时**完成，Fable 5.1 为 12 小时，成本低 **51%**

**安全**：官方称越界尝试比 Opus 5 **少约 85%**；prompt injection 成功率在 Gray Swan 上并列最低；网络安全类任务被**路由到 Opus 4.8**，生物类任务需额外验证。

### B. GPT-6 Sol / GPT-6 Luna（OpenAI，同日）

- **Sol：$2/$10**（GPT-5.6 Sol 为 $4/$20，砍半），缓存读 $0.20（input 的 10%）
- **Luna：$0.10/$0.50**（GPT-5.6 Luna 为 $0.20/$1.20），缓存读 **$0.01**
- AutomationBench：Sol 在 xhigh/max 档 **33.2% @ $0.27/task**，而 Opus 5 max 档 26.9% 且成本是其 **11.1 倍**
- DeepSWE v1.1：Sol max **68.8%**，基本追平 Fable 5（69.9% @ xhigh），成本约 **20%**
- FrontierCode 1.1：Sol **49.3% @ $2.14/task** vs Fable 5.1 **50.3% @ $12.83/task**
- Luna max 档的表现约等于 Opus 5 / Fable 5 的 medium 档，成本低 **93% / 96%**

**但**：Artificial Analysis Intelligence Index 上，Sol 仅从 **47 升到 48**，Luna **停在 37**。the-decoder 的判词是：「**per-task 成本砍半，智能分数停在 GPT-5.6 水平**」。更不利的是 GDPval-AA v2.1 上出现**回归**——Sol 掉约 **100 Elo**，Luna 掉约 **75 Elo**，归因于呈现质量下降与结果不完整。

## 三、机制拆解：为什么「缓存读降 60%」比「输入降 20%」重要得多

一个长时 agent 的账单结构和聊天机器人完全不同。聊天是一次性的大输入 + 小输出；agent loop 是**同一份上下文被反复重读几十上百次**——系统提示、工具定义、已读文件、历史轨迹，每一轮都要再喂一遍。在成熟的 agent 实现里，**缓存读往往是第一大成本项**，而不是新输入。

所以把缓存读从 input 价的 10% 压到 **5%**，等于对「上下文越滚越长」这件事做了一次结构性减税。它的受益者非常明确：**轮次多、上下文长、任务跑得久**的工作负载——也就是真正的 agent，而不是包装成 agent 的单次调用。

反过来看 OpenAI：GPT-6 Sol 的缓存读也是 $0.20，**与 Opus 5.5 完全相同**。也就是说，**两家的价差不在缓存层，而在新鲜输入与输出上**（$2/$10 vs $4/$20）。对长上下文重读型负载，两家的差距比表头价差小；对大量生成型负载，差距才拉开。这个区分直接决定你该把哪类任务放到哪家。

## 四、正反观点

### 支持方：这是 agent 从 demo 走向生产的价格拐点

- 单价、token 用量、速度**三条线同时改善**，三者相乘才是 40% 的来源，而不是单纯打折
- Artificial Analysis 独立确认 Opus 5.5 拿到 **Intelligence Index 58 分**，「我们测过的最高分，且领先数点」，并在 10 项评测中**领先 6 项**（HLE 61.4%、SciCode 66.9%、GDPval-AA、AA-Briefcase、AA-Omniscience、AutomationBench-AA）
- 价格下探的幅度足以改写「自托管开源权重模型」的算账逻辑——GPT-6 Luna 的定价已经压到主流开源推理服务的区间内

### 质疑方：便宜的是 token，不是任务

这一面更值得你读两遍：

- **token 胃口把折扣吃掉了**。Artificial Analysis 同架测量：Opus 5.5 在 max 档**每题约消耗 119K 输出 token**，而 GPT-6 Astra 只用 **27K**——约 **4.4 倍**。AA 的原话是，Opus 5.5「在每任务成本上与 Opus 5 持平，尽管输出 token 是 1.6 倍」。**单价降 20%、用量涨 60% ≈ 打平**。官方宣称的 40% 省钱，成立条件是你真的让它少用 token。
- **官方数与独立数存在口径差**。Terminal-Bench 4.0：官方 66.4%，AA 同架只有 **59.6%**（与 GPT-6 Astra 打平）。不是造假，是 harness 与 effort 档不同——但意味着**你不能拿官方数字做预算假设**。
- **Opus 5.5 并非全面领先**。AA 口径下它在 CritPt（物理研究）、AA-LCR（长上下文推理）、GDP.pdf 上落后；官方口径下 Terminal-Bench-Science（58.7% vs GPT-6 Astra 64.6%）、AutomationBench（40.0% vs 41.4%）也落后。
- **max 档有失控风险**。Simon Willison 实测：max 思考等级在一个简单 SVG 任务上**把 128K 输出上限想爆了**，耗时 20 分钟、花掉 $2.56。他的结论很直接：「**if it over-thinks to breaking point on a stupid SVG prompt I don't trust it not to do the same for more interesting work.**」
- **Vals AI 测到垂直场景回归**：法律检索、医疗编码、税务 agent 上相对前代出现退步。
- **OpenAI 这一侧几乎没有能力增益**：Index 47→48、Luna 原地不动、GDPval-AA 上还掉了约 100 Elo。这是一次**纯粹的价格动作**。

## 五、深度解读：对行业，以及对做多 agent 系统的我们

**对行业**：这一代的竞争维度正式从「谁更聪明」切换到「**谁能让同一件事更便宜地跑完**」。两家在一小时内互相贴价，说明前沿能力的差异已经小到**不足以支撑价格溢价**——这是能力同质化的典型信号，也解释了为什么两边都把叙事重心放在「每任务成本」而不是「基准分数」。一个附带效应：当闭源前沿把价格压到开源自托管的区间，「为了省钱而自己搭」这条理由正在失效，剩下的理由只有数据主权与可控性。另一个观察值得记下：Anthropic 一边在公开场合呼吁行业减速，一边发旗舰并挑起价格战——**主张与商业动作的张力，已经是一个稳定的观察项，不是偶发。**

**对我们，六条可执行判断：**

**① 立刻重测账单基线，但要按「每任务成本」而不是「每 token 单价」。** 今天最容易犯的错，是看到 −20%/−60% 就直接改预算。真实变量是 token 用量。做法：取 3–5 条你最贵的真实 agent 轨迹，在新旧模型上各跑一遍，**记录的是完成一次任务的总花费和总轮次**，不是单价。AA 的 119K vs 27K 说明这个差异可以大到 4 倍。

**② 先去掉继承来的 effort 设置，从 medium 重新起步。** 官方 40% 的省钱口径是 **default 比 default**（Opus 5.5 medium vs Opus 5 high）。同名 effort 档下，Opus 5.5 每轮想得比 Opus 5 **更多**——所以**把 effort 钉死在 high 的团队会完整地失去这次降价**。另外注意：**中途改 effort 会让 prompt cache 失效**，别在会话中间调档。

**③ max 档进黑名单，除非有硬性输出上限保护。** Willison 的 SVG 案例不是段子，是 agent loop 的真实失效模式：无人值守时，一次过度思考就能同时烧掉时间、预算和输出配额。我们的立场应该是：**默认 medium，按任务类型升到 high，max 仅在人工在场时使用**，并对单次调用设 token 与时长熔断。

**④ 这次的 breaking changes 必须排进本周，它们会静默打断现有 agent。** 清单：
- `thinking: {"type":"disabled"}` 直接返回 **400** —— thinking 已不可关闭，改用 effort 控制深度
- `tool_choice: "any"` 或指定 tool 的强制用法**报 400** —— 改 `auto` + `strict: true`，把工具适用范围写进 prompt
- thinking blocks **不可变**：系统提示/工具/历史消息变更后重放会报错（2026-08-31 后创建的账号默认）—— 会话要做成 **append-only**，指令更新走会话中的 system message
- `computer_20251124` 在 Claude API 与 Google Cloud 上**被拒**，迁到 `computer_toolset_20260801`（Bedrock 仍接受旧版）
- **静默变化**：工具调用之间的内部说明现在以 `display: "omitted"` 的 thinking block 出现，**默认对用户不可见**——如果你的产品靠它渲染进度条，会无声消失

**⑤ 给无人值守 loop 加「提前收工」检测。** Opus 5.5 在长任务上有时会**以一段文字汇报结尾，而不是发出下一个 tool call**。对自动化编排来说这等价于静默中断。处理方式：把纯文本轮当作「进度报告」而非「任务完成」，维护外部任务清单做真实完成判定，自动追加续跑 prompt，但**限制 2–3 次**以免陷入死循环。同时补上 `stop_reason: "refusal"` 的处理分支——拒答类目已扩大到生物与推理提取，建议配 fallback 模型。

**⑥ 把路由做成按成本结构分流，而不是按品牌忠诚。** 两家缓存读同为 $0.20 这个事实，给出了清晰的切分线：**长上下文、多轮重读型任务**（代码库审计、长文档 agent）两家成本接近，按能力选（Opus 5.5 在 Terminal-Bench 同架 52.5% vs Sol 43.9%）；**大量新鲜输入/大量生成型任务**（批量抽取、分类、改写）价差是实打实的 2 倍，GPT-6 Sol 甚至 Luna 更合适。AA 同架的一组数可以直接拿来做决策锚点：**Sol max = 47.5 分 @ $1.06/task，Opus 5.5 默认档 51.2 @ $1.34/task**——多付 26% 换约 3.7 分，值不值取决于你的任务对尾部质量有多敏感。

**一个反向警告**：别把这一天读成「AI 变便宜了，可以大胆铺量」。更准确的读法是——**能力增长这一代基本停滞，厂商把优化预算全押在了成本上**。如果你的产品路线图押注的是「下一代模型会更聪明所以现在的失败率会自动消失」，9/22 是一个明确的证伪信号：**这一代不会替你解决质量问题，只会让你更便宜地重复它。**

## 六、接下来盯什么

1. **Google 会不会跟价**。如果 Gemini 侧在两周内也做一次同量级下调，就说明这是全行业的成本对齐，而非两家的战术冲突；不跟，则说明 Google 选择用 AX/Agent Substrate 那条「基础设施护城河」路线迎战（参见 9/21 AX 篇）。
2. **缓存读定价会不会成为新的竞争维度**。两家现在同为 $0.20，谁先把它压到 $0.10 以下，谁就在争长时 agent 这个高价值负载。
3. **Artificial Analysis 后续的同架 token 用量数据**。119K vs 27K 若在更多任务上复现，「Anthropic 用 token 换分数」就从单次观察变成结构性特征，会直接改变路由策略。
4. **Vals AI 的垂直回归是否被修**。法律/医疗/税务三个场景的退步，是判断「通用基准提升是否等于垂直场景提升」的最好试纸。
5. **GPT-5.6 于 2026-10-14 从 ChatGPT / ChatGPT Work / Codex 退役**——还在这条链路上的集成需要在三周内完成迁移。
6. **开源权重阵营的反应**。当闭源价格压到自托管区间，观察 DeepSeek / Qwen 侧是继续降价、还是转向「数据主权」叙事。
7. **Anthropic「减速主张 vs 发布节奏」的张力是否被公开追问**——这关系到它后续政策发声的可信度权重。
