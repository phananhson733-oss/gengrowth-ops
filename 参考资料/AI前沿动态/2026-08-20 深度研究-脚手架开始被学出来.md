# 🧠 深度研究 ｜ 脚手架开始被学出来：Ornith-1.5 把「模型给自己出题」做成了开权重配方

> **一句话定性**：真正的新闻不是这批权重在几项榜单上打平了 Claude Opus 4.8，而是它第一次把「模型自己出题 → 自己搭脚手架 → 用自己的解题结果做 RL」这套完整闭环，连同奖励公式一起，以 **MIT 许可**公开了出来——我们这行手写了三年的 scaffold，在这里是一个被梯度优化的对象。

**来源**：Ornith 团队（据多方报道为 AI 创业公司 **DeepReinforce**，创始人 Jiwei Li，斯坦福 CS 博士、MIT TR 35 岁以下创新者；*该归属经社区与 officechai 等报道，官方页面未直接署名，标注为待确认*）
🔗 原始链接：https://ornith.ai/ornith_1_5.html
**日期**：2026-08-19（官方 X 帖与多数媒体口径；explainx 记为 8/20）
**社区热度**：Hacker News 头版，200 分 / 69 评论

## 一、为什么这一篇值得单独深读

过去半年我们在这个监测里反复碰到「递归自我改进」这条线：6/9 推过 Anthropic《When AI builds itself》（Claude 写了 Anthropic 80%+ 的合并代码）；8/18 推过 OpenAI 把安全闸门从「发布前」搬进「训练中」。这两条讲的都是**大厂内部**的递归——工程侧的、闭源的、只能听人转述的。

Ornith-1.5 的不同在于：它把递归的**另一半**——训练循环本身——连公式带权重一起放到了 HuggingFace 上，许可是 MIT，可无限制商用。

对做多 agent 系统的团队来说，这条比任何一次模型跑分更值得停下来看。因为它动的不是模型能力，是**我们的工作对象**：任务集是谁定的、scaffold 是谁写的、评测信号从哪来。这三样在 Ornith 的框架里，都不再是人的手工艺。

## 二、核心事实

### A. 发布形态（硬信息）

- **三个尺寸**：397B MoE（旗舰）、35B MoE（每 token 激活约 **3B**）、9B Dense（含 `Ornith-1.5-9B-Mobile` 量化版，目标 iPhone / Android）
- **许可**：MIT——商用与研究均无限制
- **基座不是自己的**：在 **Qwen3.5 与 Gemma 4** 的 checkpoint 上做 continued pretraining + mid-training + post-training。这是一套**后训练方法**，不是从零的基础模型
- **可跑性**：9B 单张消费级 GPU 或 Apple Silicon 即可；35B / 397B 需多卡serving
- **数字口径**：官方声明所有 Ornith-1.5 结果为 **五次独立运行平均**

### B. 机制拆解：闭环是怎么合上的

Ornith-1.0 做的是「自我脚手架」（self-scaffolding）；1.5 把它扩成三段式闭环：

**① 提议任务（Proposer）**
输入 = 一个环境或代码库 + 关于任务类型的高层指令 + **模型自己此前的解题历史**。输出 = 逐步变难的新任务。官方原话：*"the system proposes progressively harder tasks"*。

**② 生成脚手架（Harness）**
模型为这道题生成或精化一套任务专用 scaffold——原文列的四件东西是：**指令、工具、分解策略、编排**（instructions, tools, decomposition strategy, and orchestration）。这四样，正是我们平时在代码里手写的那四样。

**③ 解题 rollout（Policy）**
在「任务 + scaffold」条件下产出解法轨迹。

**闭合动作**：rollout 的奖励**同时反向传播到三个阶段**，用 GRPO 联合优化。官方措辞：*"Reward from the rollout is propagated across all three stages"*。

模型不只是在变得更会解题——它同时在学「怎么出更好的题」和「怎么搭更好的脚手架」，因为**同一份梯度信号打在三处**。

### C. 奖励公式（这是全篇最可抄的部分）

**任务奖励**：`R_task = V(q,s) × D(q,s,{τ}) × N(q)`

| 项 | 含义 | 细节 |
|---|---|---|
| **V** 有效性 | 任务是否自洽、scaffold 是否可执行、解法评测是否可靠 | 「不可验证的任务什么也拿不到」 |
| **D** 前沿难度 | **以经验成功率为中心的高斯奖励，峰值 p\* = 0.2** | 太易与太难都不给分 |
| **N** 新颖度 | 1 减去与 buffer 中历史任务的最大相似度 | 防止刷同一类题 |

**脚手架奖励**：`R_harness = C(q,h) × F(h,{τ}) × H(h)`

| 项 | 含义 |
|---|---|
| **C** | scaffold 是否对齐任务规格 |
| **F** | 奖励对解法质量的保真度 |
| **H** | **抗 reward hacking 的能力** |

**关键设计选择**：两个都是**乘法**，不是加权和。官方解释：*"The multiplicative formulation encourages the proposer to generate tasks that satisfy all three properties simultaneously"*——任一项归零，整体归零。加法式会让某一项拉满掩盖另一项塌陷；乘法式不会。

**rollout 奖励**：二元通过/失败，或由「正确性 + 完成度 + 效率 + 约束满足」组合打分。

### D. 成绩（Ornith-1.5-397B vs Claude Opus 4.8 vs Kimi K3）

| 基准 | Ornith-1.5-397B | Opus 4.8 | Kimi K3 | Ornith-1.0 |
|---|---|---|---|---|
| Terminal-Bench 2.1 (Terminus-2) | **86.1** | 85.0 | 88.3 | 77.5 |
| Terminal-Bench 2.1 (Claude Code harness) | **85.2** | 78.9 | – | 78.2 |
| SWE-bench Verified | **86.0** | 85.8 | 86.2 | 82.4 |
| WideSearch | **80.8** | 72.9 | – | 75.2 |
| BrowseComp | **86.6** | 84.3 | 91.2 | 79.7 |
| SWE-bench Pro | 65.1 | **68.0** | – | 62.2 |
| DeepSWE | 56.0 | **59.0** | 67.5 | 8.0 |
| NL2Repo | 59.5 | **69.7** | – | 48.2 |
| Frontier-Bench v0.1 | 13.5 | **21.1** | 23.0 | 2.7 |
| HLE（无工具） | 44.6 | **49.8** | 43.5 | 30.2 |
| GPQA Diamond | 92.8 | **93.6** | 93.5 | 88.1 |
| MCP-Atlas | 80.0 | **82.2** | 82.3 | 76.4 |
| Toolathlon-Verified | 71.2 | **76.2** | 73.2 | 43.2 |

**诚实读数：17 项里赢 4 项。** 官方与转发者的说法（「4 wins over Claude Opus 4.8」）本身没撒谎，但「开源模型打平 Opus 4.8」这个流传版本是掐头去尾的——在 Frontier-Bench、NL2Repo、DeepSWE 这些更难、更接近真实工程的档上，差距仍然清楚。而 Kimi K3（7/27 我们推过的那个 1.4TB 开权重巨兽）在多项上仍高于 Ornith。

### E. 自改进到底有没有起作用：看代际跳变

比「打没打赢 Opus」更有信息量的，是 1.0 → 1.5 的自身跳变：

- **DeepSWE（397B）：8.0 → 56.0**（+48 点）
- **DeepSWE（35B）：0 → 22.0**（从零到有）
- **Frontier-Bench（397B）：2.7 → 13.5**（5 倍）
- **NL2Repo（35B）：34.6 → 46.2**
- **SWE-bench Pro（35B）：50.4 → 59.6**

DeepSWE 从 8 分跳到 56 分，很难用「过拟合榜单」解释——DeepSWE 的任务多样性高于 SWE-bench，更难被针对性刷分。**这是这篇里最硬的一条证据：这套训练循环确实改变了某些东西。**

## 三、正反两面

### 支持方主张

1. **方法是公开的、可复现的**。三段式奖励设计、p\*=0.2、乘法形式，都写在博客里。哪怕这批权重不行，**配方本身有独立价值**——任何人可以把它套到别的基座上。
2. **许可给得干净**。MIT，无附加条款。对比 Kimi K3 的 modified-MIT，Ornith 这一档在合规上更省事。
3. **可跑性是真的**。35B MoE 每 token 只激活 3B，HN 上已有人报告在 Apple Silicon 上跑 35B 做网页抓取任务，「在更高量化档下比 Qwen3.8-27B 更快」。9B 有移动端量化版。
4. **代际跳变支撑机制有效**（见上节 E）。

### 质疑方 / 风险

1. **同尺寸档被更小的模型压住。** 拿 Qwen 官方模型卡（8/14 发布，Apache 2.0）直接对照 Ornith-1.5-35B：

   | | Qwen3.8-27B | Ornith-1.5-35B |
   |---|---|---|
   | Terminal-Bench 2.1 (Terminus) | **73.0** | 67.8 |
   | SWE-bench Pro | **61.7** | 59.6 |
   | DeepSWE | **42.2**（1.1 版） | 22.0 |

   *注：DeepSWE 版本号不同（1.1 vs 未标版本），不完全可比；但 Terminal-Bench 与 SWE-bench Pro 是同口径。* 结论是：**在编码这一档，一个更小的 27B 仍然更强。**

2. **零第三方复现**。explainx 的评述说得直白：*"leaderboard numbers and reproduced numbers diverge often enough that 'self-reported' should always carry an asterisk."* 397B 的旗舰数字至今没有独立复现。

3. **实测与榜单打架**。HN 上有开发者报告，上一代 `Ornith-1.0-9B` 实际用起来**不如 Qwen3.5-9B**，与公布分数相反。

4. **自改进发生在训练期，不在你机器上**。这是最容易被标题党模糊的一点——原文分析点破：*"It happens during training, not at inference time on your machine."* 你下载到的是一个**静态权重**，它不会在你的代码库上继续给自己出题。

5. **基座是别人的**。Qwen3.5 与 Gemma 4 出的力有多大、自改进循环出的力有多大，没有消融实验区分。

6. **社区的直觉性怀疑**。HN 上最高赞的怀疑之一：*"Another day another startup claiming some vague version of RSI to try to close their round."* 以及一个技术上更尖锐的追问：提升到底来自权重变化，还是**只是更好的 agentic 代码 harness 在引导输出**。

7. **工程可用性有瑕疵**。发布当天有用户报告 HuggingFace 权重下载返回 400。

8. **纯 chat 模式弱**。去掉工具后表现明显下滑（HLE 无工具 44.6 vs 有工具 56.1），这是一个**专为 agent 场景后训练**的模型，别拿它当通用对话模型评估。

## 四、深度解读：对行业，以及对「做多 agent 系统的我们」

### 对行业

**第一，前沿的「方法护城河」正在快速漏水。** 一家小公司，用别人的开源基座，靠一套后训练配方，在几项 agentic 编码基准上做到了与半年内最强闭源模型同量级。它没有超越前沿，但它证明了**逼近前沿的成本正在从「训练一个基础模型」下降到「设计一个训练循环」**。这与 7/27 Dario《Our position on open-weights models》里的担忧、7/24 黄仁勋牵头的开权重公开信，构成了同一张图的两面。

**第二，递归自我改进这条线从「大厂内部叙事」变成了「公开配方」。** 6/9 我们读 Anthropic 那篇时，它是一份带政策诉求的战略文件；今天这份是一段可以直接复制的工程实现。**当自改进配方是 MIT 许可的时候，「集体减速」这类协调机制的执行面就少了一大块。** 这是本条最值得长期盯的安全含义。

**第三，「scaffold 是护城河」这个假设开始松动。** 过去两年，agent 产品的差异化很大程度靠手写的编排、工具集和分解策略。Ornith 把这四样明确列为**被优化的参数**。方向一旦成立，手写 scaffold 的相对价值会随时间下降。

### 对我们（可执行判断）

**1. 立刻可抄的第一条：p\* = 0.2 的难度前沿。**
我们做 agent 回归集时的惯性，是收集「失败样本」或「代表性样本」。Ornith 给的读数是：**最有训练/诊断价值的任务，是成功率在 20% 附近的那一档**——太易的没梯度，太难的也没梯度。
> **行动项**：把我们现有的 agent 评测集按经验成功率分桶，单独切出 **15%–30% 的「前沿桶」**，作为迭代时的主看板。100% 桶用于回归防退化，0% 桶单独归档不参与日常评分。

**2. 立刻可抄的第二条：乘法奖励 + 显式的抗 hacking 项。**
我们系统里凡是有「agent 给自己或给兄弟 agent 打分」的环节，只要是加权求和，就存在**某一维拉满掩盖另一维归零**的结构性漏洞。Ornith 两个奖励式子都用乘法，并且把 `H`（抗 reward hacking）单列为一个因子。
> **行动项**：审计我们所有自评/互评打分函数，把「有效性」类判据（结果是否可验证、执行是否真的成功）从加权项改为**乘法门**——不可验证 = 0 分，而不是扣分。这与 8/13 已推的《三个 Claude 共享一台机器，四小时后开始互相投毒》是同一道防线。

**3. 中期动作：把 scaffold 从代码里挖出来，变成可寻址、可版本、可评测的对象。**
这是本条对我们最重要的战略含义。短期结论**不是**「别写 scaffold 了」——恰恰相反，Ornith 证明 scaffold 是有梯度可优化的高价值对象。但前提是它**必须先被显式化**：
> **行动项**：我们每一条 agent 链路的「指令 + 工具集 + 分解策略 + 编排」四件套，应当有独立的标识、版本号，以及绑定到前沿桶的成功率读数。藏在代码里、没有版本、没有对应指标的 scaffold，既无法被人优化，将来也无法交给任何训练循环。**这是一件今天就该做、且与是否采用 Ornith 无关的事。**

**4. 选型判断：进候选池做 A/B，不进主力路由。**
诚实的结论是：**在编码这一档，Qwen3.8-27B（8/14，Apache 2.0）仍是更稳的选择**——更小、更强、且已有更广的社区实测。Ornith-1.5 的价值在于 35B MoE(3B 激活) 这个自托管友好的形态，以及它的方法论。
> **行动项**：把 Ornith-1.5-35B 加入本地 agent 档的 A/B 候选，与 Qwen3.8-27B 在**我们自己的前沿桶**上跑对照；不要基于厂商榜单换主力。

**5. 把「独立复现」写成硬门槛。**
本条真正的风险不是模型差，是**自报数字与复现数字之间的系统性偏差**——而且这个偏差在 Ornith 上是有先例的（1.0-9B 的实测反转）。
> **行动项**：任何进入主力路由的模型，必须先在我们自己的评测集上过一遍，厂商榜单只用于决定「是否值得花时间测」，不用于决定「是否上线」。

## 五、接下来盯什么（信号）

1. **是否出现第三方独立复现**——尤其 397B 的 Terminal-Bench 2.1 与 DeepSWE。若一周内无人复现出接近数字，本条的可信度需大幅下调。
2. **是否有人把这套配方移植到别的基座**。若「自出题 + 自脚手架 + GRPO 三段联合」能在第三方基座上复现出同量级跳变，**这套方法的价值远大于这批权重**——那才是真正的格局事件。
3. **消融实验**：Qwen3.5/Gemma 4 基座贡献 vs 自改进循环贡献。官方至今没给。
4. **HuggingFace 权重可用性恢复**，以及实际的 tok/s、显存占用、长上下文表现读数（官方未公布 context length）。
5. **前沿实验室是否跟进公开同类训练配方**。Anthropic 6/4 的 RSI 文章、OpenAI 8/18 把闸门搬进训练期，都指向同一个方向：**训练循环本身正在变成产品**。若某家把训练循环开源，这条线会立刻升级。
6. **安全侧反应**。一个 MIT 许可、能自我扩课程的开权重模型族，正是 Dario 7/27 那篇里所担心的形态。留意是否被 EU AI Act 的 GPAI 条款或美方框架点名。
