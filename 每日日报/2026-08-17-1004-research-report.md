今天读什么｜别把每次成功都留在聊天里：把 Agent 经验做成可验证的“技能包”

### 1. 适合谁读 / 预计阅读时间
适合已经在用 AI 做研究、内容生产、线索整理、代码协作或跨工具自动化的人。尤其适合这样的团队：同一个任务每周都要重新解释流程；某位同事一离开，Agent 就不知道“以前是怎么做对的”；提示词越写越长，却仍会漏步骤、误用工具。预计阅读约 10 分钟。

### 2. 为什么值得读
一次高质量交付往往包含很多隐性经验：先查什么、哪些来源可以信、什么条件下停止、格式如何验收、失败时如何降级。这些经验若只留在聊天记录或某个人脑中，下次同类任务仍要从零开始；若一股脑塞进系统提示，又会让所有任务背着无关规则，既慢又容易跑偏。

更合适的单位是“技能包”：为一类重复且可验收的工作保存一份简短入口说明、分步骤操作、参考资料、模板和必要脚本。Agent 先看目录决定是否匹配，再加载核心流程，遇到特定情形才读取细节或运行脚本。它不是把 Agent 训练成固定流水线，而是把稳定的组织经验从临时对话中抽出来，让模型把精力放在仍需要判断的部分。

Anthropic 提出的核心是“渐进披露”：先加载技能名称和适用范围，命中任务后读主说明，只有需要时才打开参考文件或脚本。OpenAI 在维护 Agents SDK 时，也把验证、发布准备、示例集成测试和代码审查等重复工作沉淀为仓库内技能，并强调：模型处理依赖上下文的判断，确定性部分交给脚本。

关键原则：**把反复出现的“怎么做对”产品化，但把不确定的判断留给 Agent 和人。**

### 3. 核心概念
**第一，技能不是长提示词。**  
长提示词通常对所有任务常驻；技能有明确触发条件，只在相关任务中加载。它应回答“何时使用、目标是什么、按什么步骤做、何时停止或转人工”，而不是把全部公司知识混在一页里。

**第二，技能要区分三层。**
- **入口层**：名称和一句适用描述，帮助 Agent 找到正确能力。
- **核心层**：少量不可省略的步骤、边界、输入输出与验收条件。
- **按需层**：API 细节、异常处理、示例、模板、脚本；只有命中具体情形才读取。

这样既避免“找不到技能”，也避免“刚开始就加载一本手册”。

**第三，模型判断与确定性动作要分工。**  
例如“从竞品材料中识别值得验证的主张”可以由模型完成；“检查链接是否可访问、标题字段是否为空、是否超过字数、生成固定格式文件”应尽量由脚本或规则完成。把确定性检查写成自然语言要求，往往比真正执行一次校验更不可靠。

**第四，技能的边界比覆盖面重要。**  
“帮我做增长”不是技能；“把公开竞品材料整理为带来源、反例和待验证项的选题证据包”才是。输入、输出、允许工具、禁止动作、完成定义越清楚，复用越稳定。涉及对外发送、写 CRM、发布或付费调用时，技能应只生成提案或变更集，明确交给审批节点，而非把执行权藏进流程。

**第五，技能也会过期，必须有版本与回归样本。**  
每次人工大改、工具接口变化、失败案例出现，都应判断是偶发情况还是流程缺口。若是后者，就更新技能并补一个最小测试：给它同类输入，验证字段、证据、边界和产物是否仍符合预期。不要只写“已优化提示词”。

### 4. 可复用方法
从一个每周至少发生两次、返工明显的任务开始，做一份最小技能包：

1. **选题要窄**：例如“把 Builder 公开动态变成中文学习文章大纲”，不要从“内容运营”开始。  
2. **写一张入口卡**：触发条件、所需输入、最终产物、禁止事项、完成标准，各一两句。  
3. **把核心流程压成 5—8 步**：收集→筛选→取证→写作→自检→交付；每步写清可观察结果。  
4. **把易变细节外置**：来源白名单、文风示例、错误码、字段字典放进参考文件；格式模板放进 assets；可确定校验写成脚本。  
5. **加两条护栏**：什么情况必须停下；什么动作只能输出草稿或变更集。  
6. **用 3—5 个真实历史任务试跑**：记录“漏了什么、哪里不必要、脚本是否真能发现错误”，再发布 v1。

衡量它是否有价值，不要只看生成更快；还要看人工补充是否减少、关键字段缺失率、重复工具调用、返工原因与可复现失败数是否下降。

### 5. GenGrowth 可以怎么用
可以先从三类高频、低风险交付件建立技能包：

- **研究证据包**：输入是公开链接或主题；输出为事实、来源、反例、适用范围和未决项。它让后续写作不必重新搜一遍，也降低把推断写成事实的概率。  
- **内容生产包**：输入是已核验的证据包；输出为不同平台的中文大纲、初稿和事实核验清单。把“不可编造来源、必须标示推断、不能自行发布”写成硬边界。  
- **增长动作提案包**：输入是名单或活动目标；输出为分层、拟更新字段、拟触达文案及风险标记，但不直接写 CRM、不直接发送。提交前用差异预览和人工审批接管。

三者最好共享统一的交付字段：任务 ID、输入版本、来源或依据、产物路径、校验结果、风险和下一步。这样技能之间传的是可验证产物，而不是一句“我已经处理好了”的口头摘要。

### 6. 今日行动
选一项本周已做过两次的工作，用 30 分钟写出它的“技能入口卡”。先不要追求万能：明确触发条件、输出模板、三条不可违反的边界，以及一个可以自动检查的规则。随后拿一份旧任务重跑；如果 Agent 能在不额外解释的情况下交出同样可验收的产物，这份经验才值得继续沉淀。
