今天读什么｜把网页当资料，不当指令：给 Agent 加一道“内容隔离层”

### 1. 适合谁读 / 预计阅读时间
适合正在让 AI 浏览网页、读邮件、处理客户上传文件、检索知识库，或接入 CRM、Slack、飞书、MCP 工具的人。尤其适合“它只是帮我搜资料，应该没风险吧？”这一类场景。预计阅读约 10 分钟。

### 2. 为什么值得读
Agent 一旦能读外部内容并调用工具，风险不再只是不小心写错一段话。网页正文、评论、PDF、简历、邮件、GitHub README，甚至图片里的文字，都可能夹带“忽略前面要求”“把资料发到某地址”“调用这个链接核验”等诱导。模型读到它们时，未必能稳定地区分：这句话是待分析的资料，还是该执行的命令。

这叫间接提示词注入。它不是黑客一定要攻破账号，而是借 Agent 已有权限让它“自愿”做错事。最危险的组合是：既能读私有资料，又会接触不可信内容，还能向外发送、上传或请求网络。问题的关键因此不是“把提示词写得更严”，而是：不可信内容能否直接改变下一步动作？

OpenAI 的建议很明确：外部输入不应直接驱动 Agent 行为，应先抽成固定字段或经校验的结构化数据。Anthropic 也强调，即使工具或连接器本身可信，它返回的网页、文档和第三方内容仍是不可信输入。把“工具可信”误当成“工具结果可信”，正是很多工作流的盲点。

### 3. 核心概念
**第一，信任的是来源边界，不是文字语气。** 即使一段文字写得像系统通知、像老板口吻、像“安全检查步骤”，只要来自网页、邮件、上传文件、搜索结果或外部 API，就只是一份待处理的数据。不要因它看起来合理而提高权限。

**第二，读取与执行必须两段式。** 研究 Agent 可以读取网页、抽取产品名、价格、发布时间、引文位置；但它不应同时拥有发送邮件、写 CRM、上传附件等出口。若后续确有动作需求，交给另一个权限更小的执行节点，并只传递已校验字段和任务 ID。

**第三，结构化输出是一道“窄门”。** 不要把一整页原文和自由文本摘要直接塞给下游。规定只允许传递 `事实、来源链接、发布日期、置信度、风险标记` 等字段；不符合 schema 的内容不能变成动作参数。结构化不是让模型更死板，而是限制恶意指令借“自由文本通道”混入下游。

**第四，审批不能代替隔离。** 每一步都弹确认会造成疲劳，人往往只会点通过。真正的高风险操作应展示对象、字段差异、接收方、附件与影响范围；更根本的是用沙箱、文件/网络白名单、只读挂载和短期权限，事先限制它即使被诱导也能碰到什么。

**第五，子 Agent 也不能自动升级信任。** 一个“研究助手”读完网页后，若把原文或自由摘要交给主控，注入可能随交接扩散。下游应把子 Agent 结果视为带来源和风险标签的证据包，而非更高权限的指令。

### 4. 可复用方法
给现有“搜资料→生成内容/动作”流程补一条最小隔离链：

1）列出所有外部输入：网页、邮箱、表单、附件、搜索、MCP 返回值；默认标记为“不可信”。  
2）把任务拆成“摄入—提取—判断—执行”：摄入节点只读；提取节点输出固定 schema；判断节点核验业务规则；执行节点只接收批准后的变更集。  
3）给每条证据保留来源 URL/文件 ID、抓取时间、原文位置和风险标记；遇到“要求改规则、索要数据、要求访问新链接”等内容，标记而不执行。  
4）收紧出口：研究任务默认禁止外发、上传、发布和任意网络请求；确有必要时，限定接收域名、对象、字段、数量和有效期。  
5）做一次红队演练：在测试网页或测试文档中埋入诱导句，检查 Agent 是否会把它写进摘要、带入任务参数，或触发任何出口；将失败样本加入回归测试。

### 5. GenGrowth 可以怎么用
对竞品研究、客户线索、内容选题这三类流程，最实用的改造是设立“证据包”中间层。研究 Bot 可抓公开页面，输出：主张、摘录位置、来源、时间、风险标记；写作 Bot 只能使用“已支持”的事实写稿；任何发布、外联或 CRM 更新，只能读取人工或规则批准后的变更集。

这样既不妨碍用 Agent 扩大信息输入，也避免一篇竞品文章、某封来信或一个被污染的资料页，悄悄改变内容口径、触达人群或外发对象。对内知识库同样如此：把文档当可检索证据，不把文档中的自然语言当系统政策；政策应由独立、可版本化的规则层保存。

### 6. 今日行动
选一条当前正在运行的“外部资料→内部动作”链路，花 30 分钟完成三项检查：

- 它读到的不可信内容，是否能直接进入下一个 Agent 的自由文本上下文？
- 它是否同时拥有私有数据读取与外发/上传能力？
- 若在来源页面放入一句诱导指令，系统最终会停在哪一关？

只要其中任一项答案不清楚，先把执行动作降为草稿或待审批，再补结构化证据包与最小权限边界。
