今天读什么｜别把所有资料塞给 Agent：给每次接力一份“任务案卷”

### 1. 适合谁读 / 预计阅读时间
适合正在让 AI 做跨多轮研究、内容生产、竞品梳理、线索跟进或自动化项目的人。尤其适合这种场景：同一任务越跑越长，聊天记录、网页结果、工具日志和临时判断不断累积；下一次运行虽然“带着历史”，却仍然找不到重点、重复查资料，甚至把已否决的方向又做一遍。预计阅读约 10 分钟。

### 2. 为什么值得读
很多团队把上下文窗口变大，当作长期任务的解法：资料尽量全放进去，盼模型自己记住。但上下文不是硬盘，而更像有限的工作台。信息越多，相关线索越可能被无关内容淹没；模型未必报错，却会在引用、优先级和步骤选择上悄悄变差。

Anthropic 把这件事称为“上下文工程”：每一步都选择最小、但信号最强的信息集合，而不是只把系统提示词写得更长。其长期运行 Agent 的实验也发现，仅靠把历史压缩成摘要仍不够：新一轮 Agent 若不知道任务总目标、已验证事实、未完成项和当前环境健康度，容易半途重做，或过早宣布完成。

对 GenGrowth 而言，这意味着研究、写作和增长工作流的可靠性，取决于能否让每一位“接班 Agent”在几分钟内回答四个问题：要交付什么？哪些事实已经确认？下一步唯一最值得做的事是什么？什么情况下必须停下并转人工？

### 3. 核心概念
**第一，区分“工作记忆”和“长期知识”。** 客户偏好、品牌规则、产品资料可进入知识库；而本次任务的目标、范围、已用来源、未决冲突和当前步骤，属于短寿命工作记忆。两者混存，会让旧任务细节污染新任务，也会让每次启动加载无关资料。

**第二，压缩不是写一段泛摘要。** 好的压缩应能让下一轮直接行动：保留决策、证据定位、已完成/未完成、失败原因、风险和下一步；丢掉冗长工具原文、重复搜索结果和已被替代的草稿。摘要只写“已研究竞品”几乎没有交接价值。

**第三，任务案卷是可回读的外部交接件。** 它不应依赖某段聊天仍在窗口中，而是以任务 ID 保存。至少包括：验收目标、边界与时限、事实—证据链接、当前状态、最近一次已验证动作、待办清单、风险/审批点、产物路径和版本。模型读案卷后再按需打开原件，而不是一上来读全量材料。

**第四，按需取用比预先灌入更稳。** 启动时只加载“任务封面”和少量高优先级材料；需要核验某结论时，再用文件路径、文档 ID、查询条件或链接取回对应片段。这样既减少成本，也避免把不相关的网页、客户资料或历史错误带入当前判断。

**第五，案卷必须带失效标记。** “确认过”的结论要标来源、时间和适用范围；价格、客户状态、竞品功能等易变信息，跨天或跨阶段应回读原始来源。案卷记录的是曾经为何这样判断，不是永久真相。

### 4. 可复用方法
先在一条高频流程试行“任务案卷 + 按需取用”：

1）**启动建封面**：把自然语言需求转为 `目标、对象范围、交付格式、截止时间、不可执行动作、验收条件`。没有这些字段，就不要让 Agent 盲目开搜。  
2）**每个里程碑更新六栏**：`已确认事实`、`证据位置`、`已完成动作`、`未决问题`、`下一步`、`风险/阻塞`。用结构化字段，少写抒情式日志。  
3）**设置收尾规则**：本轮结束前必须回读关键产物、更新案卷并写明“下一轮从哪里开始”；未验证的假设不能伪装成完成。  
4）**重启先验收后续做**：新 Agent 先读案卷、检查上次产物是否仍可用，再选一个最小下一步；发现环境或证据已变，就回到核验，而非沿用旧计划。  
5）**定期清理**：把已废弃草稿、重复检索和过期结论移出工作记忆；原始材料可保留在知识库，但不默认注入上下文。

### 5. GenGrowth 可以怎么用
以“竞品洞察→内容选题包”为例：研究 Agent 建案卷，记录目标受众、已核验的竞品页面、主张—证据对应关系和仍缺的价格/案例信息；写作 Agent 只读已支持的主张与品牌要求，生成草稿；审核 Agent 回读高影响链接并把不确定项打回案卷。若第二天要更新，只重查标为易失效的页面，而不是整份报告重做。

同样的结构可用于“线索→外联草稿”：案卷保存身份解析证据、触达限制、可用素材和草稿版本；任何发送动作仍须经过既有规则与人工审批。案卷提高的是交接与可追溯性，不会替代权限控制。

### 6. 今日行动
挑一条本周会跨两次以上运行的流程，建立一个共享模板。先只强制四项：`验收目标、已确认事实及出处、下一步唯一动作、风险/待确认项`。连续跑 5 个任务后，检查三件事：重复检索是否减少、重启后是否仍要“猜进度”、人工能否在 1 分钟内判断该不该继续。再决定是否增加版本、失效期和自动回读。
