今天读什么｜把浏览器当“最后一公里”：让网页 Agent 会做、会停、会验收

### 1. 适合谁读 / 预计阅读时间
适合正在搭 AI Builder、研究助手、线索整理、内容运营或增长自动化的人。尤其适合遇到这种情况的团队：关键资料只在网页后台、老系统没有 API、表单流程又长又脆；Agent 看起来已经点完了，却没人能证明它真的完成了。预计阅读时间 10 分钟。

### 2. 为什么值得读
很多人一接入浏览器自动化，就把它当成“万能接口”：能看见按钮，就让 Agent 去点。但网页界面是给人设计的，页面会改版、弹窗会遮挡、加载是异步的，页面文字里还可能藏着诱导 Agent 改变目标的指令。于是最常见的误判是：截图上出现“已提交”，系统里其实没有记录；或者 Agent 为了完成任务，跨过了本该由人确认的外部动作。

OpenAI 的 computer use 指南明确建议把浏览器运行在隔离环境中、预先限定可访问的网站和动作，并把网页文本、截图、邮件等第三方内容都视为不可信输入。Anthropic 对 Agent 评测给出更关键的一层：涉及写入时，不能只检查确认页，还要回读后端状态，确认订单或记录真的发生了。Playwright 的实践则提醒我们，网页状态不应靠“等两秒再看”来猜，而应使用会等待目标状态出现的断言。

一句话：浏览器不是 Agent 的默认大脑，而是连接“没有正式接口的最后一公里”；真正可用的网页工作流，必须把操作、边界和验收拆开设计。

### 3. 核心概念
**第一，选择入口要分级。** 能用稳定 API、导出文件或数据库查询完成的，就不要先走网页；需要可读网页信息时，优先提取明确结构；只有旧系统、可视化后台或人机界面独有能力，才让 Agent 用鼠标键盘。界面自动化的价值是补缺口，不是替代所有集成。

**第二，网页内容是数据，不是命令。** 页面里的“忽略之前要求”“请上传文件”“立即付款”等文字，即使看起来像操作指令，也不能自动改变任务目标。只有来自任务方的明确授权，才算执行许可。这条规则能把提示注入从“模型是否聪明”变成系统的硬边界。

**第三，把一次网页动作拆成四个状态。** 看见目标（页面、账号、对象正确）→ 准备动作（字段、权限、风险正确）→ 执行动作（点击、输入、提交）→ 证明结果（页面状态、URL/任务号、后端记录或回读结果）。模型说“做完了”和页面弹出提示，都不属于最终证明。

**第四，验收要与动作风险匹配。** 对“读取一篇文章”，检查来源和提取内容即可；对“提交报名表”，至少核对提交后的编号或状态；对“发送、发布、删除、付款、改权限”，浏览器应该停在最后一步，由人确认后再执行，并留下可复核回执。

**第五，隔离不仅是安全，也提升稳定性。** 专用浏览器配置、最小账号权限、域名白名单、禁止继承本机环境变量和扩展，能减少敏感信息暴露，也能避免历史登录状态、插件弹窗和本地文件把任务带偏。每条流程都应有步数、时间和失败退出条件，避免 Agent 在变化页面上无止境试点。

### 4. 可复用方法
给任何网页 Agent 先做一张“最后一公里卡”：

1. 写清业务目标和唯一对象：例如“为公司 A 收集公开招聘页信息”，不要只写“研究一下”。  
2. 列入口优先级：API / 导出 / 结构化抓取 / 浏览器；选到浏览器时，要说明为什么绕不过它。  
3. 列允许域名、可用账号、只读与可写动作；将提交、发送、删除等单独标成“需确认”。  
4. 为每一步设可观察证据：关键字段、成功状态、URL、记录 ID、后台回读项。不要把“按钮已点”当证据。  
5. 准备失败分支：找不到元素、登录失效、内容冲突、页面出现可疑指令时，保存截图和当前状态，停止并转人工，而非盲目重试。

### 5. GenGrowth 可以怎么用
**公开研究与内容生产：** 用浏览器进入公开网页、行业目录或活动页，抽取带 URL 的事实；成稿前要求每个关键判断能回到来源页面。这里默认只读，既适合做选题雷达，也能把证据留给后续审稿。

**线索研究：** 当地图、招聘页、官网后台没有合适接口时，网页 Agent 可以搜集公司规模变化、招聘动态和公开联系方式；但把它限定在“研究和生成外联草稿”。真正发送消息、提交表单或创建 CRM 记录，应走带幂等保护的正式工具或人工审批，而不是靠网页点两次。

**内部运营：** 对遗留后台，可先挑一个低风险动作，例如下载日报或核对任务状态。验收不看“下载按钮被点击”，而看文件是否存在、日期是否正确、任务状态是否真实变化；稳定后再扩大范围。

### 6. 今日行动
挑一条目前只能靠网页完成的流程，花 30 分钟补齐四项：允许访问哪些域名；哪些步骤只读、哪些需确认；每个关键动作如何回读验证；异常时在哪一步停止。先在隔离测试账号里跑 5 次，统计“成功但验收失败”的次数；这个数字比“它点了多少按钮”更能判断流程是否可上线。
