今天读什么｜别让 Agent 一次性把检索问题写死：用“宽搜—判别—窄搜”逐层收敛

### 1. 适合谁读 / 预计阅读时间
适合用 AI 做竞品研究、客户洞察、内容选题、行业情报或知识库问答的人。尤其适合这种情况：你给了 Agent 一段看似完整的需求，它却一上来抛出很长、很精确的搜索句；结果不是搜不到，就是只得到几条迎合原假设的材料。预计阅读约 10 分钟。

### 2. 为什么值得读
人做陌生课题时，通常不会先写出“完美搜索词”。我们会先问：这个领域里有哪些叫法、主要玩家和可用资料？看到第一批线索后，才决定该追哪条、该排除什么。很多 Agent 工作流却反过来：把用户原话和一堆限定条件一次塞进检索框，期待搜索引擎直接给答案。

这会制造两个隐患。其一，长查询把未知概念、旧术语或错误前提一起锁死，召回结果很少，Agent 容易误判为“没有证据”。其二，即使有结果，也可能只覆盖它最初写进查询的那一小块世界。

Anthropic 在其多智能体研究系统复盘中提到，Agent 很容易偏好过长、过具体、结果稀少的查询；它们采用的改进是：先用短而宽的查询观察资料，再逐步缩小焦点。关键不在于“多搜几次”，而在于每一轮都必须产生一个能改变下一轮的问题或边界。对 GenGrowth 而言，这是一种把检索从“问答动作”变成“逐步消除不确定性”的工作法。

### 3. 核心概念
**第一，宽搜不是漫游。** 它只回答定位问题：有哪些同义词、客户如何描述痛点、官方资料在哪里、当前有哪些替代方案。第一轮的交付不该是结论，而是一张“术语—对象—来源类型”小地图。

**第二，窄搜要由证据驱动。** 看到“内容自动化”同时指代文案生成、审批流和跨渠道发布后，下一轮不能继续泛搜；应改问其中哪一种能力影响目标客户，以及它有哪些可核验的限制。查询收窄的依据是上一轮发现，不是最初直觉。

**第三，每轮都要有判别门。** 搜到页面不等于获得进展。应明确本轮要判断什么，例如“是否存在付费需求信号”“这是否是官方能力”“案例适用的是中小企业还是大客户”。若答案没有改变候选对象、假设或来源优先级，这一轮只是重复消耗。

**第四，收敛也需要停止条件。** 不是资料越多越好。关键假设已有两类独立证据支持、反证回合没有发现会改变决策的材料、或新增结果连续两轮只是在重复时，就应转入综合或标记缺口。把“继续搜索”写成默认动作，会让 Agent 用成本掩盖不确定性。

### 4. 可复用方法
给任何研究型任务加一张四栏“检索漏斗卡”，不必重做系统：

1）**先写决策与未知项。** 例如：`本周是否为 SaaS 客户试做竞品内容快报？` 未知项只列 2—3 个：客户是否有持续需求、资料是否可稳定取得、交付是否能形成差异。

2）**第一轮宽搜只拿地图。** 用短查询分别寻找客户语言、行业术语、主要产品/替代方案、官方资料入口。输出不超过 10 条线索，并记录每条属于“词汇、对象、证据源还是反例”。不要急着写推荐。

3）**设置判别门并拆分第二轮。** 从地图中选择真正会改变决策的两个分支；每个分支写清“要证实什么、优先看哪类来源、什么结果会否定它”。例如需求优先看招聘、公开案例和用户讨论；功能优先看官方文档和实际演示。

4）**建立查询日志。** 每轮仅保存：查询目的、得到的新信息、淘汰/新增的假设、下一轮动作。不要把完整网页原文反复塞回上下文。这样人能检查 Agent 为什么转向，后续任务也不会重踩已排除的路径。

5）**按收敛信号结束。** 连续两轮没有新增高质量来源、关键结论已达到预设证据门槛，或剩余问题只能靠访谈/内部数据回答时，停止搜索，输出“当前结论 + 证据边界 + 待确认项”。

### 5. GenGrowth 可以怎么用
可先把这套漏斗接到“选题/客户研究卡”中。研究 Agent 只读公开资料，第一阶段交词汇地图和候选问题；第二阶段才交带来源的主张；最终内容或服务判断只读取已通过判别门的证据包。

这样能减少两个常见浪费：一是把客户的一句话需求当成精准检索词，二是让内容人员在几十条链接里重新判断什么值得写。对外发布、CRM 写入和客户外联仍应留在独立审批环节；检索漏斗的职责只是让前一阶段的判断更可追溯，而不是自动替团队做承诺。

### 6. 今日行动
任选一个正在做的研究任务，花 20 分钟做一次小试验：

- 删除原来的长搜索句，改成 3 个短的“地图问题”；
- 为第二轮写出两个判别门和一个反证问题；
- 用表格记录“这一轮新增了什么、因此下一轮为什么改变”；
- 如果连续两轮没有新增有效信息，直接产出缺口清单，而不是继续让 Agent 搜。

一周后复盘：哪些问题在第一轮就被澄清？哪些长搜原来只是把假设写得更像事实？这会比单纯比较“搜到多少链接”更能判断工作流是否变好。
