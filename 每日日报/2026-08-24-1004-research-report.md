今天读什么｜别把 Agent 全部同时开跑：用“在制品上限”守住增长自动化的交付速度

1. 适合谁读 / 预计阅读时间  
适合已经有多个 AI 任务在跑的人：日报采集、竞品研究、内容草稿、线索补全、知识库入库或跨工具自动化。尤其适合这样的阶段：系统看起来很勤快，待处理任务越来越多，但真正能审、能用、能推进的成果反而变慢。预计阅读约 10 分钟。

2. 为什么值得读  
很多团队遇到积压，第一反应是“再多开几个 Agent”。这往往只把拥堵从入口搬到后面：同一批网页同时抓取、同一个模型或 API 被打满、审核人收到几十份半成品，优先事项则埋在低价值任务后面。真正稀缺的通常不是触发任务的能力，而是稳定完成一个工作单元的能力。

这就是“在制品上限”（WIP limit）的意义：同时进行的任务要有明确上限，超过上限的请求先排队、合并或拒收，而不是继续占用工具、模型和人的注意力。Temporal 的任务队列让 Worker 只在有空闲容量时领取任务，并支持路由、持久化与服务端节流；其核心不是把队列塞满，而是让工作与实际处理能力相匹配。[1]

对增长自动化来说，这个转变很关键。目标不是让系统“瞬间开始一百件事”，而是让高价值任务在承诺的时间内、带着完整证据和可审查产物完成。

3. 核心概念  
第一，区分三种限制。**并发上限**限制此刻有多少步骤正在执行，防止模型、浏览器或数据库同时过载；**启动节流**限制一段时间内能新开多少次，防止突发流量压垮第三方接口；**拒收/合并规则**则决定哪些重复或低价值请求根本不进入队列。Inngest 将三者与去重、优先级并列为流量控制手段，说明它们解决的不是同一个问题。[2]

第二，队列不是待办清单。待办清单可以无限长；运行队列必须有服务承诺。每个任务应有对象、优先级、截止时间、估计成本、可等待时长和取消条件。没有这些字段，排队只是在积累不确定性。

第三，节流不等于放慢。它是在入口把峰值摊平，给关键任务留出可预测的通道。以 Inngest 的定义为例，节流会把超过时间窗口上限的运行延后入队；并发控制则限制正在执行的步骤数量。[3] 二者组合后，系统既不会瞬时冲垮外部 API，也不会因为一个慢任务把所有资源锁死。

第四，优先级必须可解释。不要只写 P0/P1；应说明“谁因何业务后果先做”。例如客户已约会议的资料包优先于一周后才看的选题探索；生产事故优先于批量资料整理。否则队列只能做到先来先做，不能做到先完成最重要的事。

4. 可复用方法  
给任一 Agent 流程加一张“入口卡”，先不用换编排平台：

1）定义一个最小工作单元。例如“核验一个竞品页面并输出证据卡”，不要把“做竞品研究”作为单个任务。  
2）为每类单元设三道门：全局并发数、每分钟启动数、单对象并发数。单对象可按客户、域名、活动或数据表分组，避免一个大批次吞掉所有容量。  
3）入口先做去重：同一对象、同一版本、同一动作仍在运行或已有合格产物，就返回已有结果或合并请求，不再重复启动。  
4）设优先级队列和等待时限。超过时限的低优先任务不应悄悄永远排队：改为摘要交付、延期、取消或转人工确认。  
5）每天只看四个数：排队量、任务等待时长、完成时长、因限额被延后或拒收的数量。前两个持续上升，先缩入口或拆任务，不要盲目扩 Agent。

5. GenGrowth 可以怎么用  
可先把“公开资料→可用增长资产”分成四条队列：

- P0：正在影响客户或上线的事实核验、对外内容复核；小并发、优先保障。  
- P1：本周要用的竞争研究、内容证据卡；按网站域名限流，避免集中抓取。  
- P2：日报候选、工具试用、选题探索；可延后，并在相同链接或主题出现时合并。  
- P3：历史资料补标签、低价值回填；只在 P0/P1 队列空闲时运行。  

关键不是建四个“机器人”，而是让所有任务在进入前都带优先级、对象和失效时间。Anthropic 建议从尽可能简单的可组合工作流开始，只有复杂度确有必要时才增加更强的自主编排。[4] 对 GenGrowth 而言，先把入口治理做好，往往比新增一个 Agent 更快看到稳定产出。

6. 今日行动  
选一个最容易堆积的流程，例如“链接进入后自动研究”。今天只完成三件事：

1）列出当前正在跑和等待中的任务，按对象与用途去重；  
2）为外部抓取或模型调用设一个保守并发上限，并把客户/域名作为单对象限制；  
3）规定等待超过一天的 P2/P3 任务自动生成缺口清单或取消，不再无限重试。  

一周后复盘：高优先任务的等待时间是否下降？若没有，再检查是入口太大、单元太粗，还是审核环节才是真正瓶颈。
