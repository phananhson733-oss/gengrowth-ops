今天读什么｜别让 Agent 定时“巡楼”：把关键变化做成会叫醒它的事件

### 1. 适合谁读 / 预计阅读时间
适合正在把 AI 用于线索跟进、内容生产、客户研究、知识库整理或内部协作的人。尤其适合已经有一堆“每 30 分钟查一次”“每天重新拉一遍”的自动化任务，却发现它们又慢、又贵、还经常重复处理同一条数据的团队。预计阅读时间约 10 分钟。

### 2. 为什么值得读
很多 AI 工作流的起点是定时器：每天早上搜一次新动态、每小时扫描一次表单、每隔几分钟检查 CRM。它简单，适合原型；但当流程变多，定时扫描会把“系统有没有变化”也变成模型、工具和数据库要反复回答的问题。结果是三种浪费：没变化也要跑；变化发生后要等下一次扫描；多个任务同时扫同一来源，造成重复与拥堵。

更成熟的做法是**事件驱动**：不是让 Agent 不断问“有新事吗”，而是在“有人提交表单、客户状态改变、文章发布、审批完成、文件更新”时，由系统发出一条事件，唤起恰当的流程。Agent 仍负责理解语境、判断优先级、生成草稿；但“什么时候开始”和“哪个对象变了”应尽量由确定性系统提供。

这不是把所有东西都换成 Webhook。轮询仍适合没有事件接口的老系统、需要定期汇总的日报，或用于兜底校验。关键变化是：把轮询从默认入口，降为明确、低频、可核对的补充路径。

### 3. 核心概念
**第一，事件不是一句“有更新了”。**  
一条可用事件至少说明：发生了什么、发生在谁身上、何时发生、来源是哪一个系统、这次投递的唯一编号是什么。没有对象 ID 和事件 ID，后续流程很难防止重复或回查事实。

**第二，触发、判断、执行要拆开。**  
触发器只负责可靠地接住变化；规则层判断是否值得处理；Agent 负责需要理解与表达的部分；执行层再做写入、建任务或生成待审核草稿。不要让收到一条消息的 Agent 直接跳到“发送给客户”。

**第三，事件至少按“可能重复”设计。**  
网络超时、上游重送、人工补发都会让同一事件再次到达。GitHub 建议利用每次投递的唯一标识防重放；Temporal 也提醒，工作流信号在少数情况下可能重复。因此，事件 ID 应进入去重表，写动作还要有自己的幂等键。重复通知可以忽略；重复发信、重复建线索则必须被拦住。

**第四，快确认、慢处理。**  
Webhook 接收端应先完成来源验证、保存最小事件和排队，再尽快返回成功；耗时的检索、模型调用、生成内容放到后台工作者。否则上游可能因超时把同一事件再次投递，造成雪崩式重跑。

**第五，事件合同也会演化。**  
不要让下游依赖一整份上游原始载荷。内部先转成自己稳定的“标准事件”，只保留流程需要的字段；新增字段通常兼容，改字段语义或删除字段应有版本与迁移期。这样 CRM、表单工具或内容平台改版时，不会把所有 Agent 一起打断。

### 4. 可复用方法
给一条现有自动化补上“事件优先”入口，可按五步做：

1. **找出最高频的无效扫描**：记录一周内触发次数、真正有变化次数、平均耗时和重复率，先挑“跑得最勤、有效最少”的一条。  
2. **写一张事件卡**：事件名、对象 ID、事件 ID、发生时间、来源、最小字段、风险等级、允许触发的后续动作。比如“新表单已提交”只创建研究任务，不直接外联。  
3. **建接收与去重层**：验明来源后把原始事件存档；以“来源＋事件 ID”去重；在超时、重送时仍保证同一业务对象不会被重复写入。  
4. **加规则再叫 Agent**：例如只让“目标行业、信息完整、未被跟进”的表单进入研究；其余先归档或等待补充。把明显规则留给程序，不要浪费一次模型判断。  
5. **保留低频对账轮询**：每天或每周抽查源系统与事件记录是否一致；发现漏事件时补偿并告警。事件驱动不是放弃巡检，而是从“不断巡楼”变成“定期盘点”。

### 5. GenGrowth 可以怎么用
可以先从“内容线索到发布草稿”做一条低风险试点：当团队在表格、Slack 或表单中新增一个带主题与来源的内容线索时，事件只创建一张任务卡；规则层去重、检查字段和主题优先级；AI 再输出研究提纲、证据缺口与多平台草稿；最后停在人工审核，不自动发布。

同样的结构也适合 B2B 增长：客户行为或 CRM 阶段变化触发“补全背景—生成跟进建议—写入待审核队列”，而不是每晚让 Agent 重扫全部客户。这样可把模型预算集中给真正发生变化、且值得处理的对象。

建议在运行记录里同时看四个数：**事件接收量、去重率、被规则过滤率、最终人工采纳率**。它们能回答：问题是上游太吵、规则太松，还是 Agent 产物不够好。

### 6. 今日行动
选一条每小时或每天运行的流程，写下它实际在等什么变化；如果能对应到一个明确的“新增 / 更新 / 完成”动作，就先为它补一张事件卡。

今天不必接通所有系统，只要完成：**事件名、对象 ID、事件 ID、默认终态和人工确认点**五项定义。下次改造时，先让它触发“创建草稿或任务”，不要直接触发外部发送。
