今天读什么｜别让 Agent 对着报错瞎猜：把工具做成“会自证、会指路”的接口

### 1. 适合谁读 / 预计阅读时间
适合正在把搜索、文档、表格、CRM、邮件或内部服务接进 AI Builder、智能体和增长自动化流程的人。尤其适合遇到过这种场景的团队：模型明明会思考，却总在工具调用上卡住——参数填错、对象不存在、权限不足、结果太长；最后它不是反复重试，就是编一个“看似完成”的答案。预计阅读时间约 10 分钟。

### 2. 为什么值得读
很多人把工具接入理解成“给 Agent 一组 API”。但对模型而言，工具的名称、说明、输入字段、返回结构和错误文本，就是它此刻的操作说明书。说明书含糊，模型再强也会猜：`user` 到底是昵称、邮箱还是内部 ID？“未找到”是可以换关键词再搜，还是用户本来就没有权限？一次工具返回 500 条记录时，下一步该筛选、分页，还是停止？

Anthropic 最近关于工具设计的文章把重点说得很直接：工具描述应像写给新同事的交接文档，隐含的业务术语、查询格式和资源关系要显式写出；严格的数据模型应同时约束输入与输出。MCP 规范也把结构化结果、输出 Schema 和可区分的执行错误列为正式能力。

它们共同提醒我们：工具不是“模型能调用的按钮”，而是 Agent 工作流中最关键的协作界面。

一句话：与其不断补“调用工具时要小心”的提示词，不如把工具本身做成能让 Agent 判断“能不能做、做了什么、失败后怎么办”的接口。

### 3. 核心概念
**第一，工具契约不只包括入参。**  
一个完整契约至少有五部分：用途与适用边界、精确输入、稳定输出、失败类型、下一步建议。只给 JSON 参数表，等于只告诉新同事“表格有几列”，却没说明什么时候该填、填错会怎样。

**第二，成功结果要可验证。**  
不要只返回“更新成功”。应返回对象 ID、关键字段、版本或更新时间、是否真的生效。这样下一步 Agent 能据此继续，人也能回读核验；这和“模型说自己做完了”是两回事。

**第三，错误应可行动，而非只可阅读。**  
`403`、`invalid input` 对程序员有信息量，对 Agent 不足。更有用的错误会区分：参数格式不对、资源不存在、无权限、临时限流、业务规则拒绝；并给出安全的补救方向，如“使用 customer_id，不接受邮箱”“30 秒后重试”“此操作需人工审批”。错误提示不是装饰，而是下一轮决策的输入。

**第四，结构化输出要为“不确定”留位置。**  
Schema 能保证字段形状，不能保证事实正确。检索为空、输入不兼容、模型拒绝、结果不完整，都应有明确状态和缺口字段；不能为了凑出合法 JSON 而把猜测塞进结果。

**第五，把大结果变成可导航的摘要。**  
工具不要把全量日志、数百条搜索记录原封不动扔回模型。默认返回总数、前几项、筛选条件、下一页游标和下一步动作；细节放在按需读取的资源或分页接口里。这既降低上下文噪声，也让 Agent 更容易选择下一步。

### 4. 可复用方法
给一个高频工具做“可诊断改造”，可按五步走：

1）收集真实调用轨迹：挑出最常见的 10 次成功、10 次失败，记录模型在哪个字段误解、失败后如何乱试。  
2）重写用途说明：写清“解决什么、何时使用、何时不要用”，并把模糊字段改为 `customer_id`、`document_url` 这类可判别名称。  
3）定义最小成功回执：统一返回 `status`、对象标识、关键结果、可核验链接或版本、下一步可选动作。  
4）设计错误分类：至少区分可修正、可重试、不可执行、需审批四类；每类附一条不越权的建议。对发送、删除、改权限等动作，错误或待审批状态不得诱导 Agent 绕过流程。  
5）把契约加入回归集：用旧的失败样本验证新版本是否少填错参数、少无效重试、能在不确定时正确停下。不要只测接口“返回 200”。

### 5. GenGrowth 可以怎么用
以“线索研究 → 生成外联草稿 → 写入待审核表”为例：

- `查找线索` 不只返回姓名列表，还返回命中依据、重复候选、未验证字段和建议补搜的维度；证据不足时状态应是“待补证”，不是伪装成合格线索。  
- `创建草稿` 返回草稿 ID、目标渠道、引用的资料版本和“未发送”状态；它不应把“草稿已建”说成“已联系客户”。  
- `写入待审核表` 若字段缺失，应指出具体缺哪一项并保留可恢复草稿；若触发重复或权限限制，应返回对应记录与人工处理入口，而非让 Agent 换个说法再建一条。

这样做的直接收益不是工具更多，而是让研究、内容和运营流程都能留下清楚的证据、失败原因与接手点。未来换模型、换 Bot 或把工具迁到 MCP，也更容易保持行为一致。

### 6. 今日行动
挑出当前最常被 Agent 调用、也最容易返工的一个工具。用最近 20 次调用给它做一次“契约体检”：

- 字段名是否有歧义？
- 成功是否有可回读凭据？
- 错误是否分类型并给出安全下一步？
- 结果是否默认过长？

今天只修复其中一个最高频问题，并用原失败样本重跑验证。
