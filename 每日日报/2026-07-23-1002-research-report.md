今天读什么｜别把业务规则藏在提示词里：给 Agent 加一层可测试的“决策护栏”

### 1. 适合谁读 / 预计阅读时间
适合正在用 AI 做选题研究、内容生产、线索筛选、客户跟进或内部自动化的人。尤其适合已经发现这种现象的团队：提示词越写越长，里面既有写作要求、品牌语气，也混着“什么客户能跟进”“什么情况下必须人工确认”“什么时候不能发”。一换模型、换工具或换 Bot，这些规则就开始漂移。预计阅读时间约 10 分钟。

### 2. 为什么值得读
很多 Agent 失控，并不是它故意越权，而是我们把本应稳定执行的业务规则，交给了一个擅长理解语言、但不保证每次判断一致的模型。

例如，“把高意向线索写入 CRM”这句话背后其实藏着一套政策：线索来自哪里？企业域名是否已验证？是否已经在触达？是否属于敏感行业？谁能批准？模型可以帮忙抽取、归纳和建议，但不该独自决定一条记录是否越过业务边界。

更稳的结构是把流程分成两层：**Agent 负责提出判断与生成候选动作；决策护栏负责用可审计的规则决定允许、拦截、转人工还是降级为草稿。** OpenAI 的 Agents SDK 把 guardrails、审批和可恢复运行放在工作流能力里；LangChain 则明确区分确定性规则与基于模型的检查，并支持在 Agent 前后、模型调用和工具调用周围插入中间件。共同信号是：安全与业务控制不应只是提示词中的一句提醒，而应成为运行时可验证的机制。

### 3. 核心概念
**第一，提示词是说明书，政策是裁判。** 提示词可以要求“谨慎处理高价值客户”，但必须由外部规则明确：客户等级达到什么阈值、允许哪些动作、谁能批准、过期后如何处理。否则“谨慎”只是一个会随上下文浮动的词。

**第二，先判资格，再让模型发挥。** 先用确定性检查处理身份、权限、数据完整度、频率上限、黑名单、预算和时间窗；通过后再交给模型做语义判断、个性化表达和优先级建议。这样不会让模型把大量时间花在本来就不能执行的任务上。

**第三，护栏的结果不只有“通过/拒绝”。** 至少保留四种状态：允许执行、改为草稿、进入人工复核、明确阻断。把所有不确定情况都一刀切拦截，会制造审批拥堵；一律放行，又会把风险推到下游。

**第四，规则与模型检查要分工。** 域名是否为空、一天是否已触达两次、是否命中禁止发送名单，适合确定性规则：快、便宜、可复现。判断文案是否像承诺效果、来源之间是否存在语义矛盾，则可用模型检查或人工复核。不要让模型替代数据库约束，也不要用正则假装能理解复杂语境。

**第五，每次判定都要留下“理由码”。** 不只记录“未发送”，还要记录 `缺少已验证域名`、`近 7 天已触达`、`涉及对外发布需审批` 等原因，以及规则版本、输入快照和最终处理人。这样才能解释、复盘、修正规则，而不是下次再补一句提示词。

### 4. 可复用方法
给任意一条“研究→判断→动作”流程加护栏，可从五步开始：

1）列出所有动作，不按工具名而按业务影响分级：读取、生成草稿、内部写入、对外发送、删除/改权限。  
2）为每个动作写一张政策卡：前置条件、禁止条件、所需证据、默认终态、审批人、失效时间。  
3）把可确定判断外置为配置或代码：例如“无来源链接不得发布”“联系人退订后永久阻断”“同公司 30 天内只允许一条首次外联”。  
4）让 Agent 返回结构化“行动提案”：对象、建议动作、依据、置信度、缺口；护栏只消费这些字段，不解析一整段自由文本。  
5）为政策写回归样本：允许、拦截、转人工各准备几例；每次改规则或模型后，确认同一输入仍得到预期终态。

### 5. GenGrowth 可以怎么用
可先从“AI 辅助外联/内容发布”中选一条低风险链路试点：研究 Agent 只产出目标客户卡和外联草稿；规则层核验来源、去重、触达频次与行业限制；满足条件的草稿进入审核队列，未满足的则标出缺口但不发送。

同一套机制也适用于内容：模型可以提出选题和首稿，但“是否可发布”由引用完整性、敏感表述、品牌禁用词、客户案例授权与负责人确认共同决定。这样沉淀的不是某个模型的临场记忆，而是一套可迁移到不同 Bot、不同模型的增长操作标准。

### 6. 今日行动
挑一条当前最容易“靠提示词硬控”的流程，花 30 分钟完成一张政策卡：

- 选一个动作：例如“创建 CRM 线索”或“发送外联”；
- 写出 3 条必过条件、3 条必拦条件、2 条转人工条件；
- 为每条规则命名并指定证据字段；
- 取最近 10 个真实样本回放，统计原来会误放行或误拦截多少个。

先不追求覆盖所有异常。只要让一个关键动作从“模型觉得可以”变成“系统能说明为什么可以”，工作流就开始变得可运营。
