今天读什么｜把高频工作做成 Agent 的“技能包”，而不是越堆越长的提示词

### 1. 适合谁读 / 预计阅读时间
适合正在搭 AI Builder、研究助手、内容生产、线索整理或增长自动化的人。尤其适合遇到这种情况的团队：一个流程最初只是一段提示词，后来不断补规则、补示例、补例外，终于变成没人敢改、换个 Bot 又得复制一遍的“提示词巨石”。预计阅读时间 10 分钟。

### 2. 为什么值得读
很多 Agent 的不稳定，不是模型不会推理，而是组织已经知道的做法没有被封装成可复用的工作能力。比如“把一场访谈整理成选题包”“把网页资料变成带出处的研究稿”“把线索转成待审核外联草稿”，常被散落在聊天记录、长提示词和资深同事脑中。每个新流程都从头教一次，既耗上下文，也无法确认大家是否遵循同一版本。

近期 OpenAI、Anthropic 与 Agent Skills 开放规范都在强调一种中间层：**技能包（Skill）**。它不是又一条万能提示词，也不是直接改外部系统的工具；它把稳定的步骤、脚本、模板、示例与校验方式放进一个可版本管理的目录，需要时才加载。这样，模型仍负责判断和表达；确定性工作交给代码；执行权限仍由工具与审批控制。

一句话：把反复成功的工作方法做成技能包，才能让 Agent 从“每次临场发挥”变成“按组织标准交付”。

### 3. 核心概念
**第一，提示词、工具、技能包各管一层。** 系统提示词只放长期有效的身份、边界和语气；工具负责读取实时数据或执行外部动作；技能包负责“这类任务该怎样完成”的可复用流程。把三者混在一起，通常会造成提示词膨胀、工具过度暴露、规则难以测试。

**第二，技能包是渐进加载的。** Agent 启动时只需看名称和简短说明；任务匹配后再读完整说明；脚本、模板和参考资料只在确有需要时读取或运行。这种分层既让技能库可以变大，也避免把所有 SOP 都塞进每次对话。

**第三，好的技能包要把“会做”变成“可验收”。** 它至少应讲清：何时使用、输入是什么、产物放哪里、执行步骤、不可触碰的边界、怎样验证完成。能由代码处理的字段检查、去重、格式转换、文件生成，不要让模型凭文字反复猜。

**第四，版本比“最新版”更重要。** 生产流程应能回答：这份报告、这次线索处理，用的是哪一版技能包？新版本先在样本上对比，再逐步替换。否则一次看似无害的文案修改，也可能悄悄改变触发范围、跳过校验或损坏产物格式。

**第五，技能包也是供应链。** 它可以带脚本和依赖，来源不明的包可能诱导 Agent 访问网络、读取不该读的文件或执行不该执行的命令。安装前必须审阅说明、脚本、依赖和网络访问；高风险动作仍应走最小权限与人工确认，不能因为“技能看起来专业”就自动放权。

### 4. 可复用方法
把一个高频流程技能化，可从五步开始：

1）挑“每周至少重复一次、且经常返工”的流程，而非一次性需求。例如“长文拆成公众号/短帖/行动卡”。  
2）先写一页最小技能说明：触发条件、输入、输出、五步以内的流程、失败时如何停下并交回人工。  
3）把确定性部分外移：链接规范化、表格字段校验、字数统计、文件命名等写成小脚本或模板。  
4）准备 5—10 个真实样本，分别检查是否正确触发、步骤是否漏做、产物是否合格、是否误碰外部动作。  
5）用版本号发布：先让少量任务使用新版本；记录失败样本后再迭代，不直接覆盖已验证的版本。

### 5. GenGrowth 可以怎么用
GenGrowth 不必先建“万能营销 Agent”，可先沉淀三类小技能包：

- **研究报告技能包**：输入主题和可信来源，输出正文、论点—证据对应表、待核实项与参考链接；证据不足时只交草稿，不把推断写成事实。  
- **内容再利用技能包**：把一篇已审定的长文拆成不同平台版本，并强制保留原文依据、受众、行动号召与禁用表述，避免“多平台改写”越改越失真。  
- **增长线索整理技能包**：把公开线索整理为结构化卡片与外联草稿；只生成草稿和优先级，不自动发送，不把资料直接写回客户系统。  

这三类包共用一张最小登记表：技能名称、负责人、适用场景、当前版本、允许工具、输入输出、测试样本、风险等级。它会比继续累加一份“超级提示词”更容易协作、审查和复用。

### 6. 今日行动
选出团队最近一个月返工最多的一项重复工作，用 30 分钟写出它的技能包骨架：触发条件、输入、输出、步骤、验收、停止条件。再挑 3 个历史任务回放：若其中任意一个无法按说明复现，就先补清楚 SOP，不急着把它接到更多工具上。
