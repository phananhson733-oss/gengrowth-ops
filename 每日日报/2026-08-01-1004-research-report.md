今天读什么｜别让 Agent 先搜一堆资料：先画一棵“决策问题树”

### 1. 适合谁读 / 预计阅读时间
适合用 AI 做竞品研究、内容选题、客户洞察、增长方案或行业跟踪的人。尤其适合这样的场景：Agent 搜回几十个链接、报告看上去很完整，但团队最后仍答不清“所以该不该做、先做什么、依据是什么”。预计阅读约 10 分钟。

### 2. 为什么值得读
研究任务最常见的浪费，不是搜不到，而是**没有先定义这次研究要帮助哪一个决策**。例如“研究 AI 内容工具市场”，如果不说明最终要决定的是选题、采购、客户定位还是产品立项，Agent 很容易把公司介绍、融资新闻、功能清单和观点全装进一篇长文；信息变多，决策反而没有变清楚。

更稳的做法是把研究起点从“大主题”改成“决策问题树”：先写出待决定的动作，再拆成几个必须回答、且彼此不同的关键问题。每个问题都指定可接受的证据、搜索边界与停止条件。这样，检索不再是漫游，而是在降低某个具体不确定性。

Anthropic 对多 Agent 研究系统的复盘指出：子 Agent 若没有明确目标、输出格式、工具/来源指引和边界，会重复搜索或留下空白。LangChain 的可审计研究案例则把“并行取证”和“无工具综合”分开，让最终写作只能使用已经找到的证据。这两个实践的共同点是：先决定问题结构，再扩大检索范围。

### 3. 核心概念
**第一，主题不等于决策。** “研究竞品”是主题；“本月是否为某类客户推出竞品快报服务”才是决策。决策应包含动作、对象、时限和衡量标准。

**第二，问题树只保留会改变选择的问题。** 以“是否做竞品快报服务”为例，可拆成：目标客户是否有持续需求？现有替代方案有什么缺口？我们能否稳定拿到可引用数据？试点的交付成本是否可控？如果一个问题无论答案如何都不改变下一步，就不要让 Agent 花预算研究它。

**第三，给每个枝节配“证据门槛”。** 客户需求不能只靠一篇趋势文章；可要求公开岗位、客户访谈、竞品定价或实际采购信号中的至少两类。产品功能优先看官方文档或可操作演示；市场判断要明确哪些是事实、哪些是推断。这样可以避免“链接很多、证据却同源”的假繁荣。

**第四，综合与检索分工。** 研究 Worker 可以带搜索工具，但最后的综合器最好只读取结构化证据包：结论、出处、反例、置信度、缺口。它不再临时检索，能减少为了写得顺而补出未经核验细节的风险。

**第五，树要允许剪枝。** 当一个关键假设被强证据否定、证据冲突超过阈值，或剩余时间不足以补齐关键缺口，应停止扩展枝节，转为“暂不决策 / 小范围试点 / 请求人工补证”。研究的好终点不一定是肯定答案，而是把不值得继续投入的方向及时关掉。

### 4. 可复用方法
用一张一页纸的研究卡启动任何高价值任务：

1）先写决策句：`在本周内，是否为 X 客群测试 Y 服务；成功以 Z 指标判断。`  
2）列 3—5 个关键问题，并标注它们分别会支持、否决还是调整什么选择。  
3）每题定义证据门槛：首选来源、最低数量、反证必须从哪里找、何时停止。  
4）按问题而不是按“研究员人设”分派：一人负责需求信号，一人负责替代品与价格，一人负责交付可行性；禁止重复搜同一泛关键词。  
5）汇总时先填决策表，再写文章：每题输出“支持 / 反对 / 未知、证据、置信度、建议动作”。只有决策表完整，才把它改写成报告或内容。

### 5. GenGrowth 可以怎么用
把“AI Builder 研究”从日报式收集升级为机会筛选。比如要判断“是否围绕某个 Agent 工具做内容与咨询包”，先建四枝：目标读者是否已有明确痛点、该工具是否有可演示的真实工作流、竞争内容是否拥挤、GenGrowth 是否能在两周内交出低风险试点。最终不要只得到一篇工具介绍，而要得到三种明确状态：进入选题和 Demo；继续补证；暂不跟进。

同一张树还能复用到客户研究：把“客户是谁”改成“是否值得进入外联草稿队列”。只有身份、痛点触发信号、现有方案和触达边界达到门槛，才进入后续文案生成；其余记录保留为待观察，而不是让 Agent 用泛化猜测强行推进。

### 6. 今日行动
挑一个正在进行的研究题，把原来的任务描述改写成一张“1 个决策＋最多 5 个问题”的表。给每题补上证据门槛与停止条件；然后检查已有资料：删掉所有不影响决策的链接。下一次让 Agent 交付时，先要求它返回决策表和证据缺口，再要求成文。
