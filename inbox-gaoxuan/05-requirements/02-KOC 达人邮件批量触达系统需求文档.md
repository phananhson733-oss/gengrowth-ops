> [!summary] 一句话结论
> 运营从已审核的达人名单中批量选择联系人，选择本次使用的一个或多个 Gmail 发件账号并点击启动。系统按发件账号分别排队、统计已发/发送中/待发和剩余额度，每封邮件明确记录由哪个 Gmail 发出；运营可以把尚未发送的任务转移给另外的 Gmail，已发送或正在提交发送的邮件不得重复分配。

> [!important] 产品关系
> 本需求与“KOC 达人发现与公开联系方式采集工具”是两个独立需求，可以部署在同一个平台中。前者负责找人和找公开联系方式，本模块只负责审核、发送、跟进、回复和禁止联系管理。

## 0. 本轮需要产品与开发优先完成的内容

```text
创建建联活动
→ 导入已审核联系人
→ 检查邮箱及联系方式来源
→ 查询历史建联和全局禁止名单
→ 排除重复、无效、退订、拒绝和黑名单
→ 选择本次使用的 Gmail 发件账号
→ 查看每个账号当日已发量、待发量和剩余额度
→ 为联系人分配发件账号
→ 选择模板并生成个性化内容
→ 运营预览确认
→ 计算容量和完成时间
→ 生成 5–15 分钟随机发送计划
→ 到点前再次检查
→ 调用邮件服务发送
→ 获取送达、退信、回复、退订等事件
→ 有回复或异常时取消后续邮件
→ 必要时把尚未发送任务转移到其他 Gmail
→ 回写达人库
```

“随机间隔”在需求中定义为发送节奏和送达率保护，不能表述为绕过或规避 Gmail 机制，也不能保证一定进入主收件箱。

# 一、为什么要做

- 手动复制联系人、称呼和模板效率低；
- 多名运营可能重复联系同一达人；
- 短时间集中发送会影响发件账号健康；
- 已回复达人仍可能收到自动跟进；
- 退订、投诉、拒绝和退信邮箱可能再次入队；
- 无法追溯每封邮件使用的来源、模板和发件账号；
- 达人发现结果与建联结果无法形成闭环。

目标是统一“选人—审核—排期—发送—跟进—回复—回写”流程，而不是只做一个群发按钮。

# 二、第一版范围

## 2.1 第一版只做

| 优先级 | 功能 | 说明 |
|---|---|---|
| P0 | 导入联系人 | 来自达人库、CSV 或表格 |
| P0 | 发送前审核 | 检查邮箱、来源及历史状态 |
| P0 | 创建活动 | 设置模板、发件邮箱和发送规则 |
| P0 | 多 Gmail 账号 | 第一版支持连接并管理 2–3 个 Gmail 发件账号 |
| P0 | 发件账号选择 | 创建活动时选择使用哪个或哪些 Gmail |
| P0 | 按邮箱统计 | 分别显示已发、发送中、待发、失败、剩余额度 |
| P0 | 发件任务分配 | 每封邮件在发送前明确分配到一个 Gmail |
| P0 | 待发任务转移 | 将尚未发送的任务转移到另一个 Gmail |
| P0 | 批量入队 | 点击一次，系统逐封排期 |
| P0 | 每日上限 | 单邮箱最高 100 封，可设更低 |
| P0 | 随机间隔 | 5–15 分钟，实际不少于 5 分钟 |
| P0 | 发送时段 | 按时区和工作时间控制 |
| P0 | 去重 | 防止同达人/邮箱重复发送 |
| P0 | 回复停止 | 检测回复后取消跟进 |
| P0 | 退信/退订/投诉 | 自动停止并进入禁止名单 |
| P0 | 状态回写 | 结果同步回达人库 |
| P1 | 最多两次跟进 | 间隔可配置 |
| P1 | AI 个性化 | 只基于公开资料，发送前可预览 |
| P1 | 回复分类 | 正向、询价、拒绝、自动回复等 |
| P2 | CRM 管道 | 报价、谈判、合作及完成阶段 |

## 2.2 第一版不做

- 不向来源不明的猜测邮箱自动发送；
- 不向无效、退订、投诉或禁止邮箱发送；
- 不绕过 Gmail 或服务商限制；
- 不通过频繁换域名规避投诉；
- 不保证每天必须发满 100 封；
- 不保证进入主收件箱；
- 不自动承诺价格、佣金、合同或交付；
- 不让 AI 自动回复价格和合同问题；
- 不未经人工确认直接启动整批邮件；
- 不以打开率作为唯一效果指标。

# 三、核心业务流程与节点说明

> [!important] 本章是第一版开发的主要依据
> 具体接入哪个邮件服务商、使用何种队列由技术评估，但以下业务节点和检查规则需要完整实现。

## 3.1 节点一：创建建联活动

| 项目 | 说明 |
|---|---|
| 操作人 | 运营 |
| 输入 | 活动名称、联系人、发件邮箱、模板、日期、每日上限、时段、跟进规则 |
| 做什么 | 创建唯一 `campaign_id` 和草稿活动 |
| 数据来源 | 运营输入 + 达人联系人库 |
| 输出 | draft 活动 |
| 失败处理 | 必填项不完整则保存草稿但不能启动 |

## 3.2 节点二：导入联系人

来源可为 KOC 发现工具的“加入建联名单”、历史达人库、CSV、Google Sheet、飞书表格或人工新增。

最小字段：`creator_id`、handle、主页、称呼、email、邮箱来源、验证状态、地区（如有）、发现来源和历史建联状态。缺少邮箱、来源或验证状态者不能直接进入自动队列。

## 3.3 节点三：联系人准入检查

| 检查 | 数据来源 | 不通过处理 |
|---|---|---|
| 邮箱存在/格式正确 | 联系人库、验证结果 | missing/invalid |
| 邮箱已验证 | 邮箱验证服务 | 人工审核 |
| 有明确公开来源 | 联系方式来源记录 | 人工审核 |
| 是否退订/投诉/永久退信 | 全局禁止名单、邮件事件 | 直接排除 |
| 是否明确拒绝 | 历史回复 | 排除或人工确认 |
| 是否本活动已发送 | 当前活动记录 | 排除 |
| 是否其他活动正在发送 | 其他队列 | 提示冲突 |
| 是否合作中 | 达人库/CRM | 默认排除或确认 |
| 是否达到重新联系冷却期 | 历史建联 | 未达到则排除 |

输出必须分为：可以发送、需要人工审核、本次跳过、永久禁止。界面显示原始导入数及各类排除数量，运营确认前不得发送。

## 3.4 节点四：查询历史建联状态

按 `creator_id`、handle、主页及邮箱综合查询达人库、历史活动、邮件事件和回复记录，输出上次发送时间、模板、发件邮箱、回复状态及是否允许再次联系。

不能只按邮箱去重：同一达人更换邮箱或使用代理邮箱时仍要提示可能重复联系。

## 3.5 节点五：选择并检查发件邮箱

| 检查 | 数据来源 |
|---|---|
| API/账号授权 | 邮件服务商 |
| 当日已发和剩余容量 | 服务商数据 + 系统记录 |
| 上一封发送时间 | 系统队列 |
| 退信/投诉/失败 | 邮件事件 |
| SPF/DKIM/DMARC | 域名配置或检查服务 |
| 暂停/预热阶段 | 系统发件账号配置 |

输出是否可发送、剩余容量、当前上限、最早开始时间和预计完成天数。异常时活动保留草稿或暂停。系统不能在未告知运营的情况下自动改用其他邮箱；是否把待发任务转移到另一个 Gmail，由运营选择或按运营事先确认的分配规则执行。

### 3.5.1 Gmail 发件账号列表

第一版预计接入 2–3 个 Gmail/Google Workspace 发件账号。系统需要为每个账号单独显示：

| 字段 | 说明 |
|---|---|
| `sender_email` | Gmail 发件地址 |
| `sender_name` | 对外显示的发件人名称 |
| `connection_status` | connected / expired / error / disconnected |
| `health_status` | normal / warning / paused |
| `daily_limit` | 该邮箱当日发送上限 |
| `sent_today` | 今天已成功提交发送的数量 |
| `sending_now` | 正在提交发送、结果尚未确认的数量 |
| `scheduled_today` | 今天已排期但尚未发送的数量 |
| `queued_later` | 已分配给该邮箱、排在后续日期的数量 |
| `failed_today` | 今天发送失败数量 |
| `remaining_capacity` | 今日剩余可用额度 |
| `last_sent_at` | 最近一次实际发送时间 |
| `next_scheduled_at` | 下一封计划发送时间 |
| `paused_reason` | 暂停原因 |

`remaining_capacity` 建议按以下逻辑计算：

```text
今日剩余额度 = 今日上限 - 今日已发送 - 正在发送 - 今日已占用的待发名额
```

界面需要明确区分“历史累计发送量”和“今天已发送量”，避免运营误判剩余额度。

### 3.5.2 创建活动时选择 Gmail

创建活动时，运营可以：

1. 只选择一个 Gmail，全部联系人先由该邮箱发送；
2. 同时选择两个或三个 Gmail，并为每个邮箱指定联系人数量；
3. 选择一个主发件邮箱，另外两个先不分配任务；
4. 主邮箱的当前任务发完后，再人工选择剩余邮箱接手尚未发送的联系人；
5. 随时查看每个 Gmail 分别负责哪些联系人。

选择邮箱时必须显示：

- 当前是否连接正常；
- 今天已经发送多少；
- 今天还可以安排多少；
- 当前待发多少；
- 预计什么时候发完；
- 是否有退信、投诉或授权异常。

### 3.5.3 为邮件分配发件账号

每一封邮件在进入发送队列前必须有唯一的 `sender_account_id`。不能仅在活动层面记录“使用了三个邮箱”，而要在单封邮件层面记录具体由哪个邮箱负责。

分配方式支持：

| 分配方式 | 说明 |
|---|---|
| 人工选择 | 运营勾选联系人并指定某个 Gmail |
| 按数量分配 | 例如 Gmail A 先发 80，剩余 120 暂不分配 |
| 平均分配 | 将名单大致平均分给选中的 Gmail |
| 按剩余额度分配 | 根据各邮箱当日剩余额度分配 |
| 后续人工接手 | 主邮箱发完后，再把尚未发送的任务转给 Gmail B/C |

第一版至少必须支持“人工选择”“按数量分配”和“后续人工接手”。

### 3.5.4 待发任务转移到其他 Gmail

运营可以在活动运行中执行“转移待发任务”：

```text
选择原发件邮箱
→ 查看该邮箱尚未发送的任务
→ 勾选全部或部分待发任务
→ 选择新的 Gmail
→ 系统检查新 Gmail 的连接、健康状态和容量
→ 重新生成发送时间
→ 更新每封邮件的 sender_account_id
→ 保存转移记录
```

允许转移的状态：

- `queued`：已入队但未排期；
- `scheduled`：已排期但未到发送时间；
- `paused`：暂停且尚未发送。

默认不允许转移的状态：

- `sending`：正在向 Gmail 提交；
- `sent`：已经发送；
- `delivered`：已经送达；
- `replied`：已经回复；
- `cancelled`：已取消；
- `bounced`：已经发生退信；
- `failed_unknown`：发送结果不确定，需要先人工确认。

转移规则：

1. 已发送邮件不得因为更换邮箱重新发送；
2. `sending` 状态必须等到服务商返回结果后才能决定；
3. 发送结果不确定时先暂停，不能直接转移，以免重复发信；
4. 转移后按照新 Gmail 的时间窗口和 5–15 分钟规则重新排期；
5. 新 Gmail 的每日上限独立计算；
6. 转移操作需要保存原邮箱、新邮箱、操作人、时间、任务数量和原因；
7. 联系人历史中同时保留“原计划邮箱”和“实际发送邮箱”。

### 3.5.5 按 Gmail 查看联系人和邮件

系统至少提供以下筛选：

- 全部邮箱；
- Gmail A；
- Gmail B；
- Gmail C；
- 尚未分配邮箱；
- 已发送；
- 正在发送；
- 今日待发；
- 后续日期待发；
- 失败；
- 暂停；
- 已回复。

每条邮件列表必须显示：达人、收件邮箱、当前发件 Gmail、原计划 Gmail、计划时间、实际时间、状态、活动和转移记录。

## 3.6 节点六：选择模板并生成内容

输入模板、达人称呼、handle、公开内容、发现来源和品牌资料，为每位达人生成主题和正文。数据来自模板库、达人库、公开内容和运营输入。

AI 个性化只能引用已保存的公开资料，不能编造视频、地区、粉丝画像、合作经历或产品体验。保存引用来源、生成时间、人工修改和最终版本。生成失败时回退普通模板或人工审核。

模板变量至少支持 `creator_name`、handle、profile_url、country、source_hashtag、source_bgm、recent_content_reference、brand_name、product_name、sender_name 和 unsubscribe_link。

## 3.7 节点七：运营预览与确认

运营需要看到导入/排除/待审核/可发送人数、发件邮箱、每日上限、发送时段、随机间隔、预计天数、模板样本、跟进次数和退订信息。

支持修改单封、批量换模板、删除联系人、发送测试邮件、保存草稿。只有点击“确认启动”后才能进入排期。

## 3.8 节点八：计算容量和完成时间

综合可发送人数、每日上限、5–15 分钟间隔、发送窗口、邮箱预热阶段、当天已发、周末/节假日和跟进占用，计算每天实际可发送量及预计完成日期。

100 封是最高上限，不是必须完成量。如果计划无法在要求日期内完成，需要提示运营，而不是压缩间隔或集中追赶。

## 3.9 节点九：生成随机发送计划

| 项目 | 说明 |
|---|---|
| 输入 | 联系人队列、发送窗口、每日上限 |
| 做什么 | 为每封邮件生成 `scheduled_at` |
| 怎么做 | 在上一封时间基础上随机增加 5–15 分钟 |
| 输出 | 分布到一个或多个工作日的队列 |
| 失败处理 | 超过时段/上限自动顺延 |

规则：实际间隔不得少于 5 分钟；系统延迟后不得集中追赶；暂停恢复后重算未发送任务；跟进邮件进入同一正常队列；每个 Gmail 分别计算自己的每日上限、上一封时间、下一封时间和 5–15 分钟随机间隔。

如果 Gmail A 和 Gmail B 同时运行，两者可以各自拥有发送队列，但系统仍需清楚记录每封邮件由哪个 Gmail 发出，并防止同一达人同时被两个 Gmail 联系。

## 3.10 节点十：发送前最终检查

到达计划时间后再次检查：活动仍运行、发件邮箱正常、当日有容量、距上一封至少 5 分钟、当前在允许时段、达人没有刚回复/退订/拒绝/退信/被拉黑，且没有人工暂停。

任一不通过则取消、顺延或等待人工处理，并保存原因，不能直接发送。

## 3.11 节点十一：调用邮件服务发送

将收件地址、主题、正文、发件邮箱、Reply-To 和退订信息发送到 Google Workspace/Gmail API 或公司选择的合规发信服务。保存服务商消息 ID、实际发送时间、最终正文、模板、达人和活动。

系统优先使用正式 API，不建议模拟点击 Gmail 网页。失败按错误类型决定是否重试，重试仍需重新入队并遵守间隔，不能立即连续重试。

## 3.12 节点十二：接收邮件事件

| 事件 | 数据来源 | 系统动作 |
|---|---|---|
| sent/delivered | 邮件服务 API/Webhook | 更新状态 |
| bounced | 退信事件 | 区分临时/永久退信 |
| replied | Gmail/企业邮箱 API、收件箱同步 | 停止后续跟进 |
| unsubscribed | 退订链接/服务事件 | 加入全局禁止名单 |
| complained | 投诉事件 | 立即停止并告警 |
| failed | 服务商错误 | 记录原因 |
| opened/clicked | 工具支持时 | 仅供参考 |

永久退信立即取消后续、更新邮箱状态、加入禁止名单并回写达人库。临时退信是否重试由规则决定，但不得立即连续重试。

## 3.13 节点十三：识别回复并停止跟进

从 Gmail/企业邮箱 API 或回复同步中取得新邮件，通过邮件线程 ID、收件邮箱和达人 ID 匹配原活动。匹配成功后立即取消所有未发送跟进；匹配失败进入人工审核。

回复分类：正向合作、询价、需要信息、暂无兴趣、明确拒绝、停止联系、自动回复、联系人错误、代理回复、其他或待人工判断。AI 可以辅助分类，但价格、合同和合作条件必须人工回复。

## 3.14 节点十四：生成自动跟进

只有首封成功、未收到真人回复、未退订/拒绝/永久退信/禁止联系、活动仍运行且未超过次数时才生成跟进。

```text
首封完成
→ 等待配置的工作日
→ 再次检查回复与禁止状态
→ 生成跟进
→ 进入正常队列
→ 按每日上限和 5–15 分钟间隔发送
```

第一版最多两次跟进。建议首封后 3–5 个工作日第一次跟进，再过 5–7 个工作日第二次跟进。

## 3.15 节点十五：异常监控和自动暂停

授权失效、连续失败、永久退信率/投诉/退订异常、服务商限制、当日发送异常、严重 API 错误或人工操作均可暂停活动/邮箱。

暂停后保留未发队列、不产生新发送、不自动换邮箱、显示原因和时间；管理员确认恢复后重新计算计划。

## 3.16 节点十六：结果回写达人库

回写 `outreach_status`、最近联系时间、campaign、发件邮箱、回复意向、邮箱状态、禁止状态和下一步动作。下一次发现模块搜到同一达人时，应直接看到最新状态。

闭环：

```text
发现达人
→ 获取公开联系方式
→ 加入建联
→ 发送邮件
→ 获取回复
→ 回写状态
→ 下次搜索避免重复联系
```

# 四、发送策略与账号保护

- 单发件邮箱每日最多 100 封，管理员可设更低；
- 2–3 个 Gmail 分别计算各自的每日上限和发送间隔，不合并成一个模糊总数；
- 系统同时显示全部 Gmail 合计数量和每个 Gmail 的独立数量；
- 首封和跟进均计入当日数量；
- 两封营销邮件实际间隔不少于 5 分钟，随机范围 5–15 分钟；
- 只在设置的日期、时区和工作时间发送；
- 达到上限/超出时段自动顺延；
- 新邮箱逐步增加量，例如 10–20、20–40、40–60，稳定后再调整；
- 支持 SPF、DKIM、DMARC、TLS、Reply-To 和退订入口检查/记录；
- 投诉、退信或授权异常时自动暂停；
- 随机间隔不能替代域名信誉、邮箱认证、名单质量和退订机制。

# 五、联系人、回复与禁止规则

允许入队：公开已验证邮箱；人工确认的公开未验证邮箱；确认适用的代理邮箱。

默认拦截：missing、invalid、inferred_unreviewed、unsubscribed、complained、hard_bounced、blocked、明确拒绝继续联系、来源不明或无法对应达人身份的邮箱。

`suppression_list` 必须跨活动生效，包含退订、投诉、永久退信、明确停止联系、人工黑名单和合规禁止记录。

# 六、默认数据结构

## 6.1 `outreach_campaigns`

保存活动 ID/名称、来源搜索、发件邮箱、模板、每日上限、最短/最长间隔、时区、发送窗口、跟进次数、状态、创建人和时间。

## 6.2 `campaign_contacts`

保存 campaign、creator/contact ID、邮箱、来源、验证、个性化、审核、历史联系、队列状态、跳过原因和加入时间。

## 6.3 `email_queue`

保存 email、campaign、creator、收件邮箱、当前 `sender_account_id`、原计划 `original_sender_account_id`、主题、正文、邮件步骤、计划/实际时间、状态、重试和失败/取消原因。

每封邮件必须有且只有一个当前发件账号。发件账号发生转移时更新当前账号，但保留原计划账号及转移历史。

## 6.4 `email_events`

保存服务商事件 ID、事件类型、时间和详情，包括 queued、scheduled、sent、delivered、bounced、replied、unsubscribed、complained、cancelled、failed 等。

## 6.5 `suppression_list`

保存邮箱、达人、原因、来源活动/邮件、加入时间、操作人和是否全局生效。

## 6.6 `sender_accounts`

保存发件账号 ID、Gmail 地址、显示名称、服务商、授权状态、每日上限、预热阶段、认证状态、健康状态、今日已发送、正在发送、今日待发、后续待发、失败数量、今日剩余额度、上次发送、下一封计划时间和暂停原因。

## 6.7 `sender_assignment_history`

保存邮件发件账号的分配和转移历史：

- `email_id`
- `campaign_id`
- `creator_id`
- `from_sender_account_id`
- `to_sender_account_id`
- `action_type`：initial_assignment / reassignment
- `reason`
- `operated_by`
- `operated_at`
- `previous_scheduled_at`
- `new_scheduled_at`

# 八、验收标准

1. 导入至少 500 条联系人，正确显示排除/待审/可发送数量；
2. 能够连接并展示至少 3 个 Gmail 发件账号；
3. 创建活动时可以选择一个、两个或三个 Gmail；
4. 每个 Gmail 分别显示今日已发、正在发送、今日待发、后续待发、失败和剩余额度；
5. 可以按 Gmail 筛选其负责的联系人和邮件；
6. 每封邮件明确保存实际由哪个 Gmail 发出；
7. 尚未发送的 queued/scheduled/paused 任务可以转移到另一个健康 Gmail；
8. sent/delivered/replied 邮件不能被转移或重复发送；
9. `sending` 或结果不确定的邮件不能直接转移，避免重复；
10. 转移后按照新 Gmail 的容量、时段和随机间隔重新排期；
11. 每次转移保存原邮箱、新邮箱、操作人、时间、数量和原因；
12. 重复、无效、退订、投诉和黑名单不会入队；
13. 同一达人更换邮箱时仍能提示重复风险；
14. 只有人工确认后活动才启动；
15. 每个 Gmail 的每日发送量分别不超过其管理员上限，最高 100；
16. 每个 Gmail 自己的任意两封实际间隔不少于 5 分钟且符合 5–15 分钟规则；
17. 超时段或超上限自动顺延，不集中追赶；
18. 到达发送时间前执行最终检查；
19. 回复后立即取消该达人所有未发跟进，包括分配给其他 Gmail 的任务；
20. 永久退信、退订、投诉和停止联系写入全局禁止名单；
21. 首封和最多两次跟进都遵守相同队列规则；
22. 发件账号异常时自动暂停并显示原因；
23. 每封邮件可追溯达人、邮箱来源、活动、模板、原计划 Gmail、实际 Gmail 和结果；
24. 结果正确回写达人库，下次搜索不会重复建联。

# 十、当前结论

第一版最小可交付：

```text
从达人库选择已审核联系人
→ 检查邮箱、来源、历史联系和禁止名单
→ 排除不能联系者
→ 选择本次使用的一个或多个 Gmail
→ 查看各 Gmail 已发、待发和剩余额度
→ 为每封邮件分配具体 Gmail
→ 选择模板
→ 预览并人工确认
→ 每个 Gmail 按自己的每日上限及 5–15 分钟随机间隔排队
→ 发送前再次检查
→ 调用正式邮件服务发送
→ 接收送达、回复、退信、退订和投诉事件
→ 必要时把尚未发送任务转给其他 Gmail
→ 自动停止不应继续的邮件
→ 把结果回写达人库
```

> [!success] 完成判断
> 运营可以连接并选择 2–3 个 Gmail，清楚看到每个邮箱分别已发多少、正在发送多少、待发多少和剩余多少；每封邮件明确记录实际发件 Gmail；未发送任务可以安全转移，已发送任务不会重复；回复、退订、拒绝或退信后能停止全部相关后续邮件，并将结果回写达人库。
