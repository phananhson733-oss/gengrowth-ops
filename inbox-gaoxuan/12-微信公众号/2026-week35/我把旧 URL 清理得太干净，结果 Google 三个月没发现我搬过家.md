# 我把旧 URL 清理得太干净，结果 Google 三个月没发现我搬过家

BY GENGROWTH

三个月前，我把一个网站从 /en/ 前缀迁到了根路径。

上周导出 Google Search Console 的效果报告后，我把所有已经跳转的旧 URL 单独加总了一遍。

结果有点离谱：

**97 个已经不存在的旧 URL，拿走了全站 88.3% 的曝光。**

统计窗口是 5 月 10 日至 8 月 9 日。旧 URL 一共获得 8,821 次曝光和 25 次点击；全站同期只有 9,986 次曝光和 39 次点击。

其中一个旧 URL，单独获得了 908 次曝光和 20 次点击。全站三个月总共 39 次点击，一半以上还记在一个已经搬走的页面名下。

网站迁移该做的几件事，我都做了：

- 旧 URL 配置了永久跳转；
- 提交了包含新 URL 的 sitemap；
- 所有内部链接都换成了新地址；
- 新页面声明了正确的 canonical。

**配置已经搬完，但 Google 的 URL 迁移显然还没有完全收口。**

## 一、先排除配置错误

看到 88.3% 时，我的第一反应不是研究 Google，而是怀疑自己哪里配错了。

这一步比后面的分析更重要。遇到类似情况，一定要先排除配置问题，否则很容易把原本正确的配置改坏。

我重新检查了七项：

1. 跳转是否一步到达最终 URL？是，没有跳转链。
2. 是否通过 robots.txt 阻止 Google 抓取旧 URL？没有。
3. 新 sitemap 是否还残留旧 URL？没有。
4. 站内是否还有链接指向旧 URL？没有。
5. 新页面的 canonical 是否指向自己？是。
6. hreflang 是否仍引用旧 URL？没有。
7. 跳转目标是否真实存在？这里发现了问题。

我查出 7 个旧 URL，虽然配置了跳转，但最终落到不存在的新页面。相当于旧门上贴了新地址，顺着地址找过去，却发现那是一间空房。

这是我的疏漏，已经修复。不过，这 7 个 URL 合计只有 58 次曝光，解释不了另外 90 个旧 URL 的情况。

**有局部配置错误，但它不是这次异常的主要原因。**

## 二、我的推断：Googlebot 还没有重新处理完这些旧 URL

永久跳转配置好了，不代表 Google 立刻就会更新搜索系统里的 URL。

Googlebot需要先重新访问旧 URL，读取永久跳转，再访问对应的新 URL。之后，Google 的系统才会逐步重新判断规范 URL，并迁移相关搜索信号。

Google 官方也说明：一次 URL 迁移要完成，Googlebot至少需要访问每个旧 URL 和新 URL 一次。

【插入 ../2026-week35-images/03-redirect-flow.png】

图注：永久跳转配置完成后，仍需等待 Googlebot重新访问和处理。

迁移后，我把主 sitemap、内部链接和页面标记全部更新为新 URL。这些操作本身没有错，但也意味着 Googlebot从站内重新发现旧 URL 的入口变少了。

它仍能通过抓取队列、外部链接和历史记录访问旧 URL，只是没有固定的重访时间。我的网站较新、抓取频率不高，因此部分旧 URL 可能尚未被重新处理。

但必须强调：

**以上是机制推断，不是效果报告本身能证明的事实。**

效果报告只能告诉我哪些 URL 获得了曝光和点击，不能告诉我 Googlebot什么时候来过。

要验证这个推断，需要继续看 URL 检查、网页索引报告和服务器日志。

## 三、占比在降，绝对数却在涨

三份“过去三个月”数据分别是：

- 8 月 3 日：7,279 次曝光，占 94.7%
- 8 月 11 日：8,821 次曝光，占 88.3%
- 8 月 12 日：9,028 次曝光，占 86.1%

只看百分比：

**94.7% → 88.3% → 86.1%**

看起来迁移正在收口。

但绝对数是：

**7,279 → 8,821 → 9,028**

它一直在增加。

占比下降，并不代表旧 URL 正在退场。真正发生的是新内容增长得更快，把全站这个分母做大了。

【插入 ../2026-week35-images/04-ratio-vs-absolute.png】

图注：占比下降，并不一定代表绝对数也在下降。

这三份数据来自不同的滚动窗口，不能当成严格的同期实验。但至少没有显示旧 URL 正在稳定衰减。

最近一个七天窗口里，45 个旧 URL 仍拿走 1,326 次曝光；全站同期共 2,183 次曝光，旧 URL 占比仍为 60.7%。

## 四、效果报告不能回答“新 URL 是否已被索引”

我把曝光最高的 8 个旧 URL 和对应的新 URL 放在一起比较。8 个新 URL 里，只有 3 个能在效果报告中查到数据，另外 5 个没有数据。

第一反应容易是：新页面是不是没有被收录？

但仅凭效果报告，不能得出这个结论。

效果报告存在数据截断和行数限制；而且大部分搜索表现数据会归到 Google 当前选择的规范 URL。因此，“查不到”不等于“没有被索引”。

永久跳转后，Google 也可能把旧 URL 作为新规范 URL 的备用名称继续显示。

应该组合观察：

1. 网页索引报告：URL 处于什么索引状态；
2. URL 检查：上次抓取时间和 Google 选择的规范 URL；
3. 新旧 sitemap：旧 URL 索引量是否下降、新 URL 是否上升；
4. 服务器日志：Googlebot是否重新请求过旧 URL。

简单来说：

- 效果报告回答：谁获得了曝光和点击？
- 网页索引报告回答：哪些 URL 处于什么索引状态？
- URL 检查回答：Google 如何处理某个具体 URL？
- 服务器日志回答：Googlebot什么时候来过？

## 五、如果你也要迁移 URL，这七件事按顺序做

### 1. 不要把“配置完成”当成“迁移完成”

永久跳转配置好，是站长一侧的工作完成；Google重新抓取和更新规范 URL，是搜索引擎一侧的工作。

### 2. 单独统计旧 URL 的效果数据

导出效果报告后，用旧路径规则筛选并加总，确认搜索表现目前记在旧 URL 还是新 URL 名下。

### 3. 百分比和绝对数必须一起看

占比下降也可能只是分母增长。两个数字必须同时观察。

### 4. 标注导出日期和统计窗口

“过去三个月”是滚动窗口。至少记录导出日期、统计起止日期、搜索类型和筛选条件。

### 5. 用新旧两份 sitemap 监测迁移

新旧 URL 可分别放入两份 sitemap，辅助发现并观察两组 URL 的索引数量变化。迁移稳定后可移除旧 URL sitemap。

lastmod 只填写真实的显著更新时间，不要伪造日期。

### 6. 高风险：不要阻止 Google 抓取旧 URL

Googlebot需要访问旧 URL，才能读取永久跳转。如果 robots.txt 阻止抓取，Google可能知道 URL 存在，却无法读取跳转响应。

不要用 noindex 替代永久跳转。

### 7. 高风险：逐一检查跳转目标

内容保留，应一对一跳转到最相关的新页面；内容合并，应跳转到真正承接原内容的页面；永久删除且没有替代内容，应返回 404 或 410。

不要把大量无关旧 URL 强行跳到首页，否则可能被视为 soft 404。

## 最后

这次复盘后，我提交了一份单独包含旧 URL 的 sitemap，用来辅助发现和监测迁移进度。

提交时间还不长，现在不能判断它是否有效。

接下来两到四周，我会继续观察：

- Googlebot是否重新访问旧 URL；
- 旧 sitemap 的已索引数量是否下降；
- 新 sitemap 的已索引数量是否上升；
- 重点页面的 Google 规范 URL 是否切换；
- 旧 URL 的曝光和点击是否下降。

等数据出来后，我会把提交前后的索引数据放在一起比较。

这次最大的教训不是某个 SEO 技巧，而是一句话：

**网站迁移不是一次配置动作，而是一个需要持续监测的过程。**

## 四、修改说明与事实校正

以下内容放在文章之后，供内部复核，不属于公众号正文。

1. 旧 URL 获得曝光，不足以单独证明新 URL 没被索引；旧 URL 也可能作为新规范 URL 的备用名称继续显示。
2. “网页会自动重定向”不一定严格先涨后跌，不能作为唯一迁移指标。
3. 页面在效果报告中查不到数据，还可能来自行数限制、数据截断或规范 URL 归属。
4. 旧 URL sitemap 可用于辅助发现和监测，但不要写成一定有效的催抓取技巧。
5. lastmod 应填写真实的显著更新时间，不要统一伪造成迁移日期。
6. 不要断言 410 一定比 404 更快。
7. 不相关跳转可能被视为 soft 404，但不要写成“权重一分不传”。
