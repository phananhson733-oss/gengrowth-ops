# 短剧数据采集迁移与发行管理平台需求文档（v4.1）

> 本文档**独立完整**，不依赖任何旧文档，彪哥只读这一份即可开工。
> 目标受众：王志彪（彪哥）。目标是把他接手过来的这套 TikTok 短剧数据采集+发行管理跑起来，并满足王玲（Lynne）的新需求。

## 核心定位（先看这个）

**「短剧发行管理」才是核心，采集器只是它的数据来源。**

- 我们要做好的工具 = **短剧发行管理**（账号台账 / 发布记录 / 选剧池 3 张业务表），让录入、查看、筛选、复盘更方便。
- 采集器（抓 TikTok 公开数据的代码）是**支撑**，负责每天自动产出播放/点赞/评论/链接/Post ID，回填到短剧发行管理里。
- 如果要迁到飞书，**只需要把「短剧发行管理」这一层迁过去**；采集器本身、以及中间层数据表（TikTok Daily Metrics）**不需要迁飞书**。

当前链路（现状）→ 目标链路：

```text
现状：
  采集器(Pengman MacBook) → SQLite → Google Sheets「TikTok Daily Metrics」→ IMPORTRANGE → Google Sheets「短剧发行管理」

目标：
  采集器(彪哥 Mac mini, 7×24) → SQLite(本地历史, 保留)
          └→ 飞书「短剧发行管理」多维表格（账号台账 / 发布记录 / 选剧池 + 自动回填数据）
```

**关键结论：迁飞书时可以跳过「TikTok Daily Metrics」这层。** 飞书不能像 Google Sheets 那样 IMPORTRANGE 引用 Google Sheets，所以正确做法是让采集器**直接写飞书表**。采集器已有写飞书的能力（`feishu_sync.mjs` 现在就在写粉丝数），只需扩展成"也写帖子指标"即可。

### 2.1 采集原理（纯公开，无付费 API，无代理）

- **账号清单**：脚本里 `usernames` 数组硬编码，当前 11 个账号（含全部短剧号）：
  `astrologywiki`、`dramapenelope`、`miraaastrology`、`shirley527146`、`shirley5276973`、`shirley5278789`、`dramadetour0`、`jolienqaq`、`dramaclips0364`、`dramavault163`、`dramaexpedition`
- **账号层**：请求两个公开页，解析内嵌 JSON：
  - `https://www.tiktok.com/@用户名` → 取昵称/粉丝/关注/获赞/签名（`__UNIVERSAL_DATA_FOR_REHYDRATION__`）
  - `https://www.tiktok.com/embed/@用户名` → 取视频列表（`__FRONTITY_CONNECT_STATE__`）
- **帖子详情层**：逐条用 `yt-dlp --dump-single-json` 取播放/点赞/评论/收藏/分享；失败降级走 `tikwm.com` 的 photo API；再失败记 error。
  - **需要 `yt-dlp` 和 Node 在 Mac mini 上装好**（当前 Node 路径写死为 `/Users/pengman/.cache/codex-runtimes/...`，迁移时必须改成 Mac mini 上的实际路径）。
- 字段缺失记 `null`（不写 0），标记 `partial`。

### 2.2 本地落盘与三路同步

数据唯一事实源是本地 SQLite（`output/tiktok_metrics.sqlite`），再分三路同步且互不阻断（任一失败不影响其余）：

- **Google Sheets** → 5 个 tab：`accounts_latest / account_history / posts_latest / post_history / runs`
- **飞书** → **目前仅写「粉丝」「粉丝同步时间」两字段，短剧帖子数据需新增**（这是 P1 飞书方案要动手改的地方，代码在 `feishu_sync.mjs`）
- **主生产记录** → 回写 `content_stage: published` 等（短剧场景不一定要，看是否需要）

谷歌表和飞书表都是 SQLite 的下游投影，不是独立数据源。迁到 Mac mini 时直接拷贝 SQLite 继续累积即可，历史数据不丢失。

### 数据回填机制（原有，需保留）

**现状（Google Sheets）**：
- 「采集数据」tab 用 `=QUERY(IMPORTRANGE(TikTok Daily Metrics 表 "posts_latest!A:Q"), ...)` 实时引用，并过滤掉 `astrologywiki`/`miraaastrology`。
- 发布记录的播放/点赞/收藏/转发/链接/Post ID 通过 `VLOOKUP(post_id, ...)` 从采集数据自动带出。
- 账号台账「粉丝数」从 `accounts_latest` 查 followers，「数据日期」查 snapshot_date。

**迁飞书后**（目标）：
- 不再走 IMPORTRANGE，改由采集器（扩展后的 `feishu_sync.mjs`）**直接写飞书表**，把帖子指标回填到「发布记录」、粉丝数回填到「账号台账」。
- 回填逻辑不变：**先填剧名/剧分类（状态=已排期）占位 → 帖子公开后补链接或自动匹配 → 数据自动回填（状态=已回填）**。
- 匹配桥接按可靠性：**用户补视频链接（最高）> 精确 post_id > 账号+发布时间窗（辅助）**。

## 9. 退路方案（若飞书做不了）
