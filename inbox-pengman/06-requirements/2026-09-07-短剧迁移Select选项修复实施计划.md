# 短剧迁移 Select 选项修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复正式飞书 Base 的 Select option 契约，使迁移计划能确定性追加源数据所需选项、`MoboReels` 能以可审计方式映射为“其他”，并保证迁移与日常记录写入都在首个 record mutation 前拒绝缺失选项。

**Architecture:** 保持现有四层边界：`schema.mjs` 只声明固定字段策略；`migration.mjs` 从最终规范化行生成并重放签名 action；`feishu-client.mjs` 只暴露 allowlist 化的字段 PUT 和 live catalog 校验；`shortdrama_ctl.mjs` 负责把完整 schema/空表证据接到 phase adapter。Schema mutation 与 record mutation 不混合，所有 option name 均由代码构造并经完整读回验证。

**Tech Stack:** Node.js `>=24`（当前验证环境 `v25.9.0`）、ES modules、`node:test`、飞书 Base v3、现有 SHA-256 manifest/receipt 证据链、zsh、`jq`、`lark-cli v1.0.91`。

```js
const OPTION_CONTROL = /[\u0000-\u001f\u007f-\u009f]/u;

function optionNamesFromRows(rows, spec) {
  const result = [];
  const seen = new Set();
  for (const row of rows) {
    const raw = row[spec.name];
    const values = spec.kind === "multi_select"
      ? raw ?? []
      : raw === null || raw === undefined ? [] : [raw];
    assertNormalizedOptionNames(values, "migration_source_invalid");
    for (const name of values) {
      if (!seen.has(name)) {
        seen.add(name);
        result.push(name);
      }
    }
  }
  return result;
}
```

## Success Criteria

- 八个动态 Select 字段受 `manifest_append` allowlist 约束；当前暂停源的六个非空字段只追加所需 options，另两个空字段无 update action。

- Manifest replay 和 `schema_spec_sha256` 能拒绝 action、option 顺序、平台行或 warning 的重算后篡改。
- Schema apply 只在 fresh 空表 mutation window 中运行，支持 before/after/third-state 判定并 exact readback。
- Data 全局 preflight 在任何 Repository write 前拦截缺项；日常 record create/update 在对应 record POST 前拦截缺项。
- 全量测试总数大于 460 且 0 fail；静态检查、plist、scope diff、字节基线和独立评审全部通过。
- 正式迁移只使用新 manifest/receipt/attestation；最终四表数量、关系、可写字段、权限和 sequence 均有独立读回证据。
