# 短剧发行管理 v5 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在目标 Mac mini 上交付由现有 Social Bot 操作的短剧发行管理系统，以飞书 Base 四表为正式业务入口，以 SQLite 为历史事实源，并安全迁移现有 Google 业务数据。

**Architecture:** 在 `gengrowth-ops` 中建立无常驻服务的 Node.js CLI `shortdrama_ctl`，负责 Job/Audit、SQLite claim/lease、launchd 监督 worker、四表 Base Adapter、迁移、同步和通知；现有 TikTok Collector 保持独立并由 Runner 调用。Hermes 侧只新增短剧 Social Skill 和运行时预授权，不增加核心工具或改变现有 AstrologyWiki Social OS。

**Tech Stack:** Node.js 24+、`node:test`、`node:sqlite`、飞书 OpenAPI、多维表格四表关系、现有 Hermes Python/pytest Skill 合约、macOS launchd。

## Global Constraints

- 需求 SSOT：`inbox-pengman/06-requirements/2026-08-30-短剧数据采集迁移与发行管理平台需求文档.md` v5.0。
- 正式 Base 固定四表：`账号台账 / 发布记录 / 选剧池 / 采集数据`；不得增加日历史快照表。
- `采集数据`按 Post ID 保存 Google 历史 ∪ SQLite latest 的最新已知投影；日历史只留 `tiktok_metrics.sqlite`，日常同步不删 Google-only 历史 Post。
- `选剧池`人工维护；采集器、定时任务和自动推荐不得修改其人工字段。
- 现有 TikTok Daily Metrics、AstrologyWiki Social OS、粉丝同步和生产记录回填保持不变。
- 不复用旧 `sync_shortdrama_to_feishu.mjs --sync` 的全表删除重建行为。
- 不新增 Hermes 核心工具，不新增常驻 HTTP 服务，不让 Skill 直接拼裸 Base API。
- Node 运行时最低版本 24；不增加 npm 生产依赖，优先使用 Node 标准库。
- Base 同表写入串行，单批最多 200 条；限流最多重试 3 次并优先遵守 `Retry-After`。
- 业务日期使用 `Asia/Shanghai`；TikTok 原始发布时间保留 ISO 时区。
- `SD-000001 / SR-000001 / SDRUN-YYYYMMDD-HHMMSS` 是稳定可读 ID。
- 人工值优先；缺失是 `null`，真实零是 `0`；机器失败不得清空旧有效值。
- 所有写入必须读回；分页不完整和字段不可用必须返回 `partial/unavailable`，不得报告有效零。
- 只有实名 actor 可写和触发采集；普通群成员只读；schema/migration apply 仅 privileged。
- 凭证只存目标运行环境 `.env`，不得进入 Git、日志、测试夹具或回复。
- 旧 Google 业务表只在七天切换时改为只读；TikTok Daily Metrics 不退役。
- Base 创建、migration apply、权限变化、launchd 安装、Social gateway 重启和 Google 只读切换均需动作时确认。
- 不在当前脏的 `/Users/awayer_mini/hermes-agent` 工作树直接实施；执行时必须先使用 `superpowers:using-git-worktrees` 创建隔离工作树。

```js
export class ShortDramaError extends Error {
  constructor(code, message, details = {}) {
    super(message);
    this.name = "ShortDramaError";
    this.code = code;
    this.details = details;
  }
}

export function toErrorResult(error) {
  const known = error instanceof ShortDramaError;
  return {
    status: "failed",
    error: {
      code: known ? error.code : "internal_error",
      message: known ? error.message : "Internal short-drama runner error",
      details: known ? error.details : {},
    },
  };
}
```

```js
export function fieldOwner(tableName, field) {
  const definition = TABLES[tableName];
  if (!definition) throw new ShortDramaError("table_not_allowed", "Unknown table", { table: tableName });
  for (const owner of ["human", "machine", "shared", "derived"]) {
    if (definition[owner].has(field)) return owner;
  }
  throw new ShortDramaError("field_not_allowed", "Unknown field", { table: tableName, field });
}

export function assertPatchAllowed(tableName, patch, actorKind) {
  for (const field of Object.keys(patch)) {
    const owner = fieldOwner(tableName, field);
    const allowed =
      (actorKind === "migration" && ["human", "machine", "shared"].includes(owner)) ||
      owner === actorKind ||
      (owner === "shared" && actorKind === "human");
    if (!allowed) {
      throw new ShortDramaError("field_owner_violation", "Field owner mismatch", {
        table: tableName,
        field,
        expected_owner: owner,
        actor_kind: actorKind,
      });
    }
  }
}
```

```js
import { ShortDramaError } from "./errors.mjs";

const batches = (rows, size = 200) =>
  Array.from({ length: Math.ceil(rows.length / size) }, (_unused, index) =>
    rows.slice(index * size, (index + 1) * size)
  );

export class FeishuClient {
  constructor({ tokenProvider, fetchJson, sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms)) }) {
    this.tokenProvider = tokenProvider;
    this.fetchJson = fetchJson;
    this.sleep = sleep;
  }

  async request(path, { method = "GET", body = undefined, token = undefined } = {}) {
    const accessToken = token ?? await this.tokenProvider();
    const payload = await this.fetchJson(`https://open.feishu.cn${path}`, {
      method,
      headers: { authorization: `Bearer ${accessToken}`, "content-type": "application/json; charset=utf-8" },
      body,
    });
    if (!payload || payload.code !== 0) {
      throw new ShortDramaError("base_request_failed", "Feishu Base request failed", {
        code: payload?.code ?? null,
        path,
      });
    }
    return payload;
  }

  async listRecords(appToken, tableId) {
    const token = await this.tokenProvider();
    const items = [];
    let pageToken = "";
    do {
      const query = new URLSearchParams({ page_size: "200" });
      if (pageToken) query.set("page_token", pageToken);
      const payload = await this.request(
        `/open-apis/bitable/v1/apps/${encodeURIComponent(appToken)}/tables/${encodeURIComponent(tableId)}/records?${query}`,
        { token }
      );
      const hasMore = payload.data?.has_more;
      if (typeof hasMore !== "boolean") {
        throw new ShortDramaError("base_response_invalid", "has_more must be boolean");
      }
      items.push(...(payload.data?.items ?? []));
      pageToken = hasMore ? String(payload.data?.page_token ?? "") : "";
      if (hasMore && !pageToken) {
        throw new ShortDramaError("base_response_invalid", "page_token missing");
      }
    } while (pageToken);
    return { items, complete: true, revision: null };
  }

  async getRecord(appToken, tableId, recordId) {
    const payload = await this.request(
      `/open-apis/bitable/v1/apps/${encodeURIComponent(appToken)}/tables/${encodeURIComponent(tableId)}/records/${encodeURIComponent(recordId)}`
    );
    return payload.data?.record;
  }

  async createRecords(appToken, tableId, records) {
    const token = await this.tokenProvider();
    const written = [];
    for (const group of batches(records)) {
      const payload = await this.request(
        `/open-apis/bitable/v1/apps/${encodeURIComponent(appToken)}/tables/${encodeURIComponent(tableId)}/records/batch_create`,
        { method: "POST", body: { records: group }, token }
      );
      written.push(...(payload.data?.records ?? []));
    }
    return written;
  }

  async updateRecords(appToken, tableId, records) {
    const token = await this.tokenProvider();
    const written = [];
    for (const group of batches(records)) {
      const payload = await this.request(
        `/open-apis/bitable/v1/apps/${encodeURIComponent(appToken)}/tables/${encodeURIComponent(tableId)}/records/batch_update`,
        { method: "POST", body: { records: group }, token }
      );
      written.push(...(payload.data?.records ?? []));
    }
    return written;
  }
}
```

方法体必须：

- 使用 app token/table ID 构造固定 OpenAPI path，不接受完整任意 URL；
- 每页 `page_size<=200`，仅接受布尔 `has_more`；`has_more=true` 时 page_token 必须非空；
- 写入批次按输入顺序切成 200；同表串行；
- 429/1254291 遵守 `Retry-After` 或递增等待，最多 3 次；
- 401/403 映射 `base_auth_failed`，字段类型/缺失映射 `base_schema_drift`；
- JSON 解析失败映射 `base_response_invalid`；
- 日志只记录 method/path/status/run_id，不记录 token、Authorization 或 body 中的自由文本。
- `createField`只能消费 `BASE_FIELD_SPECS`生成的结构；view/dashboard 方法只消费规格 6.5 中固定定义，不能接受用户自由 JSON。
- `createTenantTokenProvider`缓存 tenant token 至服务端 `expire-300s`，并为同进程并发请求共享一个 in-flight auth Promise；明确 401/无效 token 时清缓存并只重取一次，其他错误不能循环重新认证。`FeishuClient`一个顶层操作（含全部分页/批次）固定复用一次 token snapshot。

```js
export class TableRepository {
  constructor({ client, appToken, tableId, tableName }) {
    this.client = client;
    this.appToken = appToken;
    this.tableId = tableId;
    this.tableName = tableName;
    this.index = null;
  }

  async loadIndex() {
    const result = await this.client.listRecords(this.appToken, this.tableId);
    if (!result.complete) throw new ShortDramaError("base_response_incomplete", "Base list incomplete", { table: this.tableName });
    const primary = TABLES[this.tableName].primaryField;
    const index = new Map();
    for (const record of result.items) {
      const key = String(record.fields?.[primary] ?? "").trim();
      if (!key || index.has(key)) throw new ShortDramaError("duplicate_base_key", "Duplicate or blank Base key", { table: this.tableName, key });
      index.set(key, record);
    }
    this.index = index;
    return index;
  }

  async upsertByKey(key, patch, actorKind) {
    assertPatchAllowed(this.tableName, patch, actorKind);
    if (!this.index) await this.loadIndex();
    const primary = TABLES[this.tableName].primaryField;
    const existing = this.index.get(key);
    const fields = { ...patch, [primary]: key };
    const [written] = existing
      ? await this.client.updateRecords(this.appToken, this.tableId, [{ record_id: existing.record_id, fields }])
      : await this.client.createRecords(this.appToken, this.tableId, [{ fields }]);
    const readback = await this.client.getRecord(this.appToken, this.tableId, written.record_id);
    for (const [field, value] of Object.entries(fields)) {
      if (JSON.stringify(readback.fields?.[field] ?? null) !== JSON.stringify(value ?? null)) {
        throw new ShortDramaError("readback_mismatch", "Base readback mismatch", { table: this.tableName, key, field });
      }
    }
    this.index.set(key, readback);
    return { record: readback, readback: "verified" };
  }
}
```

`BaseRepositories` 将 `accounts/dramas/captures/releases` 映射到四个真实 table ID；关系字段只接受已从对应 Repository 解析出的真实 `record_id` 数组，不接受用户提供的任意 record ID。

`syncManyByKey`固定执行：完整 `loadIndex`一次 → canonical diff → 将 create/update集合各交给 FeishuClient（其内部 200 条分批）→ 再完整分页读取目标表一次 → 只对本批变更主键逐字段核对。不得逐行调用 `getRecord`造成 N+1。`syncManyMachine`在批量 diff 前对每个 patch执行 field-owner 校验；采集数据和迁移使用批量接口，单条人工 mutation 使用 `upsertByKey`。

`machineUpsertWithInvariant`固定执行：读取目标 → 提取 human/shared projection → 仅发送 machine 字段 patch → 读回目标 → 验证请求内没有 human/shared 字段且未出现非请求字段被服务器改写。它不比较全表 hash，也不因其他记录的人工编辑失败。

`linkCaptureSafely`在写`采集记录`关系前保存该发布的`Post ID/视频链接/账号/日期`匹配输入，关系写后立即重读。Base API 不提供关系字段 CAS；若这些输入或关系并发变化，不做自动清空或补偿写，保留当前关系并抛`concurrent_human_change + next_step=manual_repair`。不得覆盖用户刚写的输入或关系字段。


- [ ] **Step 3: 实现 CLI 分派和 actor policy**

`shortdrama_ctl.mjs`：

- `parseCommand`只接受规格中固定 group/action；
- 所有 payload 从显式文件读取 JSON，文件必须位于 Runner 允许的临时 payload 目录；校验后以`O_NOFOLLOW`只打开一次，并对 descriptor 的 dev/ino/type/size 与 lstat 比对后有界读取；也支持 `--payload -` 从 stdin 读取；
- Social session 模式必须从注入的 `HERMES_SESSION_PLATFORM/PROFILE/USER_ID/CHAT_ID`解析身份，并拒绝显式 `--actor-id/--chat-id`；human mutation 再按 operator/privileged allowlist授权；
- 单字段直接写只注册`pool update-field`和`release update-field`，payload 必须精确为`{key,field,value}`；表、actor、chat由固定 action 和 Social ContextVars绑定，调用`HumanOpsService.applySingleField`后返回 before/after/readback。不得注册通用`update`、自由 table/action executor，也不得改变`preview-update/apply-update`多字段语义；
- 批量预览只注册`pool preview-batch`和`release preview-batch`，payload 必须精确为`{items:[{key,patch},...]}`；Runner 固定 action=`batch_update`及表/actor/chat，继续由`apply-update`消费 receipt。不得让 Skill 传入任意 table/action；
- 账号台账与采集数据只注册`account list|get`和`capture list|get`；Social reader 可读，本地业务调用拒绝。Runner 固定绑定`账号台账.账号ID`/`采集数据.Post ID`并调用`HumanOpsService.query`完整 index，返回 table、rows/record、`readback=complete`、`source=base_complete_index`或明确`not_found`；不得注册任何 account/capture 写、delete 或通用 query action；
- `pool/release list|get`也返回同一 complete envelope 与精确`not_found`，避免 Skill 按表猜测不同返回形状；
- 无 gateway session 的本地 migration apply/schema/repair 才接受显式 `--actor-id`，且只允许 privileged；
- `schedule tick`只接受安装器生成的 0600 随机 capability，不接受旧 marker、actor/chat 或 Social session；plist 只保存固定 capability 文件路径；
- `schedule health`只接受内部调用：北京时间 10:00 后若当天无 success/partial 终态，用带 owner/expiry 的`claimHealthAlert`向固定 Ops chat 告警一次；crash 后 stale claim 可回收，旧 owner 不可标记；有 running Job时报告当前 step/lease，不能误报成未启动；
- `queue drain`只供 launchd label 调用：用当前 PID claim 一个 queued/expired-lease Job，运行 Worker 后退出；外部 actor 不能指定 run_id 绕过 claim；
- 每次 `queue drain`结束前调用 `listUndeliveredTerminal`重试终态通知，包括 worker crash 重试耗尽和先前 notification_failed；数据终态不得因通知重试而变化；
- `sync start`入队后只执行不带 `-k`的固定 `launchctl kickstart`唤醒 label，不 fork detached worker；
- 所有输出单个 JSON object 到 stdout；诊断到 stderr；exit 0 仅用于 success/valid no-op，partial 使用独立非零码并仍输出 JSON；
- 导入模块时不得自动执行，便于测试；仅 `process.argv[1]`等于当前文件时运行 `main()`。
