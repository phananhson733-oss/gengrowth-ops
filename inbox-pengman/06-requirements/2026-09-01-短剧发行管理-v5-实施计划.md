# 短剧发行管理 v5 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在目标 Mac mini 上交付由现有 Social Bot 操作的短剧发行管理系统，以飞书 Base 四表为正式业务入口，以 SQLite 为历史事实源，并安全迁移现有 Google 业务数据。

**Architecture:** 在 `gengrowth-ops` 中建立无常驻服务的 Node.js CLI `shortdrama_ctl`，负责 Job/Audit、单实例锁、四表 Base Adapter、迁移、同步和通知；现有 TikTok Collector 保持独立并由 Runner 调用。Hermes 侧只新增短剧 Social Skill 和运行时预授权，不增加核心工具或改变现有 AstrologyWiki Social OS。

**Tech Stack:** Node.js 24+、`node:test`、`node:sqlite`、飞书 OpenAPI、多维表格四表关系、现有 Hermes Python/pytest Skill 合约、macOS launchd。

## Global Constraints

- 需求 SSOT：`inbox-pengman/06-requirements/2026-08-30-短剧数据采集迁移与发行管理平台需求文档.md` v5.0。
- 正式 Base 固定四表：`账号台账 / 发布记录 / 选剧池 / 采集数据`；不得增加日历史快照表。
- `采集数据`按 Post ID 保存 SQLite 最新帖子投影；日历史只留 `tiktok_metrics.sqlite`。
- `选剧池`人工维护；采集器、定时任务和自动推荐不得修改其人工字段。
- 现有 TikTok Daily Metrics、AstrologyWiki Social OS、粉丝同步和生产记录回填保持不变。
- 不复用旧 `sync_shortdrama_to_feishu.mjs --sync` 的全表删除重建行为。
- 不新增 Hermes 核心工具，不新增常驻 HTTP 服务，不让 Skill 直接拼裸 Base API。
- Node 运行时最低版本 24；不增加 npm 生产依赖，优先使用 Node 标准库。
- Base 同表写入串行，单批最多 200 条；限流最多重试 3 次并优先遵守 `Retry-After`。
- 业务日期使用 `Asia/Shanghai`；TikTok 原始发布时间保留 ISO 时区。
- `SD-000001 / SR-000001 / SDRUN-YYYYMMDD-HHMMSS` 是稳定可读 ID。
- 人工值优先；缺失是 `null`，真实零是 `0`；机器失败不得清空旧有效值。
- 所有写入必须读回；分页不完整和字段不可用必须返回 `partial/unavailable`，不得报告有效零。

export class ShortDramaError extends Error {
  constructor(code, message, details = {}) {
    super(message);
    this.name = "ShortDramaError";
    this.code = code;
    this.details = details;
  }
}

export function toErrorResult(error) {
  const known = error instanceof ShortDramaError;
  return {
    status: "failed",
    error: {
      code: known ? error.code : "internal_error",
      message: known ? error.message : "Internal short-drama runner error",
      details: known ? error.details : {},
    },
  };
}

export function fieldOwner(tableName, field) {
  const definition = TABLES[tableName];
  if (!definition) throw new ShortDramaError("table_not_allowed", "Unknown table", { table: tableName });
  for (const owner of ["human", "machine", "derived"]) {
    if (definition[owner].has(field)) return owner;
  }
  throw new ShortDramaError("field_not_allowed", "Unknown field", { table: tableName, field });
}

export function assertPatchAllowed(tableName, patch, actorKind) {
  for (const field of Object.keys(patch)) {
    const owner = fieldOwner(tableName, field);
    if (owner === "derived" || owner !== actorKind) {
      throw new ShortDramaError("field_owner_violation", "Field owner mismatch", {
        table: tableName,
        field,
        expected_owner: owner,
        actor_kind: actorKind,
      });
    }
  }
}

```js
export class TableRepository {
  constructor({ client, appToken, tableId, tableName }) {
    this.client = client;
    this.appToken = appToken;
    this.tableId = tableId;
    this.tableName = tableName;
    this.index = null;
  }

  async loadIndex() {
    const result = await this.client.listRecords(this.appToken, this.tableId);
    if (!result.complete) throw new ShortDramaError("base_response_incomplete", "Base list incomplete", { table: this.tableName });
    const primary = TABLES[this.tableName].primaryField;
    const index = new Map();
    for (const record of result.items) {
      const key = String(record.fields?.[primary] ?? "").trim();
      if (!key || index.has(key)) throw new ShortDramaError("duplicate_base_key", "Duplicate or blank Base key", { table: this.tableName, key });
      index.set(key, record);
    }
    this.index = index;
    return index;
  }

  async upsertByKey(key, patch, actorKind) {
    assertPatchAllowed(this.tableName, patch, actorKind);
    if (!this.index) await this.loadIndex();
    const primary = TABLES[this.tableName].primaryField;
    const existing = this.index.get(key);
    const fields = { ...patch, [primary]: key };
    const [written] = existing
      ? await this.client.updateRecords(this.appToken, this.tableId, [{ record_id: existing.record_id, fields }])
      : await this.client.createRecords(this.appToken, this.tableId, [{ fields }]);
    const readback = await this.client.getRecord(this.appToken, this.tableId, written.record_id);
    for (const [field, value] of Object.entries(fields)) {
      if (JSON.stringify(readback.fields?.[field] ?? null) !== JSON.stringify(value ?? null)) {
        throw new ShortDramaError("readback_mismatch", "Base readback mismatch", { table: this.tableName, key, field });
      }
    }
    this.index.set(key, readback);
    return { record: readback, readback: "verified" };
  }
}
```

`BaseRepositories` 将 `accounts/dramas/captures/releases` 映射到四个真实 table ID；关系字段只接受已从对应 Repository 解析出的真实 `record_id` 数组，不接受用户提供的任意 record ID。

`readLatestPosts` 使用与现有 `persistence.mjs::posts_latest` 相同的关联 SQL：

```sql
SELECT p.post_id,p.username,p.post_url,p.content_type,p.published_at,p.caption,
       p.first_seen_at,p.last_seen_at,s.snapshot_date,s.captured_at,

       s.collection_status,s.missing_fields

JOIN post_snapshots s ON s.post_id=p.post_id
WHERE s.snapshot_date=(
  SELECT MAX(x.snapshot_date) FROM post_snapshots x WHERE x.post_id=p.post_id
)
ORDER BY p.username,COALESCE(p.published_at,''),p.post_id;
```

Matcher 规则完整实现：

1. 从人工视频链接解析 `/video|photo/<digits>`，只接受与账号一致的精确 Post ID；
2. 人工 Post ID 精确匹配，且不可已被另一发布占用；
3. 有精确 datetime 时，同账号 ±6 小时仅一个未占用候选才匹配；
4. 只有日期时，北京时间同一自然日仅一个未占用候选才匹配；
5. 其他情况返回候选，不写关系；
6. 一条 Post ID 不能被两条 active 发布记录占用。
