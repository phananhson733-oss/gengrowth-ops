# 短剧账号发行管理平台需求文档（MVP）

> 本文档给执行 AI / 开发者看的可行性判断、制作方向、字段定义和验收细节。
> 目标：**今天（2026-08-20）内做出一个最小可用版本**，能看到所有 TikTok 短剧账号的数据，并能手动记录每条发布。
> 平台约束（已定稿）：**主表 = Google Sheets，可视化 = Google Looker Studio**。使用者为 Pengman 与高璇两人（lynne 不天天看）。飞书暂不纳入 MVP（见第 2 节选型论证）。

---

## 0. 一句话需求

做一个**短剧账号发行管理表/工具**：
1. 能看到我们**所有 TikTok 短剧账号**的数据（账号名可点进主页、粉丝等）。
2. 每条**发布记录**一行：账号、剧名、剧分类、播放量、点赞、收藏、转发、RS收益。
3. 手动填"用了哪个账号 + 发了什么剧"；播放等互动数据**尽量自动抓**（复用现有采集），抓不到则手动填。
4. 未来（不做进 MVP）：自动抓"发布了什么剧"进行匹配。

---

## 1. 可行性判断（结论）

| 需求 | 可行性 | 说明 |
|---|---|---|
| 看到所有短剧账号数据 | ✅ 高 | 现有 `tiktok-public-capture` 采集器已能抓账号粉丝 + 帖子指标（views/likes/comments/favorites/shares），**只需把采集账号清单从 astrologywiki 账号切到短剧账号** |
| 互动数据自动抓 | ✅ 高 | 现有采集器已输出 `post_history`（views/likes/comments/favorites/shares），直接复用 |
| 账号名可点进主页 | ✅ 高 | 表格里放主页链接字段即可（Google Sheet / 飞书多维表格都支持超链接单元格） |
| 手动填"账号 + 剧名 + 剧分类" | ✅ 高 | 用下拉（数据验证）约束账号、剧分类 |
| 手动/自动回填播放数据 | ✅ 高（自动）/ 中（半自动） | 现有采集器能自动抓帖子指标；但"哪条帖对应哪部剧"需要人工匹配（MVP 先人工关联） |
| 自动抓"发布了什么剧" | 🔶 低（不纳入 MVP） | 需要从 caption/文案识别剧名，或从 RS Boost 后台拿数据，MVP 先不做 |
| RS收益（RS Boost 后台） | 🟡 中 | **RS Boost 后台没有公开 API/CSV 导出（待确认）**，MVP 先人工回填；未来有 API 再自动同步 |

**核心结论**：
- **现有采集器是最大资产**——播放/点赞/收藏/转发四项已经能自动抓，这是最重的活。
- MVP 真正的难点只有两个：①采集账号清单切到短剧账号；②"每条发布 = 哪个账号 + 哪部剧 + 剧分类"的人工录入 + 与采集数据的关联。
- **"自动识别发布了什么剧"今天不做**，留到 V1。

## 2. 平台选型（已定稿：Google Sheets + Looker Studio）

### 最终决策：主表 Google Sheets，可视化 Google Looker Studio

**决策理由（针对"播放数据自动抓 + 你和高璇用 + 今天做完"）：**

1. **播放/点赞/收藏/转发自动抓，只有 Google Sheets 今天能零开发做到。**
   - 现有 `tiktok-public-capture` 采集器**原生写 Google Sheets**（`accounts_latest / posts_latest / post_history`），已每天自动抓短剧账号的帖子指标。
   - 复用 TikTok Daily Metrics 同一份数据，播放数据直接取，无需新开发。

2. **飞书多维表格要自动抓播放，需改共享采集器，今天做不完且有生产风险。**
   - 现有 `feishu_sync.mjs` 只同步账号级"粉丝"，不写帖子指标（播放/点赞/收藏/转发）。
   - 要接飞书需：改共享采集器加"写飞书帖子指标" → 飞书建 5 个类型匹配的字段 → 授权 → 端到端测试。改动影响全团队生产链路（Social OS / TikTok Daily Metrics / 飞书资产表），一天内不现实。
   - 飞书留作后续 V1 接入（README 已有 feishu sync 基建可复用）。

3. **使用者是 Pengman + 高璇两人**：Google Sheets 协作编辑完全够用（实时同步），lynne 不天天看，不需要飞书的企业协作/看板优势。

4. **可视化用 Looker Studio（免费，零后端）**：连这个 Google Sheets 建仪表盘，能力覆盖需求（表格/趋势/分类对比/得分卡/筛选器，见第 6 节）。

### 不采用
- **飞书多维表格**：作为 MVP 主表（自动抓播放做不到）；后续 V1 可做飞书只读看板。
- **Notion**：不考虑。
- **网页/应用（Next.js）**：技术可行但今天做完有风险，且采集器仍写 Sheets；放 V2。

> **最终：MVP = Google Sheets 主表（复用现有采集器自动抓播放）+ 人工录入关联 + Looker Studio 可视化仪表盘。**

## 3. 表格结构（MVP 核心）

### Sheet A：账号台账（所有短剧账号）

| 字段 | 类型 | 说明 |
|---|---|---|
| 账号名 | 文本 | 如 user12027302755050 |
| 主页链接 | 超链接 | 可点击跳转 TikTok 主页 |
| 粉丝数 | 数字 | 采集器自动写或手动填 |
| 所属组 | 下拉 | A纯切片 / B生活 / C测试 / D重养 |
| 定位垂类 | 文本 | 如 狼人、霸总 |
| 表现形式 | 下拉 | AI真人剧 / AI漫剧 |
| 状态 | 下拉 | 未发 / 养号中 / 发布中 / 重养 |

### Sheet B：发布记录（每条视频一行）⭐ 主表

| 字段 | 类型 | 数据来源 |
|---|---|---|
| 日期 | 日期 | 手动填 |
| 账号名 | 下拉（引用 Sheet A） | 手动选 |
| 主页链接 | 引用 | 由账号名带出 |
| 剧名 | 文本/下拉 | 手动填 |
| 剧ID（RS Boost） | 文本 | 手动填（可选） |
| 剧分类 | 下拉 | RS Boost 分类：爱情/霸总/复仇/狼人/逆袭/离婚/重生/战神/甜宠… |
| 视频链接 | 超链接 | 手动填（发布后从 TikTok 复制） |
| 播放量 | 数字 | **自动抓**（采集器 post_history）或手动 |
| 点赞 | 数字 | **自动抓**或手动 |
| 收藏 | 数字 | **自动抓**或手动 |
| 转发 | 数字 | **自动抓**或手动 |
| 评论 | 数字 | **自动抓**或手动（用户原需求未列，但采集器有，建议保留） |
| RS收益 | 数字 | **手动回填**（RS Boost 后台，每周一次） |
| 备注 | 文本 | 手动 |

**关联逻辑（关键）**：采集器按 `post_id` 抓帖子指标。MVP 阶段，Sheet B 的"视频链接"里包含 `post_id`（URL 末尾数字），可通过它**手动或半自动**把采集到的播放数据对到这条记录。V1 再做自动匹配。

### Sheet C：选剧池（可选）

- 剧名 / 剧ID / 剧分类 / 上线日期 / 生命周期 / 是否已排期（从选剧台工具挑候选）

## 4. 数据流

```text
TikTok 短剧账号（改采集清单）
  → 现有 tiktok-public-capture 每日采集
  → SQLite（事实数据）
      └→ Google Sheets：accounts_latest / posts_latest / post_history（现有能力）
  → 新增：短剧发行管理 Sheet
       ├→ Sheet A 账号台账：粉丝从 accounts_latest 引用
       └→ Sheet B 发布记录：播放/点赞/收藏/转发从 post_history 关联，其余手动
```

## 5. Looker Studio 可视化设计（必做）

**工具**：Google Looker Studio（免费、零后端），数据源 = 短剧发行管理 Sheet 的"发布记录"和"账号台账"。

> Looker Studio 免费版 100% 免费：无限仪表盘/报告、连 Google Sheets 免费、无用户数量限制。只有连非 Google 平台或用 Pro（$9/用户/月）才收费——我们都不涉及。

### 5.1 仪表盘页结构（3 个视图页）

**页 1：总览（Dashboard）**
- **顶部得分卡**：总播放、总点赞、总收藏、总转发、总RS收益、总发布数、在推账号数。
- **时间序列折线图**：每日总播放/总发布随时间变化（看整体涨势）。
- **账号对比柱状图**：8 个账号的总播放或平均点赞排序（谁表现好）。

**页 2：发布表现（Performance）**
- **表格**：账号 / 剧名 / 剧分类 / 视频链接 / 播放 / 点赞 / 收藏 / 转发 / RS收益（主表视图，可排序）。
- **剧分类占比饼图**：爱情/霸总/复仇/狼人…各占多少发布与播放。
- **分类平均播放条形图**：哪个垂类平均播放最高。
- **筛选控件**：按账号、日期范围、剧分类动态筛选。

**页 3：账号与转化（Accounts & ROI）**
- **账号明细表格**：账号 / 粉丝 / 发布数 / 总播放 / 总RS收益 / 单条平均播放。
- **散点图**：播放 vs 点赞率，找"高播放低互动"和"高互动"的剧。
- **漏斗图**（可选）：播放 → 点赞 → 收藏 → 转发 → RS收益（看转化率）。
- **下钻**：点某账号，看它发的每条剧表现。

### 5.2 交互能力（Looker 原生，无需代码）
- **筛选控件**：账号下拉、日期范围、剧分类（最实用）。
- **下钻**：点击图表元素看下一层明细。
- **多报告页**：上 3 页之间切换。
- **自动刷新**：数据源连接 Google Sheets，打开/刷新时取最新数据。

### 5.3 局限说明
- 不展示视频封面缩略图（只看数字）。
- 实时性取决于数据源刷新（Sheets 打开/刷新取数），与现有 TikTok Daily Metrics 同一口径。

## 8. 验收标准（MVP 算完成的条件）

1. 打开表格能看到所有短剧账号，账号名可点击跳转主页，粉丝数有值。
2. 每发一条内容，能手动选账号 + 填剧名 + 选剧分类 + 填视频链接。
3. 该条内容的播放/点赞/收藏/转发，能通过采集数据回填（自动或半自动）到对应行。
4. RS收益列存在，可手动填写。
5. **Looker Studio 仪表盘已建立**：至少能按账号/日期看到播放趋势（第 5 节的页 1 总览 + 页 2 发布表现）。

## 9. 风险与备注

- **采集器账号清单是共享配置**：改的时候务必新增/保留原 astrologywiki 采集，别破坏现有数据管道。
- **RS Boost 后台数据**是核心业绩指标但自动化不确定，MVP 人工回填是必要的妥协。
- **"自动识别剧"**是最大增值但最不确定的部分，留给 V1，MVP 不追求。
- 播放数据是**公开抓取的近似值**，可能与 TikTok 后台有差异，与现有 astrologywiki 采集同一口径，可接受。
- Looker Studio 免费版足够；不要为 MVP 购买 Pro 或第三方连接器。
