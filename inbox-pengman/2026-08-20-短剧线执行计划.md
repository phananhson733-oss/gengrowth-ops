## 2. 方向测试框架（破解"排列组合太多"）

### 2.1 核心认知：三维度不是平等的组合，各管一层

| 维度 | 管什么 | 决策方式 |
|---|---|---|
| 表现形式（AI漫剧 / AI真人剧） | 内容供给 + 版权合规 + 生产成本 | **供给侧决策，不靠测试**——当前走 RS Boost = AI真人剧（有授权）为确定性主路径；AI漫剧除非另有独立版权源，否则最多 1 个测试号 |
| 场景（校园/职场/奇幻异世界…） | 受众画像（发给谁看） | 并入"垂类包"选择 |
| 剧情（龙傲天/扮猪吃老虎/离婚/复仇…） | 转化钩子（为什么看完/点链接） | 并入"垂类包"选择 |

**不要枚举 2×N×M 的全组合**（会爆炸）。把场景×剧情压成"垂类包"。

### 2.2 垂类包选择（只选 4–6 个）

候选垂类包示例（用 RS Boost 官方分类 + 选剧台数据 + dramafinds 剧库确认有剧可推）：
- 奇幻异世界 × 龙傲天/战神
- 都市职场 × 复仇/逆袭
- 现代 × 离婚/重生
- 校园 × 甜宠/暗恋
- 现代 × 隐婚/霸总
- 古装 × 宅斗/身份错位

筛选标准：①RS Boost 里有这类剧可推 ②钩子天然强（复仇/龙傲天这类 3 秒即懂） ③与我们目标市场/语种匹配。

### 2.3 8 账号映射（每号只测一个变量）

| 账号组 | 变量 | 说明 |
|---|---|---|
| A1–A4（纯切片） | 4 个垂类包 | 每号 1 个垂类，无人设，悬念切片为主 |
| B1–B2（生活号） | 1–2 个垂类包（人设混合） | 生活 2:1 短剧切片起步，保真人信号 |
| C1–C2（测试号） | 测评/排名形式 | 吃搜索流量、原创度高、版权风险低 |

### 2.4 测试节奏与判定

- 每号**连发 5–8 条**（1–2 条/天，约 2 周），期间不换垂类。
- 判定门槛：**同号内 3 条以上过线**（>500 播放且点赞率 >5%）→ 该垂类继续；否则换垂类（或换号）。
- 每条做变体（不同钩子/封面/口播），**不原样重复发**（平台判重复压流量）。
- 链接/口令从第一条起就带上（RS Boost 口令不要求 1000 粉），每条记录数据。
- 2 周后对比：A（无人设纯切片）vs B（人设混合）vs C（测评形式）哪个在"播放稳定性 + 链接点击 + RS Boost 转化"上更好，把资源向赢家倾斜。

## 4. 养号、运营与剪辑 SOP（按 AitoEarn 文档）

> 来源：https://docs.aitoearn.ai/zh/help/tiktok-account-operations
> 说明：AitoEarn 是短剧分销平台，其 TikTok 运营指南与我们的 RS Boost 短剧路径高度同构，可直接落地。**注意**：其中"买成品邮箱、IP 切换、口令引导"等与 TikTok 官方"禁止用多账号绕过执法/虚假互动"存在灰色地带，执行时以 RS Boost + TikTok 官方条款为准，不全盘照搬。

### 4.1 地区与 IP（先定环境再动账号）

- 账号地区、内容语种、目标受众**三者保持一致**（欧美：英语剧/本土剧；东南亚：本地语种/翻译剧/高频更新）。
- **单个账号只做一个语种、一个内容方向**，避免影响系统推荐。
- 不频繁切换 IP、设备语言、账号地区；切换前先暂停账号操作，确认环境一致再登录。

### 4.2 养号流程（新号/重养号通用）

**注册前物料**：未注册过 TikTok 的邮箱（推荐 Outlook）；干净稳定的目标地区 IP；独立手机或云手机；提前备好剧集片段/标题/简介/推广链接/标签。

**养号操作**：
1. 刷视频半天（看目标垂类内容）。
2. 间歇点赞：每 10 条点 1–2 次。
3. 随机评论：简短自然（如 "Nice!"），不刷屏。
4. 选择性关注：3–5 个相关领域账号。

**合格账号检查**：
- 算法适配：推荐内容与兴趣匹配。
- 关注可见性：关注的账号出现在关注列表、被关注时出现在被关注列表。
- 双向验证：用另一账号搜索确认新号可被检索到。

**验证通过后**：
- 绑定支付方式或邮箱；开始发布时**前 3 条保持日更**。

**测试视频与账号分档**（发 ≤15 秒实拍原创测试片，等 24h 看播放）：
| 播放量 | 状态 | 操作 |
|---|---|---|
| ≤300 | 无效号 | 弃用，刷机后重新注册 |
| 300–1000 | 合格号 | 保留并优化内容 |
| ≥1000 | 天选号 | 绑定矩阵资源，重点运营 |

- 批量 0 播放：检查代理 IP 纯净度和设备指纹伪装。
- 测试内容：避免搬运素材，画质 ≥1080p。
- **筛选通过后 48 小时内完善头像、简介、垂直标签**；首发保持日更节奏。

**账号异常处理**：
| 现象 | 处理 |
|---|---|
| 点赞/关注无反馈 | 静置养号 1–2 天 |
| 关注列表持续为空 | 换 IP 后重试 |
| 养号超 3 天仍无法互动 | 弃号重注册 |

### 4.3 剪辑要求（短剧切片）

**视频时长**：建议 2–5 分钟；**新号最开始控制在 3 分钟左右**（太长影响完播率与推流）。

**常见剪辑形式**：
| 形式 | 特点 |
|---|---|
| 配乐卡点混剪 | 节奏鲜明，适合新号 |
| 原片片段 + 标题 + 配乐 | 操作简单，适合快速制作 |
| 解说配音 + 原片 | 便于说明剧情、引导用户 |

**前 3–5 秒高能元素**（至少包含 1 类）：
| 类别 | 剧情关键词 |
|---|---|
| 冲突爆发 | 强强对峙 / 财富突降 / 突发反转 |
| 感官刺激 | 亲密吻戏 / 惊悚悬疑 / 便装穿越 |
| 身份逆转 | 扮猪吃虎 / 霸总强宠 / 萌娃变故 |
| 情感共鸣 | 弱势委屈 / 不公遭遇 / 悲情失忆 |

**剪辑红线**：
- 前 5 秒避免全景慢镜头。
- 避免线性叙事，优先倒叙/插叙。
- 不建议只用纯文字解说，要让画面直接给看点。
- 避免把多集原片合并成长视频（影响完播与推流）。
- **不要直接搬运原片，须二次剪辑、删冗余、提炼核心看点**。
- 封面风格统一，让用户能快速识别同一剧集/账号；可突出链接/口令/播放量，但别遮挡核心画面。
- 结尾加主页引导文案。
- 做口令推广时，在画面中突出 App 名称和口令，帮用户完成搜索。

**版权与素材**：背景音乐和字体注意版权——**用 TikTok 或 CapCut（剪映国际版）音乐库**，避免侵权。

### 4.4 最佳发布时间（供起测，再用后台校准）

| 时段 | 中国 | 美东 | 美西 |
|---|---|---|---|
| 早间流量 | 7:00–9:00 | 18:00–20:00（前一日） | 15:00–17:00（前一日） |
| 午间碎片 | 12:00–13:00 | 23:00–00:00（前一日） | 20:00–21:00（前一日） |
| 傍晚放松 | 16:00–18:00 | 3:00–5:00（次日） | 0:00–2:00（次日） |
| 夜间峰值 | 21:00–22:00 | 8:00–9:00（次日） | 5:00–6:00（次日） |

> 这是通用基准，最终用账号后台 Analytics → Follower Activity 校准。

### 4.5 内容审核红线（TikTok）

- 禁止 18+ 内容：色情、血腥、暴力、性暗示、烟酒等。
- **不直接搬运；不做简单去重（加水印/滤镜）**——会触发限流/封号。
- 规避建议：动态模糊高速移动画面、多重马赛克叠加关键区域、用可定制智能识别遮罩。
- 多次被提示内容有问题 → 限流甚至封号。

## 5. 发行管理平台 MVP（可视化工具）

**定位**：短剧线专属的发布记录 + 数据可视化工具。**与 TikTok Daily Metrics 分开**——TikTok Daily Metrics 继续管全部账号，发行平台只管短剧账号（未来再考虑合并/迁移）。

### 5.1 数据模型（先于工具定清楚）

**Sheet/表 A：短剧账号台账**（只含短剧线账号）
- 账号 / UID / 主页链接 / 所属组（A/B/C/D）/ 定位垂类 / 表现形式 / 粉丝 / 状态

**Sheet/表 B：发布记录**（每条视频一行）
- 日期 | 账号 | 剧名 | 剧ID（RS Boost） | 方向分类（下拉，用 RS Boost 官方分类） | 表现形式 | 垂类包 | 视频链接 | 发布时间 | 播放 | 点赞 | 评论 | 分享 | 收藏 | RS Boost 归因（转化/佣金，回填） | 备注

**Sheet/表 C：选剧候选池**（可选）
- 从选剧台/RS Boost 里挑出的待推剧：剧名 / 剧ID / 方向分类 / 上线日期 / 生命周期 / 是否已排期

### 5.2 MVP 功能分级

| 版本 | 功能 | 形态 |
|---|---|---|
| **MVP（尽快）** | ①记录：选账号、填剧名、选方向分类、填链接 ②查看：按账号/日期/方向筛选 ③可视化：播放/点赞/趋势图表 ④RS Boost 归因人工回填 | **可视化仪表盘**（推荐 Google Looker Studio 连 Google Sheets，免费、零后端）或轻量单页 |
| **V1** | RS Boost 后台数据自动同步（若有 API/CSV 导出）；TikTok 播放数据自动采集（复用现有采集脚本，指向短剧账号） | 在 MVP 基础上加数据管道 |
| **V2** | 独立 Web 应用：账号管理 + 选剧看板（对接选剧台数据）+ 发布排期 + 自动周复盘 | 自建轻量应用（Next.js/Vercel） |

### 5.3 关键实现路径（MVP 推荐做法）

1. 新建 **Google Sheets：短剧发行管理**（三张 tab：账号台账 / 发布记录 / 选剧池）。
2. **方向分类下拉**：列 RS Boost 官方分类（爱情/霸总/复仇/狼人/逆袭/离婚/重生/战神…），做完贴进表 B。
3. **可视化**：Google Looker Studio 连这个 sheet 建 3 个视图（账号概览 / 发布表现 / 趋势），免费且改动快。
4. **播放数据**：先人工填或复用现有 TikTok 采集脚本把短剧账号的播放/互动写进表 B（把采集目标从 astrologywiki 账号切到短剧账号）。
5. **RS Boost 归因**：先人工回填（每周一次），确认 RS Boost 有无 API/CSV 导出后再自动化。
