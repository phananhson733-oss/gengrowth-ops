# 社媒竞品账号与视频链接分析工具需求文档

## 0. 一句话结论

第一版不要做完整“竞品社媒增长系统”，先做一个**给链接就能分析账号或视频的半自动工具**。

最重要的两个能力：

1. **输入账号链接 → 输出账号概览和内容风格分析。**
2. **输入视频链接 → 输出视频结构、hook、表现形式和可借鉴点分析。**

自动寻找竞品账号、长期监控、自动生成选题、自动生成脚本都放到后续阶段。

### 系统做什么

- 读取账号链接和视频链接；
- 抓取公开可见字段；
- 输出结构化账号分析和视频分析；
- 回写到默认记录界面。

### 系统不做什么

- 不自动寻找竞品账号；
- 不自动发布内容；
- 不依赖登录态；
- 不承诺拿到后台数据；
- 不把 AI 结论直接当最终运营策略。

### 第一版成功标准

- 10 条视频链接里至少 7 条能产出可用分析或明确失败原因；
- 5 个账号链接里至少 3 个能产出账号概览或明确失败原因；
- 输出结果是结构化记录，不是散文；
- 抓不到的字段统一标记 `待补数据/待确认`。

## 一、为什么要做

现在做社媒竞品调研时，主要问题不是“不会分析”，而是：

- 每次都要手动打开账号和视频；
- 手动记录粉丝、播放量、点赞、评论、时长很慢；
- AI 分析格式不统一；
- 视频分析容易只停留在“讲了什么”，没有拆 hook、第一帧、字幕、CTA；
- 调研结果不方便沉淀到结构化表格或记录系统里，后续难比较。

所以第一版工具的目标是：**把人工看账号 / 看视频 / 整理表格的重复劳动降下来**。

## 二、第一版范围

### 第一版只做

| 功能 | 说明 |
|---|---|
| 视频链接分析 `P0` | 输入 TikTok / YouTube Shorts 视频链接，输出单条视频分析 |
| 账号链接分析 `P1` | 输入 TikTok / YouTube Shorts 账号链接，输出账号概览 |
| 结构化结果回写 | 把账号和视频分析结果写入固定表格或记录系统 |
| AI 结构化总结 | 用固定字段输出分析，不要散文式总结 |
| 数据缺口标记 | 抓不到的字段标记 `待补数据/待确认` |

### 第一版不做

- 不自动寻找竞品账号；
- 不自动判断哪些账号是最终竞品；
- 不做 Instagram / X；
- 不自动发布内容；
- 不自动下载和长期保存所有视频；
- 不依赖登录态；
- 不做复杂数据库；
- 不做长期监控和定时周报。

## 三、使用流程

第一版不把“Google Sheet 手动填入”写死。链接输入方式可以是以下任一种：

- Google Sheet；
- 飞书多维表格；
- CSV；
- 简单表单；
- 机器人 / Agent 对话输入后再写入表格。

第一版默认使用 `Google Sheet` 作为输入输出界面，因为最容易先跑通、也最容易给同事排查问题。

如果同事更习惯 `飞书多维表格`，可以一比一替换，字段保持一致即可。

`CSV` 和 `机器人 / Agent 自动写入` 不作为第一版必须支持。

### 流程 A：账号链接分析

```text
运营提供账号链接
→ 工具读取账号链接
→ 抓取公开账号数据
→ 抓取最近公开视频列表
→ AI 总结账号定位、内容形式、常见主题
→ 回写账号分析表
```

适用场景：

- 发现一个可能值得学习的账号；
- 想快速判断这个账号值不值得继续研究；
- 想看这个账号主要做什么内容、表现如何。

### 流程 B：视频链接分析

```text
运营提供视频链接
→ 工具读取视频链接
→ 抓取公开视频数据
→ 提取 caption / 时长 / 播放 / 点赞 / 评论 / 分享
→ 如可行，补充转写文本或关键帧
→ AI 输出视频结构化分析
→ 回写视频分析表
```

适用场景：

- 看到一条竞品视频表现好；
- 想拆解它为什么有效；
- 想判断是否适合改编给自己的产品账号。

## 四、默认表格结构

如果第一版采用表格作为输入 / 输出界面，建议使用 4 个 tab。

如果后续改成飞书多维表格、CSV 或机器人写入，字段保持一致即可。

### 1. `account_links`

运营手动填账号链接，或由机器人 / Agent 自动写入。

| 字段 | 说明 |
|---|---|
| product_name | 产品名，例如 AstrologyWiki |
| platform | TikTok / YouTube |
| account_url | 账号链接 |
| note | 人工备注 |
| status | pending / done / failed |

### 2. `account_analysis`

工具输出账号分析。

第一版建议先只保留最小字段，够判断“值不值得继续研究”即可。

| 字段 | 说明 |
|---|---|
| product_name | 产品名 |
| platform | 平台 |
| account_url | 账号链接 |
| handle | 账号 handle |
| followers | 粉丝数 |
| video_count | 视频数，如可见 |
| bio | 简介 |
| recent_video_count | 本次抓到的视频数量 |
| main_topics | AI 总结的主要主题 |
| main_formats | AI 总结的主要形式 |
| worth_tracking | yes / no / unsure |
| reason | 为什么值得或不值得继续看 |
| data_confidence | verified_public / best_effort / manual / unavailable |
| checked_at | 抓取时间 |

### 3. `video_links`

运营手动填视频链接，或由机器人 / Agent 自动写入。

| 字段 | 说明 |
|---|---|
| product_name | 产品名 |
| platform | TikTok / YouTube |
| video_url | 视频链接 |
| account_handle | 账号 handle，可空 |
| note | 人工备注 |
| status | pending / done / failed |

### 4. `video_analysis`

工具输出视频分析。

| 字段 | 说明 |
|---|---|
| product_name | 产品名 |
| platform | 平台 |
| video_url | 视频链接 |
| account_handle | 账号 handle |
| publish_date | 发布时间，如可见 |
| duration_seconds | 视频时长 |
| caption | 视频文案 |
| views | 播放量 |
| likes | 点赞 |
| comments | 评论 |
| shares | 分享 |
| topic | 视频主题 |
| format_type | 口播 / 录屏 / 图文 / AI host / meme / 产品演示等 |
| opening_text | 首屏文字，如可见 |
| hook | AI 提炼的 hook |
| hook_type | 身份代入 / 好奇缺口 / 关系痛点 / 名人热点 / 工具演示等 |
| structure | 视频结构 |
| cta | CTA |
| replicable_elements | 可借鉴点 |
| non_replicable_elements | 不适合复制点 |
| adaptation_for_product | 如果给本产品改编，应该怎么做 |
| risk_note | 风险，例如夸张、侵权、宿命化、过度预测 |
| analysis_confidence | high / medium / low |
| analyzed_at | 分析时间 |

## 五、AI 分析要求

AI 不要只回答“视频讲了什么”，而要拆短视频结构。

### 单条视频至少分析

1. 视频主题；
2. 视频时长；
3. 视频表现形式；
4. 开头 hook；
5. 首屏文字或第一帧，如可见；
6. 前 3 秒是否有身份代入 / 好奇缺口 / 情绪刺激；
7. 视频结构；
8. CTA；
9. 可借鉴点；
10. 不适合复制点；
11. 如何改编给当前产品账号；
12. 数据缺口。

### 账号至少分析

1. 账号定位；
2. 粉丝和视频规模；
3. 近期内容主题；
4. 主要内容形式；
5. 表现较好的视频类型；
6. 是否值得继续监控；
7. 值得借鉴的方向；
8. 不建议模仿的方向。

## 六、平台数据边界

### TikTok

TikTok 是重点平台，但公开数据不稳定。

第一版要求：

- 能抓多少抓多少；
- 账号页抓不到完整视频列表时，不算失败；
- 允许运营手动补视频直链；
- 单条视频链接优先于账号列表；
- 抓不到字段必须写 `待补数据/待确认`。

### YouTube Shorts

YouTube Shorts 相对更稳定，适合作为第一版重点。

第一版优先获取：

- 标题；
- 发布时间；
- 播放量；
- 视频链接；
- 频道信息。

likes、comments、retention 如果拿不到，不影响第一版验收。

## 七、技术实现建议

第一版可以用任一方案：

| 环节 | 可选方案 |
|---|---|
| 操作界面 | Google Sheet / 飞书多维表格 / CSV |
| 自动化编排 | n8n / Make / 本地脚本 |
| TikTok 数据 | Apify / 第三方公开采集器 / 页面解析 |
| YouTube 数据 | YouTube Data API / 公开页面解析 |
| AI 分析 | GPT / Claude / Gemini / 通义 / DeepSeek |
| 输出 | Google Sheet 回写 |

优先级：

1. 先做一个最简单的链接输入和结果回写界面；
2. 先做 `P0` 视频链接分析；
3. 再做 `P1` 账号链接分析；
4. 最后再考虑自动找账号。

## 八、验收标准

第一版只用一个测试产品验收即可。

### 视频链接分析验收

输入 10 条 TikTok / YouTube Shorts 视频链接后：

- 至少 7 条能返回基础公开数据或明确失败原因；
- 每条成功记录能写入 `video_analysis`；
- 每条成功记录至少包含主题、hook、形式、CTA、可借鉴点、不适合复制点；
- 缺失字段有 `待补数据/待确认` 标记。

### 账号链接分析验收

输入 5 个账号链接后：

- 至少 3 个账号能返回账号概览或明确失败原因；
- 成功记录能写入 `account_analysis`；
- 每个成功账号能输出账号定位、主要主题、主要形式、是否值得继续看；
- 如果无法抓完整视频列表，也要说明原因。

### 表格验收

- 默认表格或记录界面可正常使用；
- `status` 可从 pending 更新为 done / failed；
- 抓取失败有原因；
- AI 输出格式稳定，不是散文。

## 九、后续扩展

第一版跑通后，再考虑：

- 自动根据产品关键词寻找候选账号；
- 每个账号自动抓最近 20 条内容；
- 自动筛选高表现视频；
- 增加 Instagram / X；
- 自动下载视频；
- 自动抽取关键帧；
- 自动转写音频；
- 每周生成竞品内容总结；
- 根据竞品模式生成选题和脚本 brief；
- 回收自家账号发布后的数据。

## 十、当前结论

这份需求第一版应该收缩成一个“链接分析工具”。

最小可交付不是完整竞品增长系统，而是：

```text
给账号链接 → 出账号分析
给视频链接 → 出视频分析
分析结果 → 回写默认记录界面
```

只要这一步跑通，后面再扩展自动找账号、批量监控和内容建议。
