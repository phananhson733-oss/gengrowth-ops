# 数据复盘入口

这里保存内容实际执行后的发布事实、周报、策略结论、`decision / next_test` 和专项复盘，是“参考 → 生产 → 复盘”的最后一环。

## 与调研资料的边界

- `01-调研资料/`：执行前或外部研究证据，回答“为什么可能这样做”。
- `02-生产/03-data-review/`：执行后的事实和结论，回答“实际发生了什么、下一步继续还是调整”。

复盘可以覆盖单条内容、账号、平台或产品，但仍通过 `product / account / platform / content_id` 标明对象，不为每个账号建立独立复盘目录。

## 当前入口

- 周报：根目录的 `2026-Www-weekly-report.md`。
- 专项复盘：`专项复盘/`。
- 历史发布记录：`历史发布记录/`，仅作数据底稿和追溯，不再维护第二套周级结论。

发布证据仍以真实链接、平台 ID 和实际发布时间为准；缺少这些字段时，明确写“主记录标记 published，发布证据待补”。

复盘确认的稳定结论应回流到 `01-reference/` 的账号分工与发布指南、`00-evergreen-workflows/` 的执行方法或下一份周计划；原始数据和当时结论继续保留在本目录。
