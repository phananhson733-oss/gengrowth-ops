# 通用社媒账号起号与轻量养号流程

> 适用于大多数品牌号、创作者号和项目社媒账号。使用时注入具体的 `product_context`、`account_context` 和平台规则，不把某个项目的设备、地区、内容类型或发布频率固化成通用要求。

## 1. “养号”的正确定位

养号不是流量开关，也不是通过机械浏览、批量点赞或延迟发帖来“骗过算法”。本流程中的轻量养号只指：

- 完成账号安全、资料和品牌身份配置；
- 了解目标社区的内容和表达方式；
- 进行少量、真实、有意义的互动；
- 用一批定位一致的内容完成冷启动验证；
- 根据真实数据判断内容、账号和技术问题。

不要承诺“养满几天就有流量”，也不要仅凭单条内容播放量判断账号被限流。

## 2. 使用前必须明确的运行时信息

开始前先填写，不完整的信息标记为“待确认”：

| 项目 | 需要确认的内容 |
|---|---|
| 账号身份 | 品牌号、创作者号、个人号、地区号或其他明确角色 |
| 平台 | TikTok、Instagram、YouTube、X、LinkedIn、Facebook 等 |
| 业务目标 | 品牌认知、互动、流量、线索、注册、购买或社区建设 |
| 目标受众 | 地区、语言、年龄、兴趣和主要使用场景 |
| 账号承诺 | 用户关注后持续能获得什么 |
| 内容支柱 | 3–5 个可持续主题及各自边界 |
| 主形式 | 短视频、图文、文字、直播或混合形式 |
| 生产能力 | 每周可稳定完成的数量、人员、工具和预算 |
| 账号负责人 | 谁拥有账号、谁保管恢复方式、谁可以发布 |
| 风险边界 | 禁止话题、版权、AI 标注、广告披露和行业合规要求 |

若项目已有账号 Playbook、周计划或内容生产系统，直接读取现有文件，不另建第二套日历或状态表。

## 3. 起号鱼骨

```text
账号立项
→ 安全与权限
→ 主页与身份配置
→ 社区观察和真实互动
→ 首批内容准备
→ 小批量发布
→ 技术与内容诊断
→ 继续、调整或停止
```

## 4. 阶段一：账号立项与安全

### 4.1 账号立项

- 一个账号必须有一个明确受众、一个主要承诺和一个负责人。
- 多账号必须具有不同身份、语言、地区、产品或内容用途；不要为了放大指标建立重复账号。
- 优先使用合法获得、长期可控的账号。不要购买来源不明的账号、身份或互动数据。
- 不使用虚假身份冒充真人、品牌或机构；创作者人设、虚拟角色或 AI Host 应避免造成身份误导。

### 4.2 安全配置

- 使用项目或公司可控的邮箱、恢复邮箱和手机号。
- 启用双重验证，并把恢复方式交由明确负责人保管。
- 使用密码管理工具，不在聊天、表格正文或公开文档存放密码、验证码和 Cookie。
- 记录账号创建日期、所有者、管理员、恢复方式是否齐全和当前权限。
- 使用可信、稳定的登录环境。不要频繁跨地区切换，也不要把代理、设备隔离或多 IP 当成通用养号要求或规避平台执法的手段。

## 5. 阶段二：主页与发布准备

首次发布前至少完成：

- 用户名、头像、名称和简介与账号身份一致；
- 简介用一句话说明内容承诺；
- 链接、联系方式和商业披露符合平台权限与规则；
- 视觉和语气有最低限度的一致性；
- 准备至少 3 条定位一致但角度不同的首批内容；
- 明确评论、私信、骚扰、敏感信息和危机内容的处理边界；
- 涉及 AI 生成、广告合作、版权素材或敏感领域时，检查相应标签和披露要求。

资料和首批内容准备好后即可发布。没有统一的“必须空养 3 天或 7 天”规则。

## 6. 阶段三：社区观察与轻量互动

目的不是制造活跃痕迹，而是让运营者理解真实社区：

1. 观察 10–20 个目标受众、同类创作者或行业账号。
2. 记录高频问题、自然语言、常见形式和评论分歧。
3. 只在确实有内容可补充时点赞、收藏、回复或关注。
4. 回应自己账号收到的正常评论和问题。
5. 将有价值的发现写回现有调研或内容记录。

禁止：

- 批量点赞、关注、取关、评论或私信；
- 复制相同评论到多个帖子；
- 账号之间互刷、互赞或人为制造热度；
- 购买粉丝、播放、点赞、评论或其他虚假互动；
- 使用自动化绕过平台限制或模拟真人行为。

## 7. 阶段四：首批内容冷启动

### 7.1 首批内容组合

首批内容建议覆盖三类作用，而不是连续发布同一种广告：

| 作用 | 目的 | 示例 |
|---|---|---|
| 身份内容 | 让用户迅速知道账号讲什么 | 核心观点、代表性问题、明确系列 |
| 价值内容 | 证明关注价值 | 教程、解释、案例、工具或清单 |
| 互动内容 | 获取真实问题和语言 | 开放问题、观点判断、评论回复 |

产品或服务可以出现，但不要让每条内容都以强销售 CTA 结束。

### 7.2 发布节奏

- 以能够持续两周以上的产能为上限，不使用统一的日更数字。
- 先发布一个小批次，再根据反馈调整；不要一次把全部库存发完。
- 同一素材跨平台复用时，按平台改写 Hook、封面、标题、Caption、长度和 CTA。
- 多账号不得同步发布完全相同的内容、文案和互动动作。
- 核心内容可以定时；热点、评论回复和社区互动保留人工处理。

## 8. 阶段五：首轮判断

建议在累计 5–10 条内容或运行约两周后做第一次判断；若平台已给出明确违规、上传失败或可见性异常，则立即检查。

### 8.1 先检查技术事实

- 内容是否成功公开，而不是草稿、仅自己可见或仍在审核；
- 账号和单条内容是否收到平台警告、版权或推荐资格提示；
- 音频、尺寸、封面、字幕、链接和地区设置是否正常；
- 是否存在重复内容、水印、未经授权素材或缺少 AI / 商业披露；
- 公开链接能否在未登录环境打开。

### 8.2 再检查内容表现

按目标选择指标，不用一个播放阈值判断所有平台：

- 触达：展示、播放、独立观看人数；
- 留存：前几秒留存、平均观看时长、完播率；
- 互动：评论、分享、收藏、有效回复；
- 账号增长：主页访问、关注转化、净增粉丝；
- 业务结果：链接点击、线索、注册、购买或其他目标动作。

至少比较同一账号的多条内容，并区分 Hook、题材、形式、发布时间和 CTA。样本少于 10 条时，结论标记为低置信度。

### 8.3 最后才判断账号问题

低流量可能来自题材、Hook、画面、账号定位、发布节奏、竞争环境或技术限制。只有在多条合格内容、技术检查和平台提示都完成后，才把“账号质量或分发限制”列为主要假设。

不要因为一两条低播放立即弃号、换设备或重建账号。

## 9. 多账号边界

- 每个账号必须有可解释的独立用途，避免重复身份和重复内容。
- 不用多个账号互相放大同一内容或操纵趋势、投票与评论区。
- 不批量注册或运营虚假账号，不通过新账号规避处罚。
- 同一团队管理多个合法账号时，保存清晰的所有权、权限和用途记录。
- 设备和网络配置由安全、权限和平台要求决定，不使用“一台手机必须对应一个 IP”作为跨平台通用规则。

TikTok 允许因创作等正当目的使用多个账号，但禁止欺骗、虚假互动和绕过执法；X 允许用途不同的多个账号，但禁止重复内容、协同放大和非真实活动。具体执行前仍需查看目标平台最新规则。

## 10. 继续、调整和停止

| 决定 | 适用情况 | 下一步 |
|---|---|---|
| 继续 | 技术正常，部分内容获得符合目标的信号 | 保留有效支柱，继续一个小批次 |
| 调整 | 有分发但留存、互动或转化弱 | 每轮只改一个主要变量 |
| 暂停 | 账号权限、素材版权、身份或安全信息不完整 | 先解决风险，不继续堆内容 |
| 停止 | 明确违规、所有权不可控或账号用途已失效 | 保存证据并停止投入；不得规避处罚 |

## 11. 最小记录字段

账号资产和运行结果写回项目已有位置，至少包含：

```yaml
account_id:
platform:
account_handle:
account_role:
target_audience:
owner:
created_at:
launch_date:
security_ready:
profile_ready:
content_pillars: []
first_batch_ids: []
current_state:
last_reviewed_at:
decision:
next_test:
```

密码、验证码、Cookie、完整恢复信息和代理凭证不得写入该记录。

## 12. 一页执行检查

- [ ] 账号身份、受众、目标和负责人明确。
- [ ] 邮箱、恢复方式、双重验证和权限安全可控。
- [ ] 主页信息与账号承诺一致。
- [ ] 已准备至少 3 条定位一致、角度不同的内容。
- [ ] 互动是真实、有意义且非批量操作。
- [ ] 未购买粉丝、互动或使用规避平台限制的自动化。
- [ ] 发布节奏符合实际产能。
- [ ] 已完成公开可见性和平台提示检查。
- [ ] 首轮结论基于多条内容，并标注置信度。
- [ ] 决定和下一轮测试已写回既有记录。

## 13. 当前官方规则参考

- [TikTok Community Guidelines — Integrity and Authenticity](https://www.tiktok.com/safety/en/policies-and-engagement/integrity-authenticity)
- [X Help — Authenticity](https://help.x.com/en/rules-and-policies/authenticity)

平台规则和功能会变化。每次为具体账号执行前，应重新检查对应平台的官方政策与账号提示；本 SOP 不替代平台规则。
