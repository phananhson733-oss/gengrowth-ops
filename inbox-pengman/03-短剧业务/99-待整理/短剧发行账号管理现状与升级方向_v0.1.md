# 短剧发行账号管理现状与升级方向

> 版本：0.1  
> 整理日期：2026-09-16  
> 核查范围：个人梳理稿与飞书「短剧发行管理」  
> 用途：供业务负责人、执行人员和新同事共同阅读

## 核心结论

当前系统已经具备账号台账、选剧池、发布记录、数据采集、管理看板和 Social Bot，基础骨架是完整的。现阶段的主要问题不是缺少更多表格，而是业务规则与数据关系尚未完全固化。

短期应优先统一账号统计口径、补齐账号定位、修复采集数据与发布记录之间的关联、建立发布与回填时限，并保持一定的未来排期库存。在数据闭环稳定前，不宜直接扩大账号数量和发布规模。

制作形态可以统一为纯切片，以降低批量生产成本；账号定位不能随之取消。每个账号仍应明确目标受众、内容语言、首选分发平台、CTA 方式和账号角色。

本文把已经核查的事实、根据事实作出的判断和后续建议分开呈现。账号完整资产数量、历史归档口径、自动采集失败原因、收益数据和 Linktree 点击数据，目前无法从现有页面确认，因此不作推断。

## 管理摘要

### 当前已经具备的能力

- 账号台账：记录账号、主页链接、粉丝数、分组和部分定位。
- 选剧池：记录剧名、分类、上线日期、生命周期、平台、语言和备注。
- 发布记录：管理排期、发布链接、Post ID、回填状态和后续表现。
- 采集数据：保存 TikTok 帖子快照及播放、点赞等指标。
- 管理仪表盘：查看活跃账号数、待公开数、待回填数和累计表现。
- Social Bot：支持查询、新增剧目、建立排期、修改部分字段和启动同步。

### 当前最需要处理的事项

1. 356 条采集数据中有 153 条没有关联发布记录，比例约为 43%。
2. 每日播放趋势只有 9 月 10 日和 9 月 11 日出现有效新增量，其余日期显示为 0。
3. 最近一次同步终态为 `partial`，当前趋势表不适合直接评价业务表现。
4. 账号数量存在约 22 个、主视图 9 条、活跃账号 7 个三种口径。
5. 当前已排期记录为 0，制作与发布容易变成当天临时处理。

## 一 当前系统如何运转

当前流程可以概括为：

> 确认账号 → 选剧 → 准备素材 → 剪辑 → 建立发布记录 → 实际发布 → 回填链接和 Post ID → 自动采集 → 复盘

飞书已经承载了大部分管理信息，Social Bot 可以查询和修改部分数据，也能启动同步任务。但 Social Bot 只负责登记排期，不会代替人员在 TikTok 实际发布。

| 模块 | 当前用途 | 已有能力 | 主要缺口 |
| --- | --- | --- | --- |
| 账号台账 | 记录账号、身份链接、粉丝数、分组和定位 | 有「在用账号」「需处理账号」视图 | 账号总量与在用口径不一致，定位字段不够完整 |
| 选剧池 | 存放剧名、分类、上线日期、生命周期、平台和备注 | 97 条记录，有未排期、已排期、按平台、按语言视图 | 旧记录的分类、日期、生命周期和备注存在空白 |
| 发布记录 | 管理排期、发布链接、Post ID 和后续数据 | 245 条记录，有流程状态及按账号、按剧视图 | 21 条待公开、21 条待回填、5 条未关联账号 |
| 采集数据 | 保存 TikTok 快照和互动指标 | 356 条记录，「部分缺失」视图为 0 | 153 条未关联发布，数据链路不完整 |
| 管理仪表盘 | 查看账号和剧目累计表现 | 展示活跃账号、待公开、待回填和累计表现 | 最近同步为 `partial`，日趋势只有两天存在有效新增量 |
| Social Bot | 查询、建排期、修改记录、启动同步 | 有预览、确认和写后校验规则 | 不能代替 TikTok 实际发布，账号资料仍需在表内维护 |

| --- | ---: | --- |
| A 纯切片 | 4 | 主力短剧切片账号 |
| B 生活 | 2 | 生活内容与短剧混合 |
| C 测试 | 1 | 测评、排名、吐槽等实验内容 |

账号台账主视图受两个筛选条件影响，只显示 9 条记录；个人原稿写的是约 22 个账号。因此，现阶段不能把 7、9 和 22 当作同一个数字。建议补充账号状态，并明确以下口径：

- 全部账号资产数
- 可登录账号数
- 活跃账号数
- 观察账号数
- 停用或归档账号数

### 选剧池

选剧池共有 97 条记录。现有字段已经覆盖剧 ID、剧名、剧分类、上线日期、生命周期、平台、语言和备注，并建立了未排期、已排期、按平台和按语言等视图。

按平台视图中，ReelShort 组有 61 条，占全部选剧池约 63%。这与原稿希望减少跨平台混用的方向一致，但还没有形成账号与平台的一对一规则。

选剧池的数据完整性不均匀。近期记录通常包含分类、上线日期和生命周期，部分旧记录只保留剧名。若这些字段不补齐，就无法稳定回答以下问题：

- 哪些题材的表现更好
- 哪个平台的内容更适合当前账号
- 新剧、热剧以及又新又热的剧分别有多少
- 不同选剧来源的成功率是否存在差异

### 采集与趋势

采集数据共有 356 条，当前「部分缺失」视图为 0 条，但「未关联发布」视图有 153 条，占约 43%。这意味着采集器取得了帖子数据，却没有把近一半记录稳定连接到发布记录。

采集数据中还出现了不在当前账号台账主视图内的账号链接，说明账号台账、发布记录和采集来源之间可能存在历史账号或漏登记账号。

每日播放趋势覆盖 9 月 4 日至 9 月 16 日，但只有两天出现有效新增播放量：

- 9 月 10 日：77426
- 9 月 11 日：76910

其他日期均显示为 0。Social Bot 指南明确说明，首日或采集断档没有可比数据时，并不代表真实新增为 0。因此，这张趋势表目前只能用于排查同步，不适合直接用于评价业务表现。

## 三 当前最需要解决的问题

| 优先级 | 问题 | 证据 | 影响 |
| --- | --- | --- | --- |
| P0 | 采集数据与发布记录未完全关联 | 153 条采集数据未关联发布 | 账号和剧目表现可能被漏算或重复解释 |
| P0 | 日趋势数据断档 | 13 天中只有 2 天有有效新增播放，最近同步状态为 `partial` | 无法稳定做日复盘和趋势判断 |
| P1 | 账号口径不统一 | 原稿约 22 个、主视图 9 条、活跃账号 7 个 | 管理层无法准确判断规模和利用率 |
| P1 | 账号定位尚未成为字段规则 | 已有分组和部分定位，但语言、平台、CTA 未形成完整组合 | 选剧和发布依赖个人记忆 |
| P1 | 没有排期库存 | 已排期视图为 0 条 | 制作和发布容易变成当天临时处理 |
| P2 | 选剧池旧数据不完整 | 部分记录缺少分类、上线日期、生命周期或备注 | 难以比较热剧、新剧、平台和题材表现 |
| P2 | 发布 ID 规则曾出现不一致 | 新增编号曾先写成纯数字，后补 `SR-000` 前缀 | 人工查询和自动关联存在风险 |

## 四 把原稿中的想法整理成可执行原则

### 制作形态统一 账号定位分开

可以把纯切片作为统一制作形态，以降低批量剪辑成本；但不能因此取消账号定位。账号的差异应从内容形态转移到受众、语言、首选平台和 CTA 上。

| 定位维度 | 建议选项 | 管理规则 |
| --- | --- | --- |
| 目标受众 | 男频、女频、男同、女同、全性别 | 每个账号只能有一个主标签，可以有一个辅助标签 |
| 内容语言 | 纯英语、单一小语种、混合小语种 | 主语言固定四周后再评估 |
| 首选平台 | ReelShort、鹊娱、MoboReels、北斗智影、其他 | 一个账号设一个首选平台，跨平台内容需在发布记录注明 |
| 内容形态 | 纯切片 | 先作为统一生产标准，特殊实验另建标签 |
| CTA | 无 CTA、Caption 链接、Linktree 结尾录屏 | 每条发布记录必须选择一种 |
| 账号角色 | 主力、放量、实验、观察、停用 | 角色决定发布频率和复盘要求 |

### 选剧来源和生命周期必须留痕

原稿列出的选剧来源可以直接转成单选字段：

1. 选剧台推荐
2. 分发平台推荐
3. 短剧平台排行榜
4. 马博洋推荐
5. 个人判断

每条发布记录必须关联选剧池中的剧，并自动带出来源、平台、分类、上线日期和生命周期。

生命周期建议改成可计算口径：

- 新剧：上线 7 天以内。
- 热剧：进入指定平台榜单或达到明确的热度门槛。
- 又新又热：同时满足新剧和热剧两个条件。

热剧门槛需要业务负责人另行确定。在门槛确定前，不应把主观印象直接写成热剧。

### 账号与平台尽量固定 但保留实验例外

固定账号的首选平台可以减少口令、链接、结算和素材归档的混乱。建议允许最多 20% 的发布量作为跨平台实验，并在发布记录中标记实验原因。

这样既能维持管理清晰，也不会因为固定平台而错过新的内容机会。

## 五 建议的标准工作流

1. **每周确认账号状态**：查看活跃账号、账号角色、首选平台、主语言和当周发布目标。
2. **批量选剧**：为每个账号准备至少 1 部主推剧和 1 部备选剧，并补齐平台、来源、分类、上线日期、生命周期和推荐理由。
3. **批量准备素材**：下载合法可用的源文件，按账号和剧 ID 建文件夹，把剧名、口令、资源链接和 CTA 要求一起交给剪辑流程。
4. **批量剪辑**：每部剧默认产出 3 个差异化片段，为每个片段生成 caption、hashtag 和版本编号。
5. **建立发布记录**：实际发布前先在飞书建排期，由系统生成 SR 编号，并关联账号、剧 ID、日期、版本和 CTA。
6. **人工发布**：按账号逐一在手机或平台后台发布。Social Bot 只登记排期，不代替实际发布。
7. **发布后回填**：当天补充视频链接和 Post ID，确保账号与 Post ID 唯一且一致。
8. **次日检查同步**：确认抓取终态为 `success`；若为 `partial` 或 `failed`，先检查错误，不重复启动任务。
9. **每周复盘**：按账号、题材、平台、语言、CTA 和发布时间比较表现，并区分累计播放和新增播放。

## 六 角色和验收标准

| 角色 | 主要职责 | 交付标准 |
| --- | --- | --- |
| 业务负责人 | 确定账号策略、实验优先级和热剧口径 | 每周给出账号目标和停止继续规则 |
| 选剧人员 | 补充选剧池并给出推荐理由 | 关键字段完整，剧目可追溯到来源平台 |
| 剪辑人员或 AI 流程 | 按剧批量产出片段、caption 和 hashtag | 文件名包含剧 ID、账号和版本，可直接交付发布 |
| 发布人员 | 按排期发布并回填链接、Post ID 和 CTA | 当天回填，不出现重复 Post ID |
| 数据负责人 | 检查同步状态、关联率和趋势表 | 同步成功，未关联发布持续下降，异常当天记录 |
| 复盘负责人 | 按账号和剧输出周报 | 结论同时说明样本量、时间段和数据完整性 |

## 七 建议的管理指标

| 指标 | 定义 | 建议目标 |
| --- | --- | --- |
| 账号信息完整率 | 活跃账号中定位、语言、首选平台、CTA、状态均完整的比例 | 第一周达到 100% |
| 选剧信息完整率 | 新建选剧记录的来源、平台、分类、上线日期、生命周期和推荐理由完整比例 | 持续 100% |
| 排期库存天数 | 未来已排期内容可覆盖的天数 | 保持 3 至 7 天 |
| 当日回填率 | 发布后当日补齐链接和 Post ID 的比例 | 不低于 95% |
| 采集关联率 | 采集记录中已关联发布记录的比例 | 先从约 57% 提升到 95% 以上 |
| 同步成功率 | 计划同步任务最终状态为 `success` 的比例 | 不低于 95% |
| 有效样本量 | 每个策略组合在得出结论前积累的发布数 | 至少 10 条再做方向判断 |

## 八 四周升级计划

| 时间 | 重点任务 | 完成标准 |
| --- | --- | --- |
| 第 1 周 | 统一账号口径和字段，补齐 7 个活跃账号定位，修正历史 SR 编号格式 | 账号信息完整率 100%，所有新记录自动生成统一 ID |
| 第 2 周 | 修复采集关联，补齐 153 条未关联数据，处理 `partial` 同步原因 | 采集关联率至少达到 90%，日趋势不再把断档显示为真实 0 |
| 第 3 周 | 按账号准备一主一备两部剧，建立 3 至 7 天排期库存 | 已排期不再为 0，每条记录关联剧目、来源和 CTA |
| 第 4 周 | 比较受众、语言、平台和 CTA 实验，输出首次周报 | 每个结论附样本量、时间段和数据完整性说明 |

## 九 需要负责人确认的决策

- 账号总口径到底是多少：22 个是全部资产、9 个是主视图记录、7 个是活跃账号，目前三者需要正式定义。
- 是否把纯切片确认为所有活跃账号的统一制作形态，同时保留受众、语言、平台和 CTA 的账号差异。
- 热剧的客观门槛是什么：建议使用平台榜单名次或明确的播放门槛，而不是凭印象标记。
- 每个账号的首选平台如何分配，跨平台实验最多允许占多少发布量。
- Linktree 是否作为正式 CTA 进入测试，哪些账号参与，成功指标看点击量、继续观看还是收益。
- 自动化边界是什么：AI 可以整理剧名、口令、资源链接、caption 和 hashtag，也可以协助维护 Linktree；涉及登录、发布或对外写入时，仍应保留人工确认。
