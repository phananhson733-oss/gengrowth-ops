## 0. 一句话需求

做一个**短剧账号发行管理工具**：
1. Google Sheets 作为唯一数据源：账号台账 + 发布记录 + 选剧池。
2. 发布记录的播放/点赞/收藏/转发、视频链接、Post ID **自动抓取回填**（复用现有采集器），剧名/剧分类/RS收益手动填。
3. 支持**定时发布**：先填剧名/剧分类占位，帖子公开后自动回填链接和数据。
4. 人类查看、筛选、录入和复盘都在同一份 Google Sheets 中完成，不再增加第二个展示系统。

## 2. 目标架构（Google 单一入口）

```text
层1 采集（已有，不改）
  tiktok-public-capture 每天抓短剧账号帖子
  → 视频链接/Post ID/播放/点赞/收藏/转发 → TikTok Daily Metrics (posts_latest)
        ↓
层2 Google 短剧表 = 唯一数据源 + 录入
  账号台账 / 发布记录（占位+回填）/ 选剧池
  自动：从 TikTok Daily Metrics 回填播放数据
  手动：填剧名/剧分类/RS收益
  查看：筛选、排序、检查发布状态和数据表现
```

**关键设计原则：**
- **Google 是唯一入口**：录入、查看、数据回填和复盘都在同一份表中完成。
- 不建立 Google → 飞书或 Google → Looker 的展示链路，减少同步、权限、字段映射和维护成本。
- 不修改共享采集器；Google 短剧表通过现有 TikTok Daily Metrics 获取公开数据。
- 未来只有在 Google Sheets 明确无法满足查看需求，且可视化收益足以覆盖维护成本时，才重新评估独立可视化层。

## 4. 定时发布：占位 → 回填 机制（核心新增逻辑）

**背景**：TikTok 定时发布的帖子在真正公开前，采集器抓不到（README 已写明"尚未公开的定时帖不会出现在公开抓取或 posts_latest 中"）。所以必然有"已填剧名但无数据"的空窗期。

**流程分两阶段：**

**阶段 1（发布前 / 定时时）—— 占位行**
- 用户填：账号名、剧名、剧分类、（可选）计划发布时间、备注
- 留空：视频链接、Post ID、播放/点赞/收藏/转发
- `发布状态 = 已排期 / 待公开`

**阶段 2（帖子公开后）—— 自动回填**
- 采集器抓到该账号新帖子后，按**匹配桥梁**把数据自动填回占位行：
  - 视频链接 / Post ID / 播放 / 点赞 / 收藏 / 转发 → 自动填
  - 剧名 / 剧分类 → 保留手动值（不覆盖）
  - `发布状态 → 已回填`

**匹配桥梁（决定哪条帖子 = 哪条占位记录），按可靠性排序：**
| 方式 | 做法 | 可靠性 |
|---|---|---|
| 1. 用户事后补链接（主用） | 帖子公开后，用户把视频链接填进该行"视频链接"列 → 系统按 post_id 自动拉数据回填 | ✅ 最高 |
| 2. 账号 + 发布时间窗（辅助） | 采集到"某账号 + 发布时间 ≈ 计划时间（±N 小时/天）"的帖子自动关联 | 🟡 中 |
| 3. 精确 post_id | 用户提前知道 post_id 就填上 | ✅ 高 |

**参考现成实现**：`reconcile_published_content.mjs` 已实现类似逻辑（精确匹配 → 人工填 post_id → 账号+时间/caption 高置信匹配 → 模糊只记不写），**直接复用这套匹配思路**，作用对象换成短剧表。

## 5. 数据回填：从 TikTok Daily Metrics 到短剧表

**方案（推荐）：短剧表通过 `=IMPORTRANGE` 或 `=QUERY` 自动引用 TikTok Daily Metrics 的 `posts_latest`，按 post_id 匹配回填。**

- 短剧表“采集数据”tab 已从静态快照改为**实时引用**：
  ```
  =QUERY(IMPORTRANGE("17NOiX9VGozHEgthpSbBN-2dyf4rJRsTQkmLubBwnICQ", "posts_latest!A:Q"),
         "select Col9,Col2,Col1,Col3,Col11,Col12,Col13,Col14,Col15 where Col2 <> 'astrologywiki' and Col2 <> 'miraaastrology'", 1)
  ```
- 发布记录用 `=VLOOKUP(post_id, 采集数据, ...)` 自动带出播放/点赞/收藏/转发。
- 账号台账“粉丝数”按账号名从 `accounts_latest` 实时查找 followers；“数据日期”按账号名查找 snapshot_date。
- **零改采集器，零风险**（这是层 2 自动回填的最省力实现）。

**若 IMPORTRANGE 方案不够用**（如需要采集器直接写短剧表），备选：给采集器加"第二个 spreadsheet 输出"支持——但要动共享代码，需额外测试，**优先级低于 IMPORTRANGE**。

## 6. Looker 与飞书处理决定（当前不执行）

### 当前决定

- **Looker Studio：不执行。** 当前阶段不投入报表搭建、字段适配和维护时间。
- **飞书多维表格：停止采用。** 不作为短剧发行管理的查看、录入或验收入口。
- **唯一入口：Google Sheets。** 所有业务操作继续在“短剧发行管理”Google 表内完成。

### 原因

1. 当前数据量和使用人数有限，Google Sheets 已能满足录入、筛选、查看和回填需求。
2. 增加 Looker 或飞书会引入第二套字段、权限、同步、视图和故障排查成本。
3. 飞书应用所有权、个人编辑权限和通讯录范围配置增加了额外协作成本。
4. 当前优先级是稳定生产与数据回填，不是建设独立可视化层。

| 项目 | 历史事实 | v3 当前状态 |

## 10. 风险与备注

- **IMPORTRANGE 权限**：首次使用需在短剧表确认授权访问 TikTok Daily Metrics（弹窗点允许一次）。若账号没有访问权限会报错，需处理。
- **播放数据是公开抓取近似值**：与 TikTok 后台可能有差异，与现有采集同一口径，可接受。
- **占位→回填的匹配**：以"用户补链接"为主，自动匹配为辅；模糊匹配只提示不写，避免误配。
- **唯一入口边界**：当前业务数据只在 Google Sheets 录入和查看；不得因为历史飞书表或同步脚本仍存在，就把飞书描述为当前生产系统。
- **历史自动化残留**：飞书同步 launchd 曾安装。文档已将其排除出 v3，但若要停止实际运行，需另行执行停用并验证。
