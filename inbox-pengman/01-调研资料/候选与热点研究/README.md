# 候选与热点研究入口

这里只保存已经获准开展的候选内容研究、信息来源和**可供下周选择的候选池**，包括：周一建立周计划、Pengman 明确要求重排、确认补充库存，或需要评估一个可能达到门槛的热点。

这里不是每天自动生成选题的入口，也不维护第二份内容进度。候选被人工选中后，在 [[inbox-pengman/02-生产/02-content-production/README|单条内容详情入口]]建立唯一记录，并由该记录保存实际阶段。

具体研究权限和来源要求以 [[inbox-pengman/AGENTS#候选与热点研究权限门|工作区规则]]为准。

## Miraa 候选池怎么使用

- 当前入口：[[inbox-pengman/01-调研资料/候选与热点研究/Miraa 候选池|Miraa 候选池]]。
- 正常目标：维护 **15–20 条**有真实来源、近期可复核、尚未被人工选中的 Miraa 候选。
- 周一：先补充/清理候选池，再从中提出 8–10 条短名单，Pengman 从中选择本周 5–7 条正式生产内容。
- 库存为 0 的启动周：先从候选池选择足够支撑“生产 10 条”的短名单；发布 5–7 条，其余达到 `ready + inventory_ready: true` 的内容留作下周库存。
- 周五：把已发布内容的 `decision / next_test` 回写为候选池的“继续挖掘 / 暂停 / 换机制”依据；不要只把结论留在聊天记录里。

每条候选至少要有：

1. 适用账号、内容形式和一句话内容机制；
2. 原始来源链接、查看日期和来源性质（用户讨论 / 竞品案例 / 已发布数据 / 运营推断）；
3. 为什么适合现在做、与最近 7–14 天内容的去重说明；
4. 预估 effort、时效窗口或复核日期；
5. 可借鉴的竞品结构或已发布内容的复盘线索。

候选池**不是第二套项目管理或内容生命周期系统**：不写 `content_stage`，不记录制作进度，也不代替周计划。只有 Pengman 选中某条候选后，才在 `02-生产/02-content-production/` 建立单条主记录并设置 `content_stage: selected`。
