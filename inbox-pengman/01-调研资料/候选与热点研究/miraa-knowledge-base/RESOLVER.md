# 落盘规则：一条信息该记在哪

拿到一条要往知识库里记的信息时，按下面的顺序问自己：

## 1. 这是一个「可以反复复用的研究结论」吗？→ Topic

如果这条信息是「关于某个选题方向，我们已经调研清楚、以后出内容可以直接
拿来用」的结论——比如「天蝎座在处理家庭冲突时倾向沉默而非对抗，评论区
反复出现『不想解释』这种语言模式」——这属于 **Topic**，存在
`topics/<topic-id>.md`。

一个 Topic 是被反复验证、可以直接支撑选题的「结论」，不是一条原始记录。

## 2. 这是「一个可以单独打开看的网页/帖子」吗？→ Source

如果这条信息是「我们看到的某一条具体的帖子、评论区、网页」——有自己的
URL、平台、发布者、能摘一句原文引用——这属于 **Source**，存在
`sources/<source-id>.md`。

一个 Source 支撑一个或多个 Topic：Topic 页的「结论」要能在它引用的
Source 页里找到原始出处。

## 3. 这是「一次抓取/巡逻/迁移动作发生了什么」吗？→ Run

如果这条信息是「knowledge base 这一次被谁、用什么方式、写入或更新了
什么」的记录——什么时候跑的、成功还是失败、动了哪些 Topic/Source——这
属于 **Run**，存在 `runs/<mode>/krun-*.json`，一旦写下就不再改动。

Run 记录的是「过程」，Topic/Source 记录的是「结果」。

## 4. 候选、脚本、审批 —— 永远不属于这里

选题候选（还没定的题目）、文案脚本、人工审批状态（H0–H5 那些门），
**永远只活在 Social OS 的 Google Sheet 里**，不会、也不应该进知识库。
知识库只存「已经调研验证过、可以复用的研究资料」，不存「正在走流程的
候选内容」。如果哪天在这个目录下面看到候选题目或者审批状态，那是写错
地方了，应该去查 Sheet 里的对应记录，而不是来改这里的文件。

## 一句话总结

> 能反复用的结论 → Topic；能单独打开的一个页面 → Source；
> 一次抓取/巡逻/迁移的过程记录 → Run；候选/脚本/审批 → 永远在 Sheet，不进 KB。
