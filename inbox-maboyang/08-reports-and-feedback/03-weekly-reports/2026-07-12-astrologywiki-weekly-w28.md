## 本周工作与 UV 增长的关系

本周所有工作围绕 UV 增长的三个层次展开：

**① 拉新（扩大搜索入口）**
32 篇文章的核心逻辑不是"发更多内容"，而是通过趋势选题在搜索意图爆发的窗口期提前占位。Arthur Fery 文章在赛事前 3 天发布，温网半决赛当天即收割 71 次点击、26.2% CTR，验证了"提前布局 + 趋势命中"能在短窗口内产生显著 UV 增量。这套选题节奏是目前站点获取新 UV 的主要引擎。

**② 理解规律（找到可复制的增长杠杆）**
实验一和实验二的目标是回答两个关键问题：UV 能否通过生日倒计时形成双峰？趋势流量能否在会话内转化为工具用户？两个实验本周均因数据基础设施问题（Yamal 排名丢失 + SPA 路由未修复）无法执行。这不是实验设计错误，而是暴露了一个更底层的问题：**在 GA4 数据不可信的前提下，我们无法判断现有 UV 的质量，也无法识别哪些内容策略真正有效**。SPA 路由修复因此成为下周最高优先级——不是技术债，而是增长决策的前置条件。

**③ 提质（把 UV 转化为有留存价值的用户）**
CTA 架构升级（11 模块）的出发点是：当前趋势 blog 带来的 UV 大多是一次性流量，用户读完即离开，不会进入工具体验。通过在 blog 页内嵌入 Right Sidebar 工具卡、TOC 锚点、相关文章等转化触点，目标是让 blog UV 中有一部分转化为工具用户，提升"有效 UV"的比例。这是除趋势词外**第一个可量化验证的增长方向**——CTA 上线前 blog 页转化率接近 0，上线后即有前后对比数据，成功标准为 blog UV → 工具点击转化率 ≥ 3%。同步推进的还有存量页面 CTR 优化（Messi 页面 983 曝光 / 0.6% CTR），通过改标题释放现有排名的点击潜力，2 周内可见数据反馈，不依赖新内容产出。

## 当前卡点与支持需求

**卡点一：GA4 数据失真，影响增长决策可信度**

网站采用 Next.js 单页应用架构，用户在页面间跳转时 GA4 的 `page_view` 事件未正常触发，导致大量 blog 页面显示"有用户访问但无浏览记录"。当前无法通过 GA4 追踪用户从 blog 到工具的完整路径，实验二的完整漏斗数据因此不可用。

**需要开发支持**：在路由切换时手动触发 `page_view` 事件（Next.js `router.events` 标准方案，工作量约半天）。这是 W29 增长实验数据可信的前置条件，请优先排进开发计划。

**卡点二：CTA 上线需配合 GA4 埋点**

CTA 架构需求文档已完成，但开发实现时需在每个 CTA 按钮上添加对应的 GA4 事件追踪代码（`tool_click` / `ask_ai_click` 等）。若只实现跳转逻辑而未埋点，实验二-A 的转化率数据将无法采集。已在需求文档中标注埋点规范，请开发实现时同步确认。
