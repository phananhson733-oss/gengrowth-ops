# 结果复盘表自动化系统

---

## 一、为什么需要这个系统

我们目前有一张结果复盘表，记录了 astrologywiki.com 所有已发布 blog 页面（225个）的上线状态和数据表现。

表里有几个关键字段需要定期回填：页面上线后的曝光量、点击数、关键词排名情况、页面流量。这些数据要从 Google Search Console 和 Google Analytics 手动查，再逐一填到表里。

**当前的问题是：**

225个页面，人工查一遍要花大量时间，所以实际上大部分字段都是"待回填"状态，没人看。结果就是：有些页面其实曝光很高但 CTR 很差，本来应该马上去优化 title 和描述——但我们根本不知道，因为没有人去查这个数据。等我们想起来要复盘的时候，最佳优化窗口已经过去了。

**核心矛盾：数据是有的，但没人有时间去看。**

---

## 二、我们想要什么效果

**不再需要人工查数据、人工判断该优化哪个页面。**

具体来说，我们希望：

1. **数据自动填入复盘表**：页面上线 14 天后、30 天后、60 天后，对应的曝光/点击/排名/流量数据自动写进表里，不需要人工操作。

2. **自动告诉我们该优化哪个页面、优化什么**：每次数据更新后，系统自动根据数据表现，生成一份优化任务清单，列出哪些页面需要优先处理、处理什么。

**理想的使用场景是：** 每天早上打开，看到一份清单，上面写着"这3个页面曝光高但没人点，去改 title"，"这2个页面排名接近首页，去加内链"——我们直接按清单执行，不需要再想"该看哪个页面"。

---

## 三、优化清单的判断逻辑

系统根据以下规则，决定每个页面需要做什么：

| 情况 | 说明 | 该做什么 |
|---|---|---|
| 曝光高但几乎没人点 | 说明页面被搜索引擎展示了，但标题/描述吸引力不够 | 优化 title 和 meta description |
| 排名进了前10但点击还是少 | 已经在首页位置，但没有抓住用户 | 重点优化 title 和描述，争取提升 CTR |
| 排名在 11–30 名 | 离首页很近，推一把有机会进去 | 加强内链 + 确认是否有 FAQ schema |
| 曝光量达标但没有 FAQ schema | FAQ schema 可以在搜索结果页展示问答，提升点击 | 补充 FAQ schema |
| 上线一个月了，没有任何关键词进 Top50 | 内容可能没覆盖到用户真正搜索的意图 | 检查内容结构，是否对齐搜索意图 |
| 曝光极低（< 10 次） | 冷门页面，暂时不值得投入精力 | 标记观察，60天后再看 |
| 流量来的国家不对 | 来访用户主要不是目标英语区用户 | 检查关键词设置和语言定向 |
| 已收录但零曝光 | 可能有技术问题（URL错误、被 noindex 等）| 排查技术问题，优先于其他优化 |

趋势词页面（世界杯/赛事/人名类）有额外逻辑：事件还没结束但曝光在快速下滑时，要追加内容更新；事件结束后曝光已经衰退，就不再投入。

---

## 四、输出是什么样的

每天自动生成一份 Markdown 文件，格式如下：

```
AstrologyWiki 博客优化任务清单
生成时间：2026-07-06

【技术排查】（先于优化处理）
- vozinha-birth-chart：已收录但零曝光，检查页面是否被 noindex

【P0 立即处理】
- bing-hastert-birth-chart：曝光 7,281 次，CTR 仅 0.4%，改 title + meta description + 补 FAQ schema

【P1 本周处理】
- harry-kane-birth-chart：排名第 18，加内链 + 确认 FAQ schema

【P2 下周处理】
- ...
```

同时，复盘表 CSV 里的数据字段同步自动填好。

---

## 五、边界说明

**系统做什么：** 自动拉数据、自动填表、自动生成任务清单。

**系统不做什么：** 不自动修改页面内容，不自动发布任何东西。所有优化动作仍由人工执行，系统只负责"发现问题、告诉你该做什么"。
