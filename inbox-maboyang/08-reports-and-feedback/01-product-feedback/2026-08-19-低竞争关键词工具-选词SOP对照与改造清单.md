# 低竞争关键词工具 · 选词 SOP 对照与改造清单

## 零、一句话结论

**工具现在的定位应该是「四问之前的粗筛」，不是「选词判定」。**

选词 SOP 的判定依据是 SERP 四问，工具目前覆盖了其中**半问**。但界面上没有任何地方说明这一点，用户会把它当判定用——**尤其是 AI Overview 那一列，它现在给出的是一个会误导人的确定性结论。**

下面按「现状 → 差距 → 改什么」展开。

## 二、对照选词 SOP：四问里缺三问

SOP 第一节的四问是判定的全部依据。工具字段对不上：

| SOP 四问 | 工具 | 现状 |
|---|---|---|
| 1. 前十里有没有**近两年注册的域名** | ❌ 没有 | — |
| 2. 前十里有没有**十万月访以下的站** | ⚠️ 半个 | 「最弱排名」是 0–1000 权重标度，**不是月访**，两个维度 |
| 3. 有没有 **UGC 位**（Reddit / Quora / StackExchange） | ❌ 没有 | — |
| 4. 顶部有没有 **AI 摘要** | ⚠️ 只抽样 20/136 | 见 2.1 |

SOP 里还有「四类直接否决」（品类级标配免费工具词 / 大厂工具功能名 / 意图错配 / 与 SERP 共识唱反调），**这四类全部需要看前十在做什么，工具目前一条都判不了。**

### 2.1 🔴 AI Overview 是最危险的一列

统计卡「已抽样第一页 **20**」，表格里 **136** 个词。**85% 的行没有真的去看第一页，而它们显示的是「未观测到」。**

SOP 原文：

> 2026-08-17 逐个截图确认的 8 个词，**8 个全部有 AI 摘要**。在当前 SERP 环境下，**没有 AI 摘要才是例外**。

**「未观测到」会被读成「没有」，但它实际的意思是「没测」。在当前 SERP 环境下，这两件事的结论正好相反。**

这跟 P0-4 全站审计里那条「observed nothing」是同一类问题：**工具报了一个干净的结论，掩盖了一个没被检查的区域。**

而 AI Overview 在 SOP 里是 🔴 级判据（完全回答用户问题时是否决项），报错方向恰好是最坏的那个。

## 三、字段级要求

| 字段 | 现在 | 要求 |
|---|---|---|
| **AI Overview** | 二态：未观测到 / 第一页有 | **三态：`有` / `没有` / `未检查`**。禁止把没测显示成未观测到 |
| **搜索量** | 136 里 94 个「数据源无数据」（69%） | 区分**「确实零量」和「数据源未覆盖」**。SOP 记过这个坑：`frase alternatives` 被判无量，但 Frase 是知名工具，是工具库覆盖不全 |
| **KD** | 大量为 0 | SOP：**「不要先看 KD，它会严重低估难度」**。`internal link checker` KD 10，但前七全是 DR 73–99。**降级展示，标注「不作判据」** |
| **最弱排名** | 权重 + 域名 + 位次 | 设计方向对，注解也对。**补月访、补域名注册年份**——那才是 SOP 的第一、二问 |
| **你的覆盖情况** | 两种含糊值 | 改三态，见第四节 |
| **动手前先查** | 所有行同一句话 | 现在等于没说。按行给不同动作，跟着覆盖情况三态走 |

## 四、应该读哪些页面

### 4.1 先更正两个判断

讨论过程中我先给出的两条判断是错的，记在这里避免再走一遍：

| 我先说的 | 实际 |
|---|---|
| 「覆盖情况不准的根因是只抓了 10 页」 | **不全对。**「不在你的查询样本里」来自 GSC 查询数据，与抓了几页无关；受 10 页限制的只有「有页面看着相关」那半边 |
| 「应该做全量抓取（sitemap 全部页面的 title/H1/slug）」 | **成本不可接受**，上万页的站做不了。而且**这件事根本不需要抓取** |

### 4.2 判断「站上有没有页面在打这个词」，需要的是 URL 清单，不是页面内容

```
sitemap.xml   →   1 次请求，拿到全部 URL
                        ↓
              关键词 ↔ URL slug 匹配      零抓取成本
```

一万个页面的 sitemap 也就是一个几 MB 的 XML，**一次请求**。匹配 slug 是纯字符串运算。

### 4.3 三层数据，各管各的

| 层 | 数据源 | 成本 | 回答什么 |
|---|---|---|---|
| **GSC 页面 + 查询报表** | API | 已经在读 | 哪些页面**已经在拿曝光**，打的是什么词 |
| **sitemap URL 清单** | **1 次请求** | 极低 | 站上**一共有哪些页面**（含零曝光的） |
| **抓取 10–20 页** | 现状 | 现状 | 站点主题、生成候选词 |

**三层合起来覆盖判断就完整了，成本几乎没变。**

第二层补上的是 GSC 的盲区：**GSC 只显示有曝光的页面。一个页面存在但零曝光，在 GSC 里看不见**——而这恰恰是最该被提示的情况（"你已经有这个页面了，只是它没排上"）。

### 4.4 覆盖情况改三态

| 判定 | 依据 | 用户该做什么 |
|---|---|---|
| **已有页面且在拿曝光** | GSC 页面报表命中 | 别写新的，去优化它 |
| **已有页面但零曝光** | sitemap 有匹配 slug，GSC 没有 | 别写新的，去查它为什么没排上 |
| **确实没有页面** | 两边都没有 | 可以进选题池 |

现在的「不在你的查询样本里」把后两种混在一起，**而它们的动作完全相反**——一个是修已有页面，一个才是写新的。

## 五、怎么把词导向 blog 创作

### 5.1 中间缺三步

```
工具输出 136 个词
      ↓  ❶ 人工 SERP 四问          ← 工具做不了（见第二节）
    通过的词
      ↓  ❷ 预处理关键词             ← Entity / Friction / Logic / Content_Angle
      ↓  ❸ 分配 cluster_id
   选题登记表  →  写作
```

### 5.2 工具输出能直接填进选题登记表的字段

| 登记表字段 | 来源 | 可用性 |
|---|---|---|
| `Target Keyword` | 关键词 | ✅ 直接 |
| `Associated Keywords` | **表三「词面相近的词」分组** | ✅ 直接，这个模块设计得好 |
| `月搜索量` | 搜索量 | ⚠️ 69% 缺失 |
| `KD` | KD | ⚠️ 按第三节降级使用 |
| `GSC Keywords` | 表二「你站点已经能回答的问题」 | ⚠️ 改三态后可用 |

### 5.3 工具填不了的字段

`Intent` · `Tier` · `Template` · `page_role` · `cluster_id` · `Entity` · `Friction` · `Logic` · `content_angle`

后四个是**预处理关键词流程**的产物，那是独立的一套 SOP，不在本工具范围内。

### 5.4 导出格式

现在的「导出 CSV」按工具自己的字段导，人工还要再做一次字段映射。

**建议直接导成选题登记表的列结构**，能填的填、填不了的留空——人工只需要补空格。

## 六、改造清单（按优先级）

| # | 改动 | 优先级 | 理由 |
|---|---|---|---|
| **1** | AI Overview 加 `未检查` 态，禁止把没测显示成「未观测到」 | 🔴 最高 | 唯一一条**会误导人做出错误判定**的，其余只是缺信息 |
| **2** | 读 sitemap 拿全量 URL 清单，与关键词做 slug 匹配（**1 次请求，不是全量抓取**） | 🔴 高 | 补上 GSC 的零曝光盲区，成本极低 |
| **3** | 覆盖情况改三态：已有页面在拿曝光 / 已有页面零曝光 / 确实没有 | 🔴 高 | 现在两态把动作完全相反的两种情况混在一起 |
| **4** | 「最弱排名」补月访与域名注册年份 | 🔴 高 | SOP 四问的第一、二问 |
| 5 | 增加 UGC 位检测（前十有没有 Reddit / Quora / StackExchange） | 中 | 四问的第三问 |
| 6 | 搜索量区分「零量」与「数据源未覆盖」 | 中 | 69% 的行受影响 |
| 7 | KD 标注「不作判据」 | 低 | 防止用户先看 KD |
| 8 | 导出对齐选题登记表列结构 | 低 | 省一次人工映射 |

### 6.1 界面上还要加一句话

无论上面改到第几条，**工具页要明说：本工具输出的是候选词，不是判定结果，动手前需过一遍 SERP 四问。**

SOP 1.1 里有实测记录：**用搜索工具的结果去判定，15 个词里 13 个的结论在换成真实浏览器 Google 之后被推翻。** 只要工具还不能真的逐词看第一页，这句话就不能省。
