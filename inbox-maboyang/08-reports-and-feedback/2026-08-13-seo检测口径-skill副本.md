# SEO 检测口径

**这份口径的每一条都对应一次真实的错误结论。** 出数之前逐条过，不要凭直觉。

---

## 〇、下结论前的八条强制检查

在说出任何「好 / 坏 / 涨 / 跌 / 异常」之前，全部回答一遍：

| # | 检查 | 不过的后果（真实案例） |
|---|---|---|
| 1 | **窗口是否相同？** | 近 3 个月 86.1% vs 一周 68.9%，被当成"恶化 17 个百分点"，实际是分母不同 |
| 2 | **分母里有没有垃圾？** | 全站 CTR 0.37%，但 66.7% 的展示来自排名 20 名开外——那部分本来就不可能有点击 |
| 3 | **占比的变化是分子动了还是分母动了？** | `/en/` 占比 68.9% → 60.8% 看似在收口，实际绝对展示 1,302 → 1,327 **不降反升**，只是新内容把分母做大了 |
| 4 | **平均值是不是两段混合？** | 某页平均排名 58.53，拆开是工具词 54–61 + 名人词 6.5–14.5，均值本身没有对应任何真实状态 |
| 5 | **基准是哪一年的？** | 用 AI Overview 普及前的 2% 当基准，得出"CTR 比正常低 25 倍"，实际只低 20–30% |
| 6 | **因果方向对不对？** | 用"用户看完页面觉得不需要"解释点击率低——但用户在**点击前**看不到页面内容，真实原因是排名 |
| 7 | **样本量撑得住结论吗？** | 104 次展示、排名 18 的页面 0 点击是**算术必然**（期望点击 0–1 次），不是内容问题 |
| 8 | **单站还是多站？** | 用一个 1.3K 月访、7 个月的站的数据写出"趋势词 vs 常青词"通则，换个站没复现，方向甚至相反 |
| 9 | **只看了异常值吗？** | 追问"7–10 带为什么这么差"两天，**没发现旁边那格"排前 6 时 CTR 高出基准 63%"是好消息** |
| 10 | **现状核实了吗？** | 涉及"现在的行业基准/平台规则/竞品状态"，必须联网查，不能用训练数据推导 |
| **11** | 🔴 **抽样验了几个？结论的措辞配得上这个样本量吗？** | 一天内犯两次：15 条结果只验 3 条就说"确实挖到真机会"（全验后准确率 53%）；点开 1 部剧就断定整站内容类型（11 部样本里 7 部与判断相反） |

### 第 11 条展开：抽样验证与全称结论

**这是与第 7 条不同的错误。** 第 7 条是「格子里样本太少不能算 CTR」，第 11 条是「**验了一部分，却对全体下判断**」。

**两个真实案例（2026-08-14，均由用户追问才发现）：**

| 案例 | 我验了 | 我说的 | 全量核实后 |
|---|---|---|---|
| 关键词工具的 15 条输出 | **3 条** | 「**确实挖到了真机会**」 | 8 对 / 2 错 / 5 无价值，**准确率 53%**，而且**量级最大的两条都是错的** |
| dramafinds.com 的内容类型 | **1 部剧** | 「内容品类**完全不同**」 | 11 部样本里 **7 部带 Ai 角标**，**结论方向相反** |

> **共同点：两次都是先形成了一个印象，再用少量样本确认它，然后用全称语气写出来。**

**操作规则：**

```
① 全称词是触发器
   "全部 / 都是 / 整站 / 完全 / 一律 / 确实"
   ——用到这些词之前，先问「我验了几个」

② 结论措辞必须挂上样本量
   ❌ 「工具挖到了真机会」
   ✅ 「抽验的 3 条里 2 条成立——样本太小，不能当准确率」

③ 关键判断要么验全，要么明确标注为「初判，待全量核实」

④ 优先验最可能推翻结论的那个样本
   不要只验最容易确认的那个
   （dramafinds 那次，我点开的恰好是全站三分之一的少数派）
```

⚠️ **不要在验完之前就把结论写进文档**——写下来之后，后续所有分析都会围着它转。

### 样本量阈值（经验值，不是统计学标准）

```
曝光 < 200  → 不能算 CTR
点击 < 5    → 不能做比较
```

**两者都要写进表格本身，不是写进脚注。** 曾把"1–6 带 CTR 0%"当证据写进对比表，那一格只有 36 次曝光——0 次和 1 次点击的差别就是 0% 和 2.8%，这个格子不携带任何信息。

### 单站结论的写法

单站结论必须写明**"这是 X 站的站内观察"**。想推广成通则，**至少需要第二个独立站复现**。手上有三个站（astrologywiki / aistorygenerator / gengrowth），复现成本不高。

## 〇之二、元教训：先质疑观察，再解释观察

**所有错误结论有一个共同点：先看到了一个模式，然后去解释它，而没有先问这个模式是不是真的。**

每次都是「数据显示 X → 给出机制解释 → 写进文档」，中间跳过了「X 这个观察本身可靠吗」。

> **正确顺序：观察 → 质疑观察 → 排除最简单的解释（通常是排名和样本量）→ 再找机制。**
>
> **多数 CTR 异常的答案就是排名。先排除它，再找别的原因。**

**补丁式修正不够。** 在文档末尾加「限制」章节是无效的——错误结论已经写在正文里、已经被引用了。**限制条款必须写在结论旁边。**

## 一、三个分母陷阱

### 1.1 占比会在问题没好转时下降

> **只要分母在增长，占比就会下降。**

**永远同时报告绝对值和占比。** 判据用绝对值，占比只作参考。

```
❌ 「/en/ 曝光占比从 68.9% 降到 60.8%，收口在起效」
✅ 「/en/ 占比 68.9% → 60.8%，但绝对展示 1,302 → 1,327 微涨。
    占比下降由新内容增长导致，旧 URL 未退。收口尚未起效。」
```

### 1.2 垃圾桶分母

排名 20 名开外的展示**不可能转化为点击**，把它们算进 CTR 分母，任何站看起来都很糟。

**报 CTR 时必须同时给两个数**：

```
全站 CTR（含全部展示）      ← 用来看规模
排名 ≤20 页面的 CTR         ← 用来判断表现
排名 >20 的展示占比          ← 说明前一个数被稀释了多少
```

### 1.3 废弃内容污染

计算「常青内容 CTR」得出 0.24%，后来发现其中 **72.5% 的展示来自已放弃定位的旧内容**。

**任何按内容类型的聚合，先确认这类内容是不是还在战略内。**

## 三、内链审计程序

### 3.1 必须先剥离组件级样板链接

**否则数字全是假的。**

三篇文章初查各显示 **68 条入链**，是全站第二名的 3.8 倍。拆开锚文本后：**67 条来自同一个 `Related Articles` 推荐卡组件**，真正的正文编辑内链只有 **2–4 条**。

**剥离方法：**

```bash
# 1. 按锚文本聚类，样板链接的锚文本高度一致（同一串标题+摘要重复出现）
# 2. 定位组件容器，整段剔除后再统计
#    典型标志：<section aria-labelledby="related-articles-heading">
#              <aside>、class 含 related/recommended/card
# 3. 剩下的才是编辑内链
```

**样板链接被搜索引擎大幅降权，不能按票数计。**

### 3.2 判断内链是不是瓶颈

**先找站内自然对照**：同期发布、同主题簇的文章，比较入链数与排名。

实例：`low-hanging-fruit` 68 条入链排 32.1，`zero-search-volume` 4 条入链排 23.2——**入链多 17 倍，排名反而差 9 位**。结论：内链已饱和，不是变量。

### 3.3 找可插入位置时要排除组件文本

推荐卡会把目标文章的**标题和摘要**渲染进每个页面，导致关键词匹配时**全站命中**。剥离组件后再做文本匹配，否则会得出"64 个页面都可以插内链"的假结论（真实值是 0）。

## 四、窗口与口径规则

1. **趋势监测用滚动 7 天。** 3 个月窗口会把变化稀释掉，看不出干预有没有起效
2. **一旦定了窗口，之后每次复算必须用同一个**，并在文档里写死
3. **跨窗口的数字不能放进同一张比较表**
4. **GSC 查询表只覆盖约 75% 的展示**（隐私阈值过滤），不能用它反推页面级总量
5. **GSC 数据有 2–3 天延迟**，导出日 ≠ 数据截止日，算天数时按数据截止日
6. **GA4 关键事件不追溯历史**，标记越晚损失越大
7. **量级/KD 引用必须标注数据源和日期**（Ahrefs 与 Semrush 口径差异可达 13 倍）

## 五、GSC 特定陷阱

- **AI Features 报表只有曝光，没有点击。** AI 引用带来的流量**无法量化**——测不到不等于没发生
- **新旧 URL 同时有曝光是迁移正常现象**，不要因此去改 canonical
- **`WEAKEST RANK` 不是排名位置**，是第一页最弱站点的域名权重（0–1000）
- **legacy sitemap 会触发"URL 有跳转"警告**，这是 Google 官方文档说明的正常现象，不是错误
- **站点地图重复提交是幂等的**，同一 URL 提交两次不会产生两条记录

## 七、输出格式要求

任何数据结论必须带上：

```
· 数据源与导出日期
· 窗口（起止日期 + 天数）
· 分母是什么，剔除了什么
· 样本量是否支撑结论
· 与之前的数字是否同口径（不同口径要明说"不可比"）
```

**如果某个数字支撑不了结论，直接说"这个数看不出来"，不要凑。**
