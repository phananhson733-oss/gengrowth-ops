# AstrologyWiki 搜索流量异常排查记录

## 一、事件概述

2026-07-26 上午10点左右，astrologywiki.com 的 GSC 曝光/点击/CTR/排名四项指标几乎同时归零，且**连续两天（7/26、7/27）真实流量崩溃**，经 GSC 与 GA4 两条独立数据管道交叉验证确认为真实事件，非报表展示延迟。截至2026-07-28，尚未恢复，判定为持续中、非已解决事件。

## 二、排查过程（按时间顺序）

### 已排除的原因

| 排查项 | 方法 | 结论 |
|---|---|---|
| 人工处罚 | GSC「安全和人工操作」面板 + 邮件通知 | 排除，未检测到任何问题 |
| robots.txt 配置错误 | curl 直接读取，检查 Disallow 规则 | 排除，规则正常，未阻挡任何相关页面 |
| 服务器/CDN 故障 | 用 Googlebot UA curl 首页 + 核心页面 | 排除，全部返回 HTTP 200，响应头正常（Vercel） |
| 7/25 部署变更引入的技术故障 | 直接询问确认 | 排除，7/25 当天无开发工作 |
| 页面索引状态 | GSC URL检查工具逐一查询核心页面 | 基本排除，`erling-haaland-birth-chart`/`vozinha-birth-chart` 均显示已收录；仅 `birth-chart-calculator` 一度显示"已发现-尚未编入索引"，已请求重新编入索引 |
| GitHub 生产仓库账号于7/24被封 | 团队内部确认 | 判定大概率无关——确认 Vercel 部署链路不依赖此账号，已部署版本正常对外服务；封号原因与本次流量异常之间无已知技术关联机制，需另行跟进但不影响本排查结论 |

### 确认为真实事件的证据

1. **GA4 独立会话数据**（不经过GSC管道，客户端真实记录）：
   - 7/26 全天 `google / organic` 渠道会话数：**2个**（正常水平约5-6个/天）
   - 7/27 全天总会话数：**5个**，且**前五大渠道中不含 google/organic**（正常应为最大渠道，日均5-6个）
2. **GSC「过去24小时」视图**：7/27整天（UTC-07:00 02:00-次日01:00）**点击次数24小时全部为0**，全天展示总量约19次（正常1000-3000+）
3. **无痕浏览器手动搜索**：`erling haaland birth chart`、`vozinha birth chart` 两个历史排名稳定（GSC 3个月平均排名分别为7.8、1.6）的核心词，前三页搜索结果均未出现 astrologywiki.com

### 排除"GSC报表延迟"这一最初假设的关键依据

最初怀疑是GSC「过去24小时」视图固有的数据处理延迟（此前已知问题），但以下证据推翻了这个假设：
- 延迟假设下数据应随时间推移逐步补齐，但 7/26 从348曝光到24小时后仅回补到371，几乎未变
- GA4 是完全独立于GSC的客户端追踪数据源，同样显示真实会话崩溃，两条独立管道交叉印证，不能再归因于单一数据源的报表问题

## 三、当前判定：大概率为跨站点的Google算法波动，非网站自身问题

**支持证据**：
- SE Roundtable / josephcharnin.com 等SEO行业信源报告 7/23-24 存在未经Google官方确认的排名波动（"Google好像重启了一批排名服务器"），此前 7/18-19 也有类似记录
- **MozCast 算法温度指数**：正常"平静期"基准约105-125°，本次自 7/18 前后跳升至持续高位平台，7/26读数138°，7/27读数136°，**截至最新读数仍未见明显降温**，与网站流量异常的时间窗口高度重合

**局限性（诚实标注）**：
- Google Search Status Dashboard 官方未确认任何 Crawling/Indexing 层面故障，"大盘波动"目前只有行业观察佐证，非Google官方证实
- MozCast 数值本身不能证明"astrologywiki.com 这次异常就是由它导致"，只能证明"同一时间窗口内，Google排名系统确实处于异常活跃调整状态"，是相关性证据不是因果证据
