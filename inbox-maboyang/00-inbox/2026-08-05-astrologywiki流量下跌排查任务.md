### 2.5 ✅ 但查出了一个真实问题：全站 soft 404

```bash
for p in /en/wiki/aries /en/thispagedoesnotexist99 /wiki/nonsense-xyz /completely-made-up-path; do
  printf "%-32s " "$p"
  curl -sL -o pg.html -w "HTTP %{http_code} " "https://www.astrologywiki.com$p"
  grep -oE '<title>[^<]*' pg.html | sed 's/<title>//'
done
```

```
/en/wiki/aries               HTTP 200  Aries                          ✅ 真页面
/en/thispagedoesnotexist99   HTTP 200  Free Birth Chart Calculator…   ❌
/wiki/nonsense-xyz           HTTP 200  Free Birth Chart Calculator…   ❌
/completely-made-up-path     HTTP 200  Free Birth Chart Calculator…   ❌
```

**任意不存在的路径都返回 200 + 首页外壳，站点没有真 404。** 与 P0-2 审计中查出的 gengrowth.ai「任意参数返回 200」是同一类问题。

**缓解因素**：这些 soft 404 都 canonical 到 `/`，Google 会合并，危害有限。**但仍应改为真 404**——否则任何拼错的外链、任何过期的内链，都会变成一个"页面"，且无法与真实页面区分。

**优先级：中。** 它是真实缺陷，但按上述缓解因素，不太可能是 -90% 的主因。

### 任务 6 · 修 apex → www 的跳转类型

**做什么**：`astrologywiki.com` → `www.astrologywiki.com` 当前是 **307 临时跳转**，应改为 **301 永久跳转**。

```bash
curl -sIL "https://astrologywiki.com/robots.txt" | grep -iE "^(HTTP|location)"
# HTTP/2 307
# location: https://www.astrologywiki.com/robots.txt
```

**为什么**：规范主机的永久变更应使用 301；307 不传递权重信号，Google 也不会据此合并主机。
