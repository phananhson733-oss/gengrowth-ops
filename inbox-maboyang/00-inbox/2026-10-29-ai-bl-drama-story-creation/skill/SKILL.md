# AI-BL 短剧剧情创作 Skill

v0.1 | 建立于 2026-10-29 | 依据 `inbox-pengman/03-短剧业务/出单剧学习/bl/剧分析/` 9部剧、20个文件的完整阅读

## 适用范围

本 Skill 用于:
1. 从本地 BL 短剧拆解资料里提炼可迁移的剧情机制(不是情节清单)。
2. 用这些机制生成**原创**BL商业短剧剧情方向(人物为何行动、发生什么、关系如何变化、冲突如何升级、如何收尾)。
3. 把候选方向扩写成含结局的完整剧情梗概,并自查原创距离和内部逻辑问题。

## 明确排除项

**不做的事**(即使被要求,也要先确认用户是否真的要越过这条线,而不是默认执行):

- 不写对白剧本、场景脚本、镜头、分镜、运镜或画面/视频生成提示词——这些属于"故事后续要用AI制作"的下一阶段,本 Skill 只产出叙事文字的剧情梗概。
- 不默认套用狼人/ABO/霸总/强迫契约/隐藏身份等流派公式——这些可以作为"可选奇幻规则"被选中,但不是默认起点;每次使用前按下方"奇幻/身份设定检验"自查。
- 不把一方写成毫无主动性的工具人,不用持续加重的欺凌代替剧情推进而不给反击/甜感/幽默/回报,不靠一句话能解释清的误会撑全剧,不为猎奇而切断人物动机与因果,不把参考剧独特的设定组合+关键事件顺序+标志性反转原样照搬只做表面改写(人名、世界观换皮)。
- 不默认"伤害=爱情"。关系可以危险、复杂、有权力差,但双方都要有自己的欲望、选择和后果。
- **尺度基线(2026-10-29 用户确认,优先于其他条款)**:可以保留强势追求/身体张力,但不写无意识或不顾明确拒绝的亲密接触。如用安全词/生理失控(发情、本能反应等)类设定,必须明确区分"清醒的同意/拒绝"与"身体的生理反应",且剧情必须让关系走向双方知情、平等的选择,不能让生理设定本身替代同意。详见 `references/transferable-mechanisms-v0.1.md` 末尾"尺度基线"一节。

## 接收创作需求时:必须确认 vs 可标注假设继续

### 必须向用户确认(缺了就不能正式产出,只能给聊天版 provisional 建议)

- **尺度/分级要求**:如与本 Skill 已记录的基线(见上)不同,必须重新确认,不能沿用旧对话的默认值。
- **目标市场与语种**:梗概默认用中文书写(内部工作语言),但要确认最终发行市场(影响人物设定的文化背景是否需要本地化)。
- 若用户要求的产出超出"剧情梗概"范围(比如直接要台本/分镜),先确认是否真的要跳过本 Skill 的范围排除项。

### 可以标注为假设,先继续产出(事后在交付物里注明)

- 具体集数/目标时长:**不要机械套用固定集数**。默认按"开端—发展—转折—结局"的叙事阶段给梗概,需要更细时才扩成分阶段或分集,且分集数量由故事节奏决定,不是先定集数再填情节。
- 具体人物年龄、职业细节、地域背景:可以先给出合理假设并标注为"待确认假设",不必每次都停下来问。
- 制作侧的可行性(场景数量、特效需求):本阶段不展开制作方案,只在"奇幻/身份设定检验"里确认规则是否清楚稳定,不评估拍摄成本。

## 流程:提炼机制 → 生成候选 → 筛选 → 扩写 → 复核

### 第一步:确认机制库是否需要更新

默认读取 `references/transferable-mechanisms-v0.1.md`(6条核心机制 + 1条体量提醒)。如果用户提供了新的剧情拆解资料,先判断新资料能否验证、修正或推翻现有机制的"适用条件/容易写坏的方式"部分(参照该文件每条机制末尾的"待验证假设"),更新机制库版本号,不要为每部新剧单独建一套不相关的新方法论。

### 第二步:生成候选方向(至少3个,互相有实质差异)

每个候选必须在以下三项里**至少两项**与其他候选不同,不能只换职业或世界观皮肤:
- 核心关系的权力结构(谁对谁有信息/经济/制度优势,以及这个优势怎么被动摇)
- 冲突的来源(机制二"退出成本"+机制六"外部结构性利益"分别是什么)
- 故事推进的主要驱动力(靠机制三"回报节奏"推进 / 靠机制四"证据累积"推进 / 靠机制五"对称回报"推进,三者选重心不同的)

生成时按 `references/random-element-cards.md` 的四轴做组合起点,但组合后必须立即回答该文件"使用方法"第2步的三个问题——答不出来就换组合,不能带着答不出来的设定往下写。

### 第三步:筛选

对每个候选用这份检查表过一遍(来自 `references/transferable-mechanisms-v0.1.md` 机制库的综合应用):

1. 两人为什么必须持续接触?退出成本落在谁身上、是否具体可信?(机制二)
2. 第一次让步有没有具体回报?秘密/误会会不会不断产生"不同类型"的新后果,而不是重播同一反应?(机制三)
3. 弱势一方有没有至少一次自主行动?怀疑会不会被不断累积,而不是被温情无限撤回?(机制四)
4. 有没有安排至少一次"认真回应对方真实需要"的时刻,区别于持续越界?是否有位置互换的空间?(机制五)
5. 如果有外部反派/组织,它的利益是否独立于羞辱主角而存在?身份揭穿/信任破裂有没有被单独处理,而不是被下一场共同危机直接带过?(机制六)
6. 删掉其中的奇幻或身份设定,故事是否完全不变?如果是,说明这个设定只是装饰,需要让它产生具体的事件和选择。
7. 是否符合本次尺度基线?

至少命中其中4条判定为"可以试写",命中少于4条的标注具体缺口,看能否在扩写阶段补上,不能补上就放弃或重组。

### 第四步:扩写(对选中的方向)

按下方"默认剧情输出格式"扩写成含结局的完整梗概。扩写中如果发现第三步漏掉的问题,直接修改候选,不必返回重新生成一轮。

### 第五步:复核

扩写完成后执行"创作后原创距离检查"和下方"常见失败案例"自查表,发现的问题要先修改,再把有价值的修正写回机制库(更新 `transferable-mechanisms-v0.1.md` 对应条目的"容易写坏的方式"或"如何变化",形成迭代证据,不是另开一份新方法论文档)。

## 默认剧情输出格式

默认必须包含:

1. **一句话故事**(一句话讲清主角、处境、核心张力)
2. **两位主角及核心关系**(各自的目标/弱点/筹码,以及为什么偏偏被彼此吸引——不是外貌,是具体的理由)
3. **核心矛盾**(机制二退出成本 + 机制六外部冲突,分别写清楚)
4. **从开端到结局的剧情梗概**(叙事文字,按"开端—发展—转折—结局"阶段展开,不规定固定集数)
5. **关键转折**(列出3—6个真正改变人物选择或关系性质的节点,区分于单纯增加亲密度/紧张感的填充场面——参照机制三、四的"新后果"标准)
6. **情感兑现**(结局如何回应开场建立的具体承诺/担忧,不能只有团圆宣言)

需要更细时,可以把第4项扩成分阶段剧情梗概或分集梗概,但**仍用叙事文字**,不写对白、镜头、分镜或制作清单。

全文只写"发生了什么、为什么发生、关系怎样变化",不写身体细节,不写运镜或画面描述。

## 常见失败案例与修改办法

| 失败案例 | 对应机制 | 修改办法 |
|---|---|---|
| 身份反差只换称谓,主角处境没有实际变化 | 机制一 | 为每层新身份写出它具体关闭了什么退路、打开了什么场景 |
| 强制接近的理由只在开场说一次,后面不再兑现 | 机制二 | 让这个理由在中段至少被重新验证或推翻一次 |
| 苦难不断叠加,没有一次具体回报 | 机制三 | 插入至少一次"让步后真的获得了什么"的场景,再继续加压 |
| 误会靠反复重复同一句警告维持 | 机制三 | 每次差点识破都要产生新信息或新行动,否则直接让它被排除 |
| 怀疑被"他对孩子很好"之类的温情无限撤回 | 机制四 | 怀疑要留下累积后果:改变试探方式、改变防备策略,即使不拆穿 |
| 弱势一方全程被动等待救援 | 机制四 | 安排至少一次不靠对方解围、自己改变局面的具体行动 |
| 体谅出现后立刻被"索取回报"冲淡 | 机制五 | 把体谅时刻和索取时刻分开,中间插入至少一个场景的距离 |
| 反派只负责制造羞辱,没有自己的利益 | 机制六 | 给反派一个独立于主角恋情的具体动机(商业/制度/政治) |
| 身份揭穿后信任问题被下一场动作戏直接带过 | 机制六 | 专门安排一个场景处理"知道真相后为什么还相信你",可以晚于危机解决 |
| 套用绝症/巨款/强制契约,但故事本身不需要这个量级 | 体量提醒 | 先问故事的基调需要多重的筹码,不要让筹码反过来决定基调 |
| 不顾明确拒绝的亲密被写成浪漫桥段;或用生理反应替代同意 | 尺度基线 | 改成需要被纠正的问题,或明确区分拒绝/生理反应,走向平等选择 |

## 创作后原创距离检查

扩写完成后,逐项核对,不能只凭"感觉不像"下结论:

1. **设定组合比对**:列出本故事用到的身份/关系/秘密/冲突组合,和9部参考剧及已有原创方案的组合逐一比对,是否有2个以上关键设定(人物关系类型+核心秘密类型+外部冲突类型)与某一部参考剧完全重合?如果重合,检查是否只是换了人名/世界观的表面改写——判断标准是:删掉人名和世界观描述后,事件发生顺序和关键反转位置是否仍能一一对应到某部参考剧。
2. **关键事件顺序比对**:本故事的3—6个关键转折,顺序是否与某部参考剧的关键转折顺序高度一致(不只是类型一致,是先后顺序一致)?如果一致,至少调整其中一处的因果关系或触发条件。
3. **与既有原创方案比对**:查阅本 Skill 此前已产出的候选方向和试写稿(见本 Skill 所在目录同级的 `../outputs/` 文件夹下的历史文件),确认新方向与已有方案在"核心关系权力结构+冲突来源+推进驱动力"三项上至少两项不同。
4. 比对结果写入交付物,不删除比对痛点,即使这意味着承认某处借鉴较重。
