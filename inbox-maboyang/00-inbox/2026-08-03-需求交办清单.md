## A · 工程 · 紧急修复 🆕

> 这一组是今天做改版前 SEO 基线时查出来的，都不在原计划里。

### A1 · 🔴 www 版本没有 301，正在与主域重复竞争

**现状**：

```
https://www.gengrowth.ai/   →  HTTP 200（不重定向）
https://gengrowth.ai/       →  HTTP 200
```

两个版本都返回 200，**各自被索引、各自在排名**。GSC 数据证实：

| 版本 | 点击 | 曝光 | 排名 |
|---|---:|---:|---:|
| `gengrowth.ai/` | 9 | 135 | 12.33 |
| `www.gengrowth.ai/` | 3 | 129 | 13.50 |

全站有 **16 个 www 页面**在独立产生曝光。

**注意**：www 版本的 canonical 已经指向非 www 了（`<link rel="canonical" href="https://gengrowth.ai"/>`），但 **canonical 只是建议，301 才是指令**，Google 目前没有采纳。

**要做的**：在 DNS / Vercel / Cloudflare 层配置 `www.gengrowth.ai` → `gengrowth.ai` 的 **301**（308 也可以）。

**验收**：

```bash
curl -sI https://www.gengrowth.ai/ | grep -iE "^(HTTP|location)"
# 期望：HTTP/2 301（或 308） + location: https://gengrowth.ai/
```

### A2 · 🔴 glossary 整个板块变成了软 404

**现状**：

```
/en/glossary/brand-visibility-score  →  308  →  /glossary/brand-visibility-score  →  最终落到 /blog
/glossary                            →  最终落到 /blog
```

**17 个 glossary 页面、437 次曝光，全部落到一个内容不相关的博客列表页。** 其中 `brand-visibility-score` 单页有 237 次曝光。

这是**软 404**——返回 200 但内容与 URL 承诺无关。Google 识别后会去索引这批页，437 次曝光会消失，同时给站点打上"有软 404"的质量标记。

**要做的**（先看 F1 的决策结果）：

| 如果决定 | 怎么做 |
|---|---|
| **保留 glossary** | 恢复页面内容，加进 sitemap.xml |
| **不保留** | 改成返回 **410 Gone**（或 404），**不要重定向到不相关页面** |

**当前状态是最差的一种**——既拿不到流量，又在发送负面质量信号。

**验收**：

```bash
curl -s -o /dev/null -w "%{http_code} %{url_effective}\n" -L https://gengrowth.ai/glossary/brand-visibility-score
# 保留 → 200 且 URL 不变；下线 → 410
```

## D · 工程 · 数据与埋点（推广前置条件）

> 这一组不做完，接下来所有渠道投入都无法判断效果。**优先级高于 C。**

### D1 · 核实现有埋点状态

**先查清楚是「新建」还是「补全」**：

```
GA4 → 管理 → 事件 → 看已配置了哪些事件、哪些标记为「关键事件」
再拉 90 天，看这些事件有没有数据
```

半天内应该能出结论。

### D2 · 补齐转化埋点

gengrowth 的北极星指标是**续接率**（工具 → 注册 → 主产品），有 pricing 页和「打开 GenGrowth」CTA，**所以必须有完整漏斗埋点**。

需要埋的五个事件：

```
① 工具页访问
② 输入 URL / 授权 GSC      ← 这个比例是产品健康度的核心指标
③ 出结果
④ 点击注册
⑤ 完成注册
```

**验收**：能在 GA4 里看到这五步各自的绝对数字。

### D3 · AI 归因 + 全站 UTM 规范

**背景**：ChatGPT / Perplexity 的 app 端**不传 referrer**，AI 来的流量会全部落进 GA4 的 Direct 桶。这一点已在 aistorygenerator 的服务器日志里实证。

**要做的**：

1. 加一个自定义维度，捕获原始 `document.referrer`
2. **所有对外发布的链接一律带 UTM**——包括社区回帖、社媒简介、目录提交

**验收**：能把「AI 来源」「社区来源」「真 Direct」三者分开。

## E · 工程 · aistorygenerator.work 🆕

### E1 · 🔴 拦截机器人流量

**服务器日志已确认**：`browser_impersonation` **12K 请求，100%**，全部来自 **ZSCALER, INC.** 出口，**Jul 26 从零启动，持续至今**。

**要做的**：在 Cloudflare 层拦截。

⚠️ **建议先按 UA 变体拦，不要直接按 ASN 拦**：

```
UA 变体只有两个：
  EdgiOS/150.0.4078.81
  EdgiOS/150.0.4078.58
```

**理由**：Zscaler 同时也是正常企业员工上网的代理出口，按 ASN 全拦可能误伤真实企业用户。先按 UA 拦，观察一周再决定是否扩大。

### E2 · 🔴 查生成 API 的调用日志（这条最重要）

**这是目前唯一能回答「网站真实使用量是多少」的数据源**，而且能同时回答三个问题：

| 查什么 | 能回答 |
|---|---|
| 生成调用的总次数 | **真实使用量**（现在完全没有这个数字） |
| 调用来源 IP / ASN | **爬虫有没有在触发生成、在烧我们的 LLM 费用** |
| 同一会话是否多次调用 | 产品粘性：生成一次就走 vs 反复生成 |

**特别注意第二行**——如果那 12K 请求里有任何一个触发了生成，我们**在为爬虫付 API 费用**。这是唯一有直接财务后果的问题。

### E3 · 补核心动作埋点

aistorygenerator 目前完全免费，没有付费转化，**关键事件为 0 是正常的**。

但缺「有没有真的用」的埋点：

```
· 生成了一个故事
· 生成后是否再生成第二次
· 哪个入口来的人真的用了
```
