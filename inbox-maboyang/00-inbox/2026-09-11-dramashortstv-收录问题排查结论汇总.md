# 二、核心结论：URL结构在两周内调整了两次，是当前问题的主要根因

不是单次迁移的余波拖了两周，是**两次连续的结构改动叠加**：第一次调整（8/27）引发的抓取积压和信任下降还没恢复，第二次调整（9/4）又来了，Google的抓取/索引系统始终没有一段稳定期完整处理完任何一版结构。

**这条根因能直接解释的现象**：
- "已抓取-尚未编入索引"积压3,406个页面（每次结构变动都会让旧地址积累的收录信号作废，新地址要从零开始重新积累，两周内归零重来两次，没有积累起来）
- 9/4断崖式流量崩溃（结构切换直接让前一批正在建立排名的URL失效）
- 手动提交新页面依旧不被收录（新地址目前还没有足够的信号支撑Google做出"值得收录"的判断）

**机制描述已根据官方口径修正（见第七节）**：不是"Google处理产能不够、页面在排队等待处理"，而是"URL结构变动导致收录信号归零，新地址需要重新积累相关性/权威度信号，这个过程被连续两次结构调整打断，没能积累起来"——这个说法更贴近Google官方对"已抓取-尚未编入索引"的定义（质量/相关性判断，不是队列积压）。

**这条根因不能解释、需要单独处理的独立问题**：见第四节。

# 四、独立于"迁移过频"、需要单独处理的问题

1. **sitemap大文件体积偏重**：sitemap/0.xml为例，10.3MB、4,917条URL，其中97,478个hreflang标签占了绝大部分体积（平均每条URL背约20个hreflang）。这是结构性冗余，不是迁移造成的，就算网站不再变动URL，文件现在的体积依然偏重，值得精简。

2. **畸形genre链接**：`/genre/id=49225`、`/en/genre/id=37675&tag=2` 这类URL格式和站内正常的 `/en/genre/[标签名]` 不是一套命名规则，实测目前已经是404，是某处代码生成的垃圾链接，浪费抓取配额，需要查清楚生成源头并清理。

3. **hreflang全站缺失**：drama/blog类页面没有任何hreflang标签，包括自引用。已确认不是这次收录问题的原因，但属于长期架构缺口，建议列入常规待办。

4. **2,474个页面被noindex排除**：抽查发现集中在第11、12集这类深层付费集数（超出免费额度、需跳转App观看），大概率是网站主动的内容策略（不索引没有免费内容可看的付费页），不是bug，**不需要处理**。

# 五、独立确认的真实发现（与本次问题无关，但值得记录）

- **Yandex→俄语剧真实导流链路**：直接在yandex.ru搜索验证，dramashortstv.com自己的页面（`/ru/watch/брак-сотканный-из-желания.../12`）已经排进Yandex自然搜索结果第一页，这是9/10当天17-18次Yandex referral会话、100%新用户的真实来源，不是可疑流量，俄语SEO在起效
- **保加利亚高互动页面**（`/bg/watch/джин-по-договор.../2,3,4`，单条最高413秒）核实为单个真实用户的正常连续追剧行为，不是批量导流，样本量过小（N=1），不需要继续深挖来源

# 六、当前解决方案（按轨道拆分，不是单一动作）

**轨道1（最高优先级，对应"迁移过频"这条根因）**：冻结URL结构，接下来这段时间不再做任何路由层改动，即便发现别的小问题也先不动。给Google一段连续、不被打断的时间处理完9/4这版结构。**验收指标**：观察GSC"已抓取-尚未编入索引"的数字是否开始下降。

**轨道2（可与轨道1同时进行，不涉及URL改动）**：精简sitemap文件体积——降低hreflang标签密度，或把现有20个大文件拆分成更多、更小的文件。**2026-09-11更新：这条已经在冻结决定之前落地**，实测robots.txt里的Sitemap声明已从20条扩到94条（sitemap.xml索引+sitemap/0.xml到sitemap/92.xml），抽样核实过是同一批内容重新分装（hub页面文件从4,917条URL/10.3MB拆成约20个每个200-300条/约500KB的小文件，播放页部分总量约30万条，与此前已知的302,060个播放页规模吻合），不是新增内容，风险低。**这正好是一次现成的自然实验**：接下来观察GSC"已抓取-尚未编入索引"的数字会不会因为文件变小而下降，可以直接检验"sitemap文件太重导致Google不愿抓取"这个判断是否成立。

**轨道3（低优先级，顺手清理）**：排查畸形genre链接（`/genre/id=XXX`格式）的生成源头并清理，不涉及路由结构改动。

**不在本次处理范围**：hreflang全站补全（列入常规待办）、noindex深层集数策略（已确认合理，不用动）。

# 七、对照官方说法核实的结果（2026-09-11新增）

用WebSearch/WebFetch核对了"已抓取-尚未编入索引"的官方定义，Google官方文档原页面已404，核实依据的是多家专业SEO站点（Onely、Yoast、SEOTesting等）对Google官方口径的转述，交叉印证一致，可信度较高但不是Google一手原文。

**核实结果，需要修正的地方**：
- 官方口径认为"已抓取-尚未编入索引"是**质量/相关性/网站结构判断**，不是"处理队列积压"——这一点我们之前的表述不够准确，已在第二节改正
- 官方列出的常见原因包括：内容不够有价值/独特、**内部链接薄弱或缺乏清晰的上下文信号**、网站结构差、重复内容、**页面曾经被收录过但后来被逐渐移出索引**

**针对"内部链接薄弱"这条，做了实测排查**：抽查了被卡住页面自己的"你可能喜欢"推荐区块，链接全部正确指向当前`/watch/`结构，没有发现内部链接还在指向旧`/video-play/`结构、绕重定向这种情况——**这个具体机制不成立**，站内链接本身是干净的。

**修正后的机制表述**：不是"Google处理产能不够，页面排队等待"，而是"URL结构变动导致旧地址积累的相关性信号作废，新地址需要重新积累，这个过程被两周内两次结构调整打断，没有一次积累完整"——这个说法和官方"质量/相关性判断"框架是兼容的，只是把"这次判断依据的信号为什么不足"讲清楚了，不是推翻迁移过频这条根因，是让机制描述更准确。
