# 短剧新站 · 域名候选清单（补充）

## 背景

v2架构设计文档定稿时，域名`cuedrama.com`标注的是"待注册确认"的占位状态。本轮任务：扩大搜索范围，找有没有比它更合适的，本文档是三轮排列组合搜索的最终结果。

## 候选池：7个，全部当前可注册（2026-09-14实测）

| 域名                  | 命名逻辑                       | 评估                                                             |
| ------------------- | -------------------------- | -------------------------------------------------------------- |
| **shortsbinge.com** | `shorts`词根 + `binge`（追剧行为） | 🟢 首选。语义最直接，且是2026-08-19那份原始调研里就选中的候选，一个月后复查依然可注册，说明不是抢注热点，风险低 |
| **episodrama.com**  | episode + drama 自造词        | 🟢 语义精准指向"分集短剧"，独一无二不撞现有品牌，代价是生造词需要一点认知成本                      |
| **shortsqueue.com** | `shorts` + `queue`（播放队列）   | 🟢 干净好懂，含词根                                                    |
| **shortsspree.com** | `shorts` + `spree`（一口气看剧）  | 🟢 含词根，语义站得住                                                   |
| **shortsloop.com**  | `shorts` + `loop`（循环看）     | 🟢 含词根，干净                                                      |
| dramaqueue.com      | 谐音drama queen              | 🟡 好记但不含`shorts`词根                                             |
| cuedrama.com        | 原候选，cue=开场提示               | 🟡 基准线，不含词根，与上面几个比没有明显优势                                       |

**推荐排序：shortsbinge.com > episodrama.com > shortsqueue.com / shortsspree.com / shortsloop.com（三者伯仲之间）> dramaqueue.com > cuedrama.com（原候选）**

`shortsbinge.com`排第一的理由：2026-08-19那份原始调研已经用Semrush验证过`drama shorts`这个词根在美国的搜索量（3.6K/月）和地域集中度（美英澳加占75%）明显优于`short drama`（93.6%集中在南亚东南亚）。`shortsbinge`保留了`shorts`这半词根，`binge`精准对应目标用户"追剧"这个行为，比不含词根的`cuedrama`更贴合已验证的选词逻辑。

## 搜索过程记录（供后续复用方法论）

三轮排列组合，共实测约80个域名，命中率逐轮下降：

- 第一轮（24个）：动词+drama/shorts组合，命中7个可注册
- 第二轮（30个）：更多动词组合+行业术语（micro/vertical）+拟声词，命中4个（其中2个语义不合格排除）
- 第三轮（30个）：故事/口袋框架+造词品牌名+新动词，命中4个（其中2个语义不合格排除）

**边际收益递减明显**，第三轮新增的合格候选只剩1个（shortsloop.com）。这个赛道抢注确实激烈，跟2026-08-19调研"附市场信号"一节记录的情况一致（reeldrama/dramareels/dramaflick等14个同类域名已全部被注册）。**不建议继续扩大排列组合搜索**，收益已经跟不上时间投入。

⚠️ **一个过程中发现并修正的方法论错误**：初次批量核查时，`dramastory.com`被脚本误判为"可注册"，原因是whois返回的转介链里混入了一台非权威服务器的"not found"文本，脚本判断逻辑没有优先处理链路更早出现的、明确的`Domain Name:`记录行。已改为"只要输出任意位置出现权威的`Domain Name:`行就判定为已注册"，重新核查了全部候选，只有这一条是误判，其余结论不受影响。
