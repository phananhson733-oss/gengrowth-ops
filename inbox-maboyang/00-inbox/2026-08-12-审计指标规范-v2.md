# 审计指标规范 v2

## 一、两个层级的分工

| | **站级** | **页面级** |
|---|---|---|
| 回答什么 | 这个站整体健康吗、哪类问题最严重 | 这一页有什么毛病 |
| 指标形态 | **比率**（占比、覆盖率、浪费率） | **单值**（字符数、个数、毫秒） |
| 数据来源 | 全站爬取 + GSC + 抓取统计 | 单页解析 |
| 谁有这个能力 | **只有我们** | Okara ✅ AITDK ✅ 我们 ⚠️ |
| 引擎完备度 | **21 / 27 = 78%** | 22 / 50 = 44% |

**站级用比率，因为绝对数没有可比性**——「180 个孤岛页」在 630 页的站是灾难，在 10,000 页的站是正常。

## 二、评分体系（两级同构）

### 2.1 两个数，不是一个

```
站级健康度  47 / 100        🔴 站级阻断项  1
页面健康度  71 / 100        🔴 阻断项      1
```

| 概念 | 定义 | 显示规则 |
|---|---|---|
| **阻断项** | 导致页面/整站**无法被索引或参与排名**的问题 | 红色，>0 时提到主位 |
| **健康度** | 加权通过率 0–100 | 阻断项 >0 时**灰显但保留数值** |

**为什么两个数**：实测 Okara 时发现它给出 `On-Page Score 100`，同一面板下却列着 3 个 Warning。**单一总分会掩盖问题。**

### 2.2 三条硬规则

1. **阻断项 > 0 时健康度灰显**，但保留数值（用户需要知道修完之后大概处在什么水平）
2. **不显示 100 分**，最高 99。满分只在"所有项通过且无待接入引擎"时出现
3. **每个扣分项必须可点开**：实测值 · 阈值 · 影响 · 怎么改。**分数不可解释就是噪音**

### 2.3 判定级别

🔴 **阻断**（不扣分，单独计数）· ⚠️ **警告**（计 0 分）· 💡 **提示**（计 50%）· ✅ **通过**（满分）· ○ **未接入**（排除出加权）

### 2.4 权重

**站级（组内权重）**

| 组 | 权重 |
|---|---:|
| A 索引健康 | 30% |
| C 结构健康 | 25% |
| B 抓取效率 | 20% |
| D 内容一致性 | 15% |
| E 搜索表现 | 10% |

**页面级（组内权重）**

| 组 | 权重 | | 组 | 权重 |
|---|---:|---|---|---:|
| 1 索引与可抓取 | **阻断制** | | 3 标题结构 | 10% |
| 9 搜索机会 | 25% | | 8 性能 | 8% |
| 2 TDK | 20% | | 7 结构化数据 | 4% |
| 4 内容 | 15% | | 5 图片 | 3% |
| 6 链接 | 15% | | | |

**组内得分 = Σ(通过项权重) ÷ Σ(全部项权重) × 100 ；健康度 = Σ(组得分 × 组权重)**，未接入项按剩余权重归一化。
