## 三、P0-2 的工具联动设计（H 组 · 本文档为唯一存档）

> 📌 **溯源**：`00-inbox/2026-07-31-前后端交接索引.md` 4.3 节写的是 *"**P0-4** 各类发现→其他工具的交接，需确认数据能真的传过去，不能只是链接跳转"* —— **原文主语是 P0-4，不是 P0-2**。原则通用，但 P0-2 的联动是 2026-08-05 审计新提的，此前未交接过。

### 3.1 ⚠️ 一个前置条件

在做联动之前，先把单个工具做完整。否则用户体验会变成：**每个工具给我一堆数据，然后让我去下一个工具再拿一堆数据。**

**建议顺序：先做 2·B2（点击深度分布）与 2·E2（一句话结论），再做 H 组。**

### 3.2 联动的判定标准

| | 弱联动 | 强联动 |
|---|---|---|
| 形态 | 报告末尾一排"你可能还需要"的工具卡片 | **一个工具的输出，正好是另一个的输入** |
| 用户感受 | 广告 | 顺理成章 |
| 实现 | 加几个链接 | **传数据** |

**只有 H1 / H2 值得做。**

### 3.3 ⭐ 2·H1 · P0-2 → P0-4：复用已抓 HTML，零额外等待

**依据**：交接索引「容易踩的坑」第 2 条明确写过「P0-2 与 P0-4 共用爬虫基础设施」。而实测显示 **P0-2 已经把 167 页的完整 HTML 抓下来了 —— P0-4 需要的就是同一批 HTML**。

```
现在：跑 P0-2 等十几秒 → 想看全站审计 → 跑 P0-4 再等十几秒（重抓同样的页）
应该：跑 P0-2 →「用这次已抓的 167 页做全站技术审计」→ 立即出结果
```

**这不是跳转，是「同一次抓取的两种解读」。**

> 🔗 与 2·C1 强相关：如果爬虫开始读 `canonical` 和 `robots` meta，**P0-4 的核心检测项在 P0-2 跑完时就已经算出来了**，边际成本接近零。

**验收**：从 P0-2 报告点进 P0-4，**不触发新的抓取请求**，结果立即呈现。

### 3.4 ⭐⭐ 2·H2 · P0-2 × P0-1：交集才是可行动的

**这条价值最高，因为它给出的东西两个工具单独都给不出来。**

| 工具 | 知道什么 |
|---|---|
| P0-2 | 哪些页面**内链弱、埋得深** |
| P0-1 | 哪些页面**曝光高、点击少** |

```
页面 曝光高 + 点击少 + 内链支撑弱
  → Google 已经在给它机会，但站内没给它支撑
  → 加内链是明确有回报的动作            ✅ 优先修

页面 内链少 + 根本没曝光
  → 修内链也没用，问题在别处            ❌ 不用管
```

现在 P0-2 报「51 页埋在 3 跳外」，用户无法判断哪些值得修。加上 GSC 数据就能排序。

⚠️ **门槛与机会**：P0-1 需要 GSC 授权，而 P0-2 免登录。**这条同时是从匿名到授权的转化点**——与 4·A2b 的思路一致，都服务于「20 人连接 GSC」。

### 3.5 2·H3 · P0-3 → P0-2（注意方向）

```
✅ P0-3 诊断出「某批页面曝光崩塌」→ 这批页面是不是内链出了问题？→ 带 URL 跳 P0-2
❌ P0-2 说你内链有问题 → 要不要看看流量降没降？（无因由的推荐）
```

**这条应该在 P0-3 那边实现，不在 P0-2**（即 3·T4a 的一部分）。

### 3.6 2·H4 · P0-2 → P0-5：暂不做

从"内链弱的页面"提主题词去找关键词机会 —— 链条太绕，用户不会这么想。

### 3.7 具体设计：不是「你可能还喜欢」，是「下一步该查什么」

报告末尾**不放工具卡片**，放**由本次结果触发的问题**：

```
┌──────────────────────────────────────────────────
│  你的站有 51 页埋在 3 跳以外
│  它们可能拿不到足够的内链支撑 —— 但值不值得修，
│  取决于它们在 Google 那边有没有曝光。
│
│  [ 连接 Search Console，看这 51 页的实际表现 ]  → P0-1
├──────────────────────────────────────────────────
│  抓取时我们还发现 66 个页面的 canonical 指向别处
│  这可能是分页/筛选的正常现象，也可能是配置错误。
│
│  [ 用这次已抓的 167 页做全站技术审计 ]  → P0-4 · 无需重新等待
└──────────────────────────────────────────────────
```

| # | 设计要点 | 说明 |
|---|---|---|
| 1 | ✅ | **有条件触发** | 没有深层页面就不显示第一条；没有 canonical 异常就不显示第二条 |
| 2 | ✅ | **说清为什么** | 不是"还有个工具"，是"**你这个结果引出了一个新问题**" |
| 3 | ✅ | **标明成本差异** | P0-4 那条写「无需重新等待」—— 这是真实差异，不是营销话术 |

### 3.8 2·H5 · CTA 指向主产品 —— 能力边界已确认

**已确认**：主产品**能给出内链建设建议，但不能代替用户执行**（无法自动往站上加链接）。

**这不是缺陷，是分工。** 痛点报告引用的那条 Reddit 帖标题是《How to **find** your orphan pages… without paying for Screaming Frog》——**那个"下午"花在「发现」上，不是花在「修」上。**

同一个毛病在多个工具上重复出现，建议一次性统一解决，而不是逐个修。

| 模式 | 涉及 | 说明 |
