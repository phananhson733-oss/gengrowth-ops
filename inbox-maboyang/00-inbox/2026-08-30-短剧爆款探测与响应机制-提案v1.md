# 短剧爆款探测与响应机制 · 提案 v1

## 一、先纠正一个前提：内容不是主要杠杆

上一次爆款的实际拆分：

```
《Великият и могъщ джин》7 天窗口，该剧总点击 5,427

  目录页（系统自动生成，我们没写一个字）    5,362 点击 · 31,631 曝光   98.8%
  我们写的 blog                              65 点击 ·  1,536 曝光    1.2%
```

**排到第 1.61 位的是目录页，不是我们的内容。** 所以"及时发布内容"这个提法方向偏了——真正决定能不能吃到热度的是**这部剧在不在库、页面有没有被索引**，内容是第二层。

### 目录页凭什么赢

三个条件同时成立：

| 条件 | 证据 |
|---|---|
| 剧在库里 | ID 38000，在旧 sitemap 的 ID 上限（38,105）之内——**擦边进来的** |
| URL 里有剧名 | `/bg/detail/38000/великият-и-могъщ-джин`，与查询词精确匹配 |
| 有 VideoObject schema | GSC「搜索结果呈现」维度：**视频结果 3,803 点击 · 平均排名 2.95 · 点击率 17.49%** |

**视频富媒体结果是这次的主要入口。** 这三条现在都已具备（剧名进 URL 和 sitemap 扩容是上周刚做完的），但**没有人在监控它们是否持续成立**。

> ⚠️ 一个后怕的细节：这部剧 ID 38000，而修复前的 sitemap 上限是 38,105。**如果爆的是 ID 40000 的剧，我们一次点击都拿不到**——那批剧当时根本没提交。

## 二、三层探测

### 第 0 层 · 供给与索引（最高优先级，目前无人管）

热度来了才发现剧不在库、或页面没被索引，后面全是零。**这层不做，探测和内容都无意义。**

| 监控项 | 阈值 | 动作 |
|---|---|---|
| 线上最大剧集 ID vs sitemap 最大 ID | 差值 > 500 | sitemap 重新生成 |
| 新剧从上架到被收录的天数 | > 3 天 | 查索引障碍 |
| 详情页 VideoObject schema 覆盖率 | < 100% | 补 schema |
| 剧名是否进 URL | 抽样 100 条 | 修链接生成器 |

### 第 1 层 · GSC 上升词监控（成本最低，数据已有）

**关键认知：GSC 能当早期信号，是因为剧已经在库里。** 一部剧刚有人搜，我们的目录页就会拿到曝光——哪怕排在第 40 位。这批"低位次、零点击、曝光在涨"的词就是热度前兆。

| 信号 | 判据 |
|---|---|
| **新词族出现** | 上一窗口曝光 = 0，本窗口 ≥ 50 |
| **拼写变体扩散** | 同一剧名的不同拼写数 ≥ 8 且在增长 |
| **曝光速度** | 单个词族日曝光环比 ≥ 3 倍 |

**拼写变体是本次观察到的最强特征**：

```
великият / великия / могъщ / могъщият / всемогъщ …      34 种写法
илайджа баран / барън / бейран / элайджа баран …        18 种写法
i'd / id / i d / i would / i rather / marry a beast …   70 种写法
```

人听说了剧名但不确定怎么拼——这是口碑正在扩散、还没沉淀成标准写法的阶段。变体越杂、越新，说明离峰值越近但还没到。

> 这条信号目前只有 3 个样本（保语 / 俄语 / 英语各一），**是观察不是规律**。需要再积累几次爆款验证。

### 第 2 层 · 站外上游（尚未验证可得性）

GSC 再快也要等 Google 先给曝光。真正的上游在站外：

| 信号源 | 逻辑 | 状态 |
|---|---|---|
| 各短剧 App 的应用内热榜 | 剧先在 App 里火，用户再去搜免费观看 | **需验证是否可抓** |
| TikTok / YouTube 短剧切片 | 切片病毒传播 → 搜全片，这是需求的真实起点 | **需验证** |
| 竞品站新增页面 | 竞品突然为某剧建页 = 他们探到了 | 可做，成本低 |
| 本地化切片账号 | 见下节溯源结果 | ✅ **已确认存在** |

### 传播机制：本地化切片账号

TikTok 站内搜保语剧名，找到在发这部剧切片的账号：

| 账号 | 语言 | 时间 | 赞 | 归属 |
|---|---|---|---|---|
| @plbtv | 俄语配音预告 | 7-07 | — | 外部 |
| Shorts films | 英语切片 | 7-31 | 3,152 | 外部 |
| **DailyShirley** | **保语切片** | **8-28** | **1,254** | 🔴 **我方同事账号** |
| **DailyShirley** | 保语切片 | 8-29 | 217 | 🔴 **我方** |
| DramaDetour | 保语切片 | 8-28 | 12 | ❓ 待确认归属 |

封面是 **AI 生成图**（TikTok 标了「Ai」角标），压着本地化剧名的大字。用户刷到切片 → 搜本地化剧名 → 落到排得上的站。

**这解释了拼写变体为什么那么多**：观众是从封面图上「看」到剧名的，不同账号的译法还不一致，所以搜的时候各拼各的。

### 🔴 关键修正一：这些不是外部信号，是我们自己的账号

DailyShirley / DramaDetour / dramaexpedition / shirley5278789 **都是我方运营账号**。我搜到的四条保语切片里，**三条是我们自己发的**，只有「Shorts films」那条英文的是外部。

所以它们**不是可监控的外部预警信号**，而是我方已有的分发渠道。

### 🔴 关键修正二：这些账号的落地页是 ReelShort，不是我们的站

实测账号资料：

| 显示名 | handle | 粉丝 | 赞 | 简介链接 |
|---|---|---:|---:|---|
| DailyShirley | `@shirley5278789` | 1,454 | 2,664 | `reelslink.com/cps/c4rqjM` |
| Drama Expedition | `@dramaexpedition` | 1,161 | 140 | `reelslink.com/cps/WEiaTt` |

跟踪链接的跳转链：

```
reelslink.com/cps/c4rqjM
  → realshortapp.onelink.me/Zof7?…&pid=cps&distribute_uid=15216
  → apps.apple.com/US/app/id1636235979        ← ReelShort App Store 页
```

**两个账号的简介链接都指向 ReelShort 的应用商店页，走 CPS 联盟分成；没有任何一个指向 dramashortstv.com。** 每个账号有独立的跟踪码（`c4rqjM` / `WEiaTt`），说明分成是按账号结算的。

> 注：`@dailyshirley` 与 `@dramadetour` 这两个 handle 分别是 0 粉丝的空号和不存在，**显示名不等于 handle**，做监控时要按 handle 记录。

### 这意味着现在有两条互不相通的业务线

```
线 A · TikTok 切片账号  →  ReelShort CPS 联盟分成    （靠给竞品导量赚钱）
线 B · dramashortstv    →  自然搜索流量              （GA4 总收入 0）
```

**两条线在争同一批需求，但没有连起来。** 切片制造了对剧名的搜索需求，这批需求落到谁手里取决于谁排得上——有时候恰好是我们，但那是自然发生的，不是设计的。

数据侧的佐证：GA4 `Organic Social` 新用户仅 **6 人**——切片确实没往站上导流，与"简介里没有站点链接"完全一致。

**时间上也对不上**：我方切片发于 8-28，而流量 8-26 就起来了——**这波不是我们自己的切片推起来的。**

### ⚠️ 仍不能过度解读

1. **无法证明 TikTok 导致了这波流量。** 我方切片晚于起量，外部切片（7-31 英语、7-07 俄语）虽早，但**跨语言的因果链是推测**。
2. GSC 8/26 才有数据，**峰值之前的真实需求曲线我们看不到**，"8/28 是峰值"这个说法本身就不可靠。
3. DramaDetour 归属未确认。

### 🔴 附带发现：ReelShort 已经在跑我们想发明的这套打法

ReelShort 站上有一个 `/fandom/` 内容板块，为这部剧发的文章包括：

```
Elijah Baran Genie Full Story Explained: Here's Everything You Might've Missed
Catch Elijah Baran and Christine Parrish in Djinn Under Contract Movie
What To Know About Eli Baran is A Genie in A Magic Lamp Full Movie
The Great and Powerful Genie Dailymotion: When Three Wishes Lead to a Marriage…
```

**这正是我们第三节排出来的优先级 2–4：演员页、剧情解释页、"full movie" 修饰词长尾。版权方自己在做，而且连 "Dailymotion" 这种盗版关联词都在接。**

含义有两层：

- **信号源**：ReelShort 为某剧发 fandom 文章 = 他们在推这部剧。这是比 GSC 更早的信号，且可监控
- **竞争**：我们的《Elijah Baran Genie Explained》直接对上他们的《Elijah Baran Genie Full Story Explained》。我们排 7.9 位

> 技术备注：ReelShort 站有 AWS WAF 拦截，curl 抓不到，需要真实浏览器。做监控要按这个成本估。

## 三、响应打法：按边际价值排序

目录页已经吃掉 98.8%，所以内容要打**目录页吃不到的词**。

| 优先级 | 做什么 | 依据 |
|---|---|---|
| **1** | 确认该剧目录页已收录、URL 带剧名、有 video schema | 这是 98.8% 的来源 |
| **2** | **演员/角色页** | Elijah Baran 词族 467 点击；该 blog 上线首日 47 点击、**点击率 8.1% 全站最高** |
| **3** | 修饰词长尾（"цял филм" / "бг аудио" / "full movie" / "full episode"）| 这批词目录页匹配得弱 |
| **4** | 剧情/结局解释页 | 待验证，本次无样本 |
| 5 | 剧集聚合 blog | **本次只带来 1.2%，不应作为首要动作** |

**这个排序推翻了本周的做法**——我们先写了剧集 blog（1.2%），演员页反而晚了几天，而演员页效率最高。

## 四、速度要求

7 天窗口的日线：

```
8/26    196 点击 ·  1,806 曝光
8/27  1,956 点击 ·  5,747 曝光     ← 一天涨 10 倍
8/28  2,872 点击 ·  8,654 曝光
```

⚠️ **这个爬升不能直接读成"需求在涨"。** GSC 是 8/26 前后才建站出数，前两天的低值可能是数据覆盖没铺开，而不是热度低。**三种解释混在一起：需求增长 / 索引改善 / GSC 覆盖启动，本次数据分不开。**

但即使打折看，**量级变化发生在一两天内，不是一两周**。含义很直接：

> **周更节奏接不住爆款。响应必须是当天或次日。**

这与我们刚定稿的 blog SOP 有冲突——那套流程（写前搜证四字段 + 18 项 QA + 双区输出）是为质量设计的，跑一篇要数小时。**爆款响应需要一条独立的快车道**：模板化、字段少、只做必要核实。

**建议**：把「演员/角色页」做成快车道的第一个模板——它优先级第 2、结构最固定（Quick Facts 表 + 剧目列表 + 观看入口）、最容易模板化。

## 六、真正的问题不是探测，是两条业务线没打通

初版提案的框架是「**探测** → 响应」，假设热度由外部产生、我们去捕捉。查完之后这个框架不成立了——**我们自己就在制造热度，只是收益给了 ReelShort。**

```
探测式（初版设想）   外部产生热度 → 我们发现 → 出内容 → 接住搜索
现状（实际在跑）     我方切片 → 观众去搜剧名 → 落到排得上的站 → 同时我方 bio 导流去 ReelShort 拿 CPS
制造式（可选方向）   先备好内容和目录页 → 我方切片投放 → 观众去搜 → 落到自己站
```

**现状的问题是顺序和收益都没设计**：切片先发，内容后补（本次切片 8/28、blog 8/29），而搜索需求落到谁手里全看运气。

### 需要你先定的一件事：两条线要不要并线

这不是我能判断的，取决于收益结构：

| 选项 | 含义 | 我缺的信息 |
|---|---|---|
| **保持分离** | 切片继续赚 CPS，站继续做 SEO，互不干扰 | CPS 月收入是多少 |
| **并线** | 切片 bio 换成站点链接，或加二级入口，把量导回自己站 | 站点当前变现方式与单位价值（GA4 总收入为 0）|
| **半并线** | bio 保留 CPS，但视频文案/评论区引导搜索剧名，让我们的页面接住 | 需先验证切片能否真的带动搜索 |

**在知道 CPS 收入之前，我不建议动 bio 链接**——那是现成的收入，站点这边目前 GA4 记录的收入是 0。

### 无论选哪条，先做这三件

| 序 | 事项 | 为什么 |
|---|---|---|
| 1 | **切片选剧与内容排期打通** | 现在切片投哪部剧，SEO 侧不知道；SEO 写哪部，切片侧也不知道。这是最低成本的改进，不涉及收益结构 |
| 2 | **设计切片 → 搜索的验证方法** | 这条路径会被记成 Organic Search，报表里看不见。可用的办法：投一部我们独占的冷门剧，看 GSC 上该剧名词族有没有起量 |
| 3 | **按 handle 而非显示名建账号台账** | `@dailyshirley` 是 0 粉丝空号、`@dramadetour` 不存在，显示名会误导 |

### 仍需你回答

| 问题 | 为什么要紧 |
|---|---|
| 切片选剧是谁定的、按什么标准 | **若已有选剧逻辑，它本身可能就是最好的爆款预测器**，比我从 GSC 倒推信号直接得多 |
| 四个账号的产能上限（条/周） | 决定能覆盖多少部剧 |
| CPS 月收入量级 | 决定并线值不值得 |
| 除这四个外还有没有别的账号 | 归属不清会把自己的动作当成外部信号（本次已发生一次）|
