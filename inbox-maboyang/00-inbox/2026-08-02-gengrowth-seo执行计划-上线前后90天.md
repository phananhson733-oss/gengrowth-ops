# SEO 执行计划：上线前后 90 天

## 零、先对齐一个预期（最重要，请先读这段）

**六个工具页在上线后三个月内不会带来有意义的自然流量。**

这不是判断，是SERP实测的结果：

| 工具主词 | 指标 | SERP实况 | 能不能打 |
|---|---|---|---|
| high impressions low clicks | 70/KD0 | DR 1 的站排第4 | ✅ 唯一真能打，但只有70量 |
| sudden drop in organic traffic | 200/KD2 | 第3名是2024年底注册的新域名 | ⚠️ 有缝 |
| find low competition keywords | 800/KD26 | 前五中三个UGC位 | ⚠️ 有缝 |
| generative engine optimization tools | 1,300/KD14 | 全listicle，产品页进不去 | ❌ 需另写横评 |
| internal link audit | 700/KD5 | **前八全DR 76-99** | ❌ KD5是假象 |
| seo audit（P0-4） | 品类KD 76-94 | 大厂锁死 | ❌ 已确认不承担获客 |

**六个词加起来，理论天花板约3,070月搜；实际能拿到的近期只有 high impressions low clicks 那70。**

执行计划v1早就写过"入口型工具完全依赖内容矩阵导流"，这轮把它量化坐实了。**现在就把这个预期同步给团队**，好过三个月后有人问"SEO怎么没效果"。

**推论**：短期看内容和社区，中期看DR，工具页排名是长期结果不是近期目标。下面的计划按这个逻辑排。

## 一、立刻做（本周，不依赖工程）

### 1.1 建立改版前基线 ⚡最急

**问题**：我们不知道 gengrowth.ai 现在的真实状态，却正要改掉整个站。改完之后无法判断是变好还是变坏。

**做什么**（半天内可完成）：

| 项 | 记录内容 | 来源 |
|---|---|---|
| 索引页数 | 当前被Google收录多少页 | GSC 覆盖率报告 |
| 现有排名词 | 有任何排名的词、位置、曝光、点击 | GSC 效果报告，导出全量 |
| 当前流量 | 近28天 & 近90天自然流量 | GSC |
| 现有外链 | RD数、DR、哪些页面被链 | Ahrefs |
| 现有页面清单 | 全站URL列表，标注保留/下线/改版 | 爬取或sitemap |

**存档到** `08-reports-and-feedback/`，命名含日期。改版上线后按同一口径复测。

**为什么最急**：改版一旦开始，旧数据就取不回来了。

### 1.2 清理旧定位内容

**问题**：blog 上还有 Growth Automation、Attribution、Experiment-Driven、Customer Stories 这批旧定位内容。DR=0阶段，**域名话题聚焦是我们少数几个能完全控制的变量**。一个同时讲增长自动化、归因模型、SEO工具的站，Google判断不出主题——这会直接抬高六个工具页的排名难度。

**做什么**：逐篇过一遍，分三类处理

| 类别 | 处理 | 判断标准 |
|---|---|---|
| 与六个工具相关 | 保留，按新分组重新归类 | 讲内链/审计/流量诊断/关键词的 |
| 无关但有流量 | noindex，保留页面 | 有排名或有外链的 |
| 无关且无流量 | 下线，301到相关页或首页 | 两者都没有的 |

**周报/实验报告类**（Week 1 Experiment Report 之类）一律移出 blog——对冷访客无价值、无搜索价值，另开 `/changelog` 或内部空间。

**成本极低，收益直接**，不需要工程也不需要设计。

### 1.3 社区从今天开始

**为什么现在就开始，不等上线**：

- P0-3 的痛点在 Reddit **每周都有新帖**（补验证时一个月内7条以上）
- P0-1 的痛点在搜索框里几乎不存在（70量），但在社区里持续七年
- **这是DR=0阶段唯一从第一天就有效、且完全不依赖工程进度的渠道**

**做什么**：r/SEO、r/bigseo、r/TechSEO、r/juststart 常驻，回答具体问题、给实际诊断。**真实参与，不是发广告**——团队已有 `2026-07-02-astrologywiki-reddit内容执行SOP.md`，复用那套规范。

**副产品**：这也是最好的用户研究——我们四批候选词里表现最好的那批，就是从社区语言里挖的。

## 二、内容启动前必做（本周内）

### 2.1 先SERP验证，再写文章

**教训**：八个主词验了四个被推翻（`hidden keywords seo` 语义是黑帽、`internal link audit` KD5实为DR76-99、`all in one seo` KD9实为DR75+霸屏、`seo content strategy` 被Google/HubSpot通吃）。

**而计划中的7篇文章，一个词都没验过。**

**✅ 2026-08-03 已完成。7 个词全部实搜，3 可写 / 1 可选 / 3 否决。完整记录见 `02-keyword-research/2026-08-03-内容选题词-serp实测结论.md`。**

| 待验证选题词 | 指标 | SERP 实况 | 结论 |
|---|---|---|---|
| **how to find low hanging fruit keywords** | 700/KD0/Parent＝自身 | 前七有 DR55、DR50、**DR42** 三个中小站 | ✅✅ **可写** |
| **zero search volume keywords** | 150/KD2/Parent＝自身 | forecast.ing 月访 **593**、域名 2024-10 排第 6；无 DR90 大厂 | ✅✅ **可写** |
| **pagerank sculpting** | 1,500/KD12/Parent＝自身 | clickrank.ai 域名 **2024-08** 排第 4；epicnewmedia 月访 1.6K 排第 9 | ✅ **可写（首篇）** |
| how to fix orphan pages | 200/KD16 | 2 个 UGC 位 + 1 小站，但工具商多、Video/Discussion 挤压 | ⚠️ 可写，排后面 |
| ~~how to fix keyword cannibalization~~ | 600/KD11 | **Semrush + Yoast 锁死前二**，仅 1 个 UGC 位 | ❌ **否决** |
| ~~site architecture seo~~ | 600/KD37 | **前六全是大站/工具商** | ❌ **否决** |
| ~~content gap analysis~~ | 1,000/KD35 | **Semrush + Backlinko + Ahrefs 霸屏** | ❌ **否决** |

**验证方法**（每词5分钟）：Google搜该词，看前十的DR分布，**关键是有没有低权重站挤进去**。有DR<40的站在前十 → 可写；前十全DR70+ → 换词。

**写一篇文章的成本远高于查一次SERP。**

### ⭐ 预判规律（08-03 发现，08-04 实测修正）

**教学型查询里**，主词若是大厂工具的功能名就被锁死——被否决的三个词全是（Content Gap 是 Ahrefs/Semrush 的功能、keyword cannibalization 是 Semrush 检测项兼 Yoast 卖点、site architecture 是技术 SEO 工具模块）。

**但 08-04 实测发现：被否决的词换个查询形态，有一半能救回来。**

| 主题 | 教学型 | 工具型 | 结果 |
|---|---|---|---|
| keyword cannibalization | ❌ Semrush + Yoast 锁死 | ✅✅ **域名 2025-06 的站排第 2，Semrush 掉第 6** | **救回** |
| content gap | ❌ 三大厂霸屏 | ✅✅ 前七有 4 个中小站 | **救回** |
| internal link | ❌ 前八 DR76-99 | ❌ 前七 DR73-99 | 救不回 |
| seo audit | ❌ 品类 KD76-94 | ❌ 前九 DR73-92 | 救不回 |

**真正的分界线不是「是不是功能名」，而是：**

> **这个功能有多少家在免费提供。**
> - **标配免费工具**（站点审计、内链检查、速度测试）→ 几十家 DR70+ 拿它当获客入口 → 换形态也救不回
> - **专门功能**（关键词自噬检测、内容缺口对比，需接 GSC 或做竞品对比）→ 做的人少 → 工具型查询有缝

**用法**：教学型被锁的词，**先别扔**——判断它是标配还是专门功能，专门功能就改验「工具型 / 替代型」查询。

完整实测见 `02-keyword-research/2026-08-04-工具型与替代型serp实测.md`。

### 2.2 重选两个集群页主词

**✅ 2026-08-03 已尝试重选，两个新候选也被否决。建议改变策略。**

| 候选 | SERP 实况 | 结论 |
|---|---|---|
| ~~seo content strategy~~ (3,500/KD12) | 被 Google / HubSpot / Semrush 通吃 | ❌ 原候选，已否 |
| ~~internal link analysis~~ (800/KD28) | 前七全是工具商 | ❌ 原候选，已否 |
| ~~internal linking best practices~~ | **前六全是 DR81–100**（Yoast/Semrush/Moz/Google官方/Siteimprove） | ❌ **比原候选还难** |
| ~~long tail keyword research~~ | **前八里五个是关键词工具商**，Semrush 第1、Ahrefs 第7 | ❌ 工具商霸屏 |

**四个候选连续失败，这不是运气问题，是结构性约束**：集群页的价值在于用一个"更宽的词"聚合文章，而**越宽的词越可能落在大厂的主场**（见 2.1 末尾的规律）。

### ⭐ 08-04 更新：「替代型」词可能是集群页的解

`semrush alternatives`（3,600/KD12）和 `ahrefs alternative`（600/KD10）SERP 实测**都可打**：

- `ahrefs alternative`：**Reddit 排第 1**，behindrankings、cotera.co、OneLittleWeb 三个中小站在前九
- `semrush alternatives`：Reddit + Quora 两个 UGC 位，OneLittleWeb 第 3，**一篇 Medium 文章排第 5**

**大厂在这类词上不占优是结构性的**——产品页做不了横评，也不会写"替代我们的产品"。前四里 SE Ranking 和 SpyFu 都是竞品工具商，**他们正是靠这个位置抢 Semrush 的用户**。

| 集群页要求 | `semrush alternatives` |
|---|---|
| 量级够大 | ✅ 3,600（比六个工具主词可打部分加起来还大） |
| SERP 可进 | ✅ Reddit 第 1、Medium 第 5、多个中小站 |
| 能聚合下游内容 | ✅ **天然可以链向每一个工具页** |
| 与工具页主词不自噬 | ✅ 完全不重叠 |

⚠️ **前提**：必须是**诚实横评**——如实写自己的局限，甚至指出竞品哪里更好。产品评审已判定三个工具都停在观测未走到判断，**这个状态下写"我们比 Semrush 好"拿到 Reddit 会被撕**。

**待办**：查这两个词的 Parent Keyword（SERP 已过，缺 Ahrefs 判定）。

### 在替代型方案确认前，仍按下面执行

**集群页暂缓，先用可打的单篇文章形成「事实集群」。**

1. 先写三篇已验证可打的文章（pagerank sculpting / low hanging fruit / zero search volume）
2. 三篇之间做内链，形成事实上的主题聚合，**不设 Pillar 页、不占 `/guides/` 的 slug**
3. **等 DR 上升后再回来建集群页**——那时现在打不动的宽词会陆续变得可打

主纲领 5.4 的集群页结构规范不受影响，前端可先按结构开发，slug 留空。

> 这与第六节"不同时铺六个话题簇，DR=0 阶段打透一个的收益远大于铺六个"一致。

**筛选顺序**（已按 08-03 / 08-04 两轮实测更新）：

```
0. 意图对不对？              ← 有的词不是打不过，是根本不该打
1. 这个功能有多少家在免费提供？
     标配免费工具 → 直接换词
     专门功能    → 继续往下
2. 查询形态能不能换？
     教学型被锁 → 试工具型 / 替代型
3. Parent ＝ 自身（Google 认它是独立主题）
4. SERP 前十有低权重站      ← 这一步不能省
5. KD < 30
6. 量级
```

注意顺序——**KD和量级放最后**。

**并行判断**：

```
· 自然排名打不动的词，看一眼 AI Overview 里有没有小站
  有 → 该词进 GEO prompt 组，走 AI 引用而非自然排名
```

## 三、需要产品决策的一件事

### 3.1 免费工具：转化资产 还是 外链资产？

**这个决定要在开发定型前做，影响功能设计。**

**背景**：Ahrefs 和 Semrush 的域名权重，相当一部分是靠免费工具被自然引用积累的。对 DR=0 的站来说，**外链是比转化更稀缺的资源**——没有DR，选什么词都排不上；有了DR，之前打不动的词会陆续变得可打。

**两条路的差异**：

| | 转化资产（当前设计） | 外链资产 |
|---|---|---|
| 成功指标 | 续接率（工具→注册→主产品） | 被多少外部站点自然引用 |
| 功能重点 | 结果导向注册和下一步 | 结果**值得被引用**：可分享链接、可嵌入、有独特数据 |
| 免费层 | 够用即可，留付费空间 | 尽可能慷慨，因为引用价值来自"真的好用" |
| 登录墙 | 保存结果时出现 | 尽量不出现 |

**不必二选一，但要定主次**，因为它影响三件具体的事：
- 扫描结果要不要生成**公开可分享的URL**（外链资产必须有，转化资产不一定）
- 免费层额度定多少（也就是工程那三个阻塞项的答案）
- 工具的成功指标怎么定（影响后续所有优化方向）

**我的建议**：DR=0阶段偏外链资产。北极星指标（续接率）不变，但**加一条"自然引用数"作为并列指标**。理由是转化的天花板受流量限制，而现在流量的瓶颈是DR。

## 四、上线时的SEO清单

工程实现时一并做掉，事后补成本高：

- [ ] **Organization schema**（主页）——GEO策略的基础设施，AI答案引擎靠它确认"GenGrowth是什么"
- [ ] **实体定义句**放进主页正文（不是只放schema）——AI引擎主要读正文
- [ ] 六个工具页的 SoftwareApplication / FAQPage / HowTo / BreadcrumbList
- [ ] sitemap.xml 提交 GSC + Bing（团队已有 IndexNow 接入需求文档可复用）
- [ ] 旧URL的 301 映射表（改版必然产生URL变更）
- [ ] robots.txt 检查——**别把爬取型工具的结果页放出去被索引**
- [ ] 工具结果页 noindex（除非走外链资产路线，那要反过来）
- [ ] 内链矩阵：主纲领第六章三层结构，尤其 blog→工具 这条
