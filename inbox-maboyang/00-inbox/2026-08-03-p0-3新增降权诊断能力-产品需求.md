# P0-3 新增「站点级降权」诊断能力

## 一、为什么要加这个

### 1.1 用户的第一个问题，工具现在完全没回答

用户打开 P0-3 时，心里排队的五个问题，第一个是：

> **"我是不是被惩罚了？"**

**工具目前一个字都没提。**

这不是锦上添花的功能——**这是流量下降场景里用户的第一诉求**。他不是想知道下降了多少（那个他自己看 GSC 也知道），他想知道**这事严不严重、是不是我做错了什么**。

而且很多人是在**凌晨两点**打开这类工具的。

### 1.2 本功能的范围：只回答「是不是惩罚」这一个问题

**先划清边界：排名下降的成因很多，惩罚只是其中一类，而且往往不是最常见的那一类。**

常见成因至少包括：

- **竞争加剧** —— 高 DR 的站点开始做同一批词，把你挤下去
- **内容时效性到期** —— 有时效的内容过了窗口期，那部分流量池自然消失
- **季节性**
- **搜索意图变化** —— Google 对同一个词的意图判定变了，你的页面类型不再匹配
- **SERP 形态变化** —— AI Overviews / 精选摘要吃掉点击，排名没变但点击掉了
- **技术故障** —— 服务器、robots、误加 noindex、去索引
- **人工处罚 / 算法层面的站点级下调** ← **本功能只管这一类**

我们自己的 astrologywiki 案例就是典型的反例：7 月下旬三周流量从 301 掉到 20，最后查实原因是**两个时效内容池同期到期**，跟惩罚毫无关系。

**本功能不负责穷举所有下降成因，它只回答一个问题：这次下降背后，有没有 Google 的人工处罚或算法层面的站点级下调。**

### 1.3 为什么这一类值得单独回答

因为它是**唯一一类恢复路径完全不同**的成因，而且内部还要再分两种：

| | 手工操作惩罚 | 算法层面的站点级下调 |
|---|---|---|
| 有无通知 | GSC「安全和人工处置」有红色警报 | 无任何通知 |
| 触发方 | Google 人工审核团队 | 算法自动评估 |
| 恢复方式 | 整改 → **提交重新审核** | 整改 → **等下一次核心更新** |
| 恢复周期 | 几天 ~ 几周 | 几周 ~ 几个月 |

**最坏的情况是**：一个人误以为自己属于算法层面的下调，于是安静地等下一次核心更新——**而实际上他有一个手工处罚挂着，不提交重新审核永远不会恢复。**

**P0-3 现在让用户完全无法区分这两种情况，也无法区分"是不是惩罚"。**

### 1.4 ⚠️「不是惩罚」是同等重要的输出

**大多数下降不是惩罚。**

工具明确告诉用户"**这些信号不支持惩罚的判断**"，和告诉他"是惩罚"**同样有价值**——因为它把用户从一条错误的恢复路径上拉回来。

一个误以为自己被惩罚的人，会去大规模删内容、清外链、提交 disavow。**而如果真实原因是竞争加剧或内容过期，这些动作全部白做，甚至有害**——删掉的可能是本来没问题的内容。

> **这就是第二节「交叉验证需满足 ≥3 条」原则存在的原因：宁可漏报，不可误报。**
>
> 误报一次惩罚的代价，远大于漏报一次。

### 1.5 一个已知的机制前提

Helpful Content System 已于 2024 年 3 月并入 Google 核心排名系统，站点级内容质量信号直接参与排名计算。这意味着**排名下降未必是页面级问题，可能是站点级信号**——而站点级和页面级的修法完全不同。

这是本次新增检测要覆盖的判别维度。

## 二、站点级信号的诊断项 × P0-3 能不能做

判断是否存在站点级排名下调，业界公认有五个交叉验证信号。逐个评估 P0-3 用 GSC OAuth 能不能算：

| # | 诊断信号 | GSC API 能算吗 | 优先级 | 说明 |
|---|---|---|---|---|
| **1** | 核心页面集体跌出前 50 | ✅ **完全可算** | **P0** | Search Analytics，page 维度，比对变点前后 |
| **2** | 非品牌词大幅下跌、品牌词基本不变 | ✅ **完全可算** | **P0** | query 维度分组对比。**判别力最高** |
| **3** | 新增内容不收录 / 收录后掉出索引 | ⚠️ 抽样可算 | P2 | URL Inspection API，有配额限制（约 2000/天） |
| **4** | 大量低质页面被索引 | ❌ **GSC 查不了** | P2 | 需 SERP 层面操作。**但 P0-4 的爬虫能算替代指标** |
| **5** | 下降日期与 Google 核心更新日期吻合 | ✅ **完全可算** | **P0** | 变点日期已有，只需一张更新日期表。**成本最低** |
| **+** | **人工处罚状态** | ❌ **无公开 API** | **P0** | 见第三节 —— 这条需要特殊设计 |

**三条 P0 可以直接做，其中第 5 条成本极低。**

⚠️ **交叉验证原则**：这些信号**必须至少同时满足 3 条**才能指向站点级下调。单条信号不足以支撑结论——这一点必须体现在输出逻辑里，不能触发一条就下判断。

## 三、⚠️ 关键设计：人工处罚这一项没有 API，但恰恰因此有更好的解法

### 3.1 先说清楚技术边界

Google Search Console 的公开 API 只有：

```
webmasters v3     → sites / sitemaps / searchanalytics
searchconsole v1  → urlInspection.index.inspect
```

**没有 Manual Actions 端点。Google 从未把人工处罚状态开放给 API。**

> 🔧 **实现前请工程复核这一点**，这是整个设计的支点。如果确认无 API，按下面的方案做。

### 3.2 所以设计成「一次用户输入」，而不是「一条查不了」

**这比有 API 还好。** 理由：这是一个**用户 10 秒就能自己查到**的信息，而它能让整个诊断分叉。

**建议的交互**（放在诊断结果最顶部，早于所有其他内容）：

```
┌────────────────────────────────────────────────────┐
│  先确认一件事 —— 这决定了下面所有建议的方向          │
│                                                    │
│  我们读不到你的人工处罚状态（Google 没有开放这个     │
│  接口）。但你 10 秒就能看到：                        │
│                                                    │
│  打开 Search Console → 左侧「安全和人工处置」        │
│  → 「人工处置」                                     │
│                                                    │
│     [ 有红色警告 ]      [ 显示"未检测到问题" ]       │
│                                                    │
│  ⓘ 为什么重要：这两种情况的恢复路径完全不同。        │
│    手工处罚不提交重新审核，永远不会自动恢复。        │
└────────────────────────────────────────────────────┘
```

### 3.3 这个设计符合 P0-3 现有的全部原则

| P0-3 原有原则 | 这个设计怎么符合 |
|---|---|
| 观察 / 假设分层 | 用户的回答是**观察**（一手事实），不是我们的推测 |
| 「查不了」如实标注 | 明说"Google 没有开放这个接口" |
| 拒绝挑一个想听的答案 | 用户自己去看真实状态，不是我们猜 |

**而且它把一条"查不了"变成了"你能查，我们教你怎么查"。**

这正是产品评审里提的"把「能查没查」和「确实查不了」分开"的思路，而且更进一步——**第三类：我们查不了，但你能查。**

## 四、新增检测组规格：「站点级信号」

建议在现有 9 项检测之外，新增一个检测组，含 4 项。

### 4.1 检测 A · 变点日期与 Google 核心更新的吻合度

| 项 | 内容 |
|---|---|
| **输入** | 变点日期（P0-3 已有）+ Google 核心更新日期表（**新增静态数据**） |
| **数据来源** | Google Search Status Dashboard（`status.search.google.com`）公布 ranking update 的起止日期。定期同步维护一张表 |
| **输出** | `变点日期 2026-07-26 落在 [某次核心更新] 的推出窗口内（2026-07-2X ~ 2026-08-0X）`<br>或 `未落在任何已知更新窗口内` |
| **证据层级** | **观察**（日期比对是事实） |
| **配套假设** | 落在窗口内 → 假设：这次下降与该更新有关。**必须写明：时间吻合不等于因果** |
| **成本** | **低**。一张静态表 + 一次日期比对 |

> **只呈现日期关系，不给概率。** 不要输出"落在 X 小时内则 Y% 是算法降权"这类表述——我们没有支撑这个数字的数据。

### 4.2 检测 B · 品牌词 vs 非品牌词分化 ⭐ 判别力最高

| 项 | 内容 |
|---|---|
| **输入** | Search Analytics API，query 维度，变点前后两个窗口 |
| **处理** | 把查询分成「含品牌词」「不含品牌词」两组，各自算点击/曝光变化率 |
| **品牌词识别** | 一期：从域名推断（`gengrowth.ai` → `gengrowth`）+ **允许用户补充**（很多品牌名和域名不同） |
| **输出** | `品牌词点击 −8%（12 个查询）｜非品牌词点击 −87%（143 个查询）` |
| **证据层级** | **观察** |
| **配套假设** | ① 显著分化 → 与站点级信号下调的模式一致<br>② 两者同跌 → 更像技术 / 抓取问题，不像内容质量信号 |
| **成本** | 中 |

**为什么这条判别力最高**：它能把「站点级内容信号」和「技术故障」分开——

**技术故障（服务器挂了、robots 写错、误加 noindex）会让品牌词和非品牌词一起跌**，而内容质量信号主要打击非品牌词。Google 还认你的品牌身份，但降低了对你内容相关性的评价。

**这是 P0-3 现有 9 项完全没覆盖的维度。**

### 4.3 检测 C · 排名分布迁移（**不是平均排名**）

| 项 | 内容 |
|---|---|
| **输入** | Search Analytics API，page 维度 + position，变点前后 |
| **处理** | **只取下降前就已存在的页面**，看它们的排名分桶迁移 |
| **输出** | `下降前有 N 个页面在前 10 → 现在其中 M 个跌出前 50`（给分母） |
| **证据层级** | **观察** |
| **成本** | 中 |

> ⚠️ **这一项必须避开一个已知的坑。**
>
> GSC 的「平均排名」是**按查询平均、不按曝光加权**。高排名高曝光的词整体消失后，剩下的长尾词会把平均值抬高，制造"排名反而变好了"的假象。
>
> 我们在 W31 周报分析中正是因此得出过错误结论，靠曝光加权对比才推翻（实测：曝光加权排名 29.2 vs 简单平均 35.7）。
>
> **所以这一项一定要做「分桶迁移」而不是「平均排名变化」，且只取下降前已存在的页面。**
>
> P0-3 现有的「不建议做」里已经有一条在提醒这个坑，本项是它的正向实现。

### 4.4 检测 D · 新内容收录状态（抽样，二期）

| 项 | 内容 |
|---|---|
| **输入** | URL Inspection API，抽样最近发布的 N 个 URL |
| **难点** | GSC 不提供"最近发布"信息。需从 sitemap 的 `lastmod` 取，或**复用 P0-2 / P0-4 的爬虫** |
| **配额** | URL Inspection API 约 2000 次/天，必须抽样 |
| **输出** | `抽查最近 20 个 URL：15 个已编入索引，5 个未编入索引`（给分母 + 标明是抽样） |
| **证据层级** | **观察**，但必须标注抽样比例 |
| **优先级** | **P2，二期** |

### 4.5 关于「大量低质页面被索引」：换个做法

这一项 GSC 查不了，但**这件事本身值得做，只是不该在 P0-3 里做**。

**P0-4 的爬虫可以算出更好的替代指标**：

- 薄内容页面占比（正文 < 300 词）
- 标签页 / 归档页 / 空分类页占比
- 这些页面是否已被 noindex

> 🔗 **这是工具间协同的机会**：P0-3 检测到站点级信号 → 建议"去跑一次 P0-4 看低质页面占比" → **带着数据跳过去**。
>
> 这正好落实产品评审里提的"三个工具互不连通"那条。

## 五、新增两条「不建议做」条目

P0-3 已经有「不建议做」这个类别（现有一条：不要因为平均位置上升就去做排名恢复）。**这是全产品最稀缺的设计，应该扩充。**

### 5.1 不要为了恢复排名去做 disavow

> **不建议做**｜不要因为排名下降就去清理外链、提交 disavow
>
> Google 的 John Mueller 在 2026 年 3 月明确说过，**大多数网站根本不需要 disavow 工具**，并把常规性的"清理有毒外链"称为花钱浪费时间。
>
> Disavow 只在一种情况下有意义：**你收到了明确涉及外链的人工处罚通知。**
>
> 依据：[上方人工处罚确认卡片的结果]

**这条价值极高**——"流量掉了 → 一定是外链有毒 → 赶紧 disavow"是这个场景里最普遍的错误反应，而且不少 SEO 服务商会借机收费。

### 5.2 不要在没有证据前假设自己被"惩罚"了

> **不建议做**｜不要在人工处罚状态确认之前，把这次下降当成惩罚去做大规模删改
>
> Google 官方对算法造成的排名下降用词是中性的：**"排名下降不代表你的页面有问题"** ——更常见的解释是其他内容相对变得更好了。
>
> 在没有证据的情况下按"被惩罚"去处理，可能会删掉本来没问题的内容。

## 六、诊断分叉后的两条输出路径

用户在第三节的卡片上做出选择后，输出应当分叉：

### 路径 A · 用户选了「有红色警告」

```
① 立即置顶显示：你有一个人工处罚在挂着
② 明确告知：不提交重新审核，永远不会自动恢复
③ 引导：GSC → 安全和人工处置 → 看通知里写的具体违规类型
④ 提示恢复周期：几天 ~ 几周（提交审核后人工复查）
⑤ ⚠️ 此时其余所有算法层面的分析降为次要，收进折叠区
```

**关键**：这种情况下，把变点检测、CTR 分析这些全部推到用户面前是**有害的**——他需要先处理那个明确的红色警告。

### 路径 B · 用户选了「未检测到问题」

```
① 排除人工处罚（作为观察记录下来，注明是用户核对的，不是我们查的）
② 跑站点级信号检测组（A / B / C 三项）
③ 按满足条数分叉 ↓
```

**B-1 · 满足 ≥3 条 → 与站点级下调的模式一致**

```
· 明确写成「与…模式一致」，不写成「你被降权了」
· 列出具体是哪几条触发的，各自的数字
· 引导去 P0-4 查低质页面占比（带数据跳转）
· 恢复周期表述见第七节
```

**B-2 · 满足 <3 条 → ⚠️ 这是最常见的结果，必须明确输出**

```
· 明确告诉用户：这些信号不支持「站点级惩罚」的判断
· 不要留白、不要含糊带过 —— 用户需要这句话把他从
  「删内容 / 清外链 / disavow」那条错误路径上拉回来
· 转而提示其他更可能的成因，并指向对应的检查方向
```

**B-2 情况下应提示的其他方向**（这些不需要新做检测，用 P0-3 现有的 9 项就能指路）：

| 观察到的形态 | 更可能的成因 | 去查什么 |
|---|---|---|
| 下降**集中在少数几个词或一个主题簇**，其余正常 | **竞争加剧**——有站点开始做这批词 | 手动看这几个词的 SERP，看前十有没有新面孔 |
| 曝光还在、位置靠后、没有跌出前 50 | 竞争加剧 / SERP 形态变化 | 同上；另看这些词有没有出 AI Overviews |
| 曝光稳住但点击塌了 | SERP 形态变化 / 查询构成变了 | P0-3 现有的「点击率变点」检测 |
| 下降的词高度集中在某类时效内容 | **内容时效性到期** | 看这批页面的主题是否有明确窗口期 |
| 品牌词和非品牌词**一起**跌 | 技术故障 / 去索引 | 查 robots、noindex、服务器可用性 |

> **注意最后一行**：品牌词与非品牌词同跌，恰恰是**排除**站点级内容信号的证据——检测 B 的价值不只在于确认，也在于排除。

## 七、恢复周期的表述方式

用户一定会问"多久能恢复"。这个必须给，但**给机制和量级，不给精确数字和成功率**。

| 场景 | 可以说 | 不能说 |
|---|---|---|
| 手工处罚（整改到位） | 几天到几周（提交重新审核后人工复查） | ~~精确到 1-4 周~~ |
| 算法层面下调 | 通常需要等下一次核心更新，可能跨越 1-3 个更新周期 | ~~2-4 个月，X% 的站点会回升~~ |

**理由**：一旦给了"2-4 个月恢复"，用户三个月后没恢复就会认为工具错了。而"等下一次核心更新"这个机制本身是 Google 官方文档明确写过的，可以放心说。

## 八、文案与设计红线

这一节适用于本功能的所有输出文案和后续迭代。

### 8.1 不使用任何无法溯源的统计数字

这个话题的行业文章里充斥着"X% 的站点流量损失超过 50%""删除低质页面后 Y% 的站点在 Z 个月内回升"这类数字，**绝大多数没有标注来源**。

**一个都不要用**，包括落地页文案。

⚠️ **落地页尤其容易想引用这类数字来制造紧迫感。** P0-3 的全部价值建立在"只说能证明的事"上，用一个无源数字就会毁掉它。

### 8.2 措辞跟着 Google，不跟着行业习惯

整个 SEO 行业习惯用"降权 / 惩罚"这种耸动框架，而 **Google 自己的表述更中性**。

我们应该站在 Google 那一边，理由有二：**它更准确**，而且**用户是带着恐慌来的，我们不该放大恐慌**。

| ❌ 不要说 | ✅ 应该说 |
|---|---|
| 你的网站被降权了 | 这些信号与站点级排名下调的模式一致 |
| 你受到了惩罚 | 我们没有观察到人工处罚的证据 |
| 你违反了 Google 规则 | 排名下降不必然意味着你做错了什么 |

### 8.3 不做 E-E-A-T 打分

Google 官方明确说过**不存在"E-E-A-T 分数"这回事**。它是人工评审指南里的框架，不是可以打钩量化的排名因素。

**不要做 E-E-A-T 自检清单或评分功能。** 这与 P0-3「不给评分只给证据」的原则也是一致的。

### 8.4 如果输出里提到 GSC「移除页面」工具，必须写明它的实际效果

GSC 的移除工具**只是临时隐藏 6 个月**，不是永久删除索引。

真正的永久移除需要页面本身返回 **404 / 410 或加 noindex**，等 Google 重新抓取后才会真正从索引中消失。

**不写清楚这一点，用户会以为点一下就永久解决了。**

## 十、验收标准

改动上线后，用一个**已知正确答案**的真实案例验收——建议用 **astrologywiki 2026 年 7 月下旬的流量下降**。

我们已经用人工方式把它彻底查清楚了：真实原因是**两个时效内容池同期到期**（世界杯决赛 7/19 + 七月星象页过月），**不是站点级降权**。四条独立证据线：无排名下跌、无人工处罚、Bing 点击反而上涨、对照站完全稳定。

| 检测项 | 期望输出 |
|---|---|
| 人工处罚卡片 | 用户查 GSC → 无处罚（已确认过） |
| 检测 A · 核心更新吻合 | 变点 7/26–7/27，比对当期是否有核心更新 |
| **检测 B · 品牌词分化** | **期望：品牌词与非品牌词不呈现显著分化**（真实原因是内容时效性，不是站点级信号） |
