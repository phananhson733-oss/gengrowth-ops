### 2.1 🔴🔴 新问题 N1：首页与 /pricing 的首屏加载后空白

**现象**：全新加载后，首屏的 H1、副标题、两个 CTA 全部不可见（连续两次截图确认，未做任何滚动）。**用户真实滚动一次之后才渐显。**

**根因**：SSR 直接把隐藏初始态写进了 HTML —

```html
<h1 class="mx-auto mt-7 max-w-[880px] …" style="opacity:0;transform:translateY(14px)">
```

等客户端 JS 移除，但**对「加载时就已在视口内」的元素没有触发**；滚动进入视口的元素都正常渐显。

**影响面**：

```bash
for u in "/" "/tools" "/tools/seo-audit" "/pricing" "/blog"; do
  printf "%-20s " "$u"
  curl -s --max-time 20 "https://gengrowth.ai$u" | grep -o 'opacity:0' | wc -l
done
```

```
/                  17 处   ← 首屏 H1 / 副标题 / CTA 全中
/tools              0
/tools/seo-audit    0
/pricing            8 处   ← 首屏 H1 / 副标题
/blog               0
```

**受影响的恰好是商业上最重要的两个页面**，工具页与 blog 不受影响（这也是工具复审时没发现的原因）。

**排查旁证**：`prefers-reduced-motion` 为 `false`；控制台无站点报错（只有浏览器扩展日志）。所以不是动画偏好设置、也不是 JS 异常，是 reveal 逻辑漏了"初始即在视口内"这种情况。

### 2.2 🟠 新问题 N2：6 字符以上的未知路径 302 跳首页

```
/abcde   (5 字符) → 404  ✅
/abcdef  (6 字符) → 302 → https://gengrowth.ai/
/free-seo-audit   → 302 → https://gengrowth.ai/
/seo-tools        → 302 → https://gengrowth.ai/
/random-word-here → 302 → https://gengrowth.ai/
```

而以下路径行为正确：

```
/abc  /x-y  /blog/does-not-exist  /zh/abc  /pricing/xyz  /tools/nonexistent-tool  → 全部 404 ✅
```

**为什么要改**：302 是临时跳转，Google 会保留原 URL 并持续重抓——既不像 301 那样合并信号，也不像 404 那样丢弃。任何拼错的外链、任何被猜测或抓取到的路径，都会变成一个永久占用抓取预算的"页面"。

**这与 astrologywiki 上查出的 soft 404 是同一类问题**，只是形式不同（那边返回 200 + 首页外壳，这边返回 302 + 首页）。

### 3.1 第 8 条修得比建议更彻底

```

现在  Repeated title text          2 / 560
```

## 五、需要确认的状态问题

### 5.1 ✅ OAuth 应用是 Testing 还是 In production —— 已解决

实际走完一次授权流程未见未验证警告页，**验证已通过**。原本担心的 Testing 模式（限 100 白名单用户、refresh token 7 天强制过期）不成立。

### 5.2 ⬜ `webmasters.readonly` 被 Google 归入哪一档

我们请求的 scope：

```
openid + email + profile + https://www.googleapis.com/auth/webmasters.readonly
```

| 档位 | 例子 | 审核要求 |
|---|---|---|
| Non-sensitive | email、profile | 无需审核 |
| **Sensitive** | **Search Console** | 人工审核 + 演示视频 |
| Restricted | Gmail、Drive 全量 | 上述全部 + 第三方安全评估（CASA） |

验证既已通过，这条只影响**后续新增 scope 时的排期预期**，优先级已降低。

### 5.3 ⬜ P0-3 里「Average position is impression-weighted」这句措辞对吗

P0-3 结果区 `Do not do` 有一条：

> **Do not chase a rankings recovery because average position went up.** Average position is impression-weighted. When high-ranking queries disappear the number rises on its own…

**建议的动作是对的**，但 `impression-weighted` 这个定性**与我们此前的记录冲突**——我们记的是 GSC 均位按查询平均而非按曝光加权。

**我无法确定哪边对，因此不下结论。请对着 Google 官方文档核一次。** 这是产品里一条明确的「不要做」，措辞错了会误导用户，核实成本极低。

### 5.4 第 10 条 OAuth 持续授权的两条实现路径

`access_type=online` 与产品「什么都不存」的定位是自洽的，但它让每次回访都要重走完整授权。

| 方案 | 做法 | 代价 |
|---|---|---|
| **A** | `access_type=offline`，服务端加密存储 refresh token，提供显式断开入口 | 需要凭证存储与吊销管理，对外"什么都不存"的表述需重新措辞 |
| **B** | 不存 token，但延长会话 / 会话内静默续期 | 实现较轻，**但无法消除 7 日回访的重新授权** |

**建议按 A 做** —— B 解决不了「7 日留存 10 人」这个指标场景，而那正是上司把它定为门槛的原因。

## 八、工具联动设计（P0-2 的 H 组）

### 8.1 前置条件

**先把单个工具做完整，再做联动。** 否则用户体验会变成：每个工具给我一堆数据，然后让我去下一个工具再拿一堆数据。

**建议顺序**：先做 `2·B2`（点击深度分布）与 `2·E2`（一句话结论），再做 H 组。

### 8.2 判定标准

| | 弱联动 | 强联动 |
|---|---|---|
| 形态 | 报告末尾一排"你可能还需要"的工具卡片 | **一个工具的输出，正好是另一个的输入** |
| 用户感受 | 广告 | 顺理成章 |
| 实现 | 加几个链接 | **传数据** |

**只有 H1 / H2 值得做。**

### 8.3 ⭐ 2·H1 · P0-2 → P0-4：复用已抓 HTML，零额外等待

交接索引明确写过「P0-2 与 P0-4 共用爬虫基础设施」，而实测显示 **P0-2 已经把 167 页的完整 HTML 抓下来了 —— P0-4 需要的就是同一批 HTML**。

```
现在：跑 P0-2 等十几秒 → 想看全站审计 → 跑 P0-4 再等十几秒（重抓同样的页）
应该：跑 P0-2 →「用这次已抓的 167 页做全站技术审计」→ 立即出结果
```

**这不是跳转，是「同一次抓取的两种解读」。**

**验收**：从 P0-2 报告点进 P0-4，**不触发新的抓取请求**，结果立即呈现。

### 8.4 ⭐⭐ 2·H2 · P0-2 × P0-1：交集才是可行动的

| 工具 | 知道什么 |
|---|---|
| P0-2 | 哪些页面**内链弱、埋得深** |
| P0-1 | 哪些页面**曝光高、点击少** |

```
页面 曝光高 + 点击少 + 内链支撑弱
  → Google 已经在给它机会，但站内没给它支撑
  → 加内链是明确有回报的动作            ✅ 优先修

页面 内链少 + 根本没曝光
  → 修内链也没用，问题在别处            ❌ 不用管
```

现在 P0-2 报「51 页埋在 3 跳外」，用户无法判断哪些值得修。加上 GSC 数据就能排序。

⚠️ **这条同时是从匿名到授权的转化点** —— 与已完成的 `4·A2b` 思路一致，都服务于「20 人连接 GSC」。

### 8.5 2·H3 · P0-3 → P0-2（注意方向）

```
✅ P0-3 诊断出「某批页面曝光崩塌」→ 这批页面是不是内链出了问题？→ 带 URL 跳 P0-2
❌ P0-2 说你内链有问题 → 要不要看看流量降没降？（无因由的推荐）
```

**这条应在 P0-3 那边实现**，已随 `3·T4a` 部分落地。

### 8.6 2·H4 · P0-2 → P0-5：暂不做

从"内链弱的页面"提主题词去找关键词机会，链条太绕，用户不会这么想。

### 8.7 具体设计：不是「你可能还喜欢」，是「下一步该查什么」

报告末尾**不放工具卡片**，放**由本次结果触发的问题**：

```
┌──────────────────────────────────────────────────
│  你的站有 51 页埋在 3 跳以外
│  它们可能拿不到足够的内链支撑 —— 但值不值得修，
│  取决于它们在 Google 那边有没有曝光。
│
│  [ 连接 Search Console，看这 51 页的实际表现 ]  → P0-1
├──────────────────────────────────────────────────
│  抓取时我们还发现 66 个页面的 canonical 指向别处
│  这可能是分页/筛选的正常现象，也可能是配置错误。
│
│  [ 用这次已抓的 167 页做全站技术审计 ]  → P0-4 · 无需重新等待
└──────────────────────────────────────────────────
```

| # | 要点 | 说明 |
|---|---|---|
| 1 | **有条件触发** | 没有深层页面就不显示第一条 |
| 2 | **说清为什么** | 不是"还有个工具"，是"**你这个结果引出了一个新问题**" |
| 3 | **标明成本差异** | 「无需重新等待」是真实差异，不是营销话术 |

### 8.8 2·H5 · CTA 指向主产品 —— 能力边界已确认

主产品**能给出内链建设建议，但不能代替用户执行**（无法自动往站上加链接）。

**这不是缺陷，是分工。** 痛点报告引用的 Reddit 帖标题是《How to **find** your orphan pages… without paying for Screaming Frog》——**那个"下午"花在「发现」上，不是花在「修」上。**

## 附：复现方法

### A · 站点全量扫描

```bash
curl -s --max-time 20 https://gengrowth.ai/sitemap.xml -o sm.xml
grep -oE '<loc>[^<]*' sm.xml | sed 's/<loc>//' > urls.txt
while read -r u; do
  code=$(curl -s --max-time 20 -o pg.html -w "%{http_code}" "$u")
  t=$(grep -oE '<title>[^<]*' pg.html | sed 's/<title>//' | head -1)
  sch=$(grep -o '"@type"' pg.html | wc -l)
  h1=$(perl -0777 -pe 's{<(script|style)\b.*?</\1>}{}gis' pg.html | grep -oc '<h1')
  printf "%s\t%s\t%s\t%s\t%s\n" "$u" "$code" "${#t}" "$sch" "$h1"
done < urls.txt
```

### B · N1 首屏空白的影响面

```bash
for u in "/" "/tools" "/tools/seo-audit" "/pricing" "/blog"; do
  printf "%-20s " "$u"
  curl -s --max-time 20 "https://gengrowth.ai$u" | grep -o 'opacity:0' | wc -l
done
```

### C · N2 未知路径的行为

```bash
for p in /abcde /abcdef /free-seo-audit /abc /blog/does-not-exist; do
  printf "%-24s " "$p"
  curl -s --max-time 15 -o /dev/null -w "%{http_code}" "https://gengrowth.ai$p"
  curl -sI --max-time 15 "https://gengrowth.ai$p" | grep -i '^location' || echo ""
done
```

### D · 第 12 条过期文案

```bash
for u in "tools/traffic-drop-diagnosis" "zh/tools/traffic-drop-diagnosis"; do
  curl -s --max-time 25 "https://gengrowth.ai/$u" -o chk.html
  echo -n "/$u  英文串: "; grep -o "still verifying this app" chk.html | wc -l
  echo -n "         中文串: "; grep -o "还在 Google 的验证队列里" chk.html | wc -l
done
```

### ⚠️ 三条环境注意

1. **macOS 没有 `timeout` 命令**，用 `curl --max-time` 代替。我复审时先用了 `timeout`，命令没跑起来却输出 0，差点据此得出「文案已撤」的错误结论。
2. **数出现次数必须用 `grep -o … | wc -l`**。`grep -c` 数的是行数，而这些页面是压缩成单行的 HTML，用 `-c` 永远返回 0 或 1。
3. **正文词数必须先剥掉 `<script>`**，否则会把 Next.js 的 RSC 载荷算进去，得到十倍以上的虚高值。
