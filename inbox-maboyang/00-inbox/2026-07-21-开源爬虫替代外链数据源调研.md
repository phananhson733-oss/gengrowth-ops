# 开源爬虫替代外链数据源调研

## 结论

可以用开源爬虫把“关键词发现”与“候选页面复检”从 SerpApi/Firecrawl Cloud 的按量 API 中迁出，也能用搜索结果反查做低成本的竞品外链线索发现；但不能把网页爬虫等同于 Ahrefs 的全网反链索引。

推荐下一阶段采用“免费来源的外链机会发现 MVP”：

1. 关键词检索使用自托管 SearXNG 或可更换的搜索适配器。
2. 候选页面沿用本工具现有正文抓取、安全过滤与本地 CSV / Google Sheet 分流。
3. 竞品输入改为搜索派生的 referring-page 线索，并显式标为 search-derived，不宣称为完整竞品反链报告。
4. DR 缺失时写为 unknown，不能编造或把估算值当 Ahrefs DR。
5. 未来只有在这个流程证明人工审核效率和转化价值后，再购买 Ahrefs 的反链数据。

## 工具核验

| 工具 | 本质 | 可替代的部分 | 不能替代的部分 | 采用建议 |
| --- | --- | --- | --- | --- |
| Firecrawl | 搜索、抓取、站点 crawl、正文/结构化提取 API | 已知 URL 的内容抓取、JS 页面抓取、站内 URL 发现、候选页复检 | 竞品完整 referring domains、历史反链索引、可靠 DR | 暂不作为第一依赖；现有页面检查器覆盖普通页面，遇到 JS 重页再评估自托管 Firecrawl |
| Agent-Reach | 面向 Agent 的安装与渠道编排层，不是统一外链数据 API | 为人工调研提供网页阅读、GitHub、RSS、部分搜索/平台通道 | 可嵌入产品的稳定 SERP/反链数据服务；全网链接图 | 不作为本地 HTML 工具的生产依赖，可作为研究员辅助工具试用 |
| SearXNG（建议新增适配器） | 自托管元搜索入口 | 关键词 footprint 查询、竞品域名的搜索派生线索 | 反链数据库、DR | 作为免费 MVP 的关键词来源，必须加速率限制、缓存与来源审计 |

Firecrawl 官方将 Search、Scrape、Crawl、Map 和 Batch Scrape 列为核心能力；这些能力适合“从已发现候选页提取正文与链接”，不等于已有全网反向链接数据库。其自托管 SDK 可不使用 API Key，但项目主体采用 AGPL-3.0，接入闭源商业服务前应做许可证复核。

来源：[Firecrawl 官方仓库](https://github.com/firecrawl/firecrawl)、[自托管说明](https://github.com/firecrawl/firecrawl/blob/main/SELF_HOST.md)。

Agent-Reach 的官方仓库明确将自身定位为安装和配置工具：零配置网页阅读主要调用 Jina Reader，搜索通过 MCP 接入 Exa，并会按平台需要使用 Cookie、登录态或代理。它适合辅助调研，但不应被当作可审计、可长期稳定运行的反链数据源；仓库也提示使用 Cookie 的平台存在封号与凭据风险。

来源：[Agent-Reach 官方仓库](https://github.com/Panniantong/Agent-Reach)。

## 对当前工具的实际影响

### 1. 关键词模式：可取消 SerpApi 的硬依赖

保留当前五类 footprint：write for us、guest post、资源页、工具目录与评论页。把 Provider 改成可配置的 SearXNG / 搜索适配器。返回结果仍经过 URL 归一、去重、黄赌毒/诈骗/恶意软件硬过滤、页面正文二次复检与人工状态字段，因此与现有 Google Sheet 的字段和分流规则兼容。

### 2. 竞品模式：改为“线索发现”，不能承诺反链全量

没有 Ahrefs、Semrush、Majestic、DataForSEO 等链接索引时，可按竞品域名和品牌名执行精确匹配、资源页、Guest Post、评测页等查询。这些查询能发现公开提及或链接到竞品的页面，再由爬虫验证页面是否真的包含目标链接。结果应保留 source_mode=competitor_search、sources 与页面证据，并在 UI/Sheet 中标注“搜索派生线索，非完整反链索引”。

### 3. DR：免费阶段不作为准入门槛

免费阶段使用内容安全、主题相关性、页面编辑质量、外链密度和人工审核替代 DR。保留 domain_dr 和 dr_source 为可空字段；没有 Ahrefs 数据时写 unknown，不能把第三方估算或空值包装为 Ahrefs DR。

## 推荐的分阶段落地

| 阶段 | 新增依赖 | 交付 | 成本与风险 |
| --- | --- | --- | --- |
| P0：当前 | 无 | Google Sheet 接收端 + 本地 UI/CSV/安全筛选 | 无反链真实数据，Apps Script 授权待完成 |
| P1：免费发现 | SearXNG 适配器；必要时 Playwright | 关键词机会与竞品搜索线索进入同一张 Sheet | 自托管、搜索引擎访问频率、robots/服务条款需控制 |
| P2：抓取增强 | 可选 Firecrawl 自托管 | JS 重页、站内 crawl 和批量正文抽取 | 部署复杂度、AGPL-3.0 合规评估、代理成本 |
| P3：数据验证 | 可选 Ahrefs 小额度 API | 以小样本验证竞品反链覆盖率与 DR 的实际增益 | 按 API unit 付费 |

## 决策建议

先不购买 Ahrefs，也不立即引入 Firecrawl。优先把现有工具增加一个可替换的免费搜索 Provider，做 50 个关键词加 5 个竞品的小样本；记录候选数、硬过滤率、人工可用率和页面抓取失败率。只有当“竞品外链完整度”确实是业务瓶颈时，再以小额 Ahrefs API 做覆盖率对照。

这条路径能先验证外链机会库是否产生有效资源，而不是先为尚未验证的反链全量需求购买数据。
