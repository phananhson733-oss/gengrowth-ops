# 趋势词桥接逻辑规范

---

## 一、问题背景

Module 1.5 的 Path ① 判断问题是："这个词有明确的占星/星座角度？"

当前执行时，操作者将"明确的占星角度"理解为**词本身带占星属性**，导致：

- "Harry Kane"、"World Cup 2026"、"golden boot race 2026" 等高热度词全部被判为无占星角度
- 系统运行 5 天零产出
- 而这类词实际上已通过 `[人名] birth chart`、`[赛事] astrology` 的形式为 astrologywiki 带来高曝光（GSC 验证）

**根本原因：** 趋势词不需要本身与占星相关，只需要**可以通过固定公式桥接到占星内容**，即可走 Path ①。

---

## 二、趋势词信息口径（新增）

Module 1 传给 Module 1.5 的不是一个裸字符串，而是一条带上下文的趋势记录。Path ① 判断必须同时看**原始趋势词、完整相关查询、语种/实体归一化、桥接候选词**，不能只看 Google Trends 第一列标题。

### 2.1 必须保留的原始字段

| 字段 | 来源 | 用途 |
|---|---|---|
| `raw_trend` | Google Trends `Trends` | 原始趋势词，不直接等同于内容关键词 |
| `search_volume_label` | Google Trends `Search volume` | 热度量级，如 `50K+` / `200K+` |
| `trend_started_at` | Google Trends `Started` | 判断窗口期和内容时效 |
| `related_queries_full` | Google Trends `Trend breakdown` | 桥接判断的核心依据，必须保留完整列表 |
| `explore_link` | Google Trends `Explore link` | 人工复核入口 |
| `source_csv_path` | 本地完整 CSV 导出 | 审计和复跑依据 |
| `capture_time` / `batch_id` | 自动化运行时生成 | 去重、Sheet 追加、通知追踪 |
| `seen_within_7d` | 本地历史记录 | 过滤反复上榜词 |
| `match_scores` | Module 1 评分 | astrology / gengrowth / tool / game / risk 分数 |
| `system_reason` | Module 1 评分理由 | 说明为什么进入候选、观察或低匹配 |

### 2.2 原始趋势词、相关查询、桥接词的关系

| 层级 | 定义 | 示例 | 用法 |
|---|---|---|---|
| 原始趋势词 | Google Trends 第一列标题 | `golden boot race 2026` | 只用于发现热度和事件窗口 |
| 相关查询 | 用户实际联想和搜索扩展 | `world cup top scorer 2026`, `golden boot world cup` | 用于识别人物、赛事、工具需求、语种 |
| 归一化实体 | 将缩写、外语、别名转成英语内容实体 | `méxico vs. inglaterra` → `Mexico vs England` | 用于生成英语站内容关键词 |
| 桥接候选词 | 面向 astrologywiki 的可发布关键词 | `Mexico vs England astrology prediction` | 用于 sitemap 检查、SERP 验证和内容通知 |

判断原则：

1. **相关查询可以触发桥接。** 如果原始趋势词不明显，但相关查询里出现人物、赛事、角色、奖项、球队、作品名，也要生成桥接候选。
2. **非英语趋势词先归一化。** 美国区 Trending Now 常出现西语/葡语词，若目标是英语站，必须先转成英语实体再判断。
3. **原始词低匹配不等于 Path ① 不通过。** 低匹配只说明原始词没有直接占星词；只要能生成可信桥接词，仍可进入 Path ① 复核。
4. **桥接词必须独立验证。** SERP、sitemap、出生信息都针对桥接词或归一化实体执行，不针对原始趋势词。
5. **完整相关查询必须进入 Sheet。** 飞书卡片只展示前 5 条，但 Sheet 的 `完整相关查询` 列必须保留全量，供人工复核。

### 2.3 真实样本的处理方式（2026-07-06 16:33 批次）

| 原始趋势词 | 搜索量 | 相关查询信号 | 归一化/抽取实体 | 建议桥接候选 | 初判 |
|---|---:|---|---|---|---|
| `méxico vs. inglaterra` | `200K+` | `raúl jiménez`, `mexico vs inglaterra 2026`, `partido mexico vs inglaterra` | `Mexico vs England`, `Raul Jimenez` | `Mexico vs England astrology prediction`; `Raul Jimenez birth chart` | 体育赛事/人物双信号，进入 Path ① 人工复核；非英语原词需英语化 |
| `isabel haugseng johansen` | `50K+` | `haaland girlfriend`, `erling haaland wife`, `haaland parents` | `Isabel Haugseng Johansen`, `Erling Haaland` | `Isabel Haugseng Johansen zodiac sign`; `Erling Haaland birth chart` | 名人关系/人物信号，需先查生日信息；生日缺失则降级或放弃 |
| `golden boot race 2026` | `50K+` | `world cup top scorer 2026`, `world cup golden boot`, `top scorer in world cup 2026` | `2026 World Cup Golden Boot` | `2026 World Cup Golden Boot astrology prediction` | 体育事件短时窗口，Path ① 可复核；24 小时内未排产则放弃 |
| `fifa brackets` | `50K+` | `fifa schedule`, `world cup 2026 bracket`, `current world cup bracket` | `World Cup 2026 bracket` | `World Cup 2026 bracket astrology prediction` / Path ② `world cup bracket tool` | 工具需求强于占星桥接，优先走 Path ②；占星桥接仅低优先级观察 |

> 这类样本说明：自动化不能只因为 `Astrologywiki匹配=0` 就彻底丢弃。应在 Module 1.5 里新增一列 `桥接复核建议`，把“可桥接但非直接命中”的词交给人工 5 分钟判断。

## 三、完整判断流程

Module 1 发现候选词后，按以下顺序依次判断：

```
Step 1：重复检查（新增）
  → 检查 astrologywiki sitemap，桥接词对应页面是否已存在
  → 已存在 → 转内容更新流程（见第四节），不再走 Path ① 新建
  → 不存在 → 进入 Step 2

Step 2：Path ① 资格判断
  → Level 1：趋势词本身属于占星话题（天象事件、星座概念等）→ 通过
  → Level 2：趋势词或相关查询属于可桥接类型（见第五节）→ 通过
  → 两级都未通过 → 继续判断 Path ②

Step 3：桥接词 SERP 验证（新增，仅 Level 2 执行）
  → 验证目标：桥接词本身（如 `Harry Kane birth chart`），而非原始趋势词
  → 前3名有超级平台（Wikipedia 人物页、Reddit 等）→ ⚠️ 标注竞争强，人工确认
  → 前10名平均 DR > 70 → ❌ 否决
  → 前10名有小站内页排名 → ✅ 加分，优先推进

Step 4：出生日期验证（热门人物专用，见第六节）

Step 5：Path ① 通过 → 生成输出通知（见第七节）
```

## 四、已有页面的处理（重复检查逻辑）

Step 1 发现 astrologywiki 已有对应页面时，不走新建流程，改为：

| 情况 | 处理方式 |
|---|---|
| 页面存在，趋势仍在窗口期 | 推送内容更新通知，内容负责人追加段落 + 更新日期（参考博客优化规范 §四）|
| 页面存在，趋势已过期 | 不处理，忽略本次触发 |
| 页面存在，但该人物/赛事有重大新进展 | 推送更新通知，注明新进展摘要 |

> sitemap 检查方式：`curl -s https://www.astrologywiki.com/sitemap.xml | grep "[桥接词slug]"`

## 五、可桥接类型定义

| 类型 | 识别方式 | 桥接公式候选 | 内容产出示例 | 适用路径 | 内容时效 | 最低证据 |
|---|---|---|---|---|---|---|
| **热门人物**（运动员/演员/政治人物/网红）| 原始趋势词或相关查询出现人名 | `[人名] birth chart` / `[人名] zodiac sign` / `[人名] rising sign` | `Harry Kane birth chart` | 路径①；若可做工具再评 Path ② | 长青 | 能抽取稳定人名；至少有出生年或星座信息 |
| **体育赛事** | 原始趋势词或相关查询包含赛事、球队、对阵、排名关键词（见附录 A）| `[赛事] astrology` / `[赛事] astrology predictions` / `[队伍 A] vs [队伍 B] astrology prediction` | `Mexico vs England astrology prediction` | 路径①；赛程/比分/括号类可另评 Path ② | 短时 | 能归一化成英语赛事实体；不是纯比分查询 |
| **影视作品/角色** | 原始趋势词或相关查询为电影、剧集、角色、演员组合 | `[角色名] zodiac sign` / `[作品] characters zodiac signs` | `Toy Story 5 characters zodiac signs` | 路径①② | 中长期 | 作品/角色实体明确 |
| **文化事件/颁奖** | 原始趋势词或相关查询包含文化事件关键词（见附录 B）| `[事件] astrology` / `[事件] zodiac predictions` | `Oscars 2026 astrology` | 路径①② | 短时 | 事件时间明确，能在窗口期内发布 |
| **游戏角色/游戏发布** | 原始趋势词或相关查询为游戏名、角色名、发布事件；角色有官方设定生日优先 | `[角色名] zodiac sign` / `[游戏名] characters zodiac signs` | `GTA 6 characters zodiac signs` | 路径①② | 中长期 | 角色或世界观有稳定资料来源 |
| **政治选举/重大政治事件** | 原始趋势词或相关查询包含选举、候选人、政治事件关键词（见附录 C）| `[选举/事件] astrology prediction` / `[候选人] birth chart` | `2026 midterms astrology prediction` | **仅路径①（astrologywiki）** ⚠️ | 短时 | 必须中立表达，不得预测胜负或背书 |

> ⚠️ **政治类内容限制**：政治相关页面属于 Google AdSense 敏感类目，会被降低 CPM 或限制广告投放。路径B新站以 AdSense 变现为目标，**不得**使用政治类桥接。仅在 astrologywiki 上产出，且内容必须从星盘/行星运行角度分析，不得发表政治立场或背书候选人。

**内容时效说明：**
- **长青**：写完后持续排名，质量优先，48小时目标可适当放宽至72小时
- **中长期**：作品/游戏热度维持数月至数年，正常48小时目标
- **短时**：赛事/颁奖窗口仅数天，必须24小时内发布，否则放弃

## 六、出生日期验证（热门人物专用）

热门人物桥接需要已知出生日期才能写 birth chart 内容。判断流程：

1. 查询 Wikidata API，检查 `date of birth`（P569）和 `place of birth`（P19）字段
2. **有完整出生日期 + 出生地** → 最优，公式用 `[人名] birth chart`，可写完整星盘
3. **有出生日期，无出生时间**（绝大多数公众人物）→ 公式用 `[人名] birth chart`，内容注明"上升星座待确认"，只分析太阳/月亮/行星位置
4. **仅知出生年份或星座** → 降级，公式改为 `[人名] zodiac sign`，Path ① 仍通过
5. **完全无生日信息** → Path ① 不通过，继续判断 Path ②

> 出生时间缺失是常态，不作为否决条件，但须在通知中标注，让内容负责人提前知道内容深度上限。

## 七、Path ① 通过后的输出

Module 1.5 判定为 Path ① 后，推送给内容负责人的通知需包含：

| 字段 | 内容 |
|---|---|
| 原始趋势词 | 如 `méxico vs. inglaterra` |
| 归一化实体 | 如 `Mexico vs England` |
| 桥接类型 | 如 `热门人物` |
| 推荐内容关键词（候选）| 如 `Harry Kane birth chart` / `Harry Kane zodiac sign` / `Harry Kane rising sign` |
| 内容时效 | 如 `长青`（决定发布优先级）|
| 相关查询摘要 | 前 5 条相关查询；完整列表写入 Sheet |
| 出生日期 | 如 `1993-07-28`（Wikidata 自动获取）|
| 出生时间 | 如 `未知`（影响内容深度，标注说明）|
| 出生地 | 如 `Galway, Ireland`（Wikidata 自动获取）|
| 桥接词 SERP 评估 | 如 `前10平均DR 32，有小站内页，✅ 可做` |
| Google Trends 估算搜索量 | 如 `500K+` |
| Trending Now 发现时间 | 如 `2026-07-06 14:00` |
| 数据来源 | 完整 CSV 路径 + batch_id |
| 桥接复核建议 | `Path ① 推荐` / `Path ① 低置信观察` / `优先 Path ②` / `放弃` |

内容负责人收到通知后按现有内容 SOP 产出文章，发布时限参考内容时效字段。

## 八、Watchlist 预置机制（可选，提升响应速度）

部分桥接机会可以提前预判（赛事参赛名单、颁奖提名名单、大选候选人），在趋势出现前提前完成 Wikidata 查询和 SERP 评估，存入 Watchlist。

触发逻辑：Module 1 发现候选词 → 先查 Watchlist → 命中则跳过 Step 4（出生日期验证），直接输出通知，响应速度提升约 2 分钟。

Watchlist 维护：每季度更新一次，由内容负责人手动维护（世界杯赛季前补充球员名单，颁奖季前补充提名名单）。
