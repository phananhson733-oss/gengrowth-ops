### ⚠️ 一处双方都错的：detail 与 video-play 的 description

**报告称「字节相同」，我上一版称「不同」——两个都是从单个样本推出的全称结论。**

40 个 ID 配对实测：

| | 结果 |
|---|---|
| **title 完全相同** | **40/40（100%）** |
| **description 完全相同** | **15/40（38%）** |
| description 不同的 25 个 | **全部是前缀一致**——detail 是 play 的前 323 字符截断版 |
| detail 的 desc 长度 | 最短 41 · **中位 323** · 最长 333 |

**机制**：两页用同一段简介，**detail 截断在约 323 字符**。简介短于此则两边字节相同（38%），更长则 detail 是 play 的前缀（62%）。

**但结论方向不变**：无论哪一档，都是两个可索引页面共用同一个标题、描述要么相同要么互为前缀。SEO 问题一样成立。

> 另发现一个个例：`/detail/37600` 的 description 是字符串 **`Default`**（占位符漏出）。90 个随机 ID 中命中 0 个，属罕见，但值得让开发查一下取值逻辑。

## 三、🔴 重大遗漏：多语言目录在制造约 24,000 页自我重复

报告把非英语目录列为「真实本地化页面」，并把 hreflang 缺失归为「多语言资产闲置」。**方向反了。**

同一部剧 ID 7982 在 8 种语言前缀下实测：

```
/th/detail/7982   html lang=th   UI「รายการตอน」    title=การกลับมาของสามีมาเฟียของฉัน
/ja/detail/7982   html lang=ja   UI「エピソード」    title=การกลับมาของสามีมาเฟียของฉัน   ← 泰语
/de/detail/7982   html lang=de   UI「Episodenliste」title=การกลับมาของสามีมาเฟียของฉัน   ← 泰语
/es/detail/7982   html lang=es                     title=การกลับมาของสามีมาเฟียของฉัน   ← 泰语
```

**UI 是真本地化，剧集主体内容不是。** 剧名与简介永远是该剧在源库里的那一种语言，不随前缀变化。

反向验证：英语剧 49017 在 `/th/`、`/ja/` 下 title 同样是英文 `My Professor Is My Alpha`。

**后果**：每部剧 20 个 URL，各自 self-canonical，页面主要可索引文本完全相同，而 **hreflang 为 0**——Google 无从判断它们是同一内容的语言变体。

**这不是资产闲置，是批量生产重复页。**

### 另外两处报告没提的

- **`/video-play` 的 meta keywords 含 `[object Object]`**：`My Professor Is My Alpha, [object Object], [object Object], ...` —— JS 序列化 bug 漏进了 meta 标签
- **www 的 canonical 指向 apex**：这点是对的，缓解了一半重复风险。报告只说 www 是重复站，没提这个
