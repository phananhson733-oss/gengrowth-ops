# 工具落地页文案审计 + 命名取舍原则

## 零、先说标准的适用性

对照的 SOP 标题是**「AstrologyWiki 工具落地页设计规范」**（7/9 写的），而 gengrowth 的工具页有自己的落地页文案文档（7/29–31）。**严格说，这份 SOP 不一定是 gengrowth 的正式标准，需要确认。**

本审计仍按它判，理由是：**字数、FAQ 条数、Schema 类型这些是通用 SEO 实践，不是 astrologywiki 特有的。** 但凡是引用 SOP 阈值的结论，都请按"参考标准"而非"验收标准"来读。

### 1.1 核心问题：H3 超标而字数不足

**P0-4 有 27 个 H3，全页只有 935 词——平均每个小标题下面只有 35 个词，一两句话。** P0-2 是 31 个 H3 配 1,229 词。

**这是"骨架搭齐了、肉没长上"**：标题层按 SEO 铺得很全，但点进去每个标题下面没有实质内容。**读者拿不到东西，Google 也容易判成薄内容。**

而 **P0-2 和 P0-4 恰恰是两个免登录的爬取型工具，是我们摩擦最低的获客入口**——这两页薄，代价最大。

### 1.2 与我们自己文案文档的对比

| | 文档英文词数 | 线上 | 上线比例 |
|---|---:|---:|---:|
| P0-1 | 1,560 | 2,495 | **160%**（上线时扩写了） |
| P0-2 | 2,611 | 1,229 | **47%** |
| P0-3 | 1,724 | 1,539 | 89% |
| P0-4 | 1,453 | 935 | 64% |
| P0-5 | 2,096 | 331 | **16%** |

**P0-1 是唯一被扩写的，也是唯一字数达标的。** 其余都在上线过程中缩水。

> ⚠️ **口径限制**：文档词数统计的是全文英文词，混入了中文分析段落里引用的关键词与 SERP 原文（P0-2 那份是样张，方法论注释特别多）。**方向可信，数值不精确，不能当精确删减率用。**

### 1.3 做得好的两项

- **FAQ 全面达标**（P0-5 除外）：8–11 条，符合 SOP
- **Schema 齐全**：Breadcrumb / FAQPage / HowTo / SoftwareApplication / Organization / Offer
  - 小偏差：SOP 规定 `WebApplication`，实际用 `SoftwareApplication`。后者是前者的父类型，**可以接受，不建议为此改动**

## 三、H1 / 产品名 / URL 到底怎么取舍

### 3.1 先把 URL 从这个问题里拿掉

**URL 不参与命名讨论，永远不动。**

三条理由：
1. **URL 是地址，不是名字。** 没有用户会把 `/tools/hidden-keywords` 读成产品名
2. **改 URL 的代价我们正在亲身承受**——`/en/` 迁移做得完全正确，仍有 **68.9% 的曝光滞留在旧 URL 上**，几个月都收不回来
3. **URL 作为排名因素的权重，今天已经很小**

> **结论：`seo-quick-wins`、`hidden-keywords` 这些 slug 和名字对不上，是正常的、且应当保持。引用工具时给链接，不要拿 slug 当名字。**

### 3.2 剩下的是 Title / H1 / 产品名三者，按"谁面对谁"分工

| | 面对谁 | 该承载什么 | 改动成本 |
|---|---|---|---|
| **Title** | **搜索结果页的陌生人** | **主词**——这是最强排名信号，也是点不点进来的唯一依据 | 极低 |
| **H1** | **刚点进来的人** | **主词或其近义**——确认"我来对地方了" | 极低 |
| **产品名** | **已经在站内的人 + 我们自己** | 卡片、导航、招募话术、内部文档 | 无成本 |

### 3.3 冲突时的判定规则

> **在 Title 和 H1 里，主词优先于产品名。产品名拥有其他所有位置。**

**理由是一个不对称：**

- **我们没有品牌搜索量。** 本周品牌词 `gen growth` 只有 5 次曝光、1 次点击。`GSC Opportunity Finder`、`Keyword Opportunity Map` 是我们发明的词，**搜索量为零**。让它们占 Title，等于把最值钱的位置让给一个没人搜的词——**纯亏，没有任何补偿**
- **而 Title 和 H1 改起来成本极低。** 等哪天品牌真有搜索量了，再把产品名放进 Title 也不迟
- **反过来 URL 是不可逆的**——所以真正需要谨慎的只有 URL，Title/H1 应该按当前 SEO 最优配置，不必为未来的品牌预留

### 3.4 那"卡片名和 H1 不一致，用户会不会困惑"

**会，而且这正是有人把产品名放进 H1 的原因。但解法不是牺牲 H1。**

**用 eyebrow（H1 上方的小标签）承接产品名**——这个组件我们已经有了，首页就在用（`A CONNECTED SEO GROWTH SYSTEM`）：

```
[eyebrow]  KEYWORD OPPORTUNITY MAP        ← 产品名，承接卡片，保证连续性
[H1]       Find Low Competition Keywords  ← 主词，承接搜索
[副标题]    讲机制、讲差异化
```

**产品名和主词都保住了，一行组件的事。**

### 3.5 已经有一页做对了，照它做

**P0-2 `internal-link-audit` 是唯一三者自洽的页面**：产品名 = H1 = `Internal Link Audit`，Title = `Free Internal Link Audit: Find Orphan and Weak Pages`，主词全页出现 34 次。

**它之所以自洽，是因为产品名本身就是主词。** 这是最省事的状态——**以后新工具命名时，优先选一个"本身就是搜索词"的名字**，就不会有这个取舍问题。
