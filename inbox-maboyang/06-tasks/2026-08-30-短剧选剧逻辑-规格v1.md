# 短剧选剧逻辑 · 规格 v1

## 〇、先排除两条走不通的路

| 路径 | 为什么不行 |
|---|---|
| **用站内播放/收藏数选剧** | ❌ **这两个计数是假的**。实测 13 部：真正的爆款《Великият и могъщ джин》显示 9.5K/6.5K，反而低于随机抽样（20.4K / 18.5K）；「Hunting Love」星标 18.5K 却只有 1.5K 播放。数值 1.2K–20.4K 随机分布，与真实表现无关 |
| 用 GSC 点击量选剧 | ❌ 点击起来时已经是峰值，来不及了 |

> 🔴 顺带：站上展示编造的互动数据，是独立于本规格的问题，建议单独处理。

---

## 一、这是两个不同的选剧问题

|  | 内容线（blog / 演员页） | 切片线（TikTok） |
|---|---|---|
| 目的 | 接住搜索需求 | 拿播放量 → CPS 安装分成 |
| 成败判据 | 能不能排上去 | 视频能不能跑量、能不能转化安装 |
| 硬约束 | 我们站上有这部剧 | **该剧必须在 ReelShort 上**（否则 CPS 链接无法转化）|
| 时机要求 | 必须**早于**需求峰值 | 越新鲜越好，但不卡死 |

**两条线的选剧标准不同，但候选池可以共用。** 下面分别定义。

---

## 一·补 · 候选池怎么来：三个信号源，角色不同（2026-08-30 实测）

单靠任何一个都不行，三者是**流水线**不是备选：

```
① 发现      ReelShort 榜单      →  产出候选剧名（它不告诉你热度走到哪）
② 定时机    Google Trends       →  这波在爬升还是已经过峰？主市场是谁？
③ 判可做    GSC                 →  我们排第几？接住了没有？
```

### ① 发现源 · ReelShort 站内榜单

实测可用：

| 位置 | 内容 |
|---|---|
| 首页 hero 轮播 | 带 `Trending` 标签。**当前轮播里就有我们的爆款《The Great and Powerful Genie》** |
| `New Release` 区块 | 有 `View all` 可翻页，卡片带 `Hot` / `Ai` 标签、性别与题材标签 |
| 剧集卡 | 显示总集数（EP.1 / EP.51）|
| 语言切换 | **ReelShort 自己就出本地化剧名**（首页出现过保语标题），可直接取译名 |

**为什么这是最好的发现源**：ReelShort 是版权方，它推哪部，哪部就有量。我们的爆款此刻正挂在它首页轮播上——不是巧合。

⚠️ **技术约束**：ReelShort 有 AWS WAF，`curl` 抓不到（`/robots.txt` 都返回挑战页）。做监控必须走真实浏览器，成本要按这个估。

⚠️ 另外 `/ranking` 路径不存在，榜单没有独立 URL，需要从首页与 `New Release` 的 View all 里取。

### ② 定时机 · Google Trends（我此前低估了它）

**实测两个已知剧，Trends 都能看见，而且比我们的 GSC 早。**

| 剧 | Trends 曲线 | 主区域 | 我们的 GSC |
|---|---|---|---|
| 《Великият и могъщ джин》 | ~8/10 一次尖峰 → 8/22 起爬升 → 8/28 高点 | 保加利亚 100 · 德国 <1 | **8/26 才有数据** |
| 《I'd Rather Marry the Beast Than You》 | ~7/25 起量 → **~7/29 峰值** → 8/17 后回落到低位 | **菲律宾 100** · 印度 <1 | 219 点击 · 均位 3.62 |

**Trends 领先我们的 GSC 约两周。**

🔴 **它还当场纠正了我两个错误**（原写在周报与提案里）：

| 我的说法 | Trends 实测 |
|---|---|
| 《I'd Rather Marry the Beast》是"正在崛起的机会，本周最高优先级" | ❌ **峰值在 7/29，已衰退一个月** |
| "英语、正好在目标市场" | ❌ **主市场是菲律宾**，我看到英文剧名就当成了欧美 |

**Trends 的定位是过滤器不是发现器**——它必须先有一个词才能查，没法拿它浏览"短剧圈现在什么火"。所以它替代不了 ①。

### ③ 判可做 · GSC

见下节。GSC 的独特价值是它告诉你**我们自己**的位置——前两个源只讲市场，不讲我们。

### 三源合用的判定

| ReelShort | Trends | GSC 均位 | 结论 |
|---|---|---|---|
| Trending / New | 爬升中 | 5–20 | 🟢 **立即做**——最理想 |
| Trending / New | 爬升中 | > 20 或无数据 | 🟢 做，但要更多投入 |
| Trending / New | 尚无数据 | 无 | 🟡 观察——太早，Trends 还没到阈值 |
| 任意 | **已过峰** | 任意 | 🔴 **不做**——《I'd Rather Marry the Beast》即此类 |
| 任意 | 爬升中 | **≤ 3** | 🔴 跳过——目录页已吃到 98.8% |

## 二、内容线选剧：从 GSC 找「需求已现、我们没接住」

### 数据源

GSC 查询报表（每日跑），按剧名/演员名归族。归族方法本次已人工做过一遍，可脚本化：同一部剧的拼写变体归为一族。

### 每族计算五个量

| 量 | 说明 |
|---|---|
| `曝光_本期` | 最近 7 天该词族总曝光 |
| `曝光_上期` | 前 7 天总曝光 |
| `变体数` | 该族下不同写法的数量 |
| `均位` | 曝光加权平均排名 |
| `点击率` | 本期点击 ÷ 本期曝光 |

### 进入候选池的条件（满足其一）

```
A · 新词族出现     曝光_上期 = 0  且  曝光_本期 ≥ 30
B · 需求加速       曝光_本期 ÷ 曝光_上期 ≥ 2  且  曝光_本期 ≥ 100
C · 变体扩散       变体数 ≥ 8  且  变体数较上期增加
```

条件 C 的依据是本次观察：三个词族的变体数分别是 34 / 18 / 70。**人听说了剧名但不确定怎么拼，说明口碑正在扩散、还没沉淀成标准写法。** ⚠️ 仅 3 个样本，是观察不是规律，需继续验证。

### 候选池内的优先级

按「推得动的程度」排，不按曝光量排：

| 优先级 | 均位 | 判断 |
|---|---|---|
| **1** | **5–20** | 已经有基础，补内容最容易推进前十 |
| 2 | 20–50 | 有需求但排不上，需要更多投入 |
| 3 | > 50 | 从头做 |
| — | ≤ 3 | **跳过**——已经吃到了，边际收益低 |

> 依据：《Великият и могъщ джин》均位 1.61，目录页已经拿走 98.8% 的点击，再补内容边际很小。而《I'd Rather Marry the Beast Than You》均位 3.62、219 点击、零内容，属于优先级 1 的典型。

### 选定后写什么

按本次实测的边际价值排序，**不是先写剧集聚合 blog**：

| 序 | 内容类型 | 依据 |
|---|---|---|
| 1 | 确认目录页已收录、URL 带剧名、有 video schema | 这是 98.8% 的来源 |
| 2 | **演员/角色页** | 上线首日 47 点击、点击率 8.1% 全站最高 |
| 3 | 修饰词长尾（`full movie` / `цял филм` / `бг аудио` / `full episode`）| 目录页匹配得弱 |
| 4 | 剧情/结局解释页 | 待验证 |
| 5 | 剧集聚合 blog | 本次只带来 1.2% |

## 三、切片线选剧：先把我们自己的数据挖出来

### 现状：我们已经有训练数据，但没人看过

四个账号（`@shirley5278789` 1,454 粉 / `@dramaexpedition` 1,161 粉 / 另两个待补 handle）已经积累了一批发帖记录，**每条的播放、点赞、完播是现成的**。

**第一步不是定标准，是先回答：我们自己发过的帖子里，跑量的和不跑量的差在哪。**

需要导出的字段：

```
发布时间 · 剧名 · 剧集来源平台 · 语言 · 封面类型（AI图/剧照）
· 文案句式 · 播放 · 点赞 · 完播率 · 主页点击 · 链接点击
```

有了这张表才能回归出选剧标准。**在此之前定的任何标准都是拍脑袋。**

### 已知的硬约束

| 约束 | 原因 |
|---|---|
| 该剧必须在 **ReelShort** 上架 | bio 链接是 ReelShort 的 CPS 跟踪链接（`reelslink.com/cps/…` → App Store），剧不在上面就无法转化 |
| 剧名要有本地化译名 | 观众要能凭封面上的剧名去搜 |

### 可先用的粗筛（待数据验证后替换）

在回归结果出来前，暂用：

```
1. 该剧在 ReelShort 上架且较新
2. 内容线候选池里优先级 1–2 的剧（两条线共用候选池）
3. 有明确的钩子情节（可截出 15–30 秒冲突片段）
```

## 四、两条线怎么配合

现在的顺序是错的：

```
现状    站上起量 → 发切片 → 补 blog        全部事后
应为    候选池 → 内容先就位 → 再投切片 → 接住搜索
```

**内容必须先于切片。** 切片会制造对剧名的搜索，如果那时我们的页面还没上线或没被收录，需求就流向别家。

| 环节 | 时间 |
|---|---|
| 候选池产出 | 每日 |
| 目录页检查（收录/URL/schema）| 选定当天 |
| 演员页 + 修饰词长尾上线 | 选定后 1–2 天 |
| 切片投放 | 内容确认被收录之后 |

> ⚠️ 这个顺序要求内容侧能在 1–2 天内出稿，而现行 blog SOP 跑一篇要数小时（四字段搜证 + 18 项 QA）。**需要一条模板化快车道**，建议先做演员页模板——优先级第 2 且结构最固定。

## 五、验证计划

选剧逻辑是否有效，用一次活体实验验证：

| 项    | 内容                                                                |
| ---- | ----------------------------------------------------------------- |
| 标的   | 《I'd Rather Marry the Beast Than You》——英语、目标市场、均位 3.62、70 个变体、零内容 |
| 动作   | 按第二节优先级 1–3 出内容，记录每步耗时                                            |
| 观测   | 该词族均位、点击、曝光的变化                                                    |
| 判据   | 内容上线后两周内，均位能否进前 3；点击能否显著增长                                        |
| 同时验证 | 从选定到内容上线实际需要多久（决定快车道要压缩到什么程度）                                     |
