# 低竞争关键词工具 —— 数据与字段规格

工具自己跑完 SERP 四问，输出的词直接送进 blog 写作页，中间不需要人工再过一遍 SERP。

---

## 一、读取哪些数据

### 1.1 用户站点，三层

| 层 | 读什么 | 请求量 | 取什么内容 | 服务于 |
|---|---|---|---|---|
| **L1** | `sitemap.xml`（有 index 就展开分片） | 1 次 + 分片数 | **只要 URL，不取页面内容** | 覆盖情况 |
| **L2** | 重点页面，选法见下 | **10–20 页，有界** | 正文 + title + H1 + 功能名 | 候选词生成 |
| **L3** | GSC 页面报表 + 查询报表 | API | URL + 查询词 + 曝光 | 覆盖情况 |

**L1 只取 URL**：判断「站上有没有页面在打这个词」是关键词与 slug 的字符串匹配，不需要读页面。所以这层可以覆盖全站，一万页也是秒级。

> 站点没有 sitemap 时，「已有页面但零曝光」这一态判不出来，**界面要明示，不能静默降级成「确实没有页面」**。

**L2 抓哪些页**，按序取满上限：

| 序 | 页面 |
|---|---|
| 1 | 首页 |
| 2 | **首页 header / footer 导航指向的内部页面** |
| 3 | 产品页 / 工具页 / 功能页 |
| 4 | 定价页 |
| 5 | blog / 资源**列表页**（不是单篇） |
| 6 | sitemap 里路径最浅的一级页面 |

排除，不占配额：

```
/about  /contact  /privacy  /terms  /legal  /careers
/login  /signup  /account  /dashboard
blog 单篇文章
分页页（?page=2、/page/2）
```

上限从 10 提到 20，按上表排序后截断，截断数量在界面显示。

### 1.2 SERP，每个候选词一次

**对全部候选词抓取**（排除确认零量的词）。一次请求产出五组数据：

```
1 次 SERP 请求
   ├─ 前十域名 + 位次     →  最弱排名
   ├─ 域名列表            →  送 RDAP 查域龄、送流量 API 查月访
   ├─ 域名白名单匹配       →  UGC 位
   ├─ 顶部区块检测         →  AI Overview 有无 + 摘要文本
   └─ 前十标题 + 页面类型  →  Intent、竞品参考
```

> **没抓到 SERP 的词不进输出表**，放进单独的「未完成检测」区并标明数量。不要用「未观测到 / 未检查」这类占位值填进表里。

### 1.3 外部数据源

| 数据 | 来源 | 说明 |
|---|---|---|
| 域名注册日期 | **RDAP**（IETF 标准，免费无 key） | `events[eventAction=registration].eventDate`。**注册日期永不变，永久缓存** |
| 域名月访 | 流量 API | **先确认 DataForSEO 是否覆盖此指标**；按域名缓存，月度刷新 |
| 搜索量 / KD / 域名权重 | 关键词数据源 API | 现有 |
| 用户自身站点权重 | 同上，查用户域名 | 用于判定分档，见第四节 |

UGC 位白名单，**零额外请求**（域名列表已在手）：

```
reddit.com  quora.com  stackexchange.com  stackoverflow.com
medium.com  news.ycombinator.com  discourse 类论坛
```

## 二、展示字段

| # | 字段 | 含义 | 数据来源 | 取值 |
|---|---|---|---|---|
| 1 | **关键词** | 候选目标词 | L2 + 生成 + 数据源扩展 | 字符串 |
| 2 | **搜索量** | 月均搜索次数 | 关键词数据源 | 整数 / `零量` / `数据源未覆盖` |
| 3 | **KD** | 数据源给的关键词难度 | 关键词数据源 | 0–100 |
| 4 | **最弱排名** | 前十里权重最低的域名及其位次 | SERP + 数据源权重 | 0–1000 + 域名 + 位次 |
| 5 | **AI Overview** | SERP 顶部有没有 AI 摘要 | SERP | 有 / 没有 |
| 6 | **你的覆盖情况** | 站上是否已有页面在打这个词 | L1 + L3 | 三态，见下 |
| 7 | **相近词分组** | 词面相近、需合并核实的词 | 词面聚类（现有模块） | 词组，单独一张表 |

现有的「**动手前先查**」列去掉，它要提示的事由字段 6 直接给结论。

**字段 6 三态**：

| 取值 | 依据 | 后续动作 |
|---|---|---|
| 已有页面且在拿曝光 | GSC 页面报表命中 | 不进写作页，转去优化现有页 |
| 已有页面但零曝光 | sitemap 有匹配 slug，GSC 无记录 | 不进写作页，转去查为什么没排上 |
| 确实没有页面 | 两边都没有 | 可进写作页 |

## 三、内部字段（后台计算，不展示）

| # | 字段 | 含义 | 用途 |
|---|---|---|---|
| 8 | 最年轻域名 | 前十里注册最晚的域名，注册于何时 | 第一问 |
| 9 | 最弱站月访 | 前十里月访最低的站，它的月访 | 第二问 |
| 10 | UGC 位 | 前十里有没有 UGC 站，在第几位 | 第三问 |
| 11 | 四问判定 | 综合结论 | 决定这个词进不进输出表 |
| 12 | AI 摘要文本 | 摘要说了什么 | 判第四问；送写作页 |
| 13 | SERP 前十 | 标题 + URL + 页面类型 | 推 Intent；送写作页 |

判定结果**不作为一列展示**——输出表里的词都是已通过的。

## 四、判定逻辑

```
第一问  最年轻域名 ≤ 24 个月        → 是 / 否
第二问  最弱站月访 < 阈值（见下）    → 是 / 否
第三问  前十有 UGC 位                → 是 / 否
──────────────────────────────────
三问全「否」                         → 放弃，不进输出表
至少一个「是」                       → 进输出表

第四问  有 AI 摘要                   → 不否决，内部标记为折扣
        AI 摘要已完全回答该问题       → 否决，不进输出表
```

第四问的「是否完全回答」用 LLM 判，输入是字段 12 的摘要文本。

**第二问阈值按用户站点强度分档**：

| 用户站点强度 | 阈值（前十最弱站月访） |
|---|---|
| 新站 / 极弱 | < 5,000 |
| 中等 | < 50,000 |
| 较强 | < 100,000 |

> ⚠️ 我们工具的权重是 **0–1000**，Ahrefs DR 和 Semrush Authority Score 都是 **0–100**，三者不可互换。分档用哪一个要定死并在字段说明标明。
>
> ⚠️ 这组阈值是提案，**先回测再上线**：拿已有人工结论的词跑一遍，判定翻转的先调阈值。

**KD 不设门槛**，保持现状展示。但 KD < 20 却三问全否的词，在「已排除」区标明原因，避免用户以为工具漏了。

**搜索量不设下限**。「数据源未覆盖」的词照常进四问。

输出表按四问强度排序，三问都是「是」的排最前。

## 五、输出到 blog 写作页

判定通过的词一键送入，传这些字段：

| 写作页字段 | 来源 |
|---|---|
| `Target Keyword` | 字段 1 |
| `Associated Keywords` | 字段 7 相近词分组 |
| `月搜索量` | 字段 2 |
| `KD` | 字段 3 |
| `Intent` | 字段 13 前十页面类型，LLM 判定 |
| `竞品前十` | 字段 13 |
| `AI 摘要文本` | 字段 12 |
| `四问判定依据` | 字段 8/9/10 的具体值，后台传后台 |

留空、由写作流程另行补齐：

```
Tier  Template  page_role  cluster_id
Entity  Friction  Logic  content_angle
```
